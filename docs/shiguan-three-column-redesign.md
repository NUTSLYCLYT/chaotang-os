# 史馆三栏页面重设计方案

## 1. 史馆定位

史馆不是普通历史记录页，而是朝堂 OS 的长期组织记忆系统。

它负责把已发生的任务、奏折、裁决、会审、执行结果、证据、风险和复盘结论沉淀成可再次调用的案卷。史馆页面的核心问题不是“展示了多少内容”，而是：

- 过去做过什么
- 当时为什么这么判断
- 结果是否达成
- 有哪些证据支撑
- 下次遇到类似事情应该怎么少犯错
- 哪些内容是真实归档，哪些只是 fallback 或演示态

一句话定义：

**史馆 = 归档 + 复盘 + 旧案召回 + 可信留痕。**

## 2. 页面总结构

页面采用三栏布局：

```text
┌────────────────────┬──────────────────────────────┬────────────────────┐
│ 左侧：案卷索引      │ 中间：史馆卷轴                │ 右侧：复盘与召回    │
│ Archive Index      │ Imperial Archive Scroll       │ Review & Recall    │
└────────────────────┴──────────────────────────────┴────────────────────┘
```

设计原则：

- 中间卷轴是主视角，承载当前选中案卷的完整叙事。
- 左侧面板负责“找案卷”和“看来源”。
- 右侧面板负责“解释价值”和“反哺下一次决策”。
- 所有模块必须显示来源状态：`LIVE`、`MIXED`、`FALLBACK`、`DEMO`。
- fallback 内容可以展示，但不能伪装成真实归档。

## 3. 左侧面板：案卷索引

左侧是史馆的检索入口，目标是让用户快速知道“史馆里有什么”。

### 3.1 总览卡

展示：

- 案卷总数
- 奏折数
- 决策档案数
- 任务履历数
- 知识条目数
- 已复盘数量
- 未复盘数量

数据来源优先级：

1. `/api/court/shiguan/stats`
2. `/api/chaotang/archive`
3. fallback 空态

### 3.2 案卷列表

展示最近归档的案卷。

每条案卷显示：

- 标题
- 类型：奏折 / 决策 / 任务 / 知识 / 宣传资料
- 所属部门
- 状态：已归档 / 待复盘 / 已复盘 / 阻断
- 来源标记：`LIVE`、`MIXED`、`FALLBACK`
- 更新时间

点击后，中间卷轴切换到该案卷。

### 3.3 筛选

筛选维度：

- 案卷类型
- 部门
- 状态
- 来源状态
- 是否已复盘
- 是否可复用

筛选只影响左侧列表，不改变中间卷轴当前内容，避免用户阅读时跳动。

## 4. 中间卷轴：史馆主案卷

中间是页面核心，用卷轴形式展示“当前案卷的完整历史叙事”。

### 4.1 卷轴头部

展示：

- 案卷标题
- 案卷编号
- 归档时间
- 来源状态
- 关联任务 ID / 奏折 ID / 决策 ID
- 当前结论：成功 / 失败 / 延期 / 观察 / 未定

如果没有选中案卷，则显示“史馆总览卷轴”。

### 4.2 事实摘要

回答：

- 这件事是什么
- 为什么进入史馆
- 最终做了什么决定
- 当前结果如何

要求：

- 只展示已有后端数据或明确 fallback。
- 不用页面文案替后端编造结果。

### 4.3 决策链

展示这件事的关键过程：

```text
上书房下旨
→ 丞相判断
→ 军机处/六部/单 Agent 执行
→ 形成奏折
→ 皇上确认
→ 史馆归档
→ 复盘状态更新
```

每一步显示：

- 时间
- 角色
- 动作
- 证据
- 状态

### 4.4 证据链

展示所有可追溯依据：

- 原始下旨内容
- 润色后旨意
- 部门回奏
- 会审结果
- 执行产物
- 外部引用
- 上传文档
- 截图 / 门禁 / 测试结果

每条证据必须带来源状态。

### 4.5 史馆判词

这是中间卷轴最重要的一段。

格式：

```text
史馆判词：
本案可归档 / 不可归档 / 仅作草档 / 待补证。

原因：
1. ...
2. ...
3. ...

可复用经验：
...

不可复用风险：
...
```

判词不应该是文学化装饰，而是业务复盘结论。

## 5. 右侧面板：复盘与召回

右侧负责回答“这份案卷以后有什么用”。

### 5.1 复盘状态

展示：

- 未复盘
- 已达成
- 未达成
- 部分达成
- 仍在观察

操作：

- 更新复盘状态
- 添加复盘说明
- 标记下次建议

后端接口：

- `POST /api/shiguan/archives/{archive_id}/retrospective`

### 5.2 可复用教训

展示从案卷中提炼出来的 lessons：

- 成功经验
- 失败原因
- 证据缺口
- 组织流程问题
- 下次建议

数据来源：

- `/api/scribe/lessons`
- 后续可接史馆归档蜂群 `shiguan_archive`

### 5.3 相似旧案召回

展示与当前案卷相似的历史案例。

每条显示：

- 案卷标题
- 相似原因
- 当时结果
- 可借鉴动作
- 不可照搬风险

目标是反哺上书房、丞相和军机处，让新任务不要从零判断。

### 5.4 下一步动作

右侧底部给出可执行动作：

- 召回旧案给上书房
- 生成复盘摘要
- 标记为可复用模板
- 要求补证
- 转为知识条目
- 进入再次会审

动作必须区分：

- 真实可执行
- 当前仅展示
- fallback 不可执行

## 6. 页面状态

### 6.1 空态

当没有真实案卷时：

- 不展示假案卷。
- 中间卷轴显示“暂无真实归档”。
- 左侧显示 0 统计。
- 右侧显示“完成上书房裁决或任务归档后，史馆将开始沉淀旧案”。

### 6.2 fallback 状态

当后端只返回 fallback：

- 页面可以显示结构。
- 所有数据必须标记 `FALLBACK`。
- 不显示“成功率”“真实案卷”等容易误导的字眼。

### 6.3 有案卷但未复盘

中间展示事实链。

右侧重点显示：

- 待复盘
- 建议补充结果
- 不能进入“可复用经验”区

### 6.4 已复盘

中间展示完整案卷。

右侧展示：

- 结论
- lesson
- 相似旧案
- 可复用模板

## 7. 与后端能力对齐

当前已存在或相关接口：

| 功能 | 接口 | 当前定位 |
| --- | --- | --- |
| 案卷统计 | `/api/court/shiguan/stats` | 史馆总览 |
| 案卷列表 | `/api/chaotang/archive` | 案卷索引 |
| 史馆分析 | `POST /api/court/shiguan/analyze` | 分析/引用，当前可能 fallback |
| 复盘状态 | `POST /api/shiguan/archives/{archive_id}/retrospective` | 更新旧案结果 |
| 旧案教训 | `/api/scribe/lessons` | lessons 聚合 |
| 发布门禁 | `/api/court/shiguan/release-gates` | 发布/审计归档 |
| 宣传归档 | `/api/court/shiguan/promo-archive` | 礼部宣传资料归档 |
| IMA 知识 | `/api/court/ima-knowledge` | 知识条目 |

后端未来应补强：

- 正式史馆案卷详情接口
- 相似旧案召回接口
- 史馆归档判词接口
- lessons 与案卷绑定
- sourceLabel 统一规范

## 8. 推荐模块取舍

保留：

- 案卷总览
- 案卷列表
- 中间卷轴
- 证据链
- 复盘状态
- lessons
- 相似旧案
- 下一步动作

弱化或移出：

- 大量纯前端 mock 的建设复盘
- 与史馆主定义无关的装饰型数据
- 没有后端事实源的“成功率”
- 没有案卷绑定的静态知识图谱

隐藏条件：

- 如果接口返回 fallback 且无真实数据，模块展示空态，不展示假内容。

## 9. 最终页面一句话

史馆页面应该让用户一眼看到：

**这件事从哪里来、怎么判断、结果如何、证据在哪、下次怎么复用。**
