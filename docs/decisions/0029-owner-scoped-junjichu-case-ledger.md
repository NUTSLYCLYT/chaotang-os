# 决策 0029：军机处私有案卷台账

## Status

Accepted — 2026-07-28

## Context

军机处目前只能从史馆读取当前用户已归档的 `REPLY`，无法查询正在进行的跨部会审。用户确认：凡经军机处会审的案卷，都应在军机处查询；可见范围严格限于发起该旨意的朝堂用户。

ADR 0028 仍规定下旨是唯一业务入口、跨部旨意由军机处串行会审、最终只归档一条 `REPLY`。因此不能把军机处做成新的下旨、调度、采证或审批入口，也不能以展示需要伪造未产生的意见。

## Decision

新增一个窄域、按 `owner_user_id` 隔离的“军机处案卷台账”，只记录进入多部门军机处路径的案卷及其真实处理检查点。台账从下旨的既有同步链路创建并更新；案卷完成时关联既有、唯一的史馆 `REPLY`，而不是替代或复制史馆归档。

军机处查询仅返回当前认证用户拥有的案卷。案卷状态固定为：`MINISTRY_REVIEWING`、`COUNCIL_REVIEWING`、`CHANCELLOR_FINALIZING`、`ARCHIVED`、`FAILED`。页面只能展示已写入的处理路径、参与部门、已完成部议、军机处结论和已归档回奏；尚未产生的内容须明确显示为等待，不得由 UI 或模型推断。

军机处页面采用“会审主舞台”：左侧为按进行中优先、最近更新排序的私有案卷列表；中央为所选案卷主卷与当前节点；右侧为六部参与/办理状态。页面只提供返回上书房下新旨和前往史馆复盘的真实入口。

## Consequences

- 收益：用户可在一个位置连续查看自己的会审进展和已归档结果；归档案卷保持与进行中案卷同一身份。
- 收益：所有查询继续由服务端根据认证会话确定所有者，浏览器不传递或选择 owner。
- 代价：需要新增后端持久化模型、迁移、私有查询契约和前端状态投影；每个同步处理节点必须原子更新案卷，失败须留下脱敏失败状态。
- 限制：这不是通用任务队列、异步编排器、人工审批台或新业务入口；不改变 ADR 0028 的单一入口、军机处串行会审、锦衣卫边界和一旨一条 `REPLY`。
