## 1. 定位与定义（三层，互相锁扣）

| 层 | 定义 | 每个词的排除作用 |
|---|------|----------------|
| 对用户 | **"第一个敢让你直接照办的AI"** | "敢"直击全行业信任崩塌死穴；"直接照办"排除参考级聊天机器人；"第一个"占类目空位 |
| 对自己 | **"AI想、代码管、结果教、你批"** | 排除纯LLM包装（无确定性骨架）、无记忆一次性工具（无"教"）、全自动（无"批"则丢问责） |
| 类目 | **可托付智能（Trustable Intelligence）** | 行业卷"更强智能"，我们卷"敢托付"；业主原词"确定的智能"为内部架构原则，"可托付"是它的用户语言 |

朝堂皮不是装饰，是定义的具象化：用户身份是**皇帝（裁决者）**，不是提问者。
下旨—回奏—圣裁三动作 = "敢让你直接照办 + 你负责批"的产品化身。主权感是
小团队竞品与大厂都未占据的情绪价位。

## 3. 核心洞察

### 3.1 确定的智能（业主命题，架构已内建）

行业卷"更聪明"，用户缺"敢托付"。本仓库从第一天就在建确定性骨架
（确定性路由/硬门/证据锚定，`chancellor_router.py` 原注释："编排是受约束选择，
不是自由agent"），LLM 只在骨架内发挥。模型快速进步的正确应对：**只建模型
变强后仍然值钱的东西**——验证层、记忆层、信任层、数据飞轮。模型是CPU，
harness 是操作系统；CPU 十八个月换代，操作系统活几十年。

### 3.2 最小完整环（最终产品的全部本质）

```
下旨 → 可托付的回奏 → 圣裁 → 真实回执 → 记忆 → 下次更准
```

**MVP = 最小完整环，不是最少功能**。环缺一步，功能再多都是死物；环完整，
每步简陋也活着、在长大。iPhone一代没有App Store，微信一代只能发文字——
最终产品不是做出来的，是留下来的。

### 3.3 爆品 vs 进化系统的矛盾（要分层设计）

爆品靠第一次惊艳传播，进化系统价值在第一百次使用。本产品是**留存品**，
需要一个爆品级入口体验（旅行场景）做获客。两层分开设计。

## 4. 成立条件（六条，缺一不可）

1. **证据可靠性"敢直接执行"级**：关键事实可回溯率100%、查不到显式标注率100%、伪造率0
2. **决策留痕"审计级"**：谁、依据什么证据、御史查过什么、何时批的（基建已在）
3. **记忆复利"越用越懂你"**：第100次比第1次准，离开=删掉一段自己（唯一真壁垒）
4. **垂直深度"比行业顾问懂"**：一个域打透 > 十个域打平
5. **交付体验"三动作"**：下旨、看回奏、点裁决；复杂性全部后台
6. **成本透明**：下旨前预估、封顶、失败退还（直击 Manus 积分焦虑）

### 产品级（六个）

| 设计 | 一句话 | 成本 |

## 7. 总排序与理由

**排序原则**：杠杆优先（先做让一切变快的事）、依赖前置、WIP=1、每步出活。

| 阶段 | 内容 | 为什么在这个位置 |
|---|---|---|
| 0（本周） | 清场：批PKT-6、清废分支、礼部激活小债 | 库存是浪费；带烂摊子开战会在最忙时被绊倒（已验证） |
| 1（第1周） | PKT-7 圣裁台 | **乘法优先于加法**：之后每个Packet审批7步变1键；自用计数启动 |
| 2（第2周） | PKT-8 下旨口 + PKT-5接线 + 锦囊前3个 | 闭环入口；最便宜一步；凡人红利首落点 |
| 3（第3周） | PKT-9 回执流 + 钦天监批注 | M7第一滴真数据来自开发本身 |
| 4（4-6周） | K系列还账 | 此时圣裁台已能加速它；前三周圣裁记录=第一批真实记忆数据。**注意**：知识飞轮蓝图明文规定 K1 前置硬门为 K0C + C1 tenant/RBAC——单用户模式可能允许 C1 缩窄范围，但这需要业主正式改判蓝图门（ADR），不能默认门已放松 |
| 5（7-9周） | 旅行场景纵切 | 依赖外部API（**申请动作现在就发起**，开发排后，日历时间不浪费） |
| 6（10周起） | 放权等级+拟票 → 移动端 | 放权默认值要等"你批过什么"的数据；先上微信推送回奏极简版垫底 |

## 8. Agent/Skill 制作纪律

**核心裁决：现阶段不造新 agent，只造确定性脚本和 prompt 库。**

实证依据：本仓库最有价值的新工具是纯确定性脚本（`dept-capability-map`），
最大浪费是资产堆积（55分支教训）。仓内已有 7 个 gongbu-* agent + **40** persona +
几十个 skill——缺的不是新 agent，是把现有的接上产品。

| 要做的 | 形态 | 为什么不是 agent |
|---|---|---|
| 圣裁台 envelope 生成 | 确定性脚本 | SHA/merge形状必须精确可审计 |
| 锦囊按钮 | prompt 模板库 | 提示词就是文本，包 agent 是过度工程 |
| 钦天监匹配 | 移植 expert-perspective 的路由方法论（该 skill 在业主个人 Claude 配置，非本仓组件），匹配引擎产品内新写 | 方法论可抄，代码不存在现成件 |
| 下旨口 spec 草稿 | PKT-5 推荐层 | 已建壳，接 provider |
| 旅行 scout | 第5阶段再定，优先 flow 节点 | 到时按真需求裁决 |

**编排**：Packet 严格串行（WIP=1）；只读调研可并行 fan-out（已验证模式）。

## 9. 质量门（新增一条产品级硬门）

保留全套：RED→GREEN、doctor、D6闸、独立复审、known-red 台账。

**新增：自用验收**——面向用户的 Packet，DONE 定义含"业主真实用过至少一次并留下
回执"。测试绿了不算完。我们自己不敢用的东西，凭什么让凡人照办。

## 10. 三个"永不"（产品宪法，靠边界定义产品）

1. **永不做通用聊天**——朝堂只接"旨"（有明确意图的委托）
2. **永不冒充确定**——查不到就说查不到；此条破一次产品即死
3. **永不抢圣裁**——最终决定永远是用户点头；全自动之日即"可托付"变"不可控"之时

## 11. 北极星指标（只看一个）

**敢直接照办率**：回奏被用户不加修改直接采纳执行的比例。
同时度量可靠性、记忆质量、理解深度。每周看一次。它不涨，加任何功能都是自欺。

测量装置：埋进圣裁台（PKT-7 spec 硬性要求），每次准奏/封驳/改后采纳各落一条
结构化记录——水表必须盖楼时埋进墙里，完工后再装要砸墙。

## 11.1 止损线（什么情况认输，现在写死，防沉没成本）

自用 100 次完成后结算一次：**敢直接照办率若低于 50%，停止加功能，回炉重审定位**
（是回奏质量问题还是定位本身错了，由当时的败仗记录裁定）。此线一旦触发不许
"再试一个功能就好了"——那正是沉没成本推人在错路上盖到第十层的方式。
阈值 50% 为业主初设，可在首次结算前以 ADR 形式调整，但不可在结算时临场调整。

## 11.2 隐私一页纸（K 系列开工前的门锁）

- **存什么**：圣裁记录（批/驳/理由）、任务回执、用户显式提供的偏好与约束。
- **不存什么**：未经显式确认的推断画像；第三方私人信息；原始凭据/支付信息
  （只存脱敏引用）。
- **怎么删**：记忆主权面板提供逐条删除与全量导出；删除即物理删除并断开索引，
  不做"软删除但继续用于训练"。
- **单用户阶段的简化**：当前唯一用户是业主本人，本页即全部约束；外部用户进入前，
  本节必须升级为正式隐私政策并过一次独立审查。

## 12. 架构级决断（最终产品怎么做）

1. **后端骨架全留，前端重开一张脸**：确定性路由/门下省/御史/史馆/D6 是真资产；
   消费者界面新开轻面（移动优先，第一版可以就是微信里收回奏+回一个字"准"），
   不在企业驾驶舱上改装。
2. **一人一朝廷**：第一版单用户单实例（业主=实例001），租户复杂度留给规模到来时。
3. **环上每步用现成零件**：第一版完整环可以没有任何新发明——全部是已存在零件的
   重新排列；新发明留给真实使用逼出的需求。

## 13. 诚实缺陷登记

1. 企业骨架转个人的治理摩擦——要后台静默化，不是照搬
2. 无移动端——个人产品生死项（第8件事）
3. 速度与诚实的张力——D0层必须快到无感，否则没人等严谨
4. 成本结构——蜂群烧token vs 个人订阅天花板，分级定价必须精算
5. 朝堂皮文化边界——中文超强差异化=出海门槛；是选择不是缺陷，但要清醒
6. 单人开发带宽——圣裁台部分自解；运营/客服/合规仍未解
7. 隐私责任——记人生数据=隐私炸弹；记忆主权面板是保险
8. 窗口以月计——细分空白+大厂峰会临近，前三件事三个月内不动则地图重画
