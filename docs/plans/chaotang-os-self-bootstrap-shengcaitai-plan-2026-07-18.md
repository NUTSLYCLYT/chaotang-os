## 0. 核心洞察：自举

2026-07-17 通宵会话的事实：业主下旨（"批PKT-1"/"同意"/"B"）、丞相拟票（方案+大神会审）、
工部执行（Codex）、御史复审（Claude packet review）、门下省拦截（D6闸+stop-hook）、
史馆归档（`.harness/changes/`）、圣裁（业主勾队列裁决表）——**朝堂的完整流程已经真实
运转了几十轮，缺的只是界面**。

因此第一个产品场景不是旅行，是**用朝堂开发朝堂**：
1. 第0天就有真用户（业主）真任务（真实开发决策），自用100次直接开始计数；
2. 每次圣裁喂记忆系统——批了什么、驳了什么、为什么，全进史馆，"进化"从第一周为真；
3. 开发效率立涨——手工 D6 envelope 流程（会话中手工做过7次）变一个按钮；
4. 产品故事最硬：这个产品是用它自己开发出来的，第一个皇帝是它的创造者；
5. 风险最低：数据源（`.harness/changes/` 全套结构）已存在，失败也只是多个内部工具。

## 1. 三周落地路径（每周末尾都在用，不是三周后才能用）

### 第一周：圣裁台（PKT-7）
- 一个前端页面读 `.harness/changes/`：奏折列表（change 卡片）+ 状态 + 证据链接
  （summary/spec/ci_summary/packet_review 已是现成结构化数据源）。
- 两个按钮：**准奏** / **封驳**。
- **权限边界（D6 写者/审者分离不可被按钮绕过）**：`approval-vN.json` 是**独立审查者**
  （Claude 复审会话）的裁决产物，绑定 review 报告的 `PACKET_REVIEW_GO`——业主的
  准奏按钮**不生成也不能生成**这份 envelope。按钮的职责分两半：
  - 准奏 = 记录业主圣裁（业主决策留痕，写入 change 记录）+ **在独立审查 GO 已存在
    的前提下**，自动化纯机械部分（SHA256 计算、B→H→R→M merge 形状组装、push）——
    自动化的是算术，不是裁决。
  - 独立审查缺失或为 NO_GO 时，准奏按钮置灰并显示原因——界面把 D6 纪律变得可见，
    而不是把它变成可跳过。
- 封驳 = 记录理由，写入 change 记录，状态回退。
- 验收：业主在界面上完成一次真实 Packet 的圣裁全流程（含一次因缺独立审查而
  置灰的负向案例），不碰命令行。

### 第二周：下旨口（PKT-8）
- 上书房输入框：一句话需求（"修复兵部关键词表"）→ 自动建 change 目录 + spec 草稿
  → 派给 Codex 会话。
- 需求入口从"跟 Claude 聊天"变成"给朝廷下旨"。
- 验收：一道旨从输入到 Codex 认领开工，全程界面内完成。

### 第三周：回执流（PKT-9 / M7 第一滴数据）
- 合并后的 Packet 自动追踪：回归还绿吗、相关 bug 复发没，结果回填原奏折。
- 验收：至少一个已合并 Packet 的回执自动出现在圣裁台上。

## 2. 丞相/钦天监交互系统：吸收 Claude Code 精髓的六个设计

| # | 设计 | 吸收自 | 要点 |
|---|------|--------|------|
| 1 | **翻牌子** | AskUserQuestion | 丞相不问开放问题，递 2-4 张牌子（选项+预览：要点/代价/风险），皇帝翻牌即定。开放提问是给用户出题，递牌子是给用户递权力。 |
| 2 | **锦囊按钮** | slash commands / skills | 顶级提示词技巧封装为一按即发的锦囊：反过来想（芒格倒推）、算笔账（ROI拆解）、唱反调（红队）、追问到底（5Why）、赌多大（置信度+下注尺寸）、说人话（去术语）。凡人不会写 prompt，锦囊替他们写——"让凡人享受红利"的第一个真实落点。成本诚实：**零新增基建成本**（纯模板库），但每次按下仍消耗一次真实模型调用，计入用户预算显示。 |
| 3 | **钦天监天象批注** | UserPromptSubmit hook 的大神建议行 | 旁观每道旨，只露一行相关提醒（可点展开完整会审，可无视），永不打断。被动而不缺席。 |
| 4 | **拟票模式** | Plan mode | 大事（不可逆/高金额/涉外，按 D0/D1/D2 硬门自动判）自动进拟票：丞相只呈方案不动手，朱批后才执行。 |
| 5 | **放权等级** | permission modes | 三档信任旋钮，按域分设：事事请旨（每步批）/ 先办后奏（办完汇报）/ 便宜行事（月度总结）。旅行查询可便宜行事，花钱必须事事请旨。 |
| 6 | **夜行军+朝会** | background agents + session digest | 重旨下达后休息，蜂群夜跑，回奏清晨推送；每日早朝摘要：昨日回奏、待圣裁、钦天监警示。等待从盯屏幕变成醒来看奏折。 |

另有此前已定稿的产品级天才设计（见会话记录，此处登记不展开）：
预算前置+失败退还、跨域自我矛盾检测、败仗博物馆、记忆主权面板、点名大神会审
（**40**人 persona 名册已存在于仓内 `skills/personas/`——54人名册是业主个人
Claude 配置里的 expert-perspective roster，非本仓组件，产品只能依赖仓内40人）、
思考的诚意可见（D2 真实节点事件流）。

## 3. 与既有架构的关系

- 圣裁台读写的就是 `.harness/changes/` + D6 闸——**不建第二套审批事实源**，只做界面。
- 丞相拟票 = PKT-5 推荐层（已 push，待接 provider）+ 翻牌子渲染。
- 钦天监天象 = 仓内 persona 名册（40人）+ 后台匹配。expert-perspective 是业主个人
  Claude 配置里的 skill（`~/.claude/skills/`），**不是本仓组件**——可移植其路由
  方法论（领域判断→专家匹配→分级深度），但匹配引擎要在产品内新写，不存在
  "接线即可"的现成件。
- 放权等级映射到 D0/D1/D2 处理深度（convergence guide 3.2 节既有分级机制）。
- 回执流 = 世界级 Agent Harness 方案 M7 的第一个真实数据源。

## 5. 诚实缺陷登记（不删不藏）

1. 企业骨架转个人的治理摩擦——租户/审批要后台静默化，不是照搬
2. 无移动端——个人产品的生死项，本方案未覆盖，排第 8 件事
3. 速度与诚实的张力——证据链比秒回 chatbot 慢，D0 层必须快到无感
4. 成本结构——蜂群烧 token，个人订阅天花板低，分级定价必须精算
5. 朝堂皮的文化边界——中文超强差异化 = 出海理解门槛，是选择不是缺陷，但要清醒
6. 单人开发带宽——圣裁台部分自解（效率工具），运营/客服/合规仍是未解
7. 隐私责任——记人生数据 = 隐私炸弹，记忆主权面板是保险不是功能
8. 窗口以月计——"AI人生管理"细分当前空白（2026-07 调研证实），7/21 大厂峰会后不保证
