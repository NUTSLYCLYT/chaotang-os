# 朝堂 OS 写实朝堂 UI V7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在既有 Figma 文件中完成 11 种页面、约 18 张状态画板的统一写实朝堂桌面 UI。

**Architecture:** 先建立 V7 设计令牌与公共组件区，再按互不重叠的页面分区并行落图。所有业务页面复用同一视觉骨架和案卷信息模型，最后由负责人统一连接原型并逐页截图验收。

**Tech Stack:** Figma Design、Figma Plugin API、现有图像资源、未来 AI 图生视频占位。

## Global Constraints

- Figma 文件固定为 `bQAkFbJd9y0INu3m9H4dIu`，页面固定为 `153:2`。
- 正式画板固定为 1440×1024。
- 全局导航固定为上书房、军机处、六部、史馆。
- 欢迎页仅保留一个正式视频方案。
- 锦衣卫不进入全局导航。
- 皇帝只对下旨、身份、查询和阅览执行人工操作，不代替 Agent 办理。
- 不删除旧版原型；V7 在新 Section 中建立。

### Task 2: 欢迎、登录、注册与上书房

**Consumes:** Task 1 公共组件。

**Produces:** 欢迎、登录、注册以及上书房四个案卷状态画板。

- [ ] 创建欢迎页，使用视频首帧占位和唯一“上朝”主操作。
- [ ] 创建登录页和注册／创建朝堂页。
- [ ] 创建上书房未下旨状态。
- [ ] 创建上书房分流中状态。
- [ ] 创建上书房办理中状态。
- [ ] 创建上书房已回奏／已归档状态。
- [ ] 连接欢迎、身份验证和上书房入口。
- [ ] 截图检查各状态只改变内容和主操作，不复制新的页面结构。

### Task 3: 六部、部级、司级与锦衣卫

**Consumes:** Task 1 公共组件。

**Produces:** 六部三级页面和锦衣卫调查详情。

- [ ] 创建六部总览，提供六部门入口和案卷概况。
- [ ] 创建部级页面，展示正在处理和处理过的案卷及下属司进度。
- [ ] 创建司级页面，展示事实、证据、办理意见和锦衣卫补证提示。
- [ ] 创建锦衣卫调查详情，仅保留返回原司级案卷的路径。
- [ ] 连接六部总览→部级→司级→锦衣卫。
- [ ] 截图检查皇帝页面中不存在保存草稿或提交 Agent 意见的操作。

### Task 4: 军机处、史馆与统一案卷详情

**Consumes:** Task 1 公共组件。

**Produces:** 军机处、史馆、统一案卷详情及必要空态／异常态。

- [ ] 创建军机处待会审、会审中、已呈送结构及无触发案卷空态。
- [ ] 创建史馆检索、筛选、正式文书预览和归档详情。
- [ ] 创建统一案卷详情，覆盖圣意理解、丞相分流、司级、部级、军机、定案、回奏和归档。
- [ ] 创建退回补办或归档异常状态。
- [ ] 连接进行中案卷到当前责任工作区，已归档案卷到史馆。
- [ ] 截图检查同一案卷在不同入口的目标一致。

- [ ] 检查字体为 Noto Serif SC / Noto Sans SC。
- [ ] 检查所有页面主操作唯一且符合皇帝权限。
- [ ] 检查锦衣卫仅从司级进入。

- [ ] 逐张获取全屏与局部截图，修复裁切、重叠、错位和占位内容。
- [ ] 配置一个 V7 正式起始点并进行 Present 实测。
