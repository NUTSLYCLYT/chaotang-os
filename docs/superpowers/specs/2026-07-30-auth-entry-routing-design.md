# 登录后进入大殿设计

## 背景

V5 登录前页面已经接入真实认证，但当前登录与注册成功都共用同一目的地计算：默认进入
`/study`。产品要求调整为：

- 登录成功默认进入 `/dadian`；
- 注册成功不自动登录，固定返回 `/login`；
- 登录页显示明确的注册成功提示；
- 来自受保护页面的安全 `next` 仍可覆盖登录默认目的地。

`/dadian` 已存在并具备自己的未认证处理，本次不修改大殿业务内容，也不修改 ADR 0028
规定的下旨、证据和归档流程。

## 已确认产品行为

1. 普通登录成功后进入 `/dadian`。
2. `/login?next=/study` 与 `/login?next=/shiguan` 登录成功后仍返回对应受保护页面。
3. 不可信、未知或空的 `next` 均回退到 `/dadian`。
4. 注册成功后固定进入 `/login?registered=1`，不采用注册页上的 `next`。
5. 登录页检测到精确的 `registered=1` 时显示“注册成功，请登录”。
6. 注册成功后浏览器不得保留 `courtos_session`，用户必须重新登录。
7. 登录或注册失败时停留当前表单并显示现有安全错误信息。

## 方案

### 目的地边界

把认证成功目的地区分为两条明确路径：

- `submitLogin` 使用安全登录目的地解析器，允许 `/dadian`、`/study`、`/shiguan`，
  默认 `/dadian`；
- `submitRegister` 成功时固定返回 `/login?registered=1`。

解析器只接受精确的站内白名单值，不接受任意相对路径、绝对 URL 或编码绕过。

### 注册会话边界

后端当前注册响应会返回一个新会话，Next.js 注册 BFF 也会把它写入 Cookie。为了保持现有
后端契约且实现“注册后重新登录”，注册 BFF 将：

1. 完成注册并取得新会话；
2. 使用该会话调用现有注销接口做尽力撤销；
3. 返回注册成功响应，但不写入新会话 Cookie；
4. 对响应调用 `clearSessionCookie`，同时清除浏览器中可能已有的旧会话。

撤销失败不能把已成功创建的账号伪装成注册失败，否则用户重试会遇到账号冲突。此时仍返回
注册成功且不向浏览器暴露会话；服务端临时会话按现有过期策略失效。这是保持现有后端契约下
的有限剩余风险。

### 页面反馈

登录表单从查询参数读取 `registered`。只有精确值 `1` 渲染非敏感成功提示。提示不包含邮箱、
用户名或其他注册资料，也不自动提交登录。

## 错误处理

- 登录与注册请求失败：沿用现有状态码到安全中文提示的映射。
- 注册后的会话撤销失败：不影响已创建账号的成功结果，不设置 Cookie。
- 不可信 `next`：静默回退 `/dadian`，不回显输入值。
- 大殿未认证：沿用 `/dadian` 现有的 `/login?next=%2Fdadian` 跳转。

## 测试

按 TDD 增加或调整以下回归：

- 默认登录目的地为 `/dadian`；
- `/dadian`、`/study`、`/shiguan` 的精确安全回跳；
- 外部 URL、未知路径和空值回退 `/dadian`；
- 注册成功目的地固定为 `/login?registered=1`；
- 注册 BFF 不设置新会话、清除已有 Cookie，并尝试撤销新会话；
- 撤销失败时仍返回注册成功且不设置会话；
- 登录页仅对 `registered=1` 显示成功提示。

最后运行前端定向测试、全量测试、lint、typecheck、build、仓库 harness 与 diff check。

## 非目标

- 不重做 `/dadian` 的视觉或业务功能；
- 不改变登录、注册字段和后端账号创建规则；
- 不扩大安全 `next` 白名单到任意页面；
- 不改变 ADR 0028 的业务流；
- 不提交、推送或部署。
