# 司级证据协议有界自愈与局部降级设计

## 背景

真实旨意“我要招两个人做量化炒股，然后让他们去开发”能够完成丞相分流、部门选司和
锦衣卫调查，但司级模型可能返回裸 `{"opinion": ...}`、包含未声明事实的 READY，或在收到
纠正提示后仍返回不合规信封。DeepSeek JSON Output 只保证 JSON 语法，不保证业务 schema。
当前实现会在纠正机会耗尽后把司级协议错误升级为整条旨意的 `model_unavailable`。

本设计遵循 `docs/decisions/0028-decree-evidence-flow-governance-baseline.md`：不接受无证事实，
不绕过司级调查边界，不改变丞相、六部、军机处和史馆的业务拓扑。

## 目标

- 对可恢复的司级 schema 与事实声明漂移进行有界纠正。
- 纠正耗尽后丢弃违规响应，以确定性的证据受限司议继续后续流程。
- 单个司的合成失败不再导致整条多部门旨意失败。
- 保持调用次数、费用和延迟存在硬上限。
- 保留现有 HTTP 成功结构和前端契约。

## 非目标

- 不增加无限重试、退避或备用模型。
- 不接受、包装、摘录或回显任何被拒模型响应。
- 不放宽 READY、事实声明、证据采用或证据绑定校验。
- 不把网络、密钥、配置或丞相路由失败降级为成功。
- 不修改 ADR 0028、史馆归档结构或锦衣卫调查权限。

## 方案选择

采用“严格校验 + 有界自愈 + 司级局部降级”。

未采用的方案：

- 多次重试模型：费用、延迟和结果不可控，且无法消除连续 schema 漂移。
- 任一司级错误整旨失败：安全但可用性过低，正是当前用户可见故障。

## 状态机

### 首次响应

- 合规 READY：采用。
- 合规 NEEDS_DATA：进入一次司级调查。
- 精确裸非空 opinion：领取 decree 级信封纠正预算并纠正一次。
- 其他 schema、解析或事实声明错误：按错误分类决定局部降级或整旨失败。

### 调查后响应

- 合规 READY 且证据绑定正确：采用。
- 合规 NEEDS_DATA：不进行第二次调查，返回 `second_data_gap` 局部降级。
- `unsupported_factual_dependency`：领取 decree 级事实纠正预算并纠正一次。
- 其他不可信响应：局部降级，但模型调用传输失败除外。

### 事实纠正响应

- 合规 READY：采用。
- 合规 NEEDS_DATA：返回 `second_data_gap` 局部降级。
- `uncited_fact_dependency`、`unsupported_factual_dependency`、`response_invalid`、
  `adoption_invalid` 或 `evidence_binding_invalid`：丢弃响应并局部降级。
- 模型调用传输失败：保持整旨失败，不伪装成正常业务结果。

## 预算

每道旨意：

- 信封纠正最多一次，使用独立原子预算。
- 事实依赖纠正最多一次，使用独立原子预算。
- 每个司最多调查一次；现有全旨意调查、抽取和 30 秒期限不变。
- 局部降级不再调用模型或调查源。

并发领取必须保持原子性。一个司消耗某类预算后，同一道旨意的其他司不得重复领取该类预算。

## 错误分类

### 可局部降级

- 司级裸 opinion 在信封纠正后仍不合规。
- 调查后或事实纠正后的 schema 无效。
- 调查后 READY 包含未声明或不支持的事实。
- 纠正后的证据采用或绑定不合法。
- 第二次 NEEDS_DATA。
- 调查无结果、超时或预算耗尽的既有稳定原因。

### 必须整旨失败

- DeepSeek 网络、认证、配置或 SDK 调用失败。
- 丞相路由无法解析或不满足部门约束。
- 部级、军机处或丞相最终汇总无法形成其既有严格契约。
- 程序错误、身份错误或未知协议错误。

该分类避免用降级掩盖基础设施不可用，同时把模型内容漂移限制在发生漂移的司级节点。

## 局部降级内容

继续复用司级调用方已有的 `fallback(reason)`，不解析被拒响应。输出只允许包含：

- “数据或模型输出未满足证据协议”的稳定说明；
- 当前不能形成事实结论的明确限制；
- 不依赖外部事实的规范性建议。

禁止包含被拒响应的 opinion、数字、实体状态、行情、招聘事实或开发能力判断。

降级时调用 `AgentEvidenceSession.record_degradation(node_id)`，内部快照记录
`model_synthesis_degraded:<node_id>`。HTTP 响应本轮不新增字段，避免扩大前后端契约。

## 数据流

1. `invoke_bureau_with_evidence` 调用模型并严格解析。
2. 合规结果按现有路径返回；NEEDS_DATA 按现有路径调查。
3. 可纠正错误领取对应原子预算。
4. 纠正结果再次通过完整 `_parse_ready` 或 `_parse_gap` 校验。
5. 若纠正耗尽且属于可局部降级分类，记录 degradation 并调用既有 fallback。
6. 部级、军机处和丞相只消费该司议文本，继续既有串行流程。
7. 最终只归档一次完整 REPLY；被拒响应及其事实不进入归档或证据采用列表。

## 安全边界

- 纠正提示保持静态、脱敏，不包含原响应、异常正文、证据正文、密钥或 provider 细节。
- 局部降级不得读取或拼接被拒 payload。
- 只有通过全部绑定校验的 evidence ID 才能被采用和归档。
- `model_unavailable` 仍用于真实模型传输或配置不可用，不用于可安全隔离的司级内容漂移。

## 测试设计

### TDD 核心序列

新增回归覆盖：

1. 裸 opinion；
2. 信封纠正后 NEEDS_DATA；
3. 调查完成；
4. 调查后违规 READY；
5. 事实纠正后仍返回不合规信封；
6. 返回确定性 fallback，记录一次 degradation，且不采用任何证据。

测试必须先在旧实现下以 `uncited_fact_dependency` 失败，再由最小实现转绿。

### 失败关闭

- 事实纠正调用发生网络/SDK 异常时仍抛出 `model_unavailable`，不得降级成功。
- `bureau_identity_invalid` 和未知错误仍抛出。
- 被拒响应中的标记字符串不得出现在 fallback、纠正提示或 session snapshot 中。
- 纠正后伪造 evidence ID、错误 fact binding 或未声明事实均只能降级，不能被采用。

### 预算与回归

- 信封与事实预算各自原子、各最多一次且互不占用。
- 同一道旨意多个司竞争同类预算时只有一个成功领取。
- 合规 READY、正常调查恢复、第二次 NEEDS_DATA 和既有 evidence fallback 行为不变。
- 运行证据协议、司级、六部、军机处、丞相图和 decree API 的扩大回归。

## 验收标准

- 指定完整失败序列在离线测试中返回司级 fallback，而非抛出协议错误。
- 违规响应未被采用、包装、记录或归档。
- 模型传输失败仍导致整旨安全失败。
- 扩大离线回归、Ruff、harness 和 `git diff --check` 通过。
- 重启后端后，经单独授权使用用户原旨意进行一次真实、无史馆归档的完整图验证。
- 只有真实图完成分流、司议、部议、军机处和最终三条建议后，任务才能标记 Accepted。
