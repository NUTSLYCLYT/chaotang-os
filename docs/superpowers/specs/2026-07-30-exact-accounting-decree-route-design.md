# 财务报表旨意精确流转设计

## 背景

用户的自然语言旨意明确指定“户部会计司”基于现有财务数据生成 2024 至 2025 年管理层综合财务报表。该任务是单部门、单承办司任务。此前运行中的旧后端仍按旨意关键词重新推断部门，错误形成军机处、礼部、工部及锦衣卫路径；现有测试又通过伪造授权和执行图掩盖了运行态漂移。

## 已确认路径

完整治理路径固定为：

`上书房 → 丞相（首次分流） → 户部 → 户部·会计司 → 户部（部级补充） → 丞相（最终汇总）`

业务承办单位只有户部和会计司。该场景必须满足：

- `route_type == "single"`；
- `departments == ["户部"]`；
- 会计司意见恰好一条，不能追加户部其他司；
- `council_verdict is None`，不创建军机处案卷；
- 路径不得包含军机处、礼部、工部、其他部门或锦衣卫；
- 财务报表使用会计司的确定性报表能力与现有财务数据，不通过锦衣卫补采；
- 最终仍保留 ADR 0028 要求的上书房、丞相首末节点和户部部级补充。

## 实现边界

1. 拟旨阶段继续由服务端语义校验把财务报表任务收敛为户部、会计司。
2. 六部执行阶段对财务报表意图采用精确司集合，模型返回任何额外司都必须经过一次安全纠正；再次不一致则在司级调用前失败。
3. 会计司生成确定性财务报表时不启用锦衣卫证据调查；原始财务数据只通过报表会话读取。
4. 正式 API 对成功结果执行完整路径一致性校验，不能只校验部门和“必选司子集”。单部门财务报表路径必须与上述固定路径完全相等。
5. 测试必须覆盖真实授权、真实正式图和真实 HTTP 边界；不得同时伪造授权与执行图来证明路由正确。
6. 增加运行态冒烟检查，至少验证当前监听服务是在本次源码加载后启动，避免旧进程造成假绿。

## 错误与副作用

模型若尝试增加其他司，最多纠正一次；第二次仍不精确时返回脱敏的 502。任何路径、部门或司级结果漂移在归档和报告发布前失败。单部门路径不会创建或更新军机处案卷。

## 验收

- 用用户完整原旨意执行真实图，处理路径精确等于已确认路径。
- 军机处调用次数、军机处开案次数和锦衣卫调查次数均为零。
- 模型选择 `["会计司", "审计司"]` 时不会执行审计司。
- API 对夹带军机处、礼部、工部、锦衣卫或额外户部司的结果拒绝并且不归档。
- 后端全量测试、静态检查、前端测试/类型检查/Lint/构建和 harness 均通过。
