# 下旨失败原因分类设计

## 范围

修复上书房下旨过程将“客户端超时”误报为“后端未启动”的问题。保留现有下旨业务流、端点和 120 秒等待上限。

## 当前原因

`submitDecree()` 将 `fetch()` 抛出的所有异常归为 `network`。其中包含由 `AbortController` 在 120 秒触发的中止。因此后续 UI 无法区分“后端不可达”与“请求超时”。

## 设计

1. 在前端下旨结果类型中新增 `timeout`，仅用于本客户端配置的超时中止。
2. 调用 `fetch()` 时记录超时是否由本地计时器触发；只有该标志为真且请求进入异常分支时，返回 `timeout`。其他异常仍返回 `network`。
3. Next.js BFF 为 `timeout` 返回稳定的 504 状态及脱敏中文文案；原有 HTTP 映射保持不变。
4. 浏览器提交边界只接受已知错误分类，因此必须将 `timeout` 加入其白名单，保留 BFF 的 504 分类而不是降级为 `unknown`。
5. 上书房 UI 将 `timeout` 映射为“下旨处理超时，请稍后重试”，而 `network` 保持“无法连接朝堂后端，请确认后端服务已启动后重试”。
6. 采用测试先行：先分别写出超时、网络异常、BFF 504 和浏览器提交边界错误分类的失败测试，再实施最小代码。

## 验收与安全边界

- 验收测试使用注入的 `fetch` 与计时器，不调用真实模型。
- 通过 `/health` 证明当前前后端可达；不通过真实下旨验证，以避免产生模型调用费用或归档副作用。
- 不调整超时值，不修改 FastAPI 端点，不改变 ADR 0028 流程。

## 追加：移除静态费用提示

用户已明确要求移除上书房的“下旨会触发真实司议、部议、军机处会审与丞相汇总，并可能产生多次模型调用费用；请确认后提交。”。删除两个 composer 标记中的该提示节点以及仅服务于该节点的 `feeNotice` 样式；保留“办理中”状态、下旨按钮和所有提交错误提示。
