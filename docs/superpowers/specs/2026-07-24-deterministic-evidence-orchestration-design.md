# 确定性证据编排与行情降级设计

## 状态

用户于 2026-07-24 确认采用本设计。第一阶段只交付中国大陆可交易股票的最新价闭环，
但所有新增边界使用通用事实计划接口，不在上层编排中绑定腾讯或任何具体数据提供方。

## 问题

当前股票行情旨意需要连续经过多次模型严格 JSON 输出。即使锦衣卫已经通过只读 MCP
取得有效行情，任一后续模型节点出现字段漂移、额外市场范围、非规范单位或不完整引用，
整条链路仍会被折叠为 `model_unavailable`，页面显示“丞相暂时无法给出回奏”。

这不是腾讯 MCP 的取数问题，而是上层把以下系统职责交给了模型自由生成：

- 是否缺少外部数据；
- 需要哪些规范事实；
- 市场、单位和数据形状；
- 取得证据后的最低可用答复。

## 目标

- 明确的大陆股票最新价旨意由系统生成规范事实计划，不再等待模型返回
  `NEEDS_DATA`。
- 史馆资料满足身份、覆盖范围和时效要求时直接使用；否则调用管理员批准的只读 MCP。
- 已取得且验证通过的行情不会因后续模型格式失败而丢失，接口仍返回安全、可核验的答复。
- 失败发生在哪个节点，就返回哪个稳定内部原因；不再把所有问题伪装成模型不可用。
- 第一阶段不硬编码比亚迪或任何公司到证券代码的映射，并适用于现有 SSE、SZSE
  能力覆盖范围内的大陆 A 股。

## 非目标

- 不迁移史馆旧数据库。
- 不新增交易、持仓、自选股修改或其它写工具。
- 不在本阶段实现新闻、统计、百科和监管文件的具体事实计划编译器。
- 不证明或放开尚未登记的 BSE 数据提供方能力。
- 不放宽证据新鲜度、引用、凭据、网络或 MCP 工具审批边界。

## 方案比较

### 方案 A：继续扩充提示词和字段纠正

改动小，但每发现一种模型漂移就要增加一个补丁；纠正机会还会在多个节点之间争用。
无法从根本上避免取得证据后仍返回全局错误。

### 方案 B：保留模型生成事实计划，增加每节点重试

比方案 A 稳定，但模型仍决定市场、指标、单位和数据形状。重试降低失败概率，却不能
保证事实范围正确，也会增加延迟和调用成本。

### 方案 C：确定性事实计划加证据保底答复

系统根据已确认的行情意图生成规范计划，模型只负责有限语义提取和改善表达。调查成功后，
模型输出若失败则使用经过验证的证据生成保底答复。该方案消除关键链路上的模型单点失败，
是本次采用的方案。

## 架构

### 1. 事实计划编译器

新增与提供方无关的事实计划边界。输入为原始旨意、部门和司级身份，输出只有三类：

- `NOT_APPLICABLE`：该编译器不处理此旨意，沿用现有模型协议。
- `PLANNED`：返回一个已规范化的 `DataGapRequest`。
- `REJECTED`：语义命中但无法安全确定实体或范围，返回稳定原因。

大陆股票最新价计划固定生成：

- `category = MARKET_QUOTE`
- `market_metric = LAST_PRICE`
- `jurisdiction = CN`
- `expected_unit = CNY`
- `expected_shape = number`
- `data_scope = EXTERNAL_PUBLIC`
- `required = true`
- `source_scope = [SHIGUAN, MCP]`

模型不得覆盖这些字段。原始旨意明确要求港股、美股、B 股或其它境外市场时，本编译器
拒绝接管，不得静默改成 A 股。

### 2. 标的提取与身份解析

标的提取按以下顺序执行：

1. 原文中的显式大陆证券代码或交易所后缀；
2. 可审计的公司名称片段提取；
3. 必要时使用一个只返回 `name` 或 `ticker` 的窄范围模型提取节点。

第三步拥有独立的一次格式纠正预算。输出仍须经过既有 provider-neutral
`InstrumentRef` 解析和 MCP 搜索验证；歧义、找不到和越界分别收敛为
`entity_ambiguous`、`instrument_not_found` 和 `market_out_of_scope`，绝不生成猜测代码。

### 3. 系统驱动的 `NEEDS_DATA`

当投资司处理明确的大陆最新价旨意时，先运行事实计划编译器，再把计划交给现有
`AgentEvidenceSession`：

1. 史馆先查；
2. 资料缺失或过期时选择已批准、只读且能力匹配的 MCP；
3. 验证类别、指标、标的、市场、时间、单位和数据形状；
4. 冻结证据并返回证据包。

这时 `NEEDS_DATA` 是编排状态，而不是依赖模型准确拼出 JSON 的建议。未命中的非行情旨意
继续沿用现有通用证据协议。

史馆返回带完整锁定事实身份的既有采用证据时，提取器直接复用该不可变快照，不再调用模型
重新抽取；锁定的 fact key、类别或 subject 与本次计划不一致时失败关闭。普通未结构化史馆
文本仍沿用现有模型提取，不得被当成已验证行情。

### 4. 分节点恢复预算

路由、部内选司、可选实体提取、司级意见、部级综合和丞相汇总各自维护独立的一次
格式纠正机会。一个节点的失败不会消耗其它节点预算，也不会重新执行已经成功的调查。

第一阶段只对行情链路启用必要的恢复：

- 行情路由继续使用既有确定性护栏；
- 非 `LAST_PRICE` 行情继续保留 ADR 0023 已批准的模型后行情路由与投资司优先护栏，
  本阶段不撤销或重定义它；
- 投资司证据计划不需要模型纠正；
- 司级、部级和最终汇总失败时进入下述保底路径。

其它事实类别后续接入时复用同一预算接口，不在本阶段重写全部节点。

### 5. 证据保底答复

调查成功并通过验证后，系统保存一份最小、确定性的行情答复：

- 标的规范名称或代码；
- 最新可得价格和 `CNY`；
- 行情真实 `as_of`；
- 来源名称和证据 ID；
- “最新可得不等于实时成交价”的提示；
- 不构成投资建议的规范性提示。

对受支持的 canonical Mainland `LAST_PRICE` 路径，确定性 renderer 输出是完整且唯一的
事实表达契约。模型响应只有在 `opinion` 与 renderer 逐字相等、
`adopted_evidence_ids` 与 renderer 选择逐项相等时才可采用。模型不得改写价格、时间、
来源、市场或指标，不得选择别的证据，也不得追加投资判断或其它未经证据支持的事实性语义。

若模型响应不完全符合该权威绑定，投资司直接采用 renderer opinion；户部逐字采用投资司
canonical opinion；丞相逐字采用户部 canonical opinion，并固定返回三条不引入新事实的
安全建议。对应节点记录 `model_synthesis_degraded`，但只要证据调查成功仍返回 HTTP 200，
不把降级伪装成完整模型成功。

`adopted_evidence_ids` 必须与 renderer 对当前 evidence pack 的实际确定性选择完全一致，
并满足同 decree、同 canonical fact、当前 pack、fresh、`SUPPORTS`、可采用核验状态、
`PRIMARY/AUTHORITATIVE` 和批准来源适配器。即使同一 pack 中另一条合格证据足以使 pack
为 `RESOLVED`，节点选择 stale、`CONTRADICTS`、`UNVERIFIED` 或未批准来源的条目仍不得
进入“已采用事实”状态。

没有取得有效证据时不得使用保底答复，也不得返回伪价格。

## 数据流

```text
原始旨意
  → 行情意图与大陆范围护栏
  → 户部 / 投资司
  → 事实计划编译器
      → NOT_APPLICABLE：既有模型证据协议
      → REJECTED：稳定业务错误
      → PLANNED：系统进入 NEEDS_DATA
  → 史馆优先
      → 新鲜且覆盖：采用
      → 缺失或过期：批准的只读 MCP
  → 证据验证与冻结
  → 投资司表达
      → 模型 opinion 与 IDs 同 renderer 完全相等：采用
      → 任一不等：采用 renderer opinion 并记录降级
  → 户部综合：逐字采用投资司 canonical opinion
  → 丞相汇总：逐字采用户部 canonical opinion + 固定三条安全建议
  → HTTP 200 + 已采用证据
```

## 稳定错误

- `model_route_invalid`
- `entity_ambiguous`
- `data_plan_invalid`
- `instrument_not_found`
- `market_out_of_scope`
- `provider_capability_missing`
- `quote_unavailable`
- `evidence_stale`
- `model_synthesis_degraded`

对外响应继续脱敏。只有可安全公开、已有产品语义的原因才映射为用户提示；内部日志和测试
按节点记录稳定原因，不记录模型原文、MCP 正文、凭据或请求头。

## 文件边界

- `backend/app/agents/fact_plans.py`：通用计划结果和编译器协议。
- `backend/app/agents/market_fact_plan.py`：大陆最新价计划及标的提取。
- `backend/app/agents/evidence_protocol.py`：接受系统预编译计划，保留非行情旧协议。
- `backend/app/agents/bureaus/agent.py`：投资司预调查和司级保底入口。
- `backend/app/agents/ministries/agent.py`：部级综合保底。
- `backend/app/agents/chancellor/graph.py`：最终汇总保底和降级状态。
- `backend/app/jinyiwei/`：复用既有协调器、身份、来源、验证和冻结能力；不加入上层业务特判。
- `backend/app/jinyiwei/extractor.py`：对完整锁定的史馆采用证据提供确定性复用，普通文本路径不变。
- 对应测试、产品任务、ADR、架构和操作文档同步更新。

## 测试与验收

### 离线测试

- 同一句大陆股票最新价旨意直接产生唯一规范事实，不调用模型生成 data gap。
- 公司名称和显式代码均可进入同一计划；代码库不存在公司到证券代码的生产字面量映射。
- 明确港股、美股、B 股请求不被改写为大陆 A 股。
- 史馆新鲜命中时不调用 MCP；缺失或过期时只调用批准的只读 MCP。
- 完整锁定的史馆行情证据不调用提取模型；锁定事实不匹配时不得重绑定。
- 调查成功后，分别注入司级、部级和丞相模型格式失败，均返回带同一证据的成功答复。
- 三层均拒绝结构合法但改写价格、时间、来源或建议的模型输出。
- adopted selection 必须等于 renderer 权威选择；stale、`CONTRADICTS`、`UNVERIFIED`
  或未批准来源的 selection 即使位于 `RESOLVED` pack 中也必须被拒绝。
- 调查失败时不生成价格，保留稳定错误。
- 非行情证据流程行为不变。
- 运行聚焦测试、后端全量测试、Ruff、四组 harness、diff check 和敏感信息扫描。

### 真实验收

在离线门禁通过且保持现有网络与凭据授权后，从 `/study` 连续下达十次
“帮我看看比亚迪的股票价格”：

- 每次都经过户部、投资司和锦衣卫证据编排；
- 非缓存取证才标记“锦衣卫（调查）”，缓存命中不得冒充新的外部调查；
- 未主动加入港股或其它指标；
- 每次取得并采用非零行情证据；
- 模型任一表达节点格式失败时允许降级，但不得出现通用 502；
- 返回的价格、时间、来源与只读 MCP 证据一致；
- 日志不包含凭据或原始 MCP 正文。

真实验收只执行查询，不执行交易、自选股修改或其它写操作。
