# 朝堂底栏动态中间槽设计

## 背景

`CourtQuickDock` 的底栏外框已经占满视口，但现有桌面布局固定为 `300px 1fr 300px`。在
`1920px` 视口中，左右入口各占 `300px`，中间留下 `1320px` 空轨道。中央“展开辅政”链接采用
绝对定位，不需要这条空轨道。

产品同时要求保留未来在底栏中间嵌入其他模块的能力，因此不能把中间轨道永久删除或永久压缩为
零宽。

## 目标

- 当前没有中间模块时，左右入口平分并覆盖底栏全部可交互宽度。
- 未来传入中间模块时，底栏自动切换为三栏，左右入口弹性收缩，中间模块获得独立区域。
- 中央“展开辅政”链接继续悬浮居中，不参与网格占位。
- 桌面和移动端都具有明确的空槽/有槽布局，不静默隐藏中间模块。
- 不改变路由、认证、API、下旨流程、证据流或 ADR 0028。

## 组件接口

`CourtQuickDock` 新增可选展示属性：

```ts
type CourtQuickDockProps = {
  centerSlot?: ReactElement | null;
};
```

`ImmersiveCourtShellProps` 新增可选的 `quickDockCenter?: ReactElement | null`，并由
`ImmersiveCourtShell` 原样传给 `CourtQuickDock`。该属性只传递 React 展示节点，不读取数据、
不发起请求，也不定义中间模块的业务能力。

`null` 或 `undefined` 明确定义为“无中间模块”；其他 React 假值不属于该接口的合法类型。未传入
节点时不渲染空的中间容器；传入 `ReactElement` 时渲染带稳定
`data-court-dock-center` 标记的中间区域，便于未来模块和测试定位。

## 布局

### 无中间模块

- 桌面与移动端均使用两个等宽弹性轨道。
- 左入口位于第一轨，右入口位于第二轨。
- 两个入口的点击区域合计覆盖底栏全部宽度。
- 左侧内容靠左，右侧“问钦天监”内容靠右，保持视觉对称。
- 右入口必须 `justify-self: stretch` 并以 `justify-content: flex-end` 对齐内容；桌面右侧只保留
  `max(16px, env(safe-area-inset-right))` 安全内边距，移动端只保留
  `max(8px, env(safe-area-inset-right))`，不得继续使用当前 `40px` 的视觉缩进。

### 有中间模块

- `960px` 及以上使用 `1fr / minmax(240px, 40vw) / 1fr` 三轨结构。
- `959px` 及以下使用 `1fr / minmax(84px, 28vw) / 1fr` 紧凑三轨结构，并隐藏左右入口副文。
- 左右入口分别位于第一、第三轨；中间节点位于第二轨。
- 右入口在第三轨中同样拉伸到轨道边缘，并保持内容右对齐和安全区内边距。
- 中间槽只承载能够放入现有 `64px` 桌面底栏或 `56px + safe-area` 移动底栏的紧凑模块。
- 中间模块自身负责内容截断和内部交互状态；底栏负责尺寸、对齐和安全区。

## 状态与错误处理

动态布局只由 `centerSlot !== null && centerSlot !== undefined` 决定，不根据节点内容、网络状态
或 DOM 测量推断。该判定由一个不依赖 React DOM 的纯函数集中提供，组件和单元测试共同使用。
中间模块如需加载、空状态或错误状态，应由该模块自身明确渲染，底栏不伪造状态、不吞掉错误，
也不改变业务流。

## 测试

按 TDD 增加以下契约：

- `CourtQuickDock` 无 `centerSlot` 时使用无槽类名，不渲染中心区域。
- 传入 `centerSlot` 时使用有槽类名，并渲染稳定中心标记。
- 纯布局判定函数覆盖 `undefined`、`null` 和合法元素存在三种输入。
- 无槽桌面布局为两等分，右入口在第二轨且内容靠右。
- 有槽桌面布局为三轨，右入口在第三轨。
- 桌面和移动端都精确约束右入口的 `stretch`、`flex-end` 与安全区右内边距，防止再次出现
  “问钦天监”悬在屏幕内侧。
- 无槽移动布局仍为两等分；有槽在 `959px` 及以下使用明确的紧凑三轨比例并隐藏副文。
- 保留移动端 fixed、左右贴边、底部贴边、高度和 safe-area 契约。

源码契约测试必须先精确提取目标规则，禁止用跨多个媒体查询的宽松正则，避免假绿。随后用真实
浏览器在桌面宽度验证无槽时左右入口宽度之和等于底栏宽度，并验证现有页面没有渲染空中心节点。

## 非目标

- 本次不实现任何具体中间业务模块。
- 不改变“问丞相”“问钦天监”入口的目标路由或文案。
- 不扩大底栏高度，不引入横向滚动。
- 不修改业务流治理基线。

## 验收标准

1. 当前页面底栏不存在空的中间点击区域，左右入口共同覆盖整栏。
2. “问钦天监”入口覆盖到右侧轨道边缘，内容仅保留规定的 safe-area 内边距。
3. 组件接口允许未来页面传入紧凑中间模块，并自动切换到三栏。
4. 中间模块不存在时不渲染占位节点。
5. 桌面、移动端和 safe-area 布局契约均有自动化覆盖。
6. 前端测试、lint、typecheck 和 build 通过。
