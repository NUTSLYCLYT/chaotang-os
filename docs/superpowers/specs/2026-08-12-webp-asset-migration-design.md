# WebP 资源迁移设计

## 目标与范围

将 `frontend/public/**/*.png` 与 `docs/product/assets/**/*.png` 中现有的 27 个 PNG 文件转换为 WebP，删除对应 PNG，并同步更新指向这些真实资源的代码、测试和 Markdown 引用。`.superpowers` 中的验收截图、文档里不存在于目标目录的历史截图名称，以及其他格式的图片不在范围内。

迁移不得改变图片尺寸、页面行为或项目业务流。当前工作区已有的其他未提交改动必须保留且不得混入本任务修改。

## 转换规则

转换器使用前端现有依赖树中的 `sharp`。脚本先读取源图元数据：带透明通道的图片使用无损 WebP；不透明图片使用质量 82 的有损 WebP。输出沿用原目录与基础文件名，仅将扩展名从 `.png` 改为 `.webp`。

单个文件只有在 WebP 已成功写入、可解码、宽高与源图一致，且透明源图的输出仍带透明通道后，才允许删除源 PNG。任一步失败时脚本以非零状态退出，并保留该源 PNG，避免产生不可恢复的半成品。

## 引用迁移

建立本次 27 个源路径到 WebP 路径的确定映射，并更新：

- `frontend/src` 中的运行时 URL；
- 对这些 URL 或磁盘文件名作断言的前端测试；
- Markdown 中明确引用这 27 个现存资源的路径、命令和验收描述。

仅仅含有 `.png` 字样、但表示已删除素材、历史验收截图、临时生成物或示例名称的文档内容不改写，因为它们并不指向本次转换的文件。

## 自动检查与测试

新增可重复运行的资源检查，至少验证：

1. 两个目标目录中不存在 PNG；
2. 27 个预期 WebP 均存在、可解码且格式为 WebP；
3. 每个输出的宽高与迁移清单一致；
4. 原透明图片转换后仍有透明通道；
5. 代码、测试和 Markdown 中不再引用这 27 个旧 PNG 路径。

测试驱动顺序为：先加入检查并观察其因现存 PNG/旧引用而失败，再执行最小转换和引用更新使其通过。完成后运行前端 `test`、`lint`、`typecheck`、`build` 与仓库 harness。最终版本按仓库规则连续执行 10 轮完整验收；任一轮失败或实现、配置、验收流程发生实质变化，都从第 1 轮重新计数。

## 非目标与风险控制

- 不调整图片构图、色彩、分辨率或页面布局。
- 不改变既有 WebP、视频、SVG 或其他文件。
- 不新增网络依赖，不调用外部服务。
- 不提交、不推送、不部署；Git 写操作需要用户另行明确授权。
- 有损 WebP 可能产生轻微像素差异，因此以可解码、尺寸、透明性、引用完整性、构建和页面资源路径为自动验收依据，并在实施后抽查代表性图片。
