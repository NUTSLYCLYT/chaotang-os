# 朝堂 OS V9 场景化交互设计

## 1. 目标

V9 不再以“古风管理后台”为页面母体，而采用“场景主导、器物承载、HUD 退后”的交互方式。

第一阶段只重绘三个标杆页：

1. 上书房：验证皇帝下旨与丞相分流。
2. 司级案房：验证 Agent 调查、证据核验与锦衣卫条件调用。
3. 军机处：验证跨部门事实共享、分歧对照与会审结论。

这三页通过后，才把同一套空间语法扩展到六部、部级、锦衣卫、史馆、统一案卷和系统异常。

## 2. 产品边界

- 唯一人工用户是皇帝。
- 丞相、六部、司级、锦衣卫、军机处和史馆均由 Agent 自动办理。
- 皇帝只执行下旨、巡视、展开案卷、召回和复盘，不代替 Agent 保存、提交、分流、调查、定案或归档。
- 锦衣卫仍是司级案卷在关键事实不足时自动进入的条件子流程，不进入全局导航。
- 已归档案卷进入史馆；进行中案卷进入当前责任工作区。
- 完整八节点流程仍只允许出现在统一案卷详情。

## 3. 设计原则

### 3.1 场景先于面板

每个页面只设置一个主场景器物：

- 上书房：御案与圣旨卷轴。
- 司级案房：证据案桌。
- 军机处：会审舆图桌。

背景不再只是壁纸。主任务入口、状态变化和案卷内容必须依附在场景器物上。

### 3.2 器物先于卡片

优先使用卷轴、奏牍、账簿、封识、签押、舆图和印章表达信息。只有需要稳定阅读的长正文才能展开为米金纸张面板。

禁止把案卷列表、证据、部门意见和流程节点默认装入等宽矩形卡片。

### 3.3 HUD 退后

常驻 HUD 仅保留：

- 全局导航。
- 当前身份和当前位置。
- 一个当前状态或责任 Agent 提示。

HUD 可见面积控制在页面约 15%–20%。不再常驻三至四个指标卡。

### 3.4 状态贴近业务物件

- 已确认：绿色签押或完整印记。
- 待补事实：朱红缺页签或断裂封识。
- 调查中：黑金密函与时间标记。
- 已归档：史馆藏印。

颜色不能单独承担状态，必须同时具有文字和器物形态。

## 4. 共用页面骨架

- 画板：1440×1024。
- 顶部全局导航：56px，降低视觉权重。
- 当前位置：不单独占据整行，合并到场景标题或面包屑。
- 场景区：从 y=56 延伸至 y=960，占页面主体。
- Footer：64px，仅保留朝代、版本和 Agent 运行说明。
- 主场景器物位于视觉中心，覆盖页面约 55%–70%。
- 详情展开层覆盖页面不超过 45%，关闭后必须能重新看到完整场景。
- 每屏最多一个朱红主动作。

## 5. 标杆页一：上书房

### 5.1 场景

皇帝御案居中，案上只放：

- 一卷待书圣旨。
- 左侧三份最近奏牍。
- 右侧笔架、御玺和回执匣。

背景为写实厚重的上书房，光线集中在卷轴，不展示左右后台面板。

### 5.2 未下旨状态

- 圣旨卷轴中央是一行可输入区域。
- 占位文案：`朕意……`
- 唯一朱红主动作：`颁旨`
- 最近三道旨意以三份叠放奏牍呈现，只显示案号、标题和状态签。

### 5.3 分流中状态

颁旨后，卷轴向下展开：

1. 原旨正文。
2. 丞相 Agent 理解，以墨色批注出现。
3. 下旨回执，以御玺印记和案卷编号出现。
4. 丞相分流，以朱批签注逐项写入。

不跳转独立丞相页面，不展示完整流程节点。

### 5.4 办理中状态

- 卷轴底部出现当前责任签：`户部 · 度支司 Agent 办理中`。
- 点击责任签进入司级案房。
- 已归档奏牍点击后直接进入史馆，不进入上书房归档管理页。

## 6. 标杆页二：司级案房

### 6.1 场景

页面中心是一张证据案桌，桌面放置：

- 拨银批文。
- 银库出库簿。
- 河工收料簿。
- 关防与封识。
- 一份缺页账簿。

案卷队列收纳在左侧奏牍架，不作为常驻大面板。点击奏牍后，相关证物在桌面亮起。

### 6.2 事实表达

- 已确认事实：附绿色签押。
- 存在矛盾：两份证物之间出现细朱线。
- 缺失事实：账簿缺页处附朱红缺页签。
- 点击证物后，从桌面边缘展开不超过 40% 宽的米金阅读层。

### 6.3 锦衣卫条件调用

关键事实不足时：

- 桌面右侧出现一封黑色封缄密函。
- 文案：`度支司 Agent 已自动调用锦衣卫`。
- 次级入口：`查看密查进展`。

不得出现“调用锦衣卫”“批准调查”“提交意见”等人工动作。

调查完成后，黑函变为已拆封回报，证据自动回填到原案桌。

## 7. 标杆页三：军机处

### 7.1 场景

页面中心是一张会审舆图桌。桌面中心放共享事实，各部门意见围绕中心排布：

- 户部：财政核销意见。
- 工部：工程量与验收意见。
- 刑部：关防和责任线索。

不再使用左侧队列＋右侧详情作为页面主结构。

### 7.2 会审表达

- 共享事实压在舆图桌心，以三枚一致签押固定。
- 分歧意见分别使用不同位置的签牌，冲突内容用细朱线连接。
- 待补事实使用空签位表达。
- 军机 Agent 的会审结论以中央金边结论牍出现。

### 7.3 案卷切换

待会审、会审中、已呈送案卷收纳在桌侧卷宗架。打开卷宗后替换桌面内容，而不是长期占据左侧三分之一屏幕。

皇帝可执行：

- 展开案卷。
- 查看部门意见。
- 查看统一案卷。

皇帝不可提交、修改或确认会审意见。

## 8. 视觉与资产要求

- 延续 V5/V8 的写实黑金、乌木、暖金、米金纸张和克制朱红。
- 每张场景图必须与页面职责一致，不能复用同一背景代替不同机构。
- 禁止现代屏幕、仪表盘、ROI、AI 图标、后台表格或烘焙 UI 文字。
- 场景需要预留器物交互和文字展开空间，不能仅作为满幅插画。
- 图像资产不足时使用 Image Generation 创建，生成后必须先验图再进入 Figma。

## 9. 交互与动效

- 卷轴展开：260–360ms，缓入缓出。
- 奏牍抽取：180–240ms。
- 证物聚焦：轻微景深变化与金线高亮，不使用夸张发光。
- 朱批写入：分段出现，不模拟逐字打字。
- 密函出现：从案桌侧面滑入并落定。
- 会审签牌移动：220–300ms，表达意见归并。

所有动效必须服务状态变化；用户选择减少动态时，改为淡入和即时状态切换。

## 10. 第一阶段不包含

- 不重绘登录、注册和欢迎页。
- 不重绘六部总览、部级、锦衣卫、史馆、统一案卷和系统状态。
- 不生成完整全流程 V9 原型。
- 不修改 V5、V6、V7、V8。
- 不实现真实视频或生产代码。

## 11. 验收标准

三个标杆页必须满足：

1. 隐去标题后，仅凭空间与器物仍能辨认上书房、司级案房和军机处。
2. 三页不得复用同一种左右栏或卡片阵列布局。
3. 常驻 HUD 面积不超过页面约 20%。
4. 主任务必须依附在卷轴、证据案桌或舆图桌上。
5. 皇帝权限没有扩大。
6. 锦衣卫仍只由司级 Agent 条件调用。
7. 每屏最多一个朱红主动作。
8. 无现代后台元素、设计阶段占位文字、设计说明、裁切和重叠；功能性输入提示“朕意……”允许保留。
9. 三页均提供 1440×1024 同视口截图，与 V8 对应页面并排验收。
10. 独立 reviewer 必须给出 Critical=0、Important=0 后才能扩展其他模块。
