# 军机处私有案卷总台设计

## 已确认的产品目标

军机处收纳当前用户朝堂下旨所产生、且确实经过军机处的全部跨部案卷：正在进行的会审与已归档的回奏在同一案卷中连续呈现。其他用户的案卷永不可见。

## 信息架构

采用“会审主舞台”。左栏是案卷列表，默认进行中优先、同状态按最近更新时间倒序，支持关键词、状态与参与部门筛选。中央是选中案卷的主卷：处理状态、已经发生的处理路径、当前等待节点，以及归档后的军机处结论和丞相回奏。右栏展示六部席位，仅标注未参与、办理中或已完成；已完成部议可按需展开。

案卷不是独立的执行命令。底部只保留“回上书房下新旨”与“前往史馆复盘”，不出现采纳、驳回、补证、派发等没有真实写入能力的按钮。

## 状态与数据边界

案卷只在丞相判定为多部门、进入军机处路径时创建。状态按真实节点推进：部门办理中、军机处会审中、丞相汇总中、已归档或失败。每次展示都以已持久化检查点为准；未产生的部门意见、军机处结论或证据不能显示为事实。

最终归档仍由史馆生成恰好一条 `REPLY`；台账只保存其关联标识和进度，不复制或重写归档内容。所有读写由后端从当前认证会话解析 `owner_user_id`，前端不持有、传递或筛选所有者。

## 验收标准

- 下旨者只能看见自己的、经过军机处的案卷；不能通过参数、缓存或前端状态跨用户读取。
- 进行中的案卷在真实节点之间显示准确状态和已发生路径；未发生内容明确为等待。
- 已归档案卷与进行中案卷使用同一案卷身份，并能跳转其对应的史馆 `REPLY`。
- 单部门旨意不会出现在军机处案卷台账。
- 新功能不新增下旨、调查、采纳、审批或执行入口，不改变 ADR 0028 规定的一旨一条 `REPLY`。

## 交付边界

需要先完成架构复核，确认台账的 SQLite schema、写入时机、失败语义、私有 GET 契约和 BFF 投影；随后再分别交付后端台账、前端军机处页面和跨端测试。不得迁入 `dev` 的旧事件总线、任务模型、模拟数据或旧 API。
