# V5 数字朝堂 UI 设计

## 目标

在不改变 V4 业务流程、页面职责与页面数量的前提下，建立一套可扩展的
“公文秩序 · 朱批系统”视觉语言。产品第一眼应是可信、清晰的现代 Agent
决策系统，第二眼才体现古代朝堂的制度与案牍语义。

本轮先交付三个代表性页面作为视觉定调版：

1. 欢迎页：验证品牌表达与首次进入系统的视觉体验。
2. 上书房：验证唯一人类操作工作台与案卷状态表达。
3. 六部 · 司级页面：验证高密度列表、证据与办理轨迹的可读性。

现有 V4 保持不变。V5 定调通过后，视觉系统再扩展到注册、登录、首次引导、
六部总览、部级、锦衣卫、军机处与史馆。

## 设计原则

- 80% 现代企业级信息设计，20% 古代朝堂语义。
- 古代感来自案牍、公文、朱批、签条、制度层级，不来自装饰素材。
- 每个视口最多一个主要朱红焦点。
- 朱批只表达皇帝意志、正式裁定或真实发生的案卷因果。
- 每项功能只保留一个主页面；错误、加载、成功与详情变化使用页内状态或覆盖层。
- 高频业务页面以列表、表格和分区线为主，避免卡片拼贴。

## 视觉基础

### 色彩

- 墨黑 `#171512`：Header 与最高层级文字。
- 宣纸 `#F3EFE4`：全局背景。
- 素笺 `#FCF9F1`：面板与正文表面。
- 朱批 `#A33A31`：主操作、皇帝动作和当前关键状态。
- 官印深朱 `#78251F`：按下态与高风险确认。
- 档案线 `#D8CEBC`：分隔、表格与输入框。
- 木褐 `#4A3B30`：深色辅助区域。
- 暗金 `#A7864F`：身份、正式归档与少量精细线条。
- 松绿 `#35675E`：成功。
- 赭石 `#946328`：警告。
- 错误红 `#8F2019`：错误语义。

朱批色占单屏面积不超过约 8%，暗金不超过约 3%。状态必须同时使用文字，
不可仅靠颜色区分。

### 字体

- `Noto Serif SC SemiBold`：欢迎页主标题、页面 H1、案卷正题和正式回奏标题。
- `Noto Sans SC`：导航、按钮、表单、表格、状态、正文与辅助信息。
- 若 Figma 中无法加载指定宋体字重，则统一回退 `Noto Sans SC`，不得混用近似字体。

### 形态与空间

- 桌面画板：1440 × 1024。
- Header：72；Footer：64；页面左右边距：72。
- 使用 8px 主节奏的间距系统。
- 业务面板、按钮、输入框：4px 圆角。
- 弹层：最多 6px 圆角。
- 卡片与控件默认无阴影；主要依赖表面色、描边与留白分层。
- 点击目标不小于 44 × 44。

## 文化签名组件

### 朱批签

案卷左侧 3–4px 的朱红批注轨，可带一个小型方印状态标。仅用于：

- 当前选中且需要皇帝关注的案卷。
- 已下旨、已定案或正式归档等权威信息。
- 异常且需要关注的案卷。

普通办理中、已处理列表项保持中性色。

### 朱批轨迹

只用于：

- 欢迎页的一份真实示例案卷。
- 上书房当前案卷的真实办理记录。
- 案卷详情中已经发生的事件。
- 正式回奏的最终裁定。

历史节点使用档案灰；当前节点、皇帝下旨、定案与正式归档才使用朱红或深朱。
不得展示尚未发生的预测流程，不得作为普通分割线或全局装饰。

## 首批页面

### V5/01 欢迎页

- 页面只保留一个强视觉锚点。
- 左侧：品牌、核心价值、主按钮“创建我的朝堂”、登录文字入口。
- 右侧：真实示例“整治永定河春汛隐患”的朱批案卷，展示已发生的分流、办理、
  回奏与归档关系。
- 删除 V4 底部三列能力卡。
- 页尾仅保留“独立朝堂 · 办理可追溯 · 正式回奏永久归档”。
- 登录前 Header 不显示六部、锦衣卫、军机处等业务导航。

### V5/02 上书房

- 上书房是唯一人类操作工作台，视觉焦点是“一句话下旨”。
- 输入区域表现为现代批示台，不模拟卷轴。
- 左侧保留最近三份案卷。
- 同一案卷容器按状态展示 Agent 理解、下旨回执、丞相分流、当前办理或正式回奏。
- 朱批轨迹只展示该案卷已经发生的事件。
- 不展示全局流程节点。

### V5/03 六部 · 司级页面

- 这是高密度验证页，优先使用列表、表格与固定列对齐。
- 顶部显示部门层级路径、处理中/已处理切换、筛选和搜索。
- 案卷列表行高 56–64px，案卷名称、编号、来源、状态、更新时间保持列对齐。
- 处理中案卷进入当前司级详情；已归档案卷进入史馆。
- 详情重点展示事实、证据、来源、可信状态和 Agent 办理轨迹。
- 关键事实不足时显示锦衣卫调用入口，但不把锦衣卫装饰成黑暗审讯空间。

## 设计系统最小范围

首批建立并复用：

- Color、Typography、Spacing、Radius 与 Stroke 变量。
- Public/App Header、Footer。
- Primary/Secondary/Tertiary Button。
- Input、TextArea、Checkbox、Field Message。
- Status Badge、Inline Message。
- Case Row、Case Status、Breadcrumb、Tabs、Filter Bar。
- 朱批签、朱批轨迹。

组件至少覆盖 Default、Hover、Focus、Pressed、Disabled；表单组件增加 Filled、Error，
按钮增加 Loading。状态不通过新增主页面展示。

## 动效与无障碍

- 页面切换与状态变化使用 120–220ms 淡入或不超过 4px 的位移。
- 下旨成功允许一次 180ms 的轻量落印反馈。
- 支持 reduced motion。
- 正文对比度至少 4.5:1；UI 边界和大字至少 3:1。
- 焦点环为可见的 2px 外环，状态同时使用文字或符号。

## 禁止项

- 龙纹、祥云、灯笼、宫殿剪影、红金渐变。
- 卷轴展开、印章飞入、墨迹飞溅等长动画。
- 仿宣纸污渍、烧边、木纹与博物馆展柜效果。
- 书法、行草、篆体用于功能文字。
- 木牌式导航、宫殿地图与古风游戏徽章。
- 三列 SaaS 功能卡或大面积圆角卡片拼贴。
- 用“钦此、御览”等词替代用户无法立即理解的操作名称。

## 验收标准

- V4 页面和交互不被修改。
- V5 首批恰好包含欢迎页、上书房、司级页面三个主页面，不创建状态副本。
- 三页在 1440 × 1024 下无文字溢出、裁切或重叠。
- 字体符合限域规则；不可用时按定义回退。
- 每屏最多一个主要朱红焦点。
- 欢迎页能在 3 秒内表达“一句话下旨，Agent 自动办理”。
- 上书房的一句话输入是首要视觉焦点。
- 司级页面在高信息密度下仍能清楚扫描案卷、状态与证据。
- 主要按钮、导航和案卷跳转具有可用的原型交互。
