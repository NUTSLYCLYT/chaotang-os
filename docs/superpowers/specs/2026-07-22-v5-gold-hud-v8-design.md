# 朝堂 OS V8：V5 黑金视觉与 HUD 设计规格

## 1. 设计目标

在不改变 V7 已确认信息架构、权限和原型链路的前提下，重新采用 V5 的黑金写实朝堂视觉，并增加克制的游戏 HUD 信息组织。V8 必须首先像一套“皇帝使用的朝堂游戏系统”，其次才像案卷管理工具。

V8 新建独立 Section 与画板，不覆盖 V5、V6、V7。

## 2. 用户与业务边界

- 唯一人工用户为皇帝。
- 丞相、六部、司级、军机处、锦衣卫均由 Agent 自动办理。
- 皇帝可以下旨、监察、阅读结果、进入责任工作区，但不代替 Agent 保存草稿、提交意见或人工分流。
- 锦衣卫只由司级 Agent 在关键事实不足时自动调用，不进入全局导航。
- 已归档案卷进入史馆；进行中案卷进入当前责任部门或司级工作区。

## 3. 核心流程

`欢迎/登录 → 上书房一句话下旨 → 丞相理解与分流 → 司级调查 → 部级汇总 → 条件性军机会审 → 丞相定案 → 正式回奏 → 史馆归档`

锦衣卫是司级案卷内的条件子流程：

`关键事实不足 → 司级 Agent 自动调用锦衣卫 → 调查回报 → 司级继续办理`

## 4. 视觉基准

### 4.1 唯一参考

以 Figma 页面 `153:2` 中的 V5 为唯一视觉基准：

- 欢迎页：`164:2`
- 登录页：`200:43`
- 上书房：`165:8`
- 司级页面：`166:34`
- V5 Foundations：`153:7`

不继承 V7 的大面积浅色政务后台风格。

### 4.2 V5 视觉语法

- 全屏写实场景背景，叠加黑色电影遮罩。
- 顶部为低矮乌黑导航，使用暖金文字和极细金线。
- 页面主体以半透明乌木 HUD 面板承载导航、筛选、摘要和辅助信息。
- 需要长时间阅读的正文、案卷和证据区域使用米金案牍面板。
- 朱红仅用于当前唯一关键行动、选中态和关键风险。
- 金色用于身份、结构、边界、状态与光线，不使用廉价发光渐变。
- 允许内阴影、暗部投影和暖金高光，但不得影响文字清晰度。

## 5. HUD 信息架构

HUD 分为三层，不把全部内容悬浮化。

### 5.1 全局 HUD

- 左侧品牌“朝堂 OS”。
- 中部固定入口：上书房、军机处、六部、史馆。
- 右侧显示“景和朝 · 皇帝”身份。
- 第二行显示当前位置或案卷编号。
- 锦衣卫不出现于此层。

### 5.2 场景 HUD

- 页面标题、当前身份、待办数量、处理中数量、归档数量。
- 当前责任 Agent、最新更新时间和关键风险可以用小型金色标记显示。
- 每屏只保留一个朱红主动作。
- 不显示全局流程节点。

### 5.3 案卷 HUD

- 仅在选中案卷或统一案卷详情中展示当前状态、责任节点、Agent 办理轨迹和条件分支。
- 完整流程节点只在统一案卷详情出现。
- 处理中案卷在当前责任工作区展开；已归档案卷跳转史馆。

## 6. 场景与页面映射

1. 欢迎页：黎明宫门或朝堂入口，视频区域与场景融合。
2. 登录/创建朝堂：宫门值守、宫禁验符或内廷身份核验场景。
3. 上书房：御案、奏折、屏风与烛火；一句话下旨为视觉中心。
4. 六部总览：六部衙门总图或宫城官署轴线，部门入口呈 HUD 官署牌。
5. 部级工作区：部堂正厅与案牍桌，强调本部总览和下属司状态。
6. 司级工作区：具体司署案房，强调证据、调查和责任 Agent。
7. 锦衣卫：暗色诏狱/密档房氛围，但保持克制，不做血腥或夸张视觉。
8. 军机处：围桌会审、舆图、灯火和多方意见对照。
9. 史馆：高大档案库、卷宗柜与暖色天光，突出正式、稳定和只读。
10. 统一案卷详情：御前展开的正式案卷，流程仅作为案卷内部 HUD。
11. 系统状态：复用当前模块场景，不新增独立世界观页面。

## 7. 页面范围

保持 11 种页面类型，不增加同功能重复页：

1. 欢迎页
2. 登录页
3. 注册/创建朝堂
4. 上书房
5. 六部总览
6. 部级工作区
7. 司级工作区
8. 锦衣卫案卷详情
9. 军机处
10. 史馆
11. 统一案卷详情

上书房的未下旨、分流中、办理中、已归档继续作为同一功能的状态画板。空状态和归档异常集中在同一系统状态板中。

## 8. 组件原则

- 新建 V8 Foundations，继承 V5 的 Header、Footer、Primary Button、Case Row 和 Status Badge 结构。
- 增加 HUD Metric、HUD Location、HUD Agent Status、Dark Panel、Parchment Panel、Evidence Row、Timeline Node。
- 重复元素必须组件化；页面只使用组件实例和必要的场景容器。
- 案卷列表选中态：左侧朱红线、米金加深、状态文字同时变化。
- 暗色面板正文对比度必须足够；长文本不直接放在复杂背景图上。

## 9. 原型交互

- 欢迎 → 登录/创建朝堂 → 上书房。
- 颁旨 → 分流中 → 办理中 → 当前责任部门。
- 六部总览 → 部级 → 司级 → 条件性锦衣卫。
- 军机处会审 → 统一案卷详情。
- 已归档案卷和正式回奏 → 史馆。
- 全局 HUD 导航在所有登录后页面可用。
- 所有可见主动作必须有 reaction；静音等真实视频控件可保留给视频接入阶段。

## 10. 验收标准

- 与 V5 并排截图时，色彩、明暗、材质、边框、标题气质和按钮层级属于同一视觉系统。
- 不出现 V7 的大面积浅色页面底、现代 SaaS 卡片阵列或普通后台观感。
- HUD 提升定位和状态感，但不遮挡核心内容，不制造满屏浮层。
- 所有模块拥有符合业务定位的场景，不强行复用同一张背景图。
- 每屏最多一个朱红主动作。
- 全局导航只有上书房、军机处、六部、史馆。
- 锦衣卫只能从司级关键事实不足状态进入。
- 流程节点只在案卷内展示。
- 所有画板无裁切、重叠、占位文案、错误字体和死主按钮。
- V5、V6、V7 保留不变，V8 独立可体验。

## 11. 实施与验收方式

- 先建立 V8 Foundations 和一张“上书房”标杆画板，与 V5 `165:8` 并排验收。
- 标杆通过后，再迁移入口、六部链、军机处、史馆和统一案卷。
- 每个模块由实现角色完成后，交给独立视觉验收角色检查。
- 最后由主负责人串联全流程并进行整体放行验收。
