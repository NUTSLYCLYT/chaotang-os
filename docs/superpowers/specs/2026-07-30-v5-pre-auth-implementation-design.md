# V5 宫门欢迎与认证页面实现设计

## 背景与目标

当前根路径、登录页和注册页已经具备真实认证能力，但视觉仍沿用较早的登录前界面。用户于
2026-07-30 确认以 Figma 文件“chaotang os 全流程桌面端原型 v1”中的
`V5/Motion A · 宫门启朝`（节点 `218:49`）作为根路径欢迎页，以
`V5/00 登录`（节点 `200:43`）作为认证页面的视觉基准。

本次目标是把 V5 的宫门仪式感落到现有 Next.js 应用，同时保留现有真实认证、会话、
`next` 参数和用户数据隔离行为。该改动不修改、绕过或替代 ADR 0028 的业务流基线。

## 用户流程

1. 未登录用户访问 `/`，看到 V5 宫门欢迎页。
2. “上朝”“已有朝堂？登录”和“跳过仪式”均进入 `/login`。
3. `/login` 使用 V5 双栏登录布局，提交现有账号或邮箱与密码。
4. “尚未创建朝堂？注册”进入 `/register`。
5. `/register` 复用同一 V5 场景、页头、页脚和表单面板，保留现有注册字段与提交逻辑。
6. 登录或注册成功后的跳转继续由现有认证实现决定；本次不新增 onboarding 或业务页跳转。

## 视觉与响应式设计

### 根路径

- 使用 Figma 导出的宫门场景原图作为全屏背景，不依赖会在约七天后失效的临时资源 URL。
- 桌面端以 1440 × 1024 原稿为比例基准，保留“朝堂 OS”“启朝”、副标题、主按钮和两个
  次级入口的位置关系。
- 页面不采用固定画布整体缩放。背景使用 cover，内容以安全区和最大宽度约束，使窄屏仍可
  阅读和操作。
- 首次进入时标题和按钮渐显；不循环播放。宫门视觉只在素材能够独立分层且无拼接假象时做
  位移动画，否则保留高质量静态宫门场景与渐显，避免伪造错误的开门效果。
- `prefers-reduced-motion: reduce` 时关闭非必要位移和渐显。

### 登录与注册

- 登录页以 Figma `V5/00 登录` 为基准：暗色宫廷背景、半透明遮罩、顶部品牌栏、底部信息栏、
  左侧品牌文案和右侧深色金边表单卡片。
- 登录表单只呈现现有真实字段：账号或邮箱、密码。不得增加原型中的“朝堂号”“皇帝身份”
  等未接入后端的字段。
- 注册页沿用相同视觉壳，但呈现当前实现已有的用户名、邮箱、密码和确认密码等字段。
- 输入框、错误文案、焦点态、禁用态和提交态必须具备足够对比度；窄屏改为单列，优先显示
  表单，避免背景和装饰遮挡控件。

## 组件边界

- `features/welcome` 负责根路径场景、欢迎文案、入口链接和仅展示型动效。
- `features/pre-auth` 继续负责登录与注册的共享视觉壳、表单组件和现有交互。
- 欢迎页与认证页可共享纯展示的 V5 背景、公共页头和页脚，但不得把认证请求状态耦合到
  欢迎页。
- Figma 返回的 React/Tailwind 代码仅作为尺寸和视觉参考；实现继续使用项目现有 React、
  Next.js、TypeScript 与 CSS Module，不引入 Tailwind 或 motion 依赖。

## 数据流与错误处理

- 根路径仅执行站内导航，不调用认证或业务 API。
- 登录和注册继续调用现有同源 BFF，并沿用当前请求载荷、cookie、错误分类和成功跳转。
- 保留 `/login?next=...` 的安全跳转行为，不允许视觉迁移丢失或绕过 `next` 校验。
- 表单提交期间保持按钮禁用和可见加载反馈；验证错误靠近对应字段，服务错误在卡片内显示。
- 背景资源失败时保留深色底色、可读文案和可操作表单，不能出现空白页。

## 素材策略

- 下载并提交 Figma 节点 `218:49` 与 `200:43` 返回的原始背景素材字节。
- 素材放入 `frontend/public` 下专用的 V5 登录前资源目录，使用稳定、语义化文件名。
- 不手绘或替换 Figma 中的图片内容；不得在生产代码中保留 Figma 临时资源 URL。
- 若两个节点素材字节一致则去重；若场景不同则分别保存。

## 测试与验收

采用测试驱动开发：

1. 先为根路径三个入口到 `/login` 的导航语义写失败测试。
2. 为登录页只保留账号或邮箱与密码、注册链接到 `/register` 写失败测试。
3. 为注册页保留现有字段和登录链接写失败测试。
4. 为登录错误、提交中状态、`next` 参数和 reduced-motion 行为补充针对性测试。
5. 最小实现通过测试后再整理共享 V5 视觉组件。

完成后运行前端 lint、typecheck、test、build，以及根 harness。使用浏览器分别在桌面和窄屏
检查 `/`、`/login`、`/register`，并核对背景裁切、文字层级、键盘焦点、错误态与真实认证
请求行为。

## 非目标

- 不修改后端认证 API、数据库、cookie 契约或用户隔离规则。
- 不增加第三方登录、找回密码、邀请制、朝堂成员或 RBAC。
- 不修改 `/study`、军机处、六部、锦衣卫、史馆或 ADR 0028 业务流。
- 不引入 Tailwind、motion 或新的 UI 组件库。
- 不把 Figma 中未实现的字段或文案冒充为真实业务能力。
