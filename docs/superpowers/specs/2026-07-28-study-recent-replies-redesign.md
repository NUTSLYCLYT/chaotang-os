# 上书房最近回奏面板视觉重设计

## 目标

将上书房左侧面板的最近三条回奏改造成与当前上书房一致的宫廷视觉，并把完整回奏交给页面中央御前卷轴展示。此次调整只改变展示与交互，不改变史馆数据来源、认证边界或下旨业务流。

## 已确认方向

采用视觉方案 A「奏牍叠卷」。

- 面板延续上书房的深墨蓝、旧金、米白和朱印色，不引入独立主题。
- 三条记录各自表现为一份窄幅奏牍：左侧旧金装订线、轻微纸面层次、右下朱色“回奏”印记。
- 奏牍默认展示回奏时间、参与部门和两行原旨摘要。
- 主操作统一命名为“展卷阅奏”，不在侧栏内展开详情，也不使用弹窗。
- 保留当前已确认的面板宽度、底栏同色背景、下半区丞相咨询与右侧暂未开放面板。

## 交互

1. 用户打开左侧面板时，继续按现有契约读取当前账号最近三条已归档 `REPLY`。
2. 用户点击某份奏牍的“展卷阅奏”：
   - 记录所选史馆档案；
   - 自动收起左侧面板；
   - 自动展开页面中央御前卷轴；
   - 在中央卷轴展示该档案的完整真实字段。
3. 历史回奏卷轴展示：
   - 原旨正文；
   - 办理过程；
   - 参与部门；
   - 回奏结论；
   - 回奏时间；
   - 责任主体。
4. 再次打开左侧面板并选择另一条记录时，中央卷轴切换到新选择。
5. 用户重新下旨并成功后，中央卷轴切回最新下旨回奏；历史选择不覆盖或伪装当前下旨状态。
6. 下旨处理中或失败时，继续使用现有处理中/失败展示，不把历史档案当作本次结果。

## 状态边界

- 最近回奏列表状态继续由 `StudyRecentRepliesState` 管理。
- 历史档案选择与当前 `DecreeUiState` 保持分离；不得把史馆 `REPLY` 转换成一次新的下旨成功状态。
- 中央卷轴增加明确的展示来源选择：
  - `current`：当前下旨流程；
  - `archive`：用户主动选择的历史回奏。
- 新下旨开始时切换回 `current`；成功后展示真实的新回奏。
- 新下旨成功仍按原规则使最近回奏列表失效，下次打开左侧面板刷新。
- 不新增 API，不修改 `/api/shiguan/archives?type=REPLY&limit=3`，不修改 ADR 0028。

## 组件职责

- `StudyClient`：保持请求、认证、失效与档案选择状态；不负责视觉。
- `StudySideDrawers`：渲染奏牍列表并发出“选择并关闭”意图；不渲染完整回奏。
- `DevStudyWorkspace`：决定中央卷轴当前展示下旨结果还是所选历史档案。
- 新增或抽取纯展示映射时，只把严格解析后的 `ShiguanArchive` 映射为卷轴视图模型，不补全、不推断缺失事实。

## 可访问性

- 每份奏牍使用真实按钮，按钮名称包含足以区分记录的原旨摘要。
- 选择后关闭面板，并将焦点转移到中央卷轴标题或卷轴容器，避免焦点落回已隐藏内容。
- 中央卷轴使用明确标题区分“史馆回奏”与“本次下旨回奏”。
- 键盘操作、Escape 关闭、可见焦点和 `prefers-reduced-motion` 继续有效。

## 状态与错误

- 加载、空结果、错误和重试仍在奏牍列表区域原位展示。
- 选择动作只针对已经严格解析且仍存在于当前列表的档案。
- 选择档案不发起第二次详情请求；完整字段来自已读取的严格列表响应。
- 401 继续跳转 `/login?next=%2Fstudy`。

## 验收与测试

- 样式测试锁定奏牍装订线、朱印、两行摘要和与上书房一致的颜色层级。
- 交互测试证明点击奏牍后：
  - 左侧面板关闭；
  - 中央卷轴展开；
  - 六个真实回奏字段出现；
  - 不存在对话框或侧栏内联详情。
- 状态测试覆盖选择不同历史档案、新下旨开始、新下旨成功，以及历史档案不污染 `DecreeUiState`。
- 回归测试覆盖咨询区、右侧面板、响应式宽度、面板背景、401、重试和请求竞态。
- 完成后运行 frontend lint、typecheck、全量测试、production build、仓库 harness 与 `git diff --check`。

## 非目标

- 不新增历史分页、搜索、筛选、编辑、删除或复盘。
- 不复制史馆完整页面。
- 不弹窗展示回奏。
- 不在左侧面板内部展开完整回奏。
- 不触发真实下旨、模型调用、锦衣卫调查或史馆写入。
