# 稳定下旨确定性编排设计

## 背景

同一旨意“我要招两个人做量化炒股，然后让他们去开发”在真实模型调用中会产生不同形状的
JSON。现有实现已经处理若干司级信封与事实声明漂移，但一次真实成功之后，`/study` 完整链路
仍再次返回 `model_unavailable`。最新案件只记录到“丞相（首次分流）”，统一的 502 边界没有
留下可区分司级、部级、会审或最终汇总的脱敏失败码。

逐个适配随机响应不能证明流程稳定。用户明确要求先修复下旨流程本身，再以同一旨意连续稳定
输出至少 10 次作为完成门槛。

## 目标

- 让代码而不是模型控制下旨的流程拓扑和响应结构。
- 将可安全隔离的模型内容或 schema 漂移限制在当前合成节点，不升级为整旨失败。
- 保持 ADR 0028 的分流、司议、部议、军机处、丞相回奏和史馆归档基线。
- 只把真实网络、认证、配置、SDK 调用和不可恢复的程序错误映射为整旨失败。
- 提供不含旨意正文、模型正文、密钥或异常原文的失败阶段和稳定错误码。
- 以真实完整链路连续成功至少 10 次作为最终验收。

## 非目标

- 不增加面向用户的新验收页面或批量下旨产品功能。
- 不放宽证据声明、证据绑定、采用或归档规则。
- 不接受、包装、回显或归档被校验拒绝的模型内容。
- 不用无限重试、备用模型或旧 `dev` 静态结果掩盖失败。
- 不修改 ADR 0028。

## 方案选择

采用“确定性编排 + 分层内容隔离 + 脱敏诊断”。

未采用：

- 继续逐个补 schema 特例：真实采样已经证明会持续出现未覆盖形状。
- 重试直到模型返回合规结果：费用、延迟和成功率不可控，且会掩盖真实 provider 故障。
- 并发执行 10 次验收：会混入速率限制、共享状态和数据库并发变量。

## 架构

下旨图继续保留现有节点与顺序：

`/study → BFF → FastAPI → 丞相分流 → 司议 → 部议 → 军机处 → 丞相汇总 → 史馆 REPLY`

职责边界调整为：

- Python 编排代码决定路由类型、部门顺序、司列表、状态字段、三条建议契约和归档时机。
- 模型只提供当前节点的候选文本或候选结构，不得决定是否跳过节点或改变响应字段。
- 每个模型合成节点经过统一分类：合规内容采用；明确列举的内容/schema 错误丢弃并在当前层
  使用确定性安全降级；传输、认证、配置、SDK 或未知程序错误继续整旨失败。
- 降级结果只能包含证据受限说明和不依赖外部事实的规范性建议，不能复用被拒绝的正文。

## 分层错误处理

### 司级

沿用现有证据协议、有限纠正预算和确定性 fallback。所有可安全隔离的信封、事实声明、采用和
绑定错误必须在司级终止，不得进入部议输入。

### 部级与军机处

部门选择器、部门汇总和会审汇总各自使用严格解析器。模型返回合法但不合业务 schema 的响应
时，丢弃候选响应，并从已经通过校验的下游输入生成确定性安全汇总。不得伪造新的事实或证据
采用关系。

### 丞相最终汇总

最终汇总必须始终由已验证的部门意见和军机处裁决生成。模型候选无效时，代码生成稳定的总结
和恰好三条唯一非空、规范性的建议；不得把被拒绝的模型正文带入结果。

### 必须整旨失败

DeepSeek 网络、认证、配置、SDK 调用失败，身份错误，状态不变量破坏和未知程序错误继续通过
现有脱敏 HTTP 边界返回失败，不能伪装为正常回奏。

## 脱敏诊断

内部失败证据只记录：

- 固定阶段：`route`、`bureau`、`ministry`、`council`、`finalize`、`archive`。
- 固定错误码，例如 `schema_invalid`、`content_unsupported`、`provider_unavailable`、
  `state_invalid`。
- 节点稳定标识和时间。

禁止记录旨意正文、提示词、模型响应、异常原文、API Key、会话令牌和用户私人数据。浏览器端
继续使用既有脱敏分类和文案。

## 测试策略

先用 TDD 覆盖此前未覆盖的部级、会审和最终汇总漂移：

- 裸文本、合法 JSON 但错误 schema、缺字段、额外字段、空文本、重复建议。
- 被拒绝内容不会出现在 fallback、最终回奏、证据采用或史馆归档中。
- provider 传输失败不会被降级成成功。
- 脱敏诊断只包含固定阶段和错误码。

随后运行证据协议、司级、六部、军机处、丞相图、API、BFF、史馆和案件生命周期回归，以及
Ruff、Harness 和 `git diff --check`。

## 真实验收

离线验证全部通过并重启最终代码后，使用同一完整旨意从真实 `/study` 链路串行提交：

1. 每次必须返回 HTTP 200。
2. 每次必须为多部门路由，包含吏部和工部。
3. 每个部门必须包含至少一个司议和非空部议。
4. 必须包含非空军机处裁决和丞相最终回奏。
5. 必须包含恰好三条唯一、非空建议。
6. 每次必须新增且仅新增一条当前用户拥有的史馆 `REPLY`。
7. 对应军机处案件必须进入完成状态。

必须连续成功至少 10 次。任一次失败立即停止验收、根据脱敏诊断修复，并在新代码下从 0 重新
计数。达到 10 次之前任务始终保持 `In Progress`。

## 安全与兼容性

HTTP 成功和失败响应字段、认证、用户隔离、史馆所有权、锦衣卫证据权限以及 ADR 0028 拓扑
保持不变。真实验收会产生至少 10 条合法史馆 `REPLY`；用户已明确确认该副作用和模型费用。
