# 中国大陆 A 股实体解析与行情取证设计

## 状态

设计方向已由用户于 2026-07-24 确认，等待书面规格复核。

## 背景与问题

当前“帮我看看比亚迪的股票价格”已经进入户部投资司并触发锦衣卫调查，
但调查最终返回 `UNAVAILABLE`，证据数量为零。真实只读腾讯自选股 MCP
测试表明：

- `data_search({"query": "比亚迪"})` 可以解析为 `sz002594`；
- 随后 `data_quote({"code": "sz002594"})` 可以取得并通过现有映射校验的行情；
- 当前调查生成的 `RequiredFact.subject` 是“比亚迪股份有限公司”；
- 现有确定性映射要求搜索候选名称与 `subject` 规范化后完全相等，因此无法接受
  腾讯返回的证券简称“比亚迪”；
- 调查问题中即使包含 `002594.SZ`，实体解析仍只使用 `subject`，不会利用明确代码；
- 同一证券的多个事实会重复执行相同的失败搜索。

因此本设计解决的核心问题是：用通用、可审计且与数据提供方无关的方式，把用户表达
解析为中国大陆 A 股的统一证券标识，再由获准的只读 MCP 获取行情。

## 已确认的产品范围

“中国大陆能交易的股票”在本阶段明确解释为：中国大陆交易所上市的 A 股。

包含：

- 上海证券交易所 A 股；
- 深圳证券交易所 A 股；
- 北京证券交易所 A 股。

不包含：

- 香港交易所股票，包括港股通标的；
- 美国及其他境外交易所股票；
- B 股；
- 基金、ETF、债券、期货、外汇、指数和板块；
- 下单、持仓、自选股修改、提醒、模拟交易或其他写操作。

用户未声明市场时，系统只在上述 A 股范围内解析。用户明确要求范围外证券时，
系统应返回稳定的范围不支持结果，不得自动替换为同名 A 股，也不得猜测其他市场。

本设计不处理丞相 `departments` 输出格式或丞相路由失败。

## 方案比较

### 方案 A：维护公司名称到腾讯代码的静态表

实现简单，但需要持续人工维护，无法覆盖新上市、改名、风险警示名称和其他公司，
并把通用领域逻辑绑定到单一提供方。不采用。

### 方案 B：只在搜索失败时删除“股份有限公司”

能够修复当前比亚迪案例，但仍无法可靠处理明确证券代码、其他法定后缀、曾用名、
风险警示名称、同名候选和北交所能力差异。不采用为完整方案。

### 方案 C：统一证券实体解析器与提供方适配器

在锦衣卫领域内建立提供方无关的统一证券实体，使用明确标识优先、有限名称规范化、
候选验证和唯一匹配完成解析。行情工具只消费已解析的统一实体，具体 MCP 代码格式
由适配器生成。采用此方案。

## 领域模型

### 统一证券实体

解析成功后生成不可变的 `InstrumentRef`，至少包含：

```json
{
  "canonical_name": "比亚迪",
  "exchange": "SZSE",
  "ticker": "002594",
  "instrument_type": "A_SHARE",
  "currency": "CNY"
}
```

`InstrumentRef` 不保存腾讯专用的 `sz002594`。提供方代码属于适配器输出，不属于
领域实体。

允许的交易所枚举：

- `SSE`：上海证券交易所；
- `SZSE`：深圳证券交易所；
- `BSE`：北京证券交易所。

### 解析输入

实体解析输入不能只接收 `RequiredFact.subject`，还应接收：

- 用户或司级 Agent 给出的原始问题；
- `RequiredFact.subject`；
- `RequiredFact.description`；
- 可选的明确市场或交易所约束。

解析器只能从这些既有文本中提取标识，不得让模型补造代码。

### 解析结果

解析结果为三态：

- `RESOLVED`：唯一、已验证的 A 股实体；
- `AMBIGUOUS`：存在多个合规候选，现有信息不足以唯一确定；
- `NOT_FOUND`：所有获准的解析步骤均未得到合规候选。

`AMBIGUOUS` 不得自动选第一个候选。上层应要求补充公司或代码信息。

## 解析算法

每个逻辑证券在一次调查中最多执行一条有界解析链，并复用解析结果。

### 第一步：提取明确证券标识

从原始问题、`subject` 和 `description` 中提取常见代码写法，例如：

- `600519.SH`、`SHSE:600519`、`sh600519`；
- `002594.SZ`、`SZSE:002594`、`sz002594`；
- 北交所对应的交易所限定写法。

代码前缀只能用于候选生成，不能作为最终事实来源。解析器仍须通过已批准的数据源
验证证券类型、交易所、代码和当前名称。明确代码通过验证后优先于名称搜索。

若同一请求出现互相冲突的多个明确代码，返回 `AMBIGUOUS`。

### 第二步：原始名称搜索

没有可验证的明确代码时，使用原始 `subject` 搜索，但只接受：

- 证券类型为 A 股；
- 交易所为 `SSE`、`SZSE` 或 `BSE`；
- 候选字段满足已批准 schema；
- 候选名称与原始名称满足规范化等价或已批准别名关系。

不得接受 ETF、基金、债券、指数、板块、港股或其他市场候选。

### 第三步：有限名称规范化

原始名称没有合规候选时，只执行一次通用名称规范化重试。规范化可以：

- 去除首尾空白并统一全角、半角和大小写；
- 去除受控列表中的公司法定后缀，如“股份有限公司”“有限公司”；
- 保留名称主体，不进行模糊联想或模型改写。

规范化结果必须非空、与原名不同且满足长度限制。一次解析不得连续生成更多搜索词。

`ST`、`*ST`、退市整理名称和曾用名不通过字符串猜测解决；只有数据源明确返回当前名称
或已批准别名关系时才能建立等价关系。

### 第四步：候选验证与消歧

候选按以下证据消歧：

1. 明确交易所和代码完全匹配；
2. 明确交易所约束匹配；
3. A 股证券类型匹配；
4. 标准名称、简称或已批准别名匹配。

仅剩一个候选时返回 `RESOLVED`；多于一个时返回 `AMBIGUOUS`；没有候选时返回
`NOT_FOUND`。不得按搜索排名、热度或返回顺序静默选择。

## MCP 能力与提供方适配

### 能力注册

锦衣卫继续只使用管理员注册并批准的只读 MCP。每个提供方声明其实际能力，包括：

- 支持的交易所；
- 支持的证券类型；
- 实体搜索能力；
- 行情快照能力；
- 分时或历史序列能力；
- 提供方代码格式。

不得因为本设计而在通用协调器中加入腾讯条件分支。

### 腾讯自选股适配

对已经解析的沪深 A 股实体，腾讯适配器生成：

- `SSE + 600519` → `sh600519`；
- `SZSE + 002594` → `sz002594`。

真实只读 smoke 已证明 `sz002594` 可用于 `data_quote`。北交所格式和工具支持状态
尚未验证，因此不得凭前缀推断为腾讯已支持。实现验收时必须单独进行真实只读能力探测；
若腾讯不支持北交所，注册表应把该能力标为不支持，并继续选择其他已接入 MCP。

### 解析复用

同一调查中的股价、成交量、涨跌幅或走势若指向同一证券，只进行一次实体解析。
后续事实复用 `InstrumentRef`，再按指标选择相应工具，禁止每个事实重复
`data_search`。

## 行情事实与工具选择

`MARKET_QUOTE` 只能作为大类，不能独自决定工具和字段。行情事实需要明确指标语义，
至少区分：

- `LAST_PRICE`；
- `VOLUME`；
- `CHANGE_PERCENT`；
- `INTRADAY_SERIES`。

用户只询问股票价格时，必须至少形成 `LAST_PRICE`，不得自动把 PE、PB、市值或月度趋势
作为回答股价的必需事实。只有用户明确询问或上层任务确有这些要求时才加入相应指标。

工具选择遵循：

- 快照型指标使用具备行情快照能力的工具，例如腾讯 `data_quote`；
- 分时序列使用具备分时能力的工具，例如腾讯 `data_minute`；
- 工具没有批准映射的指标不得从同一返回值推断。

## 史馆优先与外部补充

现有“史馆优先”原则保持不变：

1. 先查询史馆中与统一证券实体和所需指标匹配的证据；
2. 证据存在且满足行情新鲜度时直接使用；
3. 缺失或过期时，按能力注册表选择只读 MCP；
4. 外部结果通过 schema、证券身份、单位、时间和数值校验后形成证据；
5. 合规证据按现有归档规则进入史馆，供后续复用。

史馆旧库未迁移是独立运行问题。史馆读取失败应记录稳定错误并继续允许 MCP 回退，
但本设计不执行旧库迁移。

## 调查状态与错误语义

不得把所有失败都折叠成“数据不足”。至少保留以下稳定内部原因：

- `instrument_not_found`：无法解析证券；
- `instrument_ambiguous`：存在多个候选；
- `market_out_of_scope`：不是中国大陆交易所 A 股；
- `provider_capability_missing`：已接入来源不支持目标交易所或指标；
- `source_unavailable`：数据源暂时不可用；
- `quote_unavailable`：证券已解析，但当前没有可验证行情；
- `stale_evidence_only`：只有过期证据。

若部分请求事实已经得到证据，调查应返回现有的部分成功语义，并允许司级 Agent
使用已解决事实回奏，同时明确未解决事实。单个非必要扩展指标失败不得抹掉已经取得的股价。

只有所有必需事实均未解决时，才返回整体 `UNAVAILABLE`。

## 安全与审计

- 所有 MCP 工具继续保持 `READ_ONLY`；
- 不新增任意 URL、动态 endpoint 或用户提供凭据入口；
- 日志和调查审计记录解析阶段、候选数量、最终交易所与代码、工具选择和稳定错误码；
- 不记录 OAuth 凭据、请求头或未脱敏的完整 MCP 响应；
- 每次名称解析最多执行原名和一次规范化名称搜索；
- 提供方失败不得触发无限重试；
- 缓存键不包含凭据。

## 缓存与归档

证券身份和行情采用不同生命周期：

- `InstrumentRef` 及已验证别名属于证券主数据，可长期保存，但遇到改名、退市或身份冲突时
  必须重新验证；
- 行情证据继续使用分钟级新鲜度策略，不得因为证券身份缓存而延长行情有效期；
- MCP 工具缓存继续受工具 TTL 与事实 freshness 的较小值约束。

## 验收标准

### 离线测试

1. “比亚迪”“比亚迪股份有限公司”“002594.SZ”和“sz002594”均解析为同一个
   `InstrumentRef(SZSE, 002594)`。
2. “贵州茅台股份有限公司”和明确代码写法解析为 `InstrumentRef(SSE, 600519)`。
3. 没有明确市场时只接受沪、深、北 A 股候选，不接受港股同名候选。
4. 多个合规候选时返回 `AMBIGUOUS`，不选择第一个。
5. ETF、基金、债券、指数和 B 股候选被拒绝。
6. 原始名称失败后最多执行一次法定后缀规范化搜索。
7. 同一证券的多个行情事实只执行一次实体搜索。
8. `LAST_PRICE` 选择快照工具，`INTRADAY_SERIES` 选择分时工具。
9. 用户只问股价时，不产生 PE、PB、市值或月度趋势必需事实。
10. 股价成功而非必要扩展事实失败时，调查保留股价证据并返回部分成功。
11. 史馆读取失败时仍可进入 MCP 回退。
12. 北交所没有可用提供方时返回 `provider_capability_missing`，不伪造腾讯支持。
13. 非 A 股明确请求返回 `market_out_of_scope`。
14. 所有测试使用临时数据库、假客户端和固定 fixture，不访问真实网络或真实凭据。

### 真实只读验收

离线测试、Ruff、后端全量测试和 harness 全部通过后，另行取得明确授权执行：

1. 腾讯 `data_search` 使用证券简称“比亚迪”解析得到 `sz002594`；
2. 腾讯 `data_quote` 使用 `sz002594` 返回可映射、正数价格和有效市场时间；
3. 从 `/study` 下旨“帮我看看比亚迪的股票价格”，最新调查至少包含一条
   `LAST_PRICE` 证据，不再因公司全称映射失败而显示“数据不足”；
4. 对北交所执行不暴露价格正文和凭据的只读能力探测，并据实登记支持状态。

真实验收只输出脱敏状态、证券代码、市场时间和响应字节数，不输出 OAuth 信息、
请求头或完整行情响应。

## 非目标

- 不修复丞相 `departments` 格式错误或 502；
- 不迁移史馆旧数据库；
- 不建设全球证券主数据平台；
- 不支持港股通或境外市场；
- 不提供投资建议；
- 不新增任何证券交易或账户写能力；
- 不通过硬编码公司到代码的映射完成验收。
