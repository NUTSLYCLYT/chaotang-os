# 锦衣卫史馆优先与通用 MCP 补证设计

## 决策状态

已由用户于 2026-07-22 逐段确认。

本设计扩展并取代
`2026-07-22-jinyiwei-general-evidence-routing-design.md` 中“外部来源必须无需凭据”
以及“每种数据源使用专用连接器”的限制。锦衣卫仍只调查和返回证据，不形成业务结论，
也不执行任何外部写操作。

## 产品目标

锦衣卫是证据补全中心，不是以 MCP 为先的通用工具执行器。司级 Agent 提出结构化
`NEEDS_DATA` 后，锦衣卫必须先从史馆查找历次业务办理沉淀的历史业务资料，逐项判断覆盖
范围和时效；只有事实缺失或已有资料不满足当前时效要求时，才通过管理员批准的 MCP 查询
实时业务系统、专业数据服务或公共信息源。

外部证据经过标准化、验证并被原司级 Agent 明确采用后，在旨意办结时归档进史馆，供以后
复用。新数据不覆盖旧档案，而是形成可追踪的时间版本。

腾讯自选股是首个真实 MCP 验收源，但不得在锦衣卫核心中写死腾讯业务逻辑。后续接入新闻、
统计、百科、内部业务系统或其他获批 MCP 时，只增加注册和映射配置，不修改核心路由。
通达信不在当前或后续计划接入范围内。

## 明确边界

- 史馆是历次业务系统资料和已采用证据的档案库，不是外部网页或行情的普通缓存。
- 锦衣卫必须先查史馆，再决定是否调用 MCP。
- 只有管理员预先登记、审核并启用的 MCP 可以参与调查。
- 普通用户和模型不能提交临时 MCP 地址、启用服务或扩大工具权限。
- 锦衣卫永久只读，只允许查询、检索和读取类工具。
- 下单、模拟交易、自选管理、提醒、消息发送、文件上传、创建、更新和删除操作一律禁止。
- MCP 可连接内部业务系统、专业数据服务或公共信息源。
- MCP 可以匿名访问，也可以使用系统统一服务账号，但不得要求普通用户提供个人凭据。
- 首个腾讯自选股账号是锦衣卫专用共享服务账号，只用于公共、只读行情查询。
- 锦衣卫只提供事实和限制；原司级 Agent 是唯一形成业务意见并声明采用证据的节点。

## 事实范围

每个所需事实除类别、主体、地区和最大可接受时效外，还必须声明数据范围：

- `INTERNAL_BUSINESS`：当前业务系统事实，例如客户、订单、项目或库存状态；
- `EXTERNAL_PUBLIC`：外部公共或专业事实，例如行情、新闻、公告、统计和百科；
- `HYBRID`：同时需要历史业务资料和当前外部事实。

数据范围参与史馆检索、MCP 能力匹配和最终证据覆盖判断。MCP 不仅等同于互联网公共数据；
管理员可以批准只读的内部业务系统 MCP。

## 总体架构

### Archive Resolver

Archive Resolver 根据所需事实检索史馆，返回候选档案证据，并逐项判断：

- 是否覆盖指定主体、地区、时间范围和事实类别；
- 是否满足请求的最大可接受时效；
- 是否存在互相冲突的历史版本；
- 是否已被此前旨意明确采用。

满足覆盖与时效的事实直接进入本次候选证据，不调用 MCP。过期事实保留为历史背景，但不得
支撑“当前”结论；对应事实槽位继续进入 MCP 补全阶段。

### MCP Registry

注册表保存管理员批准的 MCP 服务、工具及能力声明。每项服务至少包含：

- 稳定服务标识、显示名称、HTTPS 地址和传输协议；
- 来源范围：内部业务系统、专业数据服务或公共信息源；
- 鉴权方式及不含秘密值的 `credential_ref`；
- 超时、速率限制、响应大小、重定向和缓存策略；
- 服务启用状态、健康状态和审批版本。

每项工具至少包含：

- MCP 工具名和输入 JSON Schema；
- `READ_ONLY` 副作用声明；
- 支持的事实类型、数据范围、地区、市场和实体类型；
- 数据时效、质量层级和使用限制；
- 确定性输出映射与验证规则；
- 工具结构摘要、配置哈希和审批版本。

### MCP Discovery and Approval

管理员接入服务分为两个阶段：

1. **发现**：系统连接 MCP 并调用 `tools/list`，把工具放入隔离的候选区。候选工具不可调用。
2. **批准**：管理员逐个确认只读属性、事实能力、数据范围、地区、时效、映射和安全限制，
   生成不可变的 `approval_version`。

远端工具名称、输入结构、鉴权方式、服务地址或受控配置发生变化时，原批准自动失效；工具
进入隔离状态，重新审核前不得调用。远端新增工具不会自动获得权限。

### Credential Provider

凭据层支持无鉴权、API Key、静态 Bearer 和 OAuth 刷新凭据。注册表只保存
`credential_ref`，真实 Token 由部署环境的秘密存储管理。凭据不得进入数据库业务字段、
日志、证据包、缓存键、异常消息或模型上下文。

腾讯自选股首期使用系统级专用服务账号。若服务账号凭据失效，只影响该 MCP；普通用户无需
登录，系统返回明确的来源授权故障。

### MCP Client

受限 MCP 客户端首期实现 Streamable HTTP。客户端只连接注册表固定的 HTTPS 域名和路径，
不接受模型、用户或 MCP 响应提供的新 URL。客户端负责会话初始化、工具调用、超时、响应
限制、协议错误归一化及凭据注入，但不理解具体业务字段。

### Capability Router

只有 Archive Resolver 判定为缺失或过期的事实槽位才能进入 Capability Router。路由器依据
事实类型、数据范围、主体、地区、市场和最大可接受时效选择工具。候选工具依次经过启用
状态、审批版本、只读属性、凭据、健康状态、数据范围、地区和时效过滤，再按来源权威性、
数据新鲜度、历史成功率和调用成本排序。

主来源失败时可尝试下一获批来源。高风险事实或需要交叉验证时可查询多个来源；来源冲突时
不得求平均或由模型任选。

### Evidence Normalizer

每个工具使用管理员批准的确定性映射将 MCP 响应转换为统一证据字段。映射可以采用受限
JSONPath 等声明式表达式，但不得执行远端代码，也不得让模型自由解释原始响应。

只有成功完成类型、单位、时间、主体、市场和覆盖验证的数据才能进入证据包。无法映射或
验证失败的响应只保留脱敏审计信息和内容哈希，不得作为事实。

统一证据至少记录：

- 事实类型、数据范围、主体和标准化实体标识；
- 事实值、单位、市场和币种；
- 数据发生时间、发布时间（可得时）和获取时间；
- 证据来自史馆还是 MCP；
- 对于 MCP 证据，记录服务、工具、审批版本和来源质量层级；
- 原始响应内容哈希、新鲜度判断及已知限制。

### Adopted Evidence Archiver

锦衣卫返回候选证据后，原司级 Agent 必须显式声明采用的证据 ID。只有已采用证据才在旨意
办结时进入史馆。未采用的 MCP 调查结果保留在锦衣卫独立审计库，不进入史馆。

归档采用追加版本：保存旨意、采用它的司级 Agent、事实类别、数据范围、主体、事实时间、
获取时间、来源 MCP 和工具、审批版本、内容哈希、时效要求及限制。新证据不得覆盖或修改
旧档案。以后召回时必须重新依据新请求判断覆盖和时效，不能因为已经归档就永久有效。

## MCP 访问策略

MCP 来源准入至少分为：

- `ANONYMOUS_PUBLIC`：免费、公开且无需凭据；
- `SERVICE_AUTHENTICATED_FREE`：不付费，但由系统级服务账号授权访问；
- `INTERNAL_SERVICE_AUTHENTICATED`：由系统级凭据只读访问内部业务系统。

每类来源均需完成合法性、稳定性、数据覆盖和使用限制审核。不存在明确再分发授权时，系统
只向当前用户展示完成任务所需的最小事实摘录，不公开原始批量数据，也不把归档或缓存建设
为对外数据服务。

## 调用流程

通用流程如下：

1. 司级 Agent 声明结构化 `NEEDS_DATA`。
2. Archive Resolver 从史馆召回相关业务档案并逐项判断覆盖与时效。
3. 已满足的事实直接采用史馆证据；过期证据只作为历史背景。
4. 缺失或过期槽位进入 MCP Registry，由 Capability Router 选择获批只读工具。
5. MCP Client 查询当前业务系统、专业数据服务或公共来源。
6. Evidence Normalizer 映射和验证结果，并与史馆证据执行冲突检查。
7. 锦衣卫冻结包含历史证据、当前证据和限制的候选证据包。
8. 原司级 Agent 只根据显式采用的证据 ID 恢复一次并形成意见。
9. 旨意办结后，Adopted Evidence Archiver 把采用证据追加归档进史馆。

以“看看比亚迪股票价格”为例：若史馆没有满足分钟级时效的行情，锦衣卫通过腾讯自选股
MCP 的获批证券搜索和行情工具取得当前数据。该行情被原司采用并办结后形成一条带事实时间
的史馆档案；下一次查询若它已经过期，仍需再次调用 MCP。

## 缓存与史馆的区别

传输缓存只用于降低短时间内重复调用 MCP 的成本，不属于史馆：

- 实时行情默认缓存不超过一分钟，并受请求 `max_age` 进一步限制；
- 新闻按查询条件、发布时间和来源缓存；
- 公告、统计和百科可以配置更长缓存，但必须保留原始发生时间和获取时间；
- 缓存键必须包含服务、工具、审批版本、标准化参数、实体标识、市场和适用日期；
- 过期缓存不能冒充当前事实；外部服务不可用时不得静默使用过期缓存。

史馆保存的是业务办理中被明确采用的版本化证据。它可以参与后续业务判断和变化追踪，但每次
召回仍须重新进行覆盖和时效验证。

## 安全控制

- 所有 MCP 输出均视为不可信外部数据，不执行其中的指令、链接或嵌套工具调用。
- 调用参数必须同时通过批准版本的 JSON Schema 和本地业务约束。
- 禁止访问本机、私网、链路本地地址及云实例元数据地址；经管理员明确登记的内部业务 MCP
  仅允许连接其固定内网目标。
- 禁止未批准重定向、协议降级和动态域名替换。
- 限制响应内容类型、字节数、嵌套深度、记录数和单次调查工具轮数。
- 每个工具有独立超时、速率限制，并共享当前旨意的全局调查预算。
- 本地写工具禁令优先于远端工具描述和账号权限。

## 故障语义

锦衣卫统一使用以下稳定故障代码：

- `archive_fact_missing`
- `archive_fact_stale`
- `source_not_configured`
- `source_not_approved`
- `source_auth_required`
- `source_auth_expired`
- `source_rate_limited`
- `source_timeout`
- `source_schema_changed`
- `response_invalid`
- `fact_stale`
- `fact_unavailable`
- `fact_conflicted`

史馆缺失或过期本身不是最终失败，而是进入 MCP 补全的原因。MCP 发生故障时先尝试其他获批
来源。所有来源失败后，证据包记录史馆覆盖、已尝试来源和限制；司级 Agent 必须说明无法
确认，不得编造。连接失败与“来源明确返回无数据”必须区分。

## 审计

每次调查记录史馆检索条件、召回证据 ID、覆盖及时效判断，以及每次 MCP 调用的服务、工具、
审批版本、脱敏参数摘要、开始和结束时间、响应哈希与大小、映射结果、验证结果和最终是否被
采用。审计日志不得记录 Token、Cookie、完整授权头或未经清洗的敏感响应。

## 首期范围

首期建设史馆优先判定、通用 MCP Registry、发现与审批、凭据接口、受限 Streamable HTTP
客户端、能力路由、确定性映射、证据标准化、采用后归档及审计。腾讯自选股作为首个真实
MCP 验收源，只批准公共只读工具：

- 证券或实体搜索；
- 行情快照；
- K 线；
- 财务数据；
- 信息披露查询。

腾讯自选股的自选、提醒、模拟交易及其他写工具不进入候选批准范围。首期不建设可视化 MCP
商店，也不允许普通用户管理 MCP。

## 验收标准

- 每个 `NEEDS_DATA` 事实槽位必须先查史馆，再决定是否调用 MCP。
- 史馆证据满足覆盖和时效时不发生外部调用。
- 史馆过期证据只能作为历史背景，对应当前事实必须进入 MCP 补全。
- MCP 只收到缺失或过期的事实槽位，不重复查询已满足事实。
- 未批准的 MCP 和工具不可被任何调查路径调用。
- 远端工具结构变化后原批准自动失效。
- 写工具不能登记为锦衣卫能力，即使远端把它描述为只读。
- 凭据不进入日志、数据库业务字段、证据、缓存键或模型上下文。
- “比亚迪”能够解析到目标证券；存在市场或实体歧义时不得静默选错。
- 行情超过请求时效时返回 `fact_stale`。
- 主来源失败时按确定顺序切换备用来源。
- 多来源或新旧证据冲突无法消解时返回 `fact_conflicted`。
- 提示注入、恶意 URL、超大响应、非法类型和未批准重定向被拒绝。
- 调查预算耗尽后停止调用，不发生无限重试。
- 只有原司明确采用的证据在旨意办结后以追加版本归档；未采用材料不进入史馆。
- 归档证据在后续召回时重新进行覆盖和时效判断。
- `/study → NEEDS_DATA → 史馆召回 → MCP 补全 → 证据包 → 原司恢复 → 采用后归档`
  端到端通过。
- 缺少有效来源时明确说明数据不足，不输出猜测事实。

## 实施顺序

1. 修复现有 `NEEDS_DATA` 可被空事实声明绕过的问题。
2. 明确事实数据范围，并完善史馆覆盖及时效判定。
3. 扩展来源准入策略并建立通用 MCP 注册、发现、批准和凭据接口。
4. 实现受限 Streamable HTTP MCP 客户端。
5. 实现只针对缺失或过期事实的能力路由、确定性映射和统一错误语义。
6. 接入腾讯自选股作为首个真实 MCP 来源。
7. 实现原司显式采用后的版本化史馆归档。
8. 完成史馆优先、协议、故障、安全、归档和端到端测试。
9. 以纯注册方式继续接入内部业务系统、新闻、统计和百科 MCP。

## 非目标

- 普通用户动态添加任意 MCP；
- 接入通达信 MCP；
- 锦衣卫执行任何写操作；
- 用 MCP 新数据覆盖或修改史馆旧档案；
- 把普通传输缓存当作史馆业务档案；
- 构建完整 MCP 应用商店；
- 绕过 OAuth、验证码、付费墙或服务方权限；
- 将第三方数据批量再分发为公共数据服务；
- 由锦衣卫直接形成投资或业务结论。
