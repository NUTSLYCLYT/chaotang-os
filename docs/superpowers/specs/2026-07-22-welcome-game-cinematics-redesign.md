# V5 欢迎页三套游戏过场动效重做规格

日期：2026-07-22
状态：待用户复核

## 1. 目标

重做三个可独立体验的 Figma 欢迎页动效：宫门启朝、玉玺落印、百官入朝。它们必须像游戏开场中的短过场，而不是图片切换、整体淡入或普通界面微动效。

本轮只重做三个动效演示，不改登录、上书房及其他业务页面。完成态的主按钮统一进入上书房，登录入口进入登录页，跳过仪式直接进入上书房。

## 2. 失败样本结论

上一版不能继续微调，原因如下：

- 宫门首帧已经处于打开状态，点击前后缺少明确的因果变化；过渡中存在重影和整图淡出。
- 玉玺像小图标匀速下移，没有重量、加速、撞击、回弹和揭印动作。
- 百官使用整组人物统一改变透明度，没有分排推进、步伐纵深或列班过程。
- 验收偏重节点与跳转，缺少真实播放、逐时刻截图和体验否决项。

失败样本保存在 `docs/product/audits/welcome-motion-v5-failure/`。

## 3. 共用体验原则

### 3.1 点击前

- 首帧必须清楚表达“尚未发生”：宫门完全闭合、玉玺尚未出现、朝堂无人列班。
- 主按钮是唯一视觉焦点；标题和辅助文案不遮挡核心动作区域。
- 用户点击后立即给出 80–120ms 的按压反馈。

### 3.2 播放中

- 动画开始后，原主按钮淡出并取消热区，避免误触。
- 每套动效只讲一个动作，不同时堆叠大量文字、光效和装饰。
- 主要物体必须作为独立素材层运动；禁止用同一张完整场景图互相淡化冒充动作。
- 所有运动采用明确的加速、减速和停顿，禁止全程匀速。
- 总时长控制在 2.2–3.2 秒，且不循环。

### 3.3 完成后

- 画面停稳 180–260ms 后再出现完成文案和“进入上书房”。
- 完成态与首帧必须一眼可辨。
- “跳过仪式”始终直接进入上书房，不先进入动画完成态。

## 4. 动效 A：宫门启朝

### 4.1 叙事目标

用户点击“上朝”后，两扇沉重宫门从完全闭合状态缓慢受力开启，晨光从门缝切入，最终显露远处大殿。重点是门的重量、空间变化和天光出现，而不是标题淡入。

### 4.2 素材分层

- 宫门后方的完整庭院与远殿背景。
- 左门扇透明素材，包含门钉、铜环及门框阴影。
- 右门扇透明素材，与左门扇保持同一透视和光向。
- 中央天光束与地面反光层。
- 前景门框和灯笼遮挡层，固定不动，用来增强纵深。

不得把一张完整宫门场景复制到左右裁切容器中。

### 4.3 时间脚本

| 时间 | 画面与动作 |
| --- | --- |
| 0–100ms | “上朝”按钮压下，金边收紧，文字亮度降低。 |
| 100–280ms | 两扇门先向内轻微回弹 4–6px，铜环和门钉高光闪过，表现门闩解除。 |
| 280–1050ms | 左右门扇以外侧门轴为支点开启；前 40% 缓慢、后 60% 加速，中央门缝由 0 扩大到约画面宽度的 28%。 |
| 520–1350ms | 天光随门缝扩张，地面反光由中央向两侧延展；门扇阴影同步退开。 |
| 1050–1600ms | 门扇继续减速到最终位置，画面进行 1.5% 的轻微前推。 |
| 1600–1850ms | 门扇停稳，灯笼亮度恢复，标题由 12px 下方淡入。 |
| 1850–2150ms | “进入上书房”出现并可点击。 |

### 4.4 否决项

- 首帧能看到明显庭院通道或大面积天空。
- 开门只表现为门扇透明度变化。
- 中间出现重复宫殿、镜像拼接或竖向接缝。
- 门扇同时消失而不是向两侧受力移动。

## 5. 动效 B：玉玺落印

### 5.1 叙事目标

用户点击“用玺启朝”后，玉玺从画面右上方被抬起，快速落向展开的诏书，产生短促撞击和画面震动；玉玺随即抬起，露出清晰朱印。重点是重量、撞击与“结果被留下”。

### 5.2 素材分层

- 御案与展开诏书背景，诏书中央必须留出真实落印区域。
- 独立透明玉玺，视角与诏书平面一致，尺寸占诏书宽度约 22–28%。
- 独立朱印，初始不可见，位置与玉玺底面精确重合。
- 撞击暗影、短促金色冲击环和少量朱砂颗粒层。
- 御案前景器物遮挡层，用于建立空间关系。

### 5.3 时间脚本

| 时间 | 画面与动作 |
| --- | --- |
| 0–100ms | 按钮压下并消失，诏书区域亮度提升。 |
| 100–360ms | 玉玺从右上方进入，先轻微上提 10px，尺寸由 92% 到 104%，表现蓄力。 |
| 360–760ms | 玉玺向落印点加速下落，最后 120ms 速度明显提高；下方阴影同步缩小并加深。 |
| 760–840ms | 玉玺接触诏书；画面整体向下偏移 3px 后回弹，冲击环快速扩散，按钮和文字保持隐藏。 |
| 840–1080ms | 玉玺压住朱印 240ms，不立即抬起，让撞击有停顿。 |
| 1080–1420ms | 玉玺向右上方抬起 60–80px，朱印从 0 到 100% 显现，朱砂颗粒快速消散。 |
| 1420–1750ms | 玉玺退到画面右侧，诏书轻微恢复平整，完成文案出现。 |
| 1750–2050ms | “进入上书房”出现并可点击。 |

### 5.4 否决项

- 玉玺尺寸像图标，无法覆盖真实印章面积。
- 只做垂直匀速移动，没有蓄力、加速、撞击停顿或揭印。
- 玉玺压住诏书时朱印已经完全可见。
- 玉玺与印痕的透视、尺寸或落点不重合。

## 6. 动效 C：百官入朝

### 6.1 叙事目标

用户点击“宣百官入朝”后，远处晨光先亮起，三组百官从纵深方向分批进入并在左右列班。重点是队列推进、远近比例和秩序感，而不是整组人物渐显。

### 6.2 素材分层

- 无人物的暗朝堂背景。
- 远排百官独立透明素材：人物小、位置靠近殿门。
- 中排百官独立透明素材：人物中等、分列中央通道两侧。
- 前排百官独立透明素材：人物最大，保留中央御道。
- 左右灯火亮层、晨光层和地面反光层。

三排素材必须分别生成或分别绘制，禁止把一张人物合照整体移动或统一改变透明度。

### 6.3 时间脚本

| 时间 | 画面与动作 |
| --- | --- |
| 0–100ms | 按钮压下并消失，标题亮度降低，为人物让出注意力。 |
| 100–480ms | 殿门方向晨光由弱到强，两侧最远灯火依次点亮。 |
| 360–950ms | 远排由 y+20px、96% 尺寸进入，移动到列班点后停稳。 |
| 560–1250ms | 中排由 y+32px、94% 尺寸进入，左右两列错开 100ms。 |
| 780–1550ms | 前排由 y+44px、92% 尺寸进入，移动距离最长，最终停在画面下半部。 |
| 1550–1820ms | 三排依次做 2–3px 的停步回弹，灯火全部点亮，地面反光增强。 |
| 1820–2100ms | 标题改为“百官就位”，由上方淡入；人物保持静止。 |
| 2100–2400ms | “进入上书房”出现并可点击。 |

### 6.4 否决项

- 三排同时出现或统一改变透明度。
- 人物只向上平移，没有远近尺寸变化。
- 人物堵住中央御道或与前景龙首、标题重叠。
- 完成态按钮仍显示“观看百官入朝”。

## 7. Figma 实现约束

- 三套效果各保留一个正式起始 Frame，并分别设置 Prototype flow starting point。
- 允许使用内部关键帧 Frame，但内部帧统一命名为 `Internal/V6/...`，不作为产品页面。
- 运动物体在所有关键帧中保持相同图层名称，使用 Smart Animate 匹配。
- 主要动作层禁止使用完整场景图重复裁切。
- 过渡态按钮必须无 reaction；完成态按钮才可进入上书房。
- 所有可见 Skip 直接进入上书房；所有 Login 进入登录页。
- 本轮不使用 CSS，不用网页模拟替代 Figma Prototype。

## 8. 新验收方式

### 8.1 结构验收

- 检查每条 Prototype reaction、flow starting point、CTA、Skip 和 Login 目的地。
- 检查过渡态不存在隐藏可点击热区。
- 检查素材是背景、运动主体、光效和前景遮挡的真实独立图层。

### 8.2 真实播放验收

- 必须在已登录的 Chrome Figma Present 中从首帧点击播放，不以静态 Frame 截图代替。
- 每套保存至少五个时刻：点击前、启动、主要动作中段、动作停稳、完成态。
- 逐帧检查重影、接缝、跳帧、错误缩放、人物/玉玺漂浮、文字遮挡和完成态文案。
- 记录实际总时长，并确认 3.2 秒内完成且不循环。

### 8.3 体验硬门槛

以下任一项出现即为 Fail：

- 首帧与完成态难以区分。
- 用户看不清“点击导致了什么”。
- 主要动作依赖整图淡入淡出。
- 运动物体缺少加速、减速或停顿。
- 中间帧明显像素材拼贴，不像同一空间中的连续动作。
- 主要动作期间仍有按钮热区或错误跳转。
- 只通过 Figma 节点检查，没有在 Present 中实际播放。

### 8.4 最终签收

- 先由实现者按上述五个时刻自验并修复。
- 再由独立 QA 从三个 flow starting point 重新播放，不能复用实现者截图。
- QA 报告必须同时给出结构结论和体验结论；两者均为 Pass 才能交付用户。

## 9. 本轮交付物

- 三套新的正式起始 Frame。
- 每套所需的独立分层图片素材。
- 三条可直接体验的 Figma Prototype 链路。
- 三套真实播放的五时刻验收截图。
- 一份独立 QA 结论。

## 10. Figma 可执行关键帧规范（覆盖前述概念时间脚本）

本节是实现与验收的唯一时序基准。每一次 Prototype 跳转只使用一组明确的时长和曲线；需要错峰或重叠的动作通过增加内部关键帧实现，不依赖实现者自行理解。

### 10.1 全局交互规则

- 正式起始 Frame 保留主 CTA、`跳过仪式` 与 `登录`。
- 点击主 CTA 后，从第一个内部关键帧开始隐藏全部按钮与热区，包括 Skip 和 Login；播放中任何位置均不可点击。
- “Skip 始终直达上书房”仅指起始 Frame 中可见的 Skip，不适用于播放中的内部关键帧。
- 完成 Frame 只显示 `进入上书房`，该按钮进入上书房；不再显示 Skip 与 Login。
- 所有内部帧使用 `After Delay` 自动前进且不循环；只有起始 Frame 的主 CTA 使用 `On Click`。

### 10.2 A／宫门启朝关键帧

| 帧 | After Delay | 跳转时长／曲线 | 目标状态 |
| --- | ---: | --- | --- |
| A0 起始 | 主 CTA 点击 | 100ms／Ease Out | 双门完全闭合；CTA 压下后消失 |
| A1 解闩 | 80ms | 180ms／Ease In Out | 双门各向内回弹 6px；门环高光出现 |
| A2 初启 | 0ms | 420ms／Ease In | 门缝从 0 扩至画面宽 10%；天光 0→35%；背景固定 |
| A3 开门 | 0ms | 530ms／Ease In Out | 门缝 10%→23%；天光 35%→80%；地面反光出现 |
| A4 减速 | 0ms | 550ms／Ease Out | 门缝 23%→28%；门影退开；背景整体放大 1.5% |
| A5 停稳 | 150ms | 250ms／Ease Out | 门扇回弹 3px 后停稳；灯笼恢复亮度 |
| A6 完成 | 无 | 无 | 标题与 `进入上书房` 出现 |

实现要求：左右门分别放在以外侧门轴为原点的裁切容器中。若 Figma 无法直接表现透视旋转，则用 3 个同一素材来源的透视关键状态（闭合、半开、全开）做 Smart Animate 近似；禁止透明度消失或整幅场景交叉淡化。

| 帧 | After Delay | 跳转时长／曲线 | 目标状态 |
| --- | ---: | --- | --- |
| B0 起始 | 主 CTA 点击 | 100ms／Ease Out | 玉玺位于右上待命位；CTA 消失 |
| B1 蓄力 | 60ms | 260ms／Ease Out | 玉玺上提 10px，缩放 92%→104%；阴影变浅 |
| B2 下落前段 | 0ms | 280ms／Ease In | 玉玺走完约 45% 落距；阴影缩小 |
| B3 下落末段 | 0ms | 120ms／Ease In | 玉玺完成余下 55% 落距并接触诏书 |
| B4 撞击 | 60ms | 80ms／Linear | 场景下移 3px；冲击环展开；朱印仍隐藏 |
| B5 压印停顿 | 180ms | 180ms／Ease Out | 场景回弹；玉玺保持压住；冲击环衰减 |

### 10.4 C／百官入朝关键帧

人物运动层至少拆为 `Far/Left`、`Far/Right`、`Mid/Left`、`Mid/Right`、`Front/Left`、`Front/Right` 六层。每层必须是透明人物素材，不得包含朝堂背景。中央御道自画面中线向左右各保留 12% 画面宽度，全程不得被人物遮挡。

| 帧 | After Delay | 跳转时长／曲线 | 目标状态 |
| --- | ---: | --- | --- |
| C0 起始 | 主 CTA 点击 | 100ms／Ease Out | 空朝堂；CTA 消失 |
| C1 晨光 | 60ms | 220ms／Ease In Out | 晨光增强；远端灯火依次点亮 |
| C2 远左 | 40ms | 250ms／Ease Out | Far/Left 入位；其余人物保持起始位置 |
| C3 远右 | 40ms | 250ms／Ease Out | Far/Right 入位；远排停稳 |
| C4 中左 | 60ms | 300ms／Ease Out | Mid/Left 入位 |
| C5 中右 | 60ms | 300ms／Ease Out | Mid/Right 入位；中排停稳 |
| C6 前左 | 80ms | 350ms／Ease Out | Front/Left 入位 |
| C7 前右 | 60ms | 350ms／Ease Out | Front/Right 入位 |
| C8 停步 | 80ms | 150ms／Ease Out | 六层分别回弹 2–4px；全部灯火点亮 |
| C9 完成 | 无 | 无 | 标题改为 `百官就位`；`进入上书房` 出现 |

相邻层可在上一帧后半程进入视觉准备态，但不得通过同一张整排人物合照实现。以上固定数值累计 2.75 秒（含起始 CTA 的 100ms 跳转），实现时不得自行增减时长，也不得删除左右错峰与停步帧。

## 11. 素材真实性检查

- 每一个运动主体必须在棋盘格或纯色检查底上单独显示一次，确认透明边界完整、无场景背景、无黑边和残留人物。
- 同一主体在所有关键帧中必须复用同一 imageHash；仅允许位置、尺寸、透明度和裁切容器变化。
- 背景 imageHash 在同一动效的全部关键帧中保持一致；A 的背景只允许 1.5% 镜头推进，不允许换图。
- A 必须展示左右门轴容器及裁切边界；B 必须核对玉玺底面与朱印落点；C 必须核对六个人物层与中央御道安全区。
- 若任何“独立图层”实际填充的是包含完整场景的位图，结构验收直接 Fail。

## 12. 连续录屏验收

- 独立 QA 必须在自己的已登录 Chrome Figma Present 会话中，从可见鼠标点击主 CTA 开始，连续录制到完成态停稳后至少 500ms。
- 录屏必须保留可读时间码或播放器时长；每套单独录制，不剪切、不倍速、不拼接。
- QA 以录屏判断加速、减速、撞击停顿、左右错峰、总时长和是否循环；五时刻截图只用于画质、接缝与构图检查。
- 每套实际总时长须在 2.0–3.2 秒之间，播放一次后停在完成态，不自动重播。
- 缺少独立 QA 录屏、录屏不含可见点击、录屏中途剪切，任一情况直接 Fail。
