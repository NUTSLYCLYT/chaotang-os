# 欢迎页宫门视频过场设计

## 目标

根路径欢迎页以用户提供的关闭宫门图片作为初始背景。用户点击“上朝”后，在同一背景层播放用户提供的开门视频；视频结束后立即跳转到 `/register`，不显示开门后的静态图片，也不额外等待。

## 范围与假设

- 关闭门素材：`1785403767165.png`（保留原图右下角水印）。
- 开门视频：`生成关闭的门的图片.mp4`。
- 关闭门图片和视频位于欢迎页专用静态资源目录，由 Next.js 直接提供。
- 原开门静态图片不再参与欢迎页运行时渲染，可以从本功能静态资源中移除。
- 页面标题、顶部导航、说明文字和操作区在视频播放期间保持显示和可见。
- “跳过仪式”和“已有朝堂？登录”继续直接进入 `/login`。
- 不修改注册页、登录页、认证逻辑、后端 API 或 ADR 0028 的业务流基线。

## 交互与状态

欢迎页客户端组件只维护两个阶段：

1. `closed`：显示关闭门背景，“上朝”按钮可用。
2. `opening`：点击“上朝”后显示并播放背景视频，“上朝”按钮禁用，防止重复启动。

视频自然结束时立即调用 `router.replace("/register")`。使用历史替换，避免用户通过浏览器返回键回到已经完成的过场页。

视频是纯背景媒介：

- 不渲染浏览器播放控件。
- 设置 `aria-hidden="true"`，不进入辅助技术的交互语义。
- 不接受鼠标、触摸或键盘操作，CSS 使用 `pointer-events: none`。
- 禁止拖动，且不提供暂停、进度、音量、全屏或画中画入口。
- 使用 `object-fit: cover` 和居中裁切，保持与图片背景相同的全屏覆盖语义。

前景内容始终位于背景层上方。视频通过用户点击触发播放；若素材包含音轨，按原视频播放，不额外提供音量操作。

## 组件边界

- `WelcomeGate` 负责两阶段状态、视频播放和注册页导航。
- `welcomeTransition.ts` 只负责 `closed → opening` 的幂等状态转换。
- 背景图片和视频同处一个不可交互的背景层。
- 不再维护 `opened` 状态、开门图渲染或 1 秒跳转定时器。

## 失败处理

- `video.play()` 被拒绝、视频加载失败或播放错误时，立即执行与自然结束相同的 `router.replace("/register")`，避免用户滞留。
- 视频结束与错误处理共享同一个幂等导航入口。

## 测试与验收

- 测试初始阶段使用关闭门图片。
- 测试点击“上朝”进入视频阶段且不会立即跳转。
- 测试视频元素无 `controls`，不可交互并具有背景语义。
- 测试视频自然结束后立即使用历史替换进入 `/register`。
- 测试视频播放失败立即使用相同路径进入 `/register`。
- 测试实现中不存在 `opened` 阶段、开门图 URL、1 秒定时器或 `/login` 过场跳转。
- 测试重复点击不会重复启动视频。
- 运行前端单元测试、lint、typecheck、build，以及仓库 harness 检查。
- 在浏览器中验证桌面与窄屏下的覆盖裁切、前景可见性、完整过场和最终注册页跳转。
