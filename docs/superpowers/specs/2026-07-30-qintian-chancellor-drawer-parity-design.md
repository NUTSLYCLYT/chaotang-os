# 钦天监与丞相侧栏同构设计

## 背景与目标

上书房左侧丞相抽屉已经形成清晰的双区结构：上部展示最近回奏，下部承载带人物头像的连续对话。当前钦天监右栏虽然功能完整，但表现为连续堆叠的长表单，视觉层级、聊天体验和信息密度与丞相抽屉不属于同一套界面语言。

本次采用用户确认的 A 方案：统一左右抽屉的骨架、标题栏、间距、聊天气泡、输入框与按钮；保留两位角色不同的职责、内容和少量强调色。

## 设计原则

- 同构而不同职：丞相回答综合判断与执行分工；钦天监回答时机、风险、反事实和复核信号。
- 先看摘要，再按需深入：钦天监默认不把正式推演表单和全部细节铺满右栏。
- 聊天始终可达：上下内容再多，底部问策输入都保持在稳定位置。
- 来源必须明确：导览、当前旨意检查、正式推演和到期复核继续显示清晰来源。
- 不改变权力边界：视觉调整不得让钦天监获得下旨、调查或归档权限。

## 抽屉骨架

左右抽屉共用同样的宽度、标题栏高度、水平内边距、关闭按钮、背景、分割线和移动端规则。

```text
┌──────────────────────────────┐
│ 身份/来源              关闭  │
│ 角色名称                     │
├──────────────────────────────┤
│ 上部工作区，约 38%           │
│ 丞相：最近回奏               │
│ 钦天监：决策雷达/到期复核    │
├──────────────────────────────┤
│ 下部对话区，约 62%           │
│ 头像 + 身份 + 左右消息气泡   │
│                              │
│ 固定输入框 + 发送按钮        │
└──────────────────────────────┘
```

桌面端继续使用 300px 抽屉；中等视口为 260px；移动端最大宽度为整个屏幕。底部仍避让御前工作台和安全区。

## 钦天监上部工作区

### 默认状态

上部标题使用“钦天监札记”，显示来源 badge、当前判断摘要和紧凑检查卡。无任务时显示两张导览卡；有任务时显示天时、关键未知、红线、改变判断的信号、最低成本验证和复核建议。

六项内容不再逐段铺成长页面，而是使用与左侧回奏条目同密度的“观星札记卡”：

- 每张卡有短标题和一到两条正文；
- 统一细边框、左侧强调线和紧凑内边距；
- 钦天监只用低饱和天青色标识来源与选中状态；
- 文字、背景和主边框仍沿用朝堂的金黑体系。

### 正式推演

正式推演默认折叠为一行次级操作“展开正式推演”。展开后在上部工作区内显示问题输入和发起按钮。推演结果继续包含三情景、置信依据、假设、证据、触发器、复核日期和人工签字要求，但使用可折叠分组，避免把聊天区推离视口。

### 到期复核

到期复核拥有上部最高优先级。它复用“回奏条目/札记卡”视觉，依次显示原判断、待核信号、实际新观察、是否失效和复核动作。复核仍按单个 trigger 留痕，不改变现有数据契约。

## 钦天监下部对话区

下部直接复用丞相对话的视觉语法：

- 用户消息右对齐，使用皇上头像和金色气泡；
- 钦天监消息左对齐，使用钦天监人物头像、角色名“钦天监”和深色气泡；
- pending、错误、空状态与丞相保持相同字号和垂直节奏；
- 输入框固定在底部，支持 Enter 发送、Shift+Enter 换行；
- 发送按钮使用相同的纸飞机图标与 disabled 状态；
- “转为拟旨输入”作为最后一条钦天监回复下方的次级文字按钮，不伪装成执行动作。

钦天监与丞相消息状态继续完全隔离，不共享消息数组或本地存储键。

## 组件边界

- `StudySideDrawers` 负责左右抽屉的共同外壳、标题栏、上下分区和可访问性行为。
- `QintianPanel` 只负责钦天监上部工作区与下部对话内容，不重新定义抽屉尺寸。
- 公共聊天视觉通过共享 CSS class 或一个小型纯展示组件复用；不合并丞相和钦天监的业务状态。
- 现有 forecast、trigger、review、consult 请求契约保持不变。

## 状态与错误处理

- provider 不可用：在上部推演区显示明确错误，聊天区保持可用；不得生成 fallback 预测。
- 推演加载：只禁用推演按钮，不锁死聊天。
- 聊天加载：只禁用聊天输入和发送按钮，不锁死雷达与推演。
- 到期复核失败：保留用户填写的观察与选择，显示紧凑错误提示。
- 切换奏折上下文：继续丢弃旧异步响应，并重置不属于新上下文的正式推演视图。

## 测试与验收

- 源码/结构测试证明左右抽屉具有相同的标题栏和 38/62 双区骨架。
- 组件纯状态测试覆盖推演折叠、展开、加载、失败和结果分组。
- 聊天测试覆盖独立消息、头像/身份、Enter、Shift+Enter、pending、错误和只预填不下旨。
- 可访问性守卫覆盖标题、区域标签、关闭焦点恢复和键盘 Escape。
- 响应式样式守卫覆盖 300px、260px、移动端满宽与底部安全区。
- 最终运行前端全量 test、typecheck、lint、build，随后在本地 `/study#qintian` 对比左右抽屉并检查控制台错误。

## 非目标

- 不改变任何后端、BFF 或钦天监数据契约。
- 不重新设计整个上书房或御前工作台。
- 不把丞相与钦天监合并为同一个聊天 Agent。
- 不新增动画系统、第三方组件库或新的全局设计系统。
