# 司级蜂群页面证据信封修复设计

## 背景

真实页面下旨测试表明，司级蜂群能够直接调用模型并生成
`{"opinion":"..."}`，但通过 `/study` 的受治理证据会话调用时，多数司节点降级为
`model_synthesis_invalid`。

根因是同一次模型调用收到两套冲突的输出契约：

- 通用司级系统提示要求只返回裸 `opinion`；
- 证据会话追加提示要求只返回完整 `READY/NEEDS_DATA` 信封。

模型通常优先遵循前者。现有纠正调用虽能要求信封，但其机会由整道旨意全局共享，
而且纠正后的事实声明仍可能不满足严格的逐句证据约束，导致多司流程中后续节点没有
独立的格式恢复机会。

## 目标

- 司级蜂群直接调用保持现有裸 `opinion` 契约。
- `/study` 页面调用的每个司级节点从第一次模型调用起只看到证据会话契约。
- 每个司级节点拥有一次独立的“裸意见转证据信封”格式纠正机会。
- 保持现有证据、调查、时限、归档和失败关闭规则不变。
- 真实单司与多司页面调用不再因双重输出契约产生
  `model_synthesis_invalid`。

## 非目标

- 不放宽 `READY` 的事实声明、证据绑定或采用证据 ID 校验。
- 不把裸 `opinion` 直接视为受治理页面调用的成功结果。
- 不增加新的外网来源、调查入口、页面功能或 API 字段。
- 不修改 ADR 0028 规定的下旨、六部、锦衣卫和史馆业务流。
- 不以重试掩盖模型虚构事实；不合规输出仍按现有规则失败关闭或降级。

## 设计

### 1. 按调用模式生成唯一输出契约

司级提示构造器区分两种明确模式：

- `direct`：保留领域职责提示及裸 `{"opinion":"..."}` 输出契约；
- `evidence`：保留相同领域职责提示，但移除裸输出契约，只附加完整且唯一的
  `READY/NEEDS_DATA` 证据协议。

调用方必须显式选择模式。普通司级直调选择 `direct`；带
`AgentEvidenceSession` 的页面处理选择 `evidence`。证据模式不得通过字符串拼接把两套
互斥格式同时放入系统消息。

### 2. 按司节点隔离格式纠正预算

`AgentEvidenceSession` 将“是否已使用裸意见格式纠正”从单个全局布尔值改为按
`node_id` 记录的集合。一个司只能领取一次纠正机会，不同司互不挤占。

该调整只作用于输出格式纠正：

- 不增加同一司的纠正上限；
- 不改变调查次数、恢复次数、抽取次数和总时限；
- 不改变其他协议纠正预算，避免扩大本次修复范围。

### 3. 严格校验与失败处理

证据模式继续要求：

- `READY` 声明全部事实性语句及其依据；
- 采用的证据 ID 必须已冻结并与声明绑定；
- 用户提供事实必须能在原始旨意中定位；
- 规范性建议不得冒充客观事实；
- 需要外部事实但没有证据时返回 `NEEDS_DATA`。

首次意外返回裸 `opinion` 时，只追加不含旧响应正文的静态纠正提示。纠正后仍不合规，
继续使用现有稳定错误码和降级路径，不自动接受其内容。

## 数据流

1. 六部选择相关司并为每个司建立唯一 `node_id`。
2. 页面路径携带共享证据会话调用司级 Agent。
3. 司级 Agent 以 `evidence` 模式构造唯一系统契约并调用模型。
4. 合法 `READY` 进入现有意见解析与证据采用流程。
5. 合法 `NEEDS_DATA` 进入现有受控调查和最多一次恢复流程。
6. 裸 `opinion` 仅触发该 `node_id` 的一次格式纠正。
7. 仍不合法的响应按现有失败关闭规则处理。
8. 部级汇总、丞相最终汇总与恰好一条 `REPLY` 归档流程保持不变。

## 测试设计

先增加会失败的回归测试，再修改实现：

- 提示单元测试：`direct` 只含裸契约，`evidence` 只含证据信封契约。
- Agent 单元测试：证据会话第一次调用不再收到裸 `opinion` 要求。
- 会话预算测试：同一 `node_id` 只能纠正一次，两个不同司可各纠正一次。
- 兼容测试：普通直调仍能解析现有裸 `opinion`。
- 安全回归测试：无证据外部事实、错误证据 ID 和不完整事实声明仍被拒绝。
- 相关后端测试、后端全量测试、ruff 与 harness 全部通过。
- 启动真实前后端后，通过 `/study` 分别提交单司和多司旨意，确认司级输入输出可见、
  不再出现由双重契约导致的 `model_synthesis_invalid`，并确认只归档一条 `REPLY`。

## 验收标准

- 页面证据模式的首个系统提示中不存在裸 `{"opinion":"..."}` 要求。
- 普通直调的对外行为没有变化。
- 多司调用中，每个司均可独立使用一次格式纠正机会。
- 严格证据校验没有放宽，缺少事实依据的输出不能作为成功司议进入后续流程。
- 离线测试与 harness 通过。
- 至少一次真实单司页面测试和一次真实多司页面测试完成；若模型或外部证据服务本身
  不可用，应以对应稳定错误码区分，不能再归因为输出契约冲突。

## 风险与控制

- 模型即使收到唯一契约仍可能生成不合规事实声明。控制方式是保留严格校验和稳定降级，
  不将本修复定义为“所有模型响应必然成功”。
- 按节点增加格式纠正可能提高多司流程的模型调用数。控制方式是每司最多一次、共享总时限
  不变，并通过页面实测观察耗时。
- 提示构造接口调整可能影响测试或内部调用方。控制方式是显式模式、默认保持直调兼容，
  并搜索全部调用点做回归验证。

## 补充设计：规范性义务表达

真实页面复测确认双重输出契约已消失，但技术司、质量司返回的合法 `READY` 信封仍可能
被降级。原始模型响应中的建议使用了“必须”“不得”“未经……不得”等明确义务表达，
而现有规范性语句识别器只接受“建议”“应当”“应该”“宜”“须”“需要”等前缀，
从而把合法的规范性条款误判成未声明的事实依赖。

本次补充只扩展明确的规范性义务前缀：

- 接受以“必须”“不得”“不应”“不应当”“严禁”“禁止”开头的条款；
- 接受以“未经……不得”构成的完整禁止性条款；
- 继续要求条款从这些规范性标记起始，不把任意陈述句视为建议；
- 继续拒绝包含“当前”“最新”“今日”“数据显示”“已完成”等观察性或时点性断言；
- 继续拒绝以“因为”“由于”“鉴于”“根据”“依据”包装事实判断的条款；
- 不改变证据 ID、事实声明、用户提供事实、调查或失败关闭规则。

回归测试必须同时证明新接受项与原有拒绝项，避免通过扩大正则把客观事实误放行为
`NOT_REQUIRED`。真实页面验收继续使用同一份多司规范性旨意；技术司和质量司不得再仅因
上述义务前缀产生 `model_synthesis_invalid`。
## 最终设计：结构化规范性声明

真实页面与整体验收证明，依靠自由文本前缀判断规范性条款并不可靠：同一建议可使用标题、
编号、祈使句或义务句表达；继续增加中文正则会同时产生事实漏放和合法建议误拒。

证据模式的 `READY` 契约改为结构化声明：

- `factual_claims` 中每条声明可以覆盖 `opinion` 中一个或多个连续实质条款；全部声明按顺序
  展开后必须完整覆盖 `opinion`，不得缺失、多余、重排、重叠或重复；
- 纯规范性条款使用 `basis: "NORMATIVE"`，且
  `evidence_ids: []`、`fact_key/category/subject: null`；
- `fact_basis: "NOT_REQUIRED"` 允许包含 `NORMATIVE` 和 `USER_PROVIDED` 声明，但不允许
  `ARCHIVED/CITED` 声明；
- `fact_basis: "CITED"` 的现有证据 ID、绑定字段和采用集合规则保持不变；
- 正常非空 opinion 不再允许空 `factual_claims`，也不再依赖“建议/必须/不得”等句首词
  推断规范性。

`NORMATIVE` 是结构声明，不是事实豁免。验证器仍拒绝包含以下信号的规范性声明：

- 当前、目前、最新、今日、昨日、实时等时点观察；
- 已完成、已发布、显示、表明、据悉等观察或认识断言；
- 客观指标与观察值的组合，包括报价、营收、利润、人口、状态、数据等；
- “当前三个项目”等时点与明确数量组合；
- “根据最新公告”“依据当前数据”等事实来源包装。

允许纯粹的目标值或规则阈值，例如“建议将覆盖率目标设为 80%”，但不得把观察到的值表述为
建议。所有声明仍须按顺序完整覆盖 opinion 条款，防止模型把未声明事实藏在自由文本中。

证据系统提示必须给出含 `NORMATIVE` 声明的 `READY/NOT_REQUIRED` 完整示例，并明确禁止
对正常非空 opinion 返回空声明列表。裸意见纠正和 resumed correction 使用相同契约。

本设计不改变对外 API、`BureauOpinion`、部议、丞相总结、调查预算、证据采用或史馆归档
格式；结构化声明只存在于司级模型与证据验证器之间。
