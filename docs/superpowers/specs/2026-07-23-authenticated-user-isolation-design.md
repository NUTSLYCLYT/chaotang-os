# 账号、登录保护与用户数据隔离设计

## 目标与范围

为当前公开欢迎页和登录前 UI 接入真实本地账号体系。用户可开放注册，以唯一用户名或邮箱加密码登录，并能退出。`/study` 与 `/shiguan` 是受保护页面；奏折和史馆的所有读写、查询、统计、召回与复盘只针对当前认证用户。

本设计不提供团队共享、管理员访问、邮箱验证、密码找回、第三方登录或生产部署。历史 SQLite 数据没有所属用户，因此继续保留在本地，但不向任何账号查询结果中返回。

## 选定方案

认证权威在 FastAPI 后端。后端在 SQLite 中保存账号和可撤销会话记录，密码以独立盐值和安全哈希保存。客户端永远不取得密码哈希或可由 JavaScript 读取的身份凭证。

Next.js 负责同源 BFF：注册、登录和退出 Route Handler 调用后端认证接口。成功登录时，Route Handler 只在同源响应中写入 `HttpOnly`、`Secure`（生产环境）和 `SameSite=Lax` 的会话 Cookie。受保护的 Next Route Handler 从 Cookie 取得会话凭证，服务端转交给 FastAPI；浏览器直接请求的仍是同源 `/api/*`，不暴露后端地址。

后端每个受保护接口统一解析会话，得到 `current_user` 后将其 `id` 传入领域服务。领域层不接受来自客户端的 owner 字段；创建操作写入认证用户 ID，读取、统计、召回、更新和自动归档都以该 ID 为强制过滤条件。前端路由在服务端优先检查会话，未登录访问业务页面跳至 `/login?next=...`；客户端在会话失效时展示明确提示并回到登录页。

## 数据与接口契约

SQLite 新增用户和会话记录：用户含不可变 ID、唯一用户名、唯一规范化邮箱、密码哈希、创建时间；会话含随机不可预测标识、用户 ID、创建/到期/撤销时间。会话标识本身不携带用户信息，并可被服务端立即撤销。

史馆记录和自动归档的奏折记录增加非客户端可控的 `owner_user_id`。为了避免将旧数据误分配，旧记录保留空归属并被所有用户查询过滤掉。所有史馆 HTTP 端点和丞相端点要求认证；健康检查、公开欢迎页、注册和登录端点保持公开。

认证端点仅返回必要的当前用户公开资料。无效凭证统一返回未认证结果；访问其他用户 ID、伪造 owner 参数或已撤销会话均不会绕过后端过滤。前端的注册、登录、退出和“当前用户”接口只传输必要字段，错误文案不泄露密码哈希或账号枚举细节。

## 页面行为

注册页面继续使用已有字段，并在成功后建立会话、跳到有效的 `next` 目标或 `/study`。登录页接受用户名或邮箱，并在成功后按同一规则跳转。邀请码在开放注册模式下仅作为可选展示来源，不用于授权判定。退出清除同源 Cookie，并要求后端撤销会话。

`/study` 和 `/shiguan` 未登录时不渲染业务数据。登录后，页面使用现有 BFF 路由读取和写入当前用户范围内数据；所有后端拒绝和会话失效都有可理解的前端状态，且不会把网络错误误报为未授权。

## 安全与错误处理

密码永不记录、回显或写入前端状态外的存储；Cookie 不可由 JavaScript 读取。登录失败使用统一凭证错误，注册冲突返回可操作但不过度泄露的提示。数据库约束保证用户名和邮箱唯一，写入在事务内完成。会话比较使用安全比较并检查到期和撤销状态。

新增认证配置必须有安全的开发默认策略和生产显式密钥/安全 Cookie 配置；真实密钥不得提交。若认证存储或配置不可用，受保护端点安全失败，不返回未过滤数据。

## 验证

测试先覆盖密码哈希、账户唯一性、会话创建/撤销/过期、认证依赖、所有领域查询的 owner 过滤和旧数据不可见。接口测试覆盖注册、用户名与邮箱登录、退出、缺失/伪造/撤销会话、跨用户读写拒绝。前端测试覆盖 BFF Cookie 行为、路由保护和会话失效呈现。

最终使用两名独立账号执行端到端流程：A 创建奏折和档案后，B 看不到、不能读取或修改；A 退出后不能继续访问受保护路由。运行前后端 lint、typecheck、测试、构建、harness 和差异检查；不进行真实模型调用。
