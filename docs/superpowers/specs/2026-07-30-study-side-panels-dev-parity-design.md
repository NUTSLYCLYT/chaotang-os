# Study 左右侧栏 Dev 视觉一致性设计

## 目标

让 `/study` 的丞相左侧栏与钦天监右侧栏在视觉和基础交互上与 `dev`
分支的上书房左右栏保持一致，同时保留当前分支已经接入的真实数据、正式推演、
触发器复核和实时问询能力。

“保持一致”覆盖：

- 面板定位、宽度、高度、层级和开合动效；
- 暗色玻璃背景、金色描边、阴影和分隔线；
- 人物横幅、身份文案、关闭入口和标题层级；
- 内容区内边距、滚动方式、卡片圆角、描边、悬停和选中态；
- 底部问询区、输入框、发送按钮以及默认、悬停、聚焦、禁用状态；
- 桌面端和移动端的尺寸及安全区行为。

不迁移：

- `dev` 的静态教程数据；
- `dev` 的旧聊天请求或模拟回复；
- `dev` 的旧任务选择、裁决或执行逻辑；
- 任何绕过当前 decree/evidence flow governance baseline 的行为。

## 选择的方案

采用“移植视觉骨架，保留业务内容”的方案。

当前 `StudySideDrawers` 继续负责开合状态、左右方向和遮罩层；新增或整理共享的
侧栏视觉壳，使丞相与钦天监使用同一套容器、人物栏、内容滚动区和底部问询区
约束。业务组件只向壳内提供内容，不自行定义第二套面板尺寸或焦点样式。

不直接复用 `dev` 整个业务组件，因为这会把静态教程和旧交互一起带入当前实现。
也不只做近似 CSS 覆盖，因为 DOM 层级不一致会继续造成尺寸、滚动和焦点态漂移。

## 组件边界

### StudySideDrawers

- 负责 fixed 定位、左右方向、显示状态、遮罩、层级和响应式宽度。
- 采用与 `dev` 相同的顶部和底部边界，不再用局部补丁修正遮挡。
- 左右面板只在方向和业务内容上不同，外壳尺寸完全一致。

### Shared advisor shell

- 承载玻璃面板、人物横幅、身份、副标题、关闭按钮和分隔线。
- 提供单一可滚动内容区与固定底部问询区。
- 暴露稳定的 header、body、footer 插槽，不感知丞相或钦天监的数据契约。

### Chancellor / Qintian content

- 丞相继续渲染当前建议、证据状态和真实问询能力。
- 钦天监继续渲染当前雷达摘要、正式三情景推演、到期触发器复核和真实聊天。
- 复杂内容可在滚动区内展开，不改变外壳高度或把输入区推出可视区域。

## 视觉规则

- 颜色、透明度、描边、圆角、字体、间距和阴影以 `dev` 对应组件为唯一来源。
- 输入控件不得依赖浏览器默认边框；默认、`:hover`、`:focus` 和
  `:focus-visible` 均显式定义，并与 `dev` 一致。
- 关闭按钮和标题必须位于人物横幅安全区内，在所有支持宽度下不可被全局导航遮挡。
- 内容滚动条只出现在 body；人物栏和底部问询区保持稳定。
- 移动端面板占满可用屏宽，但沿用 `dev` 的内部间距和触控目标尺寸。

## 数据与错误处理

本次不改变 API 契约和状态机。真实 provider 不可用时继续明确展示服务不可用，
不得伪造判断。加载、空状态、错误和正式推演结果只改变 body 内容，不改变共享壳。

## 测试与验收

自动化测试先锁定以下回归：

1. 左右侧栏使用同一共享视觉壳和对应方向。
2. header、滚动 body、固定 footer 的结构存在。
3. 输入框默认和获取焦点时都不出现非 `dev` 边框或轮廓。
4. 移动端宽度、桌面端宽度、顶部与底部边界符合 `dev`。
5. 当前丞相和钦天监的真实业务入口、状态与回调仍可工作。

实现后运行前端相关单测、全量测试、类型检查、lint 和 build，并在
`http://127.0.0.1:3010/study#qintian` 实际检查：

- 左右面板分别打开时的截图；
- 标题和关闭按钮无任何遮挡；
- 输入框默认、悬停和聚焦状态；
- 内容较长时只有中间 body 滚动；
- 钦天监真实问询和正式推演入口仍存在。

## 非目标

- 本次不重新设计钦天监信息架构；
- 不新增业务接口、预测能力或数据源；
- 不修改中央卷轴和底部御前工作台；
- 不把视觉一致性扩展到 `/study` 之外的页面。
