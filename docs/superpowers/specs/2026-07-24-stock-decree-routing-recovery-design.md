# 股票行情旨意路由与证据协议恢复设计

## 状态

已由用户于 2026-07-24 确认方向，待书面规格复核后实施。

## 问题

同一句“帮我看看比亚迪的股票价格”在真实 DeepSeek 调用中出现了两种错误路径：

- 被判为多部门事项并进入军机处；
- 被判为单部门事项但错误进入吏部。

错误进入吏部后，司级模型没有按协议返回 `NEEDS_DATA`，而是直接生成依赖外部
行情的意见。证据协议以 `unsupported_factual_dependency` 拒绝该无证据结论，
异常最终被 HTTP 层安全映射为 `model_unavailable`，页面显示“丞相暂时无法给出回奏”。

腾讯自选股 MCP、OAuth 和分钟行情 smoke 均已独立验证成功。史馆旧库未迁移会产生
降级警告，但不是本次 502 的直接原因。

## 方案比较

### 方案 A：只增强提示词

在丞相和户部提示词中加入股票示例。改动最小，但真实模型已经表现出非确定性，
无法保证同一句旨意稳定进入户部投资司，因此不采用。

### 方案 B：完全确定性关键词路由

所有部门和司级选择都由关键词表决定。结果稳定，但会取代现有模型分流，并把通用
业务路由退化成持续增长的关键词规则，因此不采用。

### 方案 C：模型分流加窄范围确定性护栏，并允许一次协议纠正

保留模型作为通用分流器，仅对明确的证券行情查询施加可审计护栏；同时增强投资司
能力描述，并在模型把缺失外部事实误写成 `READY` 时进行一次受限格式纠正。
这是已确认并将实施的方案。

## 设计

### 明确行情意图

新增一个小型、无供应商依赖的行情意图判定函数。只有文本同时表达证券标的和行情
查询时才命中，例如“股票/股价/证券/行情/stock/share/ticker”与
“价格/现价/报价/多少/quote/price”组合出现。单独出现“投资”“价格”或公司名称
不会命中，避免扩大路由范围。

### 丞相路由护栏

丞相模型仍先给出通用路由结果。若原始旨意明确命中行情意图，则在进入 LangGraph
分支前把有效路由规范化为：

```json
{
  "route_type": "single",
  "departments": ["户部"]
}
```

模型产生的原始说明不作为事实依据；规范化后的说明明确记录这是证券行情查询，
便于审计。非行情旨意完全保留现有模型路由行为。

### 户部投资司护栏

投资司能力描述增加“证券行情、股票价格、市场数据、估值观察”。当户部收到明确
行情旨意时，投资司必须出现在所选司列表中，并置于第一位；模型仍可在确有必要时
选择其他户部司，但不得把投资司漏掉。非行情旨意保持现有司级选择结果。

### 一次受限协议纠正

司级证据协议首次收到 `READY`，但仅因
`unsupported_factual_dependency` 被拒绝时，追加一条静态纠正消息并重新调用同一
司级模型一次。纠正消息只说明：

- 当前意见依赖尚未提供的外部事实；
- 不得猜测或继续输出 `READY`；
- 必须按既有 schema 返回 `NEEDS_DATA`。

纠正不适用于 `model_unavailable`、JSON/schema 错误、非法证据 ID、证据绑定失败、
第二次 `NEEDS_DATA` 或调查恢复后的无效结果。纠正后仍不合规时继续失败关闭，不做
第三次尝试。纠正成功后沿用现有调查预算、30 秒单次外部调用上限和一次调查/恢复
流程。

单部门最坏模型调用上限由 11 次增加为 12 次，仅在上述协议纠正被触发时发生。

## 数据流

```text
旨意
  → 丞相模型通用分流
  → 明确行情意图护栏（户部 single）
  → 户部模型选择司
  → 行情意图护栏（投资司优先）
  → 投资司首次意见
      → 合规 NEEDS_DATA：直接调查
      → 错误 READY/无外部证据：纠正一次后进入调查
  → 锦衣卫按史馆优先、外部 MCP 补充取得行情
  → 投资司恢复并引用证据
  → 户部补充、丞相回奏
```

## 错误与安全边界

- 不绕过现有证据绑定、采纳和新鲜度校验。
- 不把任何腾讯、WeStock、证券代码或 URL 写入通用路由核心。
- 不扩大 MCP 工具权限，仍为只读查询。
- 未命中明确行情意图时，不改变现有六部和三十九司路由。
- 纠正消息不包含模型原始响应、异常文本、凭据或证据正文。
- 史馆迁移问题单独处理，不与本次修复捆绑。

## 测试与验收

先写失败测试，再写生产代码：

1. 比亚迪股票价格稳定规范化为 `single + 户部`。
2. 普通“产品价格”“人员投资培训”等文本不误命中行情护栏。
3. 户部行情旨意始终首先包含投资司；普通户部旨意不变。
4. 首次无证据 `READY` 被纠正一次，随后 `NEEDS_DATA` 能进入现有调查流程。
5. 纠正仍失败、模型不可用、非法证据绑定时继续失败关闭且不重复调用。
6. 使用假模型和假协调器完成端到端离线回归，证明处理路径包含
   `户部 → 投资司 → 锦衣卫（调查）`。
7. 运行相关测试、后端全量 pytest、Ruff、四组 harness 和敏感信息扫描。
8. 离线门禁通过后，重启本地服务，用真实模型和只读腾讯 MCP 重试同一句旨意；
   验收页面不再显示通用 502，调查证据数大于零并保留真实行情 `as_of`。

## 非目标

- 不修复或迁移史馆旧数据库。
- 不建设通用规则引擎或替换所有模型路由。
- 不新增证券交易、持仓、自选股修改或其他写工具。
- 不对所有证据协议错误做自动重试。
