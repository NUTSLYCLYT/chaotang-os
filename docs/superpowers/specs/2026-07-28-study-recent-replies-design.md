# 上书房最近三次下旨回奏设计

## 背景与目标

上书房左侧抽屉的上半区当前显示当前页面会话内存中的下旨尝试，刷新后清空，
且记录不是史馆已归档的权威回奏。用户已确认改为展示当前账号最近三条已归档
`REPLY`，并允许在上书房内点击查看完整回奏。

目标是复用现有史馆只读契约，不新建后端业务入口，不复制或推断回奏数据。

## 数据来源与边界

- 左侧抽屉打开时，通过现有受认证同源 BFF 请求
  `GET /api/shiguan/archives?type=REPLY&limit=3`。
- 后端继续按 `owner_user_id` 限定当前账号，并按
  `created_at DESC, id ASC` 返回确定性的最近三条。
- 页面初次加载和模块导入不发起请求；只有用户主动打开左侧抽屉才读取。
- 不再把当前页面内存中的成功或失败尝试作为“最近下旨记录”展示。
- 不迁移 `dev` 的旧数据、模拟档案或旧 API，不修改 ADR 0028。

## 交互设计

左侧抽屉上半区标题改为“最近三次下旨回奏”。

每条折叠记录默认展示：

- 原旨摘要；
- 回奏时间；
- 参与部门；
- 可辨识的“查看回奏”操作。

点击记录后在原列表位置展开，展示该史馆 `REPLY` 已有的真实字段：

- 原旨正文；
- 办理过程；
- 参与部门；
- 回奏结论；
- 回奏时间；
- 责任主体。

再次点击同一条记录收起。一次只展开一条，避免 300px 面板被多个长回奏同时
占满。展开内容独立滚动，不遮挡抽屉关闭操作或下半区丞相咨询。

## 状态与错误处理

- `idle`：尚未打开左侧抽屉，不发请求。
- `loading`：显示明确加载文案，保留关闭操作。
- `ready`：展示最多三条真实回奏。
- `empty`：显示“尚无已归档回奏”，不伪造示例。
- `error`：显示脱敏错误与“重试”操作；401 复用现有安全登录跳转。
- 新下旨成功后仅将列表标记为过期，不在后台自动读取；用户下一次打开左抽屉时
  刷新。若抽屉已打开，保持当前内容，避免突然替换用户正在阅读的回奏。

## 组件与数据流

- 新增上书房专用的最近回奏请求/状态模块，负责构造固定查询、严格解析史馆
  envelope、维护加载状态与选中档案 ID。
- `StudyClient` 只负责记录“成功下旨后列表已过期”，不保存史馆档案副本。
- `StudySideDrawers` 接收最近回奏状态和打开/重试/选择回调，负责渲染，不直接
  访问后端。
- 继续复用现有 `/api/shiguan/archives` Route Handler 和史馆档案字段定义，
  不新增后端端点。

## 验证

- 纯函数测试锁定固定查询为 `type=REPLY&limit=3`，并验证严格响应解析。
- 状态测试覆盖首次打开读取、重复打开不重复读取、成功下旨后失效、下次打开刷新、
  401、空结果、错误与重试。
- UI 源码守卫覆盖最多三条、展开/收起、真实回奏字段、加载/空/错误状态，以及
  下半区丞相咨询和右侧空面板保持不变。
- 前端运行 lint、typecheck、全量测试与 production build；仓库运行 harness 和
  `git diff --check`。

## 非目标

- 不增加历史分页、搜索、筛选、编辑、删除或复盘操作。
- 不在上书房复制史馆的完整三栏页面。
- 不展示失败下旨尝试，也不把咨询对话当作下旨记录。
- 不触发真实下旨、模型调用、锦衣卫调查或史馆写入。
