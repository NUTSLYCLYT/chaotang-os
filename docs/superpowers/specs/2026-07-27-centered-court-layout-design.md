# 朝堂页面居中与中宽屏布局修复设计

## 背景

迁入的沉浸式朝堂页面在超宽屏和部分中等宽度视口下存在两类布局问题：

- 共享内容容器限制为 `1600px` 后仍按网格起始边对齐，视口超过 `1600px` 时整页向左偏移。
- 军机处、部院部门/衙署和仕官台使用固定三栏最小宽度，但响应式断点低于三栏实际所需宽度，导致约 `1080px` 至 `1260px` 区间出现右侧裁切或视觉偏移。

## 目标

- 所有使用 `ImmersiveCourtShell` 的页面在超宽屏中保持水平居中。
- 军机处、部院部门/衙署和仕官台在三栏无法完整容纳前切换为较窄布局。
- 保持宽屏现有三栏结构、视觉风格、数据流和交互行为不变。
- 不修改后端、路由契约、业务逻辑或其他 Agent 正在处理的文件。

## 方案

### 共享容器

在 `ImmersiveCourtShell.module.css` 的 `.content` 上增加水平自动外边距，使受 `max-width` 约束的网格项在可用区域内居中。继续保留 `width: min(100%, 1600px)`，不改变页面最大内容宽度。

### 三栏响应式断点

将下列布局的三栏收缩断点调整到能覆盖其固定列宽、间距和场景内边距的安全区间：

- `JunjichuScene.module.css`
- `ministries.module.css`
- `ShiguanWorkspace.module.css`

统一采用 `@media (max-width: 1280px)` 作为切换点。宽于该值时保留当前三栏；等于或窄于该值时使用文件中已有的两栏或单栏降级规则，不引入新的布局模式。

## 测试

新增或扩展前端源码布局契约测试，直接验证：

- 共享 `.content` 同时具有 `1600px` 最大宽度和水平居中规则。
- 三个固定三栏布局均在不低于其最小安全宽度的断点前触发降级。

按 TDD 顺序先运行测试确认 RED，再修改 CSS 并确认 GREEN。随后运行前端定向测试、完整测试、lint、typecheck 和 build，并在本地浏览器中检查超宽屏及中等宽度视口。

## 非目标

- 不重做大殿、六部总览或上书房的视觉权重。
- 不强制将所有固定列改为 `minmax()` 弹性列。
- 不改变页面内容、认证状态或 API 请求。

## 验收标准

1. 超过 `1600px` 的视口中，共享内容区域左右留白相等。
2. 约 `1100px` 至 `1280px` 的视口中，目标三栏页面不再发生横向裁切。
3. 宽屏三栏页面的列宽和信息层级保持原样。
4. 前端测试、lint、typecheck 和 build 全部通过。
