# 军机处全功能三栏实施方案

- 版本：v1 · 2026-07-09
- 对应产品文档：`frontend/dev/notes/军机处-全功能三栏承载方案-2026-07-09.md`
- 实施范围：`/command-center` 默认军机处作战页
- 核心约束：不改变现有左 / 中 / 右三栏结构，不新增顶层页面，不把军机处改成 dashboard
- 中栏形态：中央主工作面必须继续显示卷轴，`EdictStage` 是主卷核心，不改成普通卡片或表格式面板
- 实施目标：把接案、路由、会审、蜂群、质量门、补证、裁决、治理等待、归档复盘全部落到军机处页面，并保证每个功能都有真实数据来源、降级标识和验收口径

---

## 0. 工程结论

军机处当前已经有三栏壳、`BattleStream`、`taskDetail`、上书房 `taskStatus`、六部表态回填和底部命令轴，但这些能力仍散在 `page.tsx` 里，且缺少页面级状态机、质量门、蜂群产线、治理等待和史馆飞轮。

本次实施不要先做视觉大改，先做四件事：

1. 新增 `JunjichuPageView` 适配层，统一合并 `taskDetail`、SSE、上书房状态、蜂群运行、归档状态。
2. 把 `page.tsx` 里的左栏 / 中栏 / 右栏拆成军机处专属组件，但继续挂在 `ShangshufangLayoutShell` 三栏槽位里；中栏继续以卷轴 `EdictStage` 承载主卷。
3. 逐步接入 `/api/swarm-runs`、质量门、governance proceed、archive search / feedback。
4. 用状态机控制按钮、空态、阻断态和可裁决态，禁止 JSX 里继续堆散乱 fallback。

## 3. 数据模型

### 3.1 核心类型

```ts
export type JunjichuStage =
  | 'empty'
  | 'accepted'
  | 'routing'
  | 'deliberating'
  | 'evidence_blocked'
  | 'quality_ready'
  | 'decision_written'
  | 'archived';

export type JunjichuSourceLabel =
  | 'LIVE'
  | 'LIVE_SWARM'
  | 'MIXED'
  | 'FALLBACK'
  | 'DEMO';

export interface JunjichuPageView {
  caseIdentity: CaseIdentityView;
  stage: JunjichuStage;
  sourceLabel: JunjichuSourceLabel;
  routing: RoutingView;
  summons: SummonView[];
  evidence: EvidenceView;
  stream: StreamView;
  council: CouncilView;
  swarmRun: SwarmRunView | null;
  gate: QualityGateView;
  governance: GovernanceGateView;
  decision: DecisionView;
  archive: ArchiveView;
  actions: JunjichuActionPolicy;
}
```

### 3.2 来源合并优先级

右栏六部表态和中栏会审结论按以下顺序合并：

1. SSE `minister.opinion` / `council.aggregated`
2. `taskDetail.result.merge.contributors`
3. `shangshufangTaskStatus.review.ministry_outputs`
4. 前端本地 `buildCommandCenterMinistryBrief`

任何来自第 4 层的内容必须显示 `FALLBACK` 或 `MIXED`，不得标成真会审。

### 3.3 阶段推导

`deriveJunjichuStage(view)` 规则：

| 条件 | 阶段 |
| --- | --- |
| 无 `taskId` 且无本地决策意图 | `empty` |
| 有 `taskId` 但未拿到任何会审 / 路由 / 蜂群数据 | `accepted` |
| 有 route plan 或召集名单，尚未开始输出意见 | `routing` |
| SSE 正在流、蜂群 running、六部意见未齐 | `deliberating` |
| `gate.status === blocked` 或 `evidence.blocking === true` | `evidence_blocked` |
| `gate.status === passed / warning` 且未裁决 | `quality_ready` |
| 已写入 decision / memorial | `decision_written` |
| 已归档 | `archived` |

页面上所有主按钮只读 `view.actions`，不在组件里重新判断。

## 5. 组件落点

### 5.1 左栏 `JunjichuLeftRail`

左栏回答“为什么开军机处”。

组件顺序：

1. `CaseIdentityPanel`
2. `RoutingReasonPanel`
3. `SummonListPanel`
4. `EvidenceQueuePanel`
5. `GovernanceGatePanel`

实现要求：

- 无 `taskId` 时只展示接案解释和入口，不铺满一堆 0 状态。
- `RoutingReasonPanel` 展示 direct / junjichu、推荐部门、弃权部门、路由依据。
- `EvidenceQueuePanel` 若 blocking，必须置顶到左栏可视区。
- `GovernanceGatePanel` 若 waiting，必须显示“等待放行后继续什么”。

### 5.2 中栏 `JunjichuCenterWorkSurface`

中栏回答“现在能不能裁”。

中栏必须保留卷轴。视觉主位仍是 `EdictStage`，它承载案由、丞相拆解、会审摘要、风险、缺证、裁决建议和下一步。`BattleStream`、`QualityGateStrip`、`VerdictActionBar` 都是卷轴下方或旁侧的工作层，不得替代卷轴本体。

组件顺序：

1. `CaseSpine`
2. `EdictStage` 卷轴主卷
3. `BattleStream` 或 stream completed replay
4. `QualityGateStrip`
5. `VerdictActionBar`

实现要求：

- `QualityGateStrip` 位于 `BattleStream` 下方、裁决按钮上方。
- `EdictStage` 在所有阶段都要存在：空态显示待接案卷轴，接案后显示真实主卷，阻断时在卷轴内写明阻断原因。
- `gate.status === blocked` 时禁用“采纳”，主按钮切到“打回补证 / 发起复核 / 重跑蜂群”。
- `gate.status === warning` 时允许采纳，但弹出或内联要求填写人工确认理由。
- 无真实 `review_id / swarm_run_id / quality_result` 时，裁决动作标注“仅记录意见”。

### 5.3 右栏 `JunjichuRightRail`

右栏回答“谁反对、谁缺证、蜂群跑到哪”。

组件顺序：

1. 战情数字
2. 六部表态
3. 冲突与风险
4. `SwarmRunPanel`
5. `ArchiveFlywheelPanel`

实现要求：

- 战情数字只显示计数，不在空态展开空卡片。
- 六部表态每张卡必须有 `SourceLabelBadge`。
- `SwarmRunPanel` 只有拿到真实 `swarm_run_id` 后才显示进度和 brief。
- `ArchiveFlywheelPanel` 在未裁决前灰显，不允许把未裁决案标成 approved。

## 6. 动作策略

新增文件：`frontend/src/features/command-center/junjichu/model/action-policy.ts`

统一产出：

```ts
export interface JunjichuActionPolicy {
  issueEdict: ActionState;
  unfoldCase: ActionState;
  summonCouncil: ActionState;
  startSwarm: ActionState;
  archive: ActionState;
  adopt: ActionState;
  requestEvidence: ActionState;
  recheck: ActionState;
  reject: ActionState;
  followup: ActionState;
  proceed: ActionState;
}
```

`ActionState`：

```ts
export interface ActionState {
  enabled: boolean;
  label: string;
  disabledReason?: string;
  requiresReason?: boolean;
  requiresHumanConfirmation?: boolean;
}
```

关键规则：

- `empty`：只启用发圣旨。
- `deliberating`：禁用采纳，允许追问、暂停或注入补证。
- `evidence_blocked`：禁用采纳，启用补证、复核、重跑蜂群。
- `quality_ready + passed`：启用五键裁决。
- `quality_ready + warning`：启用采纳，但要求人工确认理由。
- `decision_written`：启用转史馆。
- `archived`：启用查看归档、写复盘、知识回流。

## 7. 分阶段实施

### Phase 1：拆 view model 和三栏组件，不接新后端

目标：

- 新增 `JunjichuPageView`、`derive-stage`、`action-policy`。
- 从 `page.tsx` 拆出左栏、中栏、右栏组件。
- 保留现有 `taskDetail`、`BattleStream`、`shangshufangTaskStatus`。
- 把现有本地 fallback 全部打上来源标签。

改动文件：

- `frontend/src/app/(dashboard)/junjichu/page.tsx`
- `frontend/src/features/command-center/junjichu/model/*`
- `frontend/src/features/command-center/junjichu/hooks/useJunjichuPageView.ts`
- `frontend/src/features/command-center/junjichu/components/*`

验收：

- 无 `taskId`：页面只出现一个待接案主卷和必要入口。
- 中栏始终显示卷轴，不出现普通卡片替代卷轴的版本。
- 有 `taskId`：左栏可见案由 / 路由 / 召集，右栏可见六部 / 风险，底部按钮按阶段启停。
- 页面仍是三栏结构，`view=council` 和 `view=cases` 不受影响。

### Phase 2：接入蜂群产线和质量门

目标：

- 接入 `/api/swarm-runs` 全套 client。
- 右栏新增 `SwarmRunPanel`。
- 中栏新增 `QualityGateStrip`。
- 裁决按钮受 `quality_result` 约束。

改动文件：

- `frontend/src/features/command-center/junjichu/api/swarm-runs.ts`
- `frontend/src/features/command-center/junjichu/hooks/useSwarmRun.ts`
- `frontend/src/features/command-center/junjichu/components/SwarmRunPanel.tsx`
- `frontend/src/features/command-center/junjichu/components/QualityGateStrip.tsx`
- `frontend/src/features/command-center/junjichu/model/action-policy.ts`

验收：

- 启动 deep / live swarm 后右栏显示真实 `swarm_run_id`。
- `quality_blocked` 时“采纳”禁用且给出原因。
- `retry` 后页面展示新的 run id 或明确错误。

### Phase 3：治理等待和补证闭环

目标：

- 页面能展示 proceed / approval / OpenClaw 等待态。
- 左栏出现 `GovernanceGatePanel`。
- 中栏 blocked 状态给出明确补证动作。

改动文件：

- `frontend/src/features/command-center/junjichu/api/governance.ts`
- `frontend/src/features/command-center/junjichu/components/GovernanceGatePanel.tsx`
- `frontend/src/features/command-center/junjichu/components/EvidenceQueuePanel.tsx`
- `frontend/src/features/command-center/junjichu/components/VerdictActionBar.tsx`

验收：

- 后端等待放行时，页面明确显示“等待圣裁 / 放行后继续会审”。
- 点击 proceed 后状态能继续推进或显示后端错误。
- 缺证阻断不会被藏在右栏小字里。

### Phase 4：史馆飞轮

目标：

- 右栏接入相似旧案、归档、复盘和知识回流。
- 裁决后显示转史馆主动作。
- 已归档案进入 `archived` 阶段。

改动文件：

- `frontend/src/features/command-center/junjichu/api/archive.ts`
- `frontend/src/features/command-center/junjichu/hooks/useArchiveFlywheel.ts`
- `frontend/src/features/command-center/junjichu/components/ArchiveFlywheelPanel.tsx`

验收：

- 未裁决案不能显示“已归档 approved”。
- 已裁决案能看到转史馆入口。
- 归档后能看到 retrospective / knowledge feedback 状态。

## 12. 第一刀建议

第一刀不要碰视觉，不接新接口，只做 `JunjichuPageView`。

原因很简单：军机处现在最大的问题不是缺卡片，而是每块卡片各自判断“我有没有数据”。先把所有数据收成一个页面级事实源，后面的质量门、蜂群产线、补证、归档都会顺很多。
