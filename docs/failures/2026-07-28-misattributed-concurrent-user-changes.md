# 并行用户改动被错误归因并回退

## Summary

Codex 在自动交付监控期间看到新的工作区改动，错误地把它们全部归因于 Claude runner，并回退了用户在同一共享工作区并行进行的修改及两份未跟踪文档。用户指出归因错误后，Codex依据删除前保存的 diff 和输出快照恢复改动。

## Root Cause

根因是所有权判断只比较了“本回合预检时的干净状态”和“稍后出现的改动”，却没有验证这些改动来自哪个进程或任务。共享工作区允许用户和其他任务在当前任务运行期间写入；文件出现时间晚于预检并不能证明它由当前 runner 创建。Codex 又在未向用户确认所有权的情况下执行回退，违反了“保留用户已有改动”和不确定时停止询问的规则。

## Prevention

- 发现允许路径外改动时先暂停当前写进程，但只读收集文件时间、进程日志、任务日志和用户并行活动证据。
- 只有日志明确记录当前任务写入，或用户确认所有权时，才允许回退；无法证明时必须把文件视为用户改动并询问。
- 自动交付开始后记录自身写入文件清单，并与 `git status` 的新增项做来源对账，不以时间先后替代来源证明。
- 涉及未跟踪文件时优先复制到系统临时备份，再考虑任何删除操作。

## Detection

`node scripts/check_harness.mjs` 可验证失败记录格式和仓库基线，但不能判断共享工作区文件所有权。自动检测应在 product-flow runner 中记录每次文件写入的规范化路径，并在 Codex 准备回退时与该清单核对；没有可验证来源时必须人工向用户确认。现阶段的人工门禁是：任何非当前任务允许路径的改动不得仅凭 `git status` 或出现时间自动回退。
