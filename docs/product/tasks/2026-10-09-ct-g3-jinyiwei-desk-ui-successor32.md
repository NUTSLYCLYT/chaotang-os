# 任务：锦衣卫案牍台 UI 完善（successor32）

## Status

Ready

## Product Definition

补齐锦衣卫只读案牍台的三个验收断点：让已批准离线新闻快照可以在浏览器内选择并预览；让全球覆盖和来源读取失败时明确呈现错误与重试；让区域点位可以回到对应调查案卷，同时保持区域级、证据优先和只读边界。

## Affected Modules

- 模块：锦衣卫全球证据覆盖、离线新闻快照预览、案卷台导航与可访问性。
- 允许路径：见 `.harness/approvals/CT-G3-JINYIWEI-DESK-UI-SUCCESSOR32-20261009.json` 的 `productPaths`。
- 前端：同源 BFF 文件导入、覆盖请求错误状态、地图点位到案卷选择、无障碍语义和相应源代码契约测试。

## Technical Plan

1. 在新闻预览面板中增加 JSON 文件选择器，仅把用户选择的离线快照提交到现有同源 `/api/jinyiwei/news` BFF；显示加载、格式错误和后端拒绝状态，不新增联网或抓取能力。
2. 为 coverage/feed 并行读取增加可见失败状态和重试动作，避免错误时伪装成“正在读取”。
3. 将地图容器改为可包含交互控件的区域语义；调查 ID 使用键盘可操作控件回到案卷台并触发既有详情读取链路。
4. 保持地图只展示证据声明的区域名称，不推断坐标，不改变史馆采纳链路，不增加后端 API。

## Delivery Constraints

- 只修改 manifest 指定的产品路径；审批文件和任务文档单独提交。
- 新闻输入必须是用户主动选择的本地 JSON；不启用外网、不跟随未知 URL、不绕过访问控制。
- 所有错误状态必须可理解、可重试；所有新增交互支持键盘焦点和只读边界。

## Acceptance Criteria

- [ ] 用户可选择符合现有合同的离线新闻 JSON，并在成功后看到条目、事件、拒绝原因和不得推断说明。
- [ ] 文件解析失败、BFF 拒绝或请求失败时显示稳定错误信息，不把失败状态显示成加载中。
- [ ] coverage/feed 读取失败时显示错误与重新读取按钮，重试会重新请求两个来源。
- [ ] 地图区域使用正确的区域语义，调查 ID 可键盘操作并回到对应案卷。
- [ ] 未引入后端路径、抓取、坐标推断、史馆写入或公开发布能力。
- [ ] 前端 build、lint、test、typecheck 全部通过。

## Acceptance Review

- [ ] 离线 JSON 导入成功和失败路径均有证据。
- [ ] 全球覆盖错误、重试和成功路径均有证据。
- [ ] 地图点位到案卷的双向入口和键盘焦点可用。
- [ ] 既有只读案牍与证据优先边界未改变。
