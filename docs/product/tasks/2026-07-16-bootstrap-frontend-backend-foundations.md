## Product Definition

- 用户确认：未确认；2026-07-16 用户要求启动产品任务、先创建 Draft，并明确不要写代码
- 问题：仓库目前没有前后端业务代码，也没有已确定的运行平台、技术栈、工程命令或前后端契约，后续功能开发缺少可运行、可测试、可持续扩展的工程底座。
- 目标用户：项目开发者、负责后续交付与验证的 Agent；最终产品用户与具体产品形态待访谈确认。
- 目标：为前端和后端分别建立最小、可运行、可测试、可构建的工程骨架，并建立前后端最小联通验证、真实工程命令、CI 检查和必要的架构决策记录。
- 非目标：本次不实现登录、权限、业务页面、业务 API、数据库模型、正式 UI 设计、生产数据、监控告警或生产部署；是否需要调整这些边界待用户确认。

## Acceptance Criteria

- [ ] 开发者可依据仓库内文档，在受支持的本地环境中完成前端和后端依赖安装，并通过明确的命令分别启动两端。
- [ ] 前端提供一个不承载具体业务的最小可运行入口，并能以自动化方式验证入口可用。
- [ ] 后端提供一个不承载具体业务的最小可运行入口和健康检查，并能以自动化方式验证服务可用。
- [ ] 前端可通过已定义的跨端契约访问后端健康检查；成功路径和后端不可用时的失败路径均可重复验证。
- [ ] 前后端分别具备真实可执行的 lint、test、build/run 命令；后端如承担评测职责，还需提供真实可执行的 eval 命令。
- [ ] CI 会执行仓库级 harness 检查以及前后端与本次框架相关的安装、静态检查、测试和构建验证。
- [ ] 技术栈、运行边界、依赖方向和跨端契约位置均经过最小原型验证，并记录为 ADR；相关 `ARCHITECTURE.md` 与 scoped `AGENTS.md` 同步更新。
- [ ] 仓库不包含密钥、真实环境文件、私人数据或运行态数据；示例配置不依赖私密信息即可完成本地验证。

> 以上验收标准为访谈初稿；在用户确认产品形态、交付边界和环境约束后再定稿。
