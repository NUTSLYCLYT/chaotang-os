长期产品是可信复杂任务超级助手；第一条可信、可收费、可验收的航线是合同决策包。

```text
合同纵切证明可信内核
→ 有人工保护的 Paid Design Pilot
```

| 角色 | 主要责任 |

### 1.2 核心 JTBD

> 当我收到一份需要尽快决定如何推进的业务合同时，帮我定位原文风险、判断严重程度、说明必须改什么和还缺什么，让我能迅速与对方、同事或律师推进，并保留完整、可追溯的决策依据。

用户要完成的决定：

- 当前是否继续推进；
- 哪些条款必须先改；
- 哪些风险可以由业务负责人承担；
- 哪些材料必须补齐；
- 哪些问题必须升级律师；
- 如何谈判、如何内部汇报；
- 新版本是否真正解决旧风险。

## 2. 目标、非目标与阶段范围

### 2.1 目标

| ID | 目标 |
| --- | --- |
| G-01 | 普通用户无需理解六部或 Agent 拓扑即可完成一次合同决策 |
| G-02 | 中位数 3 分钟内出现第一个可定位原文的有用风险，不承诺 3 分钟完成全案 |
| G-03 | 每个高风险结论有文件版本、原文位置、来源层级和缺证状态 |
| G-04 | 交付可下载、可核验、可重新打开的完整成果包 |
| G-05 | 证据不足、超范围、OCR 失败或工具故障时诚实停止或部分交付 |
| G-06 | 任务计划、正式奏折、现实动作分别由人独立决定 |
| G-07 | 用付费、复用、时间节省、真实 outcome 和贡献毛利证明价值 |
| G-08 | 用同一内核支持未来专业包，但本版本不以六部齐全验收 |

### 2.2 非目标

- 不替代律师，不保证合同绝对安全。
- 不输出“AI 批准签署”“绝对可签”或无条件安全结论。
- 不支持跨境、劳动、证券金融、强监管专项合同。
- 不自动付款、签约、发送、发布、分享或删除。
- 不开放公众自助注册，不卖无限量通用助手。
- 不展示或承诺完整 41 司生产能力。
- 不用 LangGraph、Temporal、OpenClaw、Hermes 或新项目重写 canonical 主链。
- 不把另一个 LLM 的高分当作确定性质量门或专家 holdout。
- 不把 worker 成功、接单回执、生成文字或部分附件显示为完成。

## 3. “一旨、一卡、一包”旅程

### 3.1 一旨：材料与目标

用户上传或粘贴合同，并提供我方角色、合同类型、当前目标、业务底线、适用法域和可选背景材料。

系统先检查身份、租户、读取权限、真实文件类型、完整性、语言、法域、合同类型、OCR 质量与恶意内容。缺页、加密、损坏、低 OCR、超范围或提示注入不得静默继续。

### 3.2 一卡：一次可理解的任务确认

确认卡只显示：

1. 系统对目标和交易立场的复述；
2. 当前唯一最关键的阻塞问题；
3. 推荐办理方案；
4. 将交付的成果；
5. 预计时间、额度/费用和读取范围；
6. 明确不会执行的动作；
7. “确认办理 / 修改计划 / 取消”。

默认每轮只问一个阻塞问题；高风险任务同一张卡最多显示三个必填缺口。确认只授权本次读取、研究、分析和成果生成，不授权现实副作用。

### 3.3 一包：结论先行

第一屏显示五种保守裁决之一、必须先处理的 3–5 项、最大未知、推荐下一步、原文锚点和下载入口。完整风险、修改建议、谈判材料、版本对比和过程放在下钻层。

### 3.4 后续闭环

```text
用户逐项处理风险
→ 补证或上传新版本
→ 系统只刷新受影响部分
→ 旧裁决标记失效或被替代
→ 用户对精确 FinalMemorial 裁决
→ 史馆固化当时版本与证据
→ 到期后采集真实 outcome
```

| 枚举 | 含义 |
| --- | --- |
| `NEED_INFO` | 缺少会改变判断的材料或背景 |

## 5. 状态、失败与完成

### 5.1 正交状态

内部至少分开保存：

```text
control_status
support_status
planning_status
mission_confirmation_status
dispatch_status
evidence_status
review_status
memorial_status
artifact_status
delivery_status
memorial_decision_status
execution_status
outcome_status
```

用户阶段：

```text
草案 → 等你补充 → 计划待确认 → 办理中 → 部分完成
→ 可供决策 → 已交付 → 待结果复盘 → 已结算
```

“已完成”不是任何 Agent 可直接写入的字段。

### 5.2 `DELIVERED` 最小公式

```text
身份与授权有效
AND 支持范围有效
AND 硬能力覆盖完整
AND 用户确认绑定当前版本
AND 证据与独立审查通过
AND FinalMemorial 唯一且未被替代
AND 必需附件全部 READY
AND 获权用户可以取回
AND 所有对象属于同一未失效 lineage
```

### 5.3 失败语义

| 失败 | 系统必须做 | 禁止 |
| --- | --- | --- |
| 身份/租户/授权无效 | 立即阻断并审计 | 先执行后补权限 |
| 超范围 | `NEED_LEGAL_REVIEW` | 通用 LLM 强答 |
| 缺页、损坏、加密、低 OCR | `NEED_INFO` 并指出具体问题 | 静默漏读 |
| 门下连续封驳 | 保持阻断、补输入或转专家 | 最大轮次自动准奏 |
| 来源未验证 | 不晋升正式证据 | 因字段非空放行 |
| 冲突或过期 | 条件化结论、局部刷新或停止 | 选择方便的一边冒充确定 |
| Provider 超时 | 局部重试、换已验证能力或转人工 | 无限重跑整图 |
| 附件失败 | 保留正文、重试附件、显示未交付 | 显示完成 |
| 用户取消 | 停止新调用并查明在途请求 | 把“请求取消”写成“已取消” |
| 新版本上传 | 建 successor，旧奏折 `SUPERSEDED` | 覆盖历史 |
| 执行状态未知 | 查单、人工介入或事故处理 | 计入成功 |
| 安全事件 | 隔离、停新任务、保留导出/删除/通知 | 隐瞒并继续扩流 |

## 6. 成果与 canonical 映射

### 6.1 ContractReviewPack

完整成果包括：

1. 一页裁决摘要；
2. 风险清单：等级、原文、位置、解释、缺证、修改建议；
3. 必须改 / 建议改 / 可接受清单；
4. 明确标为建议的修订文本；
5. 对外谈判话术与内部确认问题；
6. 必须升级业务负责人或律师的问题；
7. 版本、来源层级、质量门和人工裁决；
8. PDF 决策报告、DOCX 建议稿、JSON 结构结果；
9. `ArtifactManifest`：文件 hash、版本、权限、状态和过期信息；
10. 审计摘要与服务边界说明。

### 6.2 canonical 投影

| 产品概念 | canonical 归属 |
| --- | --- |
| 一旨 / MissionContract | `DecisionTask` 的版本化输入或快照 |
| 组阁与计划 | `ChancellorRouteDecision` |
| 可靠派单 | `OutboxEvent` |
| 执行与候选分奏 | `DecreeExecutionEvent / CourtReview` |
| 证据和御史门通过 | `FinalMemorial` |
| 用户对精确奏折裁决 | `EmperorDecision` |
| 不可变案卷 | `ShiguanArchive` |
| 后来结果 | append-only outcome 事件/投影，须经 amendment 定名 |

MissionContract、EvidencePacket、ArtifactManifest 只能是版本化协议，不能成为平行数据库。

## 7. 数据、安全与法律

- 合同正文、附件、OCR、风险结果和评论默认为租户机密。
- tenant、user、object、purpose、授权引用任一缺失时 fail closed。
- 下载使用短时、对象级、可撤销授权；默认无公开链接。
- 平台管理员默认不得浏览正文；事故访问需受控批准并审计。
- 校验真实文件类型；阻断宏、恶意脚本、病毒、压缩炸弹、密码保护和异常嵌套。
- 文件内容与 OCR 均是不可信输入，不得改变权限、法域、读取范围或质量门。
- 生产 provider 必须冻结保留、训练使用、处理区域、subprocessor 与退出策略。
- 日志、trace、告警和截图不得包含全文、密钥或可还原敏感片段。
- 删除覆盖主库、对象存储、索引和缓存；备份按冻结策略到期淘汰。
- 原文、反馈和裁决不得自动进入共享知识、训练或 Skill；只有获授权、去标识、人工复核的抽象规则可以候选晋升。
- R1 前由中国大陆商事合同经验法律顾问批准支持矩阵、五种裁决、免责声明和升级规则。
- 法律复核服务必须单列责任主体、数据共享、时限、费用和交付物。

## 8. 指标与阶段门

### 8.1 R0 退出门

- 30+ 合法脱敏/授权黄金合同，覆盖采购、销售、服务。
- 10/10 浏览器主流程可终止，含失败恢复、导出一致性和人工确认。
- 5 名未参与开发的目标用户中至少 4 名无工程师帮助完成任务。
- 首个有用风险时间中位数 ≤ 3 分钟。
- 高风险原文引用覆盖率 100%，缺证显式标记率 100%。
- P0 风险召回 100%，P1 风险召回 ≥ 90%，高风险 precision ≥ 80%。
- 虚构条款、伪来源晋升、错误完成、未授权动作、跨租户泄露均为 0。
- 断线、取消、冲突、过期、附件失败和 `UNKNOWN` 均不显示完成。
- 精确 integration HEAD、required checks、独立 review 与回滚说明齐全。

### 8.2 R1 入口门

- R0 全部门通过。
- 法律顾问批准支持/拒答矩阵和产品文案。
- DPA、保密、用途、处理者、保留删除、支持和退出协议生效。
- 每份客户结果按 Pilot 协议由指定人工复核者审阅。
- trace、审计、P1 告警、成本归集和租户 kill switch 生效。
- 至少一份有边界、有人审、可退出且已付款的共创协议；未付款只能称 Design Partner，不称 Paid Pilot。

### 8.3 R1 退出到 R2 的门

- 至少 5 家目标客户完成试用、3 家 30 天内主动复用、1 家付款、1 条获书面授权的可核验 outcome 或证言。
- 至少 120 份合法脱敏/授权合同，开发集与冻结 holdout 按模板族隔离并双人标注。
- holdout 关键问题召回 ≥ 95%，原文锚点准确率 ≥ 98%，严重性 macro-F1 ≥ 0.85。
- 重大有害修改建议为 0；一般有害或明显劣化建议 ≤ 1%。
- 未解决关键风险却输出 `PROCEED_TO_HUMAN_APPROVAL` 为 0。
- 应升级未升级、跨租户、伪原文/伪来源、未授权动作均为 0。
- 10/10 真实浏览器与下载闭环通过；无陪同完成率、人工决策完成率均 ≥ 80%。
- 无未关闭 release-severity P0/P1；备份恢复、删除、密钥轮换、事故通知和 N-1 回滚实测通过。
- 至少 30 个付费任务完成模型、OCR、工具、存储和人工成本归集；贡献毛利中位数 ≥ 60%，P10 ≥ 0。

## 10. Rollout、Rollback 与停止条件

### 10.1 Rollout

```text
R0：
内部 feature flag
→ 合成/脱敏材料
→ 30+ 黄金集
→ 5 人无陪同测试

R1：
命名 tenant allowlist
→ 每 tenant 固定席位、页数、预算
→ 每份结果人工复核
→ 每周复盘前三个主链阻塞
→ 5/3/1/1 + 质量/安全/成本门

R2：
不可变 release artifact
→ 内部 canary
→ 既有 Pilot canary
→ 少量新邀请客户
→ 一个完整业务周期
→ 分批扩流
```

新客户邀请、合同摄取、模型版本、OCR provider、导出和每项能力必须有独立 kill switch。

### 10.2 Stop-ship

任一情况立即 No-Go：

- 跨租户/跨用户泄露；
- 伪原文、伪来源、伪条款、伪执行成功；
- 关键风险未解决却错误放行；
- 应升级律师而未升级；
- 未授权现实副作用；
- 门下最大轮次 fail-open；
- 接单回执或部分附件显示完成；
- 删除、备份、恢复或事故通知无法验证；
- release HEAD、artifact、schema 或运行身份不一致；
- required check、独立 review 或 release-severity P0/P1 被绕过。

### 10.3 Rollback

1. 停止新邀请和新任务摄取；
2. 对受影响租户关闭能力或进入只读；
3. 既有成果保持只读、可导出、可删除；
4. 受影响奏折标为 `SUPERSEDED / UNDER_REVIEW` 并主动通知客户；
5. 回切 N-1 不可变应用产物；数据库不做临场破坏性 downgrade；
6. schema 不兼容时进入维护模式并执行已演练 forward-fix；
7. 保留事故证据、完成补救和 postmortem 后才重新扩流。

## 12. 本 PRD 的完成定义

本 PRD 的产品冻结在以下条件满足时成立：

- 产品 Owner 确认“超级助手是产品、合同是第一 Offer、合同先于六部宽度”；
- `PROJECT_PRODUCT.md` 不再存在相反的当前产品字段；
- 融合蓝图成为只读的 accepted decision record；
- 每条 REQ 都有唯一 ID、阶段、用户结果和失败语义；
- 对外宣传、销售协议、UI、API 和导出使用同一支持范围与五种裁决；
- 未验证能力继续标 `DIRECTORY_ONLY / SANDBOX / INTERNAL`；缺失的评测或运行证据单独标 `NO_DATA`。

实现开工还额外要求：

- M0–M10 Owner 批准显式 amendment；
- amendment 映射 REQ、canonical owner、schema、迁移、反例测试和回滚；
- 当前 integration HEAD 干净、可追溯且通过独立 stop-gate；
- 不把本 PRD 的“产品冻结”误报为“工程完成”或“生产就绪”。
