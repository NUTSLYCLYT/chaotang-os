# Request analysis

## 目标

在不写业务代码的前提下，将既有产品、架构、任务分级、企业治理、部门专业机制、质量门、GitHub 雷达和全面完善路线整合成可长期执行的唯一指导文件。

## 验收

- 明确最终产品形态和唯一主线。
- 明确简单/复杂任务处理机制及升级规则。
- 明确各部门专业能力契约和企业责任机制。
- 明确功能保留、隐藏、适配和退役规则。
- 明确 GitHub 候选的 ADOPT/TRIAL/ASSESS/HOLD 裁决。
- 每个执行阶段包含目标、依赖、任务、产物、验收、价值和回滚。
- 明确现在立即执行的第一批事项。
- 不修改业务代码和运行状态。
