## 总战略

```text
全量功能盘点
→ 功能宇宙冻结
→ 统一底座
→ 全部能力接入
→ 每项功能独立跑通
→ 全朝廷组合联调
→ 失败与恢复联调
→ 全量内部验收
→ 用户测试与数据评估
→ 收敛上线范围
→ 只对上线能力做生产硬化
```

核心区别（对旧"刑部首发"方案）：

| 原方案 | 新方案 |
| --- | --- |
| 只开发刑部首发链路 | 所有规划能力都进入内部集成 |
| 非首发能力暂缓开发 | 非首发能力可以实现，但默认隐藏 |
| 先决定上线范围 | 先跑通，再根据证据决定 |
| G1–G5 前禁止扩展 | 允许开发扩展，但不得进入生产 |
| 目标是立即 Release Candidate | 目标先是 Full-Court Integration Build |

关键原则：

> 发散的是产品能力，不是代码事实源；保留全部有效功能，不保留三套重复实现。

```text
功能宇宙：现在冻结（FULL_COURT_V1）
上线范围：以后决定
新想法：只进 docs/plans/FULL_COURT_V2_BACKLOG.md
```

## 保留的安全约束

- 不使用未经授权的真实客户合同；
- 不允许跨租户；
- 不允许演示数据冒充 LIVE；
- 不允许 AI 自动执行不可逆动作；
- 不允许多个 Agent 同仓并发写代码；
- 不允许前端产生第二套状态机；
- 不允许恢复已经退役的前端 BFF。

## 七级成熟度

| 等级 | 状态 | 定义 |
| -: | --- | --- |
| L0 | 只有想法 | 文档或 TODO，没有明确契约 |
| L1 | 已定义 | 有输入、输出、所有者和状态 |
| L2 | 局部可运行 | 模块自身可以在隔离环境运行 |
| L3 | 已接入主链 | 使用真实 API、事件、数据库和状态机 |
| L4 | 内测跑通 | 正常、失败、权限、恢复和 E2E 路径通过 |
| L5 | 候选上线 | 质量、性能、安全、迁移和观测达标 |
| L6 | 生产上线 | 外部 CI、签名、Staging、Canary、回滚完成 |

目标：**所有 FULL_COURT_V1 功能至少 L3；核心功能 L4。** L5/L6 只对收敛后上线能力实施。

## 功能"跑通"的统一定义（16 条全满足）

1. 有唯一能力 ID；
2. 有明确用户价值；
3. 有 canonical owner；
4. 有正式输入输出契约；
5. 使用统一状态机或事件；
6. 不依赖前端静态假数据；
7. 正常路径实际通过；
8. 失败路径实际通过；
9. 权限和租户负向路径实际通过；
10. 页面刷新或服务恢复后状态不丢失；
11. 有 sourceLabel；
12. 有 Trace；
13. 有测试；
14. 有 Feature Flag；
15. 有回滚或禁用方式；
16. 没有把 MOCK/FALLBACK 描述为 LIVE。

不算跑通：页面能打开、代码文件存在、接口返回 200、Agent 能生成一段文本、测试全 Mock 通过、文档写了"已完成"。

## 能力域（14 域）

1. 身份、租户和权限（邀请注册、登录、成员/裁决人/租户管理员/内部运营/平台管理员、跨租户隔离、演示/真实模式隔离）
2. 上书房与旨意系统（文本/文件/合同输入、原始输入版本、背景补充、DecisionTask、任务版本、D0/D1/D2、取消/补充/重新发起）
3. 丞相系统（问题理解、拟票、规格判断、部门推荐、朱批、路由版本、成本耗时区间、不支持范围、最终倾向、反方理由、改判条件、复裁建议）
4. 军机处和执行调度（唯一路由、Outbox、Worker、幂等、重试、超时、DAG、并发控制、局部重跑、补证只失效受影响节点、再议产生新路由版本、单点问话不重跑全链）
5. 六部与专署——一个部门 ID、一个能力注册表、一个正式输入契约、一个正式回奏契约、一个主实现；重复实现只能选 canonical owner，其余转 adapter/deprecated/历史参考
6. 锦衣卫（证据采集、来源、鲜度、可信状态、去重、证据版本、任务和租户绑定、人工核验、主动密折内部实验；只提供证据，不生成正式业务结论）
7. 御史质量门（证据完整性、sourceLabel、高风险原文锚点、必需部门告病、跨租户、不支持法域、缺失材料、冲突、利益声明、候选与正式奏折重复；PASS / REJECT_WITH_REASONS / ABSTAIN；不得偷偷改写结果再放行）
8. 正式奏折与圣裁（候选奏折、冲突汇总、丞相建议、FinalMemorial 唯一晋升、准奏/补证/复核/驳回/再议/传某部问话/复裁日/终止、人工裁决、不可逆动作保护）
9. 史馆（原始输入、拟票版本、路由版本、执行事件、部门回奏、证据、冲突、御史判定、正式奏折、人工圣裁、复裁、结果回填、全文检索、版本比较、删除保留策略）
10. 翰林和离线飞轮（轨迹评测、失真分析、人工改判分析、策论候选、Prompt/Schema 版本、Golden cases、回归评测；不得直接修改生产行为）
11. 钦天监（预测、依据、到期日、可逆性、二阶效应、结果结算、命中率、样本不足；只作非阻塞批注；样本不足时 `value = null, status = NO_DATA`，不显示伪精确百分比）
12. 国力仪表盘（丞相押注命中率、御史封驳率、各部告病率、缺证率、传话失真率、人工改判率、结果回填率、跨租户违规数；所有指标带样本数、时间窗口、数据来源、截止时间、是否含 DEMO、状态）
13. 外部集成（邮件 MCP、企微 MCP、文档 Provider、LLM Provider、Embedding、外部知识、通知、Webhook、失败/限流/权限；允许沙箱账号、合成数据、明确标记的模拟 Provider，但必须显示 DEMO/MOCK/SANDBOX/FALLBACK，不得标 LIVE）
14. 运维与平台（OpenTelemetry、Feature flag、SLO、错误预算、CI、Attestation、Release commander、Staging、Canary、回滚、Secret Store、数据删除、生产诊断）

## 分支模型

| 线 | 分支 | 用途 |
| --- | --- | --- |
| 实验线 | `lab/*` | 技术验证、新 Provider/Prompt/Agent/算法；不能作为功能完成证据 |
| 全量集成线 | `integration/full-court-v1` | 主开发线；一个 Codex 写入者、一个任务分支、一个 Worktree、Claude Code 独立审查、合并后跑累计集成测试 |
| 发布线 | `release/<version>` | 全量内测完成后从 integration 选择 Flag/导航/GA/Beta/Internal/延期；不删除未上线功能，只关闭入口和生产 Flag |

## Codex / Claude Code 分工

- Codex：唯一写入者（实现、运行、测试、修复、本地提交、生成证据）。
- Claude Code：永久只读（审查盘点、架构统一、计划、diff、重复实现、第二事实源、MOCK/FALLBACK 漂白、权限/租户/证据链）。
- 允许并行：只读 Agent 分查不同模块/前后端/能力图与重复实现。
- 禁止并行：两个 Agent 同时改 integration、状态机、数据库迁移、公共契约、能力注册表。

## 收敛评分（Wave 8）

| 维度 | 权重 |
| --- | --: |
| 用户真实价值 | 25% |
| 使用频率 | 15% |
| 决策差异化 | 15% |
| 稳定性 | 15% |
| 证据可信度 | 10% |
| 成本与延迟 | 10% |
| 安全与合规风险 | 10% |

分级：GA 候选（L4+、价值高、稳定、证据完整、风险可控、真实用户愿用）/ Beta（价值高但质量成本稳定性未达标）/ Internal（治理有用、客户价值不直接，如国力、翰林、Provider、质量控制面）/ Deferred（价值低、重复、低频、成本过高、无真实闭环）/ Retired（重复实现、无正式 owner、依赖旧事实源、与统一状态机冲突、无独立价值）。
