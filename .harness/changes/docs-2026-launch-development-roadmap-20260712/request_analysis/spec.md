# 规格说明：docs-2026-launch-development-roadmap-20260712

## 背景

朝堂 OS 已具备主要产品模块、后端运行能力和 Harness，但 production 代理、P0-B 用户隔离、最终发布门禁、合同首发切片和真实付费证据尚未形成统一执行顺序。需要一份能够供后续 Claude Code/Codex 冷启动执行的跨线开发路线图。

## 范围

- 统一产品目标、首发切片、非目标和永久边界。
- 记录当前事实、未完成事项和需用户确认的假设。
- 定义十个工作流、依赖图、任务、验收、验证和回滚。
- 定义用户故事、指标、证据等级、反模式和计划变更协议。
- 将“原项目最小修复、避免重构、先上线”设为实施硬约束。
- 将 verification-loop 固化为每个候选提交和正式发布的强制门禁。

## 非目标

- 不在本变更中修改前端、后端或运行配置。
- 不宣称尚未重新验证的 production 链路已通过。
- 不改变大殿冻结边界、部门协议或数据权限。
- 不以路线图名义授权框架替换、系统重构或新建平行产品入口。

## 验收标准

- 后续 Agent 可只读本路线图理解当前目标、执行顺序和退出条件。
- 路线图区分事实、假设和推荐，不把 workaround 视为 production 证据。
- 每个阶段包含目标、任务、验收和回滚。
- 文档遵守 Loop + Harness、source label 和前后端事实源边界。

## 验证计划

- 运行根级 `node scripts/harness-doctor.mjs`。
- 人工核对 `docs/PROJECT_PRODUCT.md`、根/前端/后端 AGENTS、验证矩阵和当前 release handoff。
