# 钦天监签字台账协议（吸收自 `~/CHAOTANG_钦天监_待裁台账.md`）

台账 #17 的文档级吸收。原档是 openclaw 时期的具体待裁清单；本协议只吸收其
**通用治理形态**，不搬运其具体待裁项（那些归 openclaw 侧，不进朝堂 OS）。

## 协议核心

凡 **不可逆 / 烧钱 / 架构分叉 / 多蜂群治理 / 上线 / 客户承诺** 的动作，
先登记、后裁决、签字才执行，不擅动。

## 台账行格式

| 列 | 含义 |
| --- | --- |
| 动作 | 一句话说清要干什么 |
| 为什么过钦天监 | 命中哪条红线（不可逆/烧钱/分叉/治理/上线/承诺） |
| 前提 | 执行前必须成立的条件（含依赖的静默窗） |
| 不可逆性 | 高 / 中 / 低 + 一句理由 |
| 归谁 | 执行负责人（人 or agent，写明"谁签字"） |
| 状态 | ⏳阻塞 / 📐已设计 / ✅备好待裁 / 🔶部分完成 / ⚠️必做 |

## 舰队静默窗

多蜂群/多 worktree 环境下，改共享历史、共享配置、共享调度层的动作，
必须约一个「舰队静默窗」：相关 agent/定时任务全部暂停，窗口内单人操作，
窗口结束后统一恢复。避免并发会话互相覆盖。

朝堂 OS 对应场景：主工作区并发会话 + `.worktrees/` 隔离已是静默窗的弱化
实现；触及 `feature-chaotang-ext` 共享历史或根护栏结构时，升级为完整静默窗。

## 不可逆动作铁律（原档原文吸收）

- 执行前：台账签字
- 执行中：可回滚优先（`git revert` > `reset --hard`；timer 可 disable）
- 执行后：史馆留痕

## 与现有 packet 流程的关系

packet 复审（B/H/R + GO/NO_GO）管**代码合入**这一种不可逆动作；
本协议管其余种类（部署上线、烧钱、外部承诺、历史重写、调度激活）。
两者同族：都是"单向门前设裁决点"。台账落点：后续在 `.harness/rules/`
建 `irreversible-actions-register.md` 时引用本协议（本包不动 rules 结构）。
