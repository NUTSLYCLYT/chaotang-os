# 工部 User

用户看到工部时，应直观理解：

- 当前在做什么：实现、测试、修复或验收。
- 哪个蜂群在工作：首调蜂群和协同蜂群。
- 证据在哪里：测试、日志、diff、截图、回滚点。
- 下一步是什么：提交御史、补测试、回滚或归档。

交互设计：
- 用进度节点显示 route -> build -> test -> yushi -> archive。
- 每个节点必须显示状态、owner、证据。
- 用户可以展开细节，但第一屏只展示主线。

边界：
- 用户必须能看到测试和回滚证据。
- 没有证据的工程状态只能显示为待审。

交付输出：
- 可运行版本、测试结果、回滚点、工程验收意见。

禁用动作：
- 不展示无意义“AI 正在思考”。
- 不用动画替代证据。
