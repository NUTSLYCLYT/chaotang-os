# 多Agent蜂群系统：架构与可维护性设计文档（精简版）

---

## 一、系统本质

本系统不是普通AI应用，而是：

> 多Agent + 流程引擎 + 状态系统 + 调度系统 + 可视化控制台

核心目标：

* 可观测
* 可干预
* 可重放
* 可演化

---

## 二、核心架构分层

```
1. Agent层
2. Flow流程层
3. 状态与调度层
4. 模型层（含LiteLLM）
5. 工具层
6. API层
7. 可视化控制台
```

---

## 三、关键设计原则

### 1. Flow配置化

必须使用配置驱动流程，而非硬编码：

```
flow:
  - pm_analysis
  - dev_impl
  - qa_test
```

作用：

* 动态调整流程
* 插入/删除步骤
* 无需改代码

---

### 2. Agent无状态化

每个Agent必须满足：

```
输入 → 处理 → 输出
```

禁止：

* 内部持久状态
* 隐式依赖

作用：

* 可替换
* 可测试
* 可隔离问题

---

### 3. Step级可观测

每一步必须记录：

```
input
prompt
model
output
tools
```

作用：

* 精准定位问题
* 支持回放
* 支持对比优化

---

### 4. 局部重跑能力

必须支持：

```
从任意Step重新执行
```

作用：

* 降低调试成本
* 避免全流程重复执行

---

## 四、调试面板设计

### 1. 模块结构

```
1. 任务总览
2. 流程执行图
3. Step调试面板
4. 干预控制台
```

---

### 2. 任务总览

功能：

* 查看任务状态
* 识别失败集中区域
* 按Agent/Flow统计问题

---

### 3. 流程执行图

形式：

```
[PM ✅] → [Dev ❌] → [QA ⏳]
```

功能：

* 快速定位问题节点
* 可点击进入Step详情

---

### 4. Step调试面板

必须包含：

```
Input
Prompt
Model信息
Output
Tool调用记录
```

作用：

* 问题定位唯一依据

---

### 5. 干预控制台

必须支持：

```
1. 局部重跑
2. 修改Prompt
3. 切换模型
4. 修改输入
```

作用：

* 实时修复问题
* 支持实验与优化

---

## 五、LiteLLM使用策略

### 1. 作用定位

LiteLLM仅用于：

* 模型统一调用
* 多模型切换
* fallback机制

---

### 2. 不负责内容

LiteLLM不负责：

* prompt管理
* 状态记录
* 调试信息
* 流程控制

---

### 3. 正确调用方式

必须封装一层：

```
Agent → ModelAdapter → LiteLLM → 模型
```

返回结构必须包含：

```
model
prompt
output
```

---

### 4. 禁止行为

禁止：

```
model="best_model"
```

必须明确记录：

```
model="gpt-4"
fallback=["claude-3"]
```

## 六、可维护性核心机制

系统可维护性的判断标准：

```
是否可以定位到：
一个Step + 一个Agent + 一次执行
```

---

### 必备能力

```
1. Step级日志
2. 输入输出记录
3. Prompt可见
4. 模型可见
5. 局部重跑
```

---

## 七、典型调试流程

### 场景：结果质量下降

```
1. 查看任务总览 → 找异常Step
2. 查看流程图 → 定位失败节点
3. 打开Step详情 → 检查：
   - prompt
   - model
   - output

4. 执行：
   - 修改prompt / 切模型
   - 局部重跑

5. 对比结果 → 更新配置
```

```
一个可观测 + 可干预 + 可验证 的AI运行控制台
```
