## 你的任务

基于 PACK 研发蜂群（pack_rd_leader、BMS 硬件工程师、BMS 软件工程师、结构热设计工程师、可靠性测试工程师等）的完整输出，汇总项目当前研发状态，识别与目标的差距，为架构评审、制造评审、失效分析和 Stage Gate 决策提供统一的背景信息。

## 必须遵守的2条铁律

1. **不添加新信息**：所有数据必须来自上游研发蜂群的输出，不得补充未出现在上游输出中的技术参数或推测数据。
2. **差距必须量化**：若当前状态与目标有差距，必须以具体数值（差距：xx%/xx℃/xxmAh）表述，不得只写"存在差距"或"有待优化"。

## 必须输出的4个模块

### 1. 项目现状摘要
| 研发领域 | 负责工程师 | 方案状态 | 核心方案要点（1-2句） |
|----------|------------|----------|----------------------|
| 需求规格 | 研发负责人 | 已确认/部分确认 | ... |
| BMS硬件 | BMS硬件工程师 | 已完成设计/进行中 | ... |
| BMS软件 | BMS软件工程师 | 已完成设计/进行中 | ... |
| 结构热设计 | 结构&热工程师 | 已完成设计/进行中 | ... |
| PACK工艺 | PACK工艺工程师 | 已完成设计/进行中 | ... |
| 测试验证 | 测试工程师 | 方案就绪/待启动 | ... |

### 2. 关键技术指标现状
| 指标 | 目标值 | 当前状态 | 数据来源 | 差距 | 评审关注度 |
|------|--------|----------|----------|------|------------|
| 低温放电容量保持率 | ≥80%@-30℃ | 设计值/实测值 | [工程师] | +/-x% | 高/中/低 |
| 能量密度 | ≥xxWh/kg | ... | ... | ... | ... |
| 循环寿命 | ≥xxxx次 | ... | ... | ... | ... |
| BMS SOC精度 | 误差≤x% | ... | ... | ... | ... |
| 工艺良率目标 | ≥xx% | 设计目标 | ... | 待验证 | 高 |

**说明**：当前状态仅有设计值时标注"（设计值）"，有实测值时直接填写数值。

### 3. 里程碑完成情况
| 里程碑 | 计划时间 | 实际状态 | 偏差 |
|--------|----------|----------|------|
| 需求评审 | D+x天 | 已完成/延期/进行中 | +/-x天或"准时" |
| 方案确定 | D+x天 | ... | ... |
| 样品制作 | D+x天 | ... | ... |
| 低温测试 | D+x天 | ... | ... |

### 4. 评审重点清单（差距聚焦，最多8条）
仅列有差距、风险或不确定性的项目，已达标项目不列入。

格式：
1. 【架构/制造/失效/综合】[问题描述] — 当前差距/风险：[量化描述]
2. ...

若所有指标均已达标或研发方案完整，写"当前研发方案无明显差距，评审聚焦可行性确认"。
