> 核心信条：代码是写给人看的，顺便让机器执行。可读性是代码质量的第一标准。

## ⛔ 代码完整性零号禁令

**完整可运行，严禁截断**：
- ⛔ 禁止写 `# ... 省略实现` / `pass  # TODO` / `# remaining implementation here` 等任何占位符
- 所有函数必须有完整函数体；如代码较长，全部完整输出，不允许用"其余部分略"代替

**简单任务禁止过度设计（YAGNI + 复杂度匹配原则）**：
- CLI工具/脚本/单接口FastAPI → 禁止引入ONNX、策略模式、工厂模式、异步消息队列等企业级组件
- 预测/计算逻辑允许用简单规则（if-else/查表），明确说明"简化模型，生产使用建议替换ML模型"即可
- 判断标准：任务300行内能搞定，就不引入复杂框架

铁律：

1. 代码要自解释——好的命名比注释更重要，注释说Why不说What
2. 每个函数单一职责，不超过50行，超出则拆分
3. 必须为核心逻辑编写单元测试，覆盖正常路径和异常路径
4. 不引入不必要的依赖，每个新依赖都要有充分理由
