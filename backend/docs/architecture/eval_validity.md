# Eval 效度底账 — 大神判分这把尺子,准在哪、不准在哪

> 诚实底账(2026-07-01)。配合 `scripts/eval_personas.py` + `scripts/eval_ci.py` 读。
> 结论先行:**信度已证(尺子刻度稳),效度未证(尺子可能整体偏斜)。分数可内部比较,不可对外背书。**

## 一、这把尺子是什么

大神判例判分 = LLM-as-judge:让大神作答 → 裁判模型对照人工真值 `reference`/`must_not` 打分(1-10)。
判官席门槛 7.5。判例见 `scripts/persona_cases/*.json`。

## 二、已证:信度 / 精度(reliability)—— ✅ 极好

test-retest 实测(同一份答案,裁判重判 3 次,温度=0):

| 抽样 case | 三次判分 | 极差 |
|---|---|---|
| taleb c1 / munger c1 / contract c1 | 全部一致 | ±0.0 |
| karpathy c3 / posner c1 / deming c1 | 全部一致 | ±0.0 |

**裁判是确定性的,重复性零方差。** 上一轮误以为的"judge 方差"实际是**上游作答变异**(作答温度 0.3 每轮生成不同答案)。
故 `eval_personas._answer` 作答温度默认降到 **0**(benchmark 要可复现);需采样多样性时 env `ANSWER_TEMP` 覆盖。

### ⚠️ 关键区分:temp=0 ≠ "取均值"(别混,踩过一次)

`ANSWER_TEMP=0` 锁定**单条最大概率(贪心)答案**,不是 deming 说的"多轮取均值"。实测反直觉:
temp=0 时 munger case1 从 7.0 跌到 **3.0**、总分 7.0 **跌破判官席门槛**——因为它的贪心答案恰好差,
而 temp=0.3 采样里有更好答案把均值抬到 8.5。**temp=0 消方差,代价是测"最可能"而非"期望质量"。**

两种温度各有正确用途,不可混用:

| 用途 | 温度 | 为什么 |
|---|---|---|
| **CI / 回归检测** | temp=0 | 可复现,隔离"是代码改动还是采样噪音" |
| **真实质量排名** | temp>0 + N 次取均值 | 贪心解不代表期望质量;munger 真实力在 [7.0, 8.5] 之间,非任一单值 |

对外引用分数或定判官席去留,**用 N 次均值**;跑 CI 看"我这次改动有没有让分数掉",**用 temp=0**。

## 三、未证:效度 / 准度(validity)—— ❌ 开放风险

**裁判(deepseek-chat)与被评(deepseek)同源。** 本环境实测:新 key 是 DeepSeek、MiniMax 余额为 0、
火山无 key、本地代理别名(swarm-judge/codex-gpt-5.5)底层全路由到 DeepSeek —— **每条路都是 DeepSeek**。

同源自评的结构性风险:裁判可能系统性偏爱自家文风/推理套路。
**一把稳定但偏斜的尺子,是稳定地偏。** 信度高 ≠ 效度高。
自评未做跨厂商交叉验证前,分数的**绝对高低不可信**,只可用于**同一裁判下的相对比较**。

### 半独立实证(deepseek-reasoner vs deepseek-chat,2026-07-01)

连**同厂换个模型**都不稳:同一批答案,reasoner 当裁判比 chat **系统性高 +0.70**(14 位全部 ≥0,
最大 +1.25),且中段排名重排(taleb 7.75→9.0 蹿 6 名)。只有头尾稳(munger 两裁判都垫底、
compliance/karpathy 都居前)。**最要命:munger chat 判 7.0(落榜)/reasoner 判 7.75(升席)——
判官席去留取决于选哪个裁判模型,7.5 门槛正压在裁判噪音带上,gate 不鲁棒。**

推论:同厂换模型已经 ±0.70 + 洗牌,真跨厂商分歧大概率更大。**绝对分必须带裁判名;gate 裁决在
7.0~8.0 区间的大神,结论随裁判翻转,不可作数。**

## 四、红线(schneier 签字)

> 同源自评在安全视角 = 用同一套逻辑既加密又验签,结构性不可信。

**任何对外用这套分数背书前(如对客户宣称"我们大神评分 9.25"),必须先补一个真正独立的第二裁判。**
否则是拿伪造的可信度做营销。

## 五、怎么破(C 备口已就位)

真第二厂商裁判到位时,一处切走,无需改代码:

```bash
export SCORE_JUDGE_BASE_URL="https://<第二厂商>/v1"
export SCORE_JUDGE_KEY="<第二厂商 key>"
export SCORE_JUDGE_MODEL="<第二厂商模型>"
python scripts/eval_personas.py            # 裁判即换成异厂商
```

候选:火山方舟(补 `ARK_API_KEY` + `ep-xxxx`)、MiniMax(充值)、任意 OpenAI 兼容的异厂商网关。
换裁判后重跑全量,**看梯度是否随裁判剧变**——若剧变,说明之前的排名是自评幻觉;若稳定,效度才算初步站住。

## 六、当前可下的结论

- ✅ 同一 DeepSeek 裁判下,temp=0.3 采样时 14 位全过 7.5;**temp=0 贪心时 munger 掉到 7.0 跌破门槛**
  (贪心答案未区分可逆/不可逆决策)。判官席去留应以 **N 次均值**为准,不以单次贪心。
- ⚠️ 该梯度**未做跨厂商效度验证**,不作对外权威。
- 📌 三条低分(taleb c1 伪分散、munger c1 可逆性、contract c1 异议期性质)是**实质漏点**非编造,
  待补对应 `references/` 知识点 —— 但**补料应在效度验证之后**,否则可能在自评噪音上补。
