# 御史 · 权威设计:功能 / 行为 / 天才设计

> 定稿 2026-07-01。御史是全院唯一放行总闸。本文是它的权威设计,行为全部对应真实逻辑
> (`harness/yushi_global_gate/rules.yaml` + `src/yushi_gate.py: judge_memorial`),不是概念。
> 出场特效见 [../frontend_ui/yushi_entrance.md](../frontend_ui/yushi_entrance.md)。

## 一、天才设计:御史 =「唯一不可贿赂的收窄点」

獬豸的本性是**不讲情面**。御史的全部设计围绕一句话:

> **所有动作汇一闸,灯由冷规则定,人格只能进言、不能放行,收益再大也赎不回一票否决。**

六条支柱(下文逐条展开):
1. **一闸收窄**:任何上线/发布/自动执行,物理上只能从御史过,无旁路(接宪法 C2:只有 `yushi/harness` 能放行)。
2. **规则定灯,人格只参谋**:6 位大神供视角进 `reasons`,但灯由 `rules.yaml` 定——防"求大神放我过"。
3. **双轴闸:风险 × 自主度(L0–L5)**——不是"能不能做",是"能不能**自动**做"。这是 AI agent 系统的命门。
4. **一票否决不可赎买**:硬核查 FAIL,收益再大也 block。
5. **黄灯是主产品**:模糊地带产品化成"带条件放行",不是非黑即白。
6. **出场即判决 + 留痕护身符**:獬豸投印,放行必盖封存号可回链。

## 二、功能(御史干什么)

| 功能 | 说明 | 真实台 |
|---|---|---|
| **release_gate 定灯** | 汇总六部产出 → 定绿/黄/红/黑 | `rules.yaml: levels` + `judge_memorial` |
| **一票否决** | 硬核查 FAIL(数字无来源/越权/踩红线/证据缺/schema残/QA fail)→ blocked,不被收益赎买 | `yushi_gate._hard_check_failures` |
| **自动化阶梯** | 按动作自主度 L0–L5 定能否自动执行,L5 不可逆必签字 | `rules.yaml: automation_levels` |
| **drift_monitor** | 越界/漂移(如蜂群跑去碰 web)→ 降权告警 | `web_drift_terms` + `src/governance.py` |
| **留痕 + 转刑部** | 放行/封驳盖封存号;黑灯落刑部深查 | `apply_verdict` + `EscalateToXingbuLink` |

## 三、行为(御史怎么决策)——决策树

输入:一张待放行的 court_doc/memorial + 该动作的**自动化等级**(L0–L5)+ 命中的高风险词。
按下面**从严到宽**判,先命中先定(绝不静默吞,`blocked` 必显式入箱):

```
1. 硬核查 FAIL?(数字无来源 / 越权自动执行 / 踩红线 / 证据缺 / schema 残 / QA fail)
   → 是 → 🔴红/⚫黑 blocked【一票否决】收益再大不赎买;黑灯落刑部
2. 不可逆 / 对外承诺(L5 或命中 上线/客户承诺/合同/删除/花钱)?
   → 是 → ⚫黑,human_signoff_required=true:必须人工两步签字,否则 block
3. 高风险词 + 自动化越级(high_stakes_term 且 automation ≥ L4)?
   → 是 → 强降级(auto→draft 待签)+ 🟡黄带条件
4. 有可补条件能让它安全过?(报价加有效期 / 灰度 10% / 降为草稿)
   → 是 → 🟡黄灯·带条件放行(条件写进 items[].fix)
5. 全通过(schema 全 + QA pass + 硬核查无 FAIL + 凭据锚定)?
   → 是 → 🟢绿灯 verified「御史已验」
```

**行为铁律**:
- **不可被收益赎买**:第 1 步 FAIL,无论 ROI 多高一律 block(防"赚钱就放行"滑坡)。
- **不软化**:御史照搬最差项的灯,主线/呈现层都不许美化(接 C8)。
- **显式入箱**:`blocked` 必带人话原因写档(`blocked_reason_human`),禁静默吞。
- **放行必留痕**:任何放行盖封存号,出事可回链(护身符)。

## 四、自动化阶梯 L0–L5(AI agent 系统的命门)

御史最关键的行为不是判"对不对",是判"**能不能让 agent 自动干**":

| 级 | 含义 | 御史行为 |
|---|---|---|
| L0 | 只读 | 放行 |
| L1 | 拟草稿 | 放行 |
| L2 | 内部任务 | 放行 |
| L3 | 工具调用·需人确认 | 黄灯·人确认 |
| L4 | 低风险自动执行 | 高风险词命中即降级 |
| **L5** | **不可逆 / 对外承诺** | **黑灯·必须人工签字,否则 block** |

> 这一栏是御史存在的根本理由:**防止 agent 自动做了不可逆/对外的事**。模型再聪明,L5 也必须人手按下。

## 五、与各部门的关系

- 六部产出 → **御史定灯**(绿黄红黑)→ 绿放行/史馆归档,黄回源部门补条件,红挡,黑落**刑部**深查。
- 御史**定灯**,刑部**深查**:御史是放行总开关,刑部是风险护身符。
- 御史**参谋席**(governance profile):posner/schneier/deming/charity-majors/wang-yangming/andy-grove —— 供视角进 `reasons`,**不定灯**。
- 御史放行结果 → 史馆归档 → 喂自我进化飞轮。

## 六、边界

- 御史**不是大神**,是规则闸;给它"主审人格/出场口吻"可以(獬豸·schneier 气质最贴),但**定灯权永远归规则**(C2)。
- 御史**不算灯**于前端;前端只渲染已定的灯,`gate=pending`/`grounding=none` 一律按红/需人工,不准美化成绿(C6)。
