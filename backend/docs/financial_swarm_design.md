# 财务估值蜂群 设计蓝图（v0.1）

> 目标：打造世界顶级"收益法估值"财务蜂群。本蓝图把本会话血泪教训（确定性包LLM、可证伪真值库、反自评、求解器优先路由、非对称风险）落成可实现的角色/模块/数据结构。
> 北极星：**算术零错 + 每数可溯源 + 判断经真实结局回测 + 地基不夯不出数。**

## 一、七条铁律（设计约束）

1. **确定性包住 LLM**：加总/折现/比率/税/勾稽全走确定性代码；LLM 只做"抽取"和"判断"，**绝不做算术**。
2. **GIGO 第0步**：先验审计意见/口径/勾稽，地基不过 → 不算。
3. **可证伪真值库 ≠ 向量库**：折现率/分成率/行业基准/可比交易，存结构化、带来源、带 status(usable/human_confirm/reject)、带 as_of。
4. **反 LLM 自评**：结果用真实结局回测（估值 vs 实际成交/融资额），建回测账本；证伪率↓ = 真进化。
5. **求解器优先路由**：确定性能算的不进 LLM；只有"判断"上多 agent 会审。
6. **非对称风险**：永远给区间+下行(清算价)，不给假精确单点。
7. **每个判断留痕、可被证伪**（skin in the game）。

## 二、角色与流水线（确定性=⚙️ / LLM窄任务=🔎 / 蜂群会审=🐝）

```
源文件
 → ⚙️🔎 ①源核验官(GIGO门): 审计意见类型/持续经营、口径一致性、三表勾稽、数据完整性 → 不过返工
 → 🔎 ②抽取官(LLM只抽结构化数字, 逐项标来源单元格/页码)
 → ⚙️ ③确定性计算引擎(非LLM): 比率/DCF/税/敏感性/勾稽/可比 → 数字唯一真源
 → 🐝 ④假设审议庭(多agent红蓝对抗): 增长率/折现率/分成率/持续经营 ← 唯一真"蜂群"
 → 🐝 ⑤大神评审(芒格/塔勒布/Marks): 致命问题+非对称风险+假设联合概率
 → ⚙️🔎 ⑥下行官: 清算价/断崖情景/尾部(确定性算清算 + 判断触发条件)
 → 🔎 ⑦奏报官: 非对称双极区间 + 待确认项清单 + 每数溯源
```
> 只有 ④⑤ 是蜂群；①③⑥ 是确定性骨架。这就是"蜂群只啃硬骨头"。

## 三、确定性计算引擎（⚙️ 必须是代码，清单）

- `ratios()`：偿债/营运/盈利/成长比率（带行业基准对照）
- `tie_out()`：三表勾稽（利润表→资产负债表未分配利润→现金流量表）一致性校验
- `dcf()`：自由现金流折现，中年折现，显式期+永续/有限期
- `wacc()`：CAPM 各参数显式输入 → 折现率（参数来自真值库）
- `tax()`：所得税（区分高企15%/一般25%）
- `sensitivity()`：折现率×增长×分成率 矩阵
- `liquidation()`：清算价（资产可变现 - 负债；无形资产依附持续经营→破产场景近零）
- `sanity_guards()`：硬约束（如净利率>毛利率=非法；折现率<无风险利率=非法；估值>企业总资产×N 触发复核）

## 四、财务真值库 schema（护城河资产）`config/fin_truth/*.yaml`

```yaml
discount_rate:
  sme_early_loss: {low: 0.18, high: 0.28, status: human_confirm, as_of: "2026", source: "..."}
contribution_rate:           # 技术分成率/专利贡献率
  battery_energy: {low: 0.20, high: 0.40, status: human_confirm, source: "25%规则/行业研报"}
industry_benchmark:
  lithium_battery: {gross_margin: [0.20,0.45], net_margin: [0.05,0.15], status: usable}
compliance:                  # 硬门槛
  income_approach_requires_going_concern: true
  std: ["CES 3203", "IVS 210"]
```
> 每条带 status/source/as_of。usable→可硬判；human_confirm→只warn。**绝不进向量库。**

## 五、golden 案例集 + 回测账本（让它"顶级"的关键）

**golden 案例集** `eval/fin_golden.yaml`：收集**已知真实结局**的历史案例
```yaml
- id: case-001
  type: 收益法估值
  inputs: {...源数据...}
  known_outcome: {actual_transaction_value: 8200000, date: "..."}  # 真实成交/融资额
  human_score: null
```
**回测账本** `data/fin_ledger.jsonl`：每个真实案子 裁定→实际结局→判错留痕（复用 `param_ledger.py` 模式）。

## 六、成功指标（反虚荣）

- ✅ **估值 vs 实际成交价的偏差分布**（MAE/中位偏差）——真分数
- ✅ **被现实证伪并改对的假设条数**（证伪率↓）
- ✅ **零算术错 + 100% 可溯源**（确定性引擎保证）
- ✅ **打 baseline**：每环节 vs 单模型，证明增量
- ❌ 不看：报告页数、知识库条目数、LLM 自评分

## 七、第一个端到端样板（先窄后扩，Karpathy式）

1. 只做**收益法估值**一条线（本司案=首个真实样本）。
2. 建：确定性引擎 + 20 个 golden 历史案例（已知成交结局）+ 回测。
3. 证明：硬案例上赢单模型、零算术错、每数可溯源。
4. 赢了再扩到 财务尽调红旗扫描 / 信用评估。
