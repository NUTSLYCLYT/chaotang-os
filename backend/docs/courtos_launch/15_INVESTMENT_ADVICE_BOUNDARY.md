## 0. 通用原则：领域准入闸（Domain Admission Gate）

> 本文件不止是"证券边界"，更是 CourtOS **「只在能负责的边界内回答」** 这条纪律的**首个实例**。
> 证券是第一个被登记的"不敢直接答"领域；框架要能容纳第二、第三个。

**原则**：任何领域问题在被路由到具体蜂群/部门**之前**，先过一道**领域准入闸**——
问一句：**"这是否属于 CourtOS 敢承担后果的领域？"**

- **敢（in-scope · 可担责）** → 正常路由到对应部门/flow，给出决策支持。
- **不敢（越界 · 需持牌 / 高责任 / CourtOS 无资格定论）** → **fail-fast**：
  - 不硬塞给"最像的蜂群"（**禁兜底 opc**）；
  - 不出直接结论；
  - 重构为「信息整理 + 风险清单 + 待补信息 + 建议持牌/人工确认」；
  - 标 `domain_not_admitted` / `needs_clarification`，前端显示"超出可负责边界，需重新分派 / 人工"。

**为什么这是护城河（段永平）**：「不知道就说不知道」不是能力缺陷，是 CourtOS 的本分与信任来源。
一个什么都敢答的系统不可信；一个清楚自己边界的系统，才敢被托付真决策。

|---|---|---|---|---|---|

## 1. 一句话结论

**CourtOS 上线 P0 阶段，不提供任何个股的买入、卖出、加仓、减仓、仓位建议。**

证券投资交易决策属于持牌专业范畴；CourtOS 只做**信息整理、风险提示、决策支持**，不出买卖结论。

---

## 2. 户部（finance）**允许**处理的范围

户部处理的是**企业经营财务**，包括：

- 企业财务分析
- 预算
- 现金流
- 毛利
- 营收
- 回款
- 成本分析
- 项目 ROI
- 企业经营投资回报
- 非个股类的经营投资决策分析

口径：**主体是"企业经营"，对象是"经营财务指标与决策"**。

---

## 3. 户部**禁止直接**处理的范围

以下一律**不由户部直接出结论**：

- 个股买入建议
- 个股卖出建议
- 加仓建议
- 减仓建议
- 仓位建议
- 荐股
- 证券投资组合建议
- 针对具体股票的交易决策

口径：**对象是"二级市场个股/证券交易决策"的，全部越线。** 「户部」这个部门前缀**不能覆盖**这条证券红线。

---

## 4. 遇到证券投资类问题时的正确行为

系统应当：

1. **不进入 `opc`**（市场方案蜂群，与个股投资无关）。
2. **不进入普通 `finance` 直接给买卖建议**。
3. **进入 `securities_advice_risk` / `legal` / `compliance`（刑部/合规/风险门）路由。**
4. **输出风险提示**，并将问题**重构**为：
   - 公开信息整理
   - 财务指标清单
   - 风险因素清单
   - 仓位/交易决策仍需补充的信息
   - 建议咨询持牌专业人士
5. **绝不输出明确的买入 / 卖出 / 加仓 / 减仓结论。**

---

## 5. 示例

**输入：**
```
户部评估:三花智控当前仓位是否该减
```

**❌ 错误行为：**
进入 `opc` 或 `finance` 后，直接回答"是否减仓"。

**✅ 正确行为：**
识别为**证券投资建议风险**，进入合规/刑部/风险门，输出类似：

> "我不能直接给出个股仓位或减仓建议。但我可以帮你整理三花智控的公开财务指标、所属行业风险、估值关注点，以及做仓位决策还需要补充的信息——最终的买卖判断应由你本人或持牌专业顾问做出。"

---

## 6. 路由策略建议

优先级与红线：

1. **`securities_advice_risk` 规则优先于 `finance` 与 `opc`**——证券投资关键词一旦命中，先进合规风险路由，不进经营财务、更不进市场方案。
2. **部门前缀「户部」不能覆盖证券投资红线**：即便用户写"户部评估…"，只要对象是个股交易，仍走证券风险门。
3. **`finance` 只处理企业经营财务，不处理个股交易建议**（见 §2/§3 口径）。
4. **未命中默认不应直接落 `opc`**：应改为 `unknown` / `needs_clarification` / `general_court_intake`（fail-fast + 请求澄清/重新分派），而不是"找个最像的蜂群硬跑"。

> 关键原则（Taleb / fail-secure）：**对一个系统不认识的领域问题，最诚实的产出是"我不知道该派谁，请明确"，而不是让一个不相关的蜂群硬答。** 兜底跑 `opc` 是把"不知道"伪装成"已处理"。
