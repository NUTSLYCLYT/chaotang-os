# 朝堂全院设计总览

> 定稿 2026-07-01。"理一遍所有部门"的总索引。每个部门一份天才设计,统一套**全院文书标准**
> (`schemas/court_doc.json`,机器面)+ **卷宗×现代**视觉基调(人类面,归前端仓 chaotang-web-lyt)。
> 标准与刑部样板见 [xingbu.md](xingbu.md)。

## 设计原则(全院一致)

1. **卖底气,不卖功能**:每个部门给客户的是"敢做某事的底气",不是一堆分析。
2. **一份内容两副面孔**:机器面 `court_doc.json`(喂飞轮/归档/门禁/eval)+ 人类面卷宗(艺术+心意)。
3. **人话在前,法条/数据在后**:结论一行先给,细节渐进展开。
4. **大神分席**:判官(可下结论)+ 顾问(只供视角,RAG 强制),接 `persona_registry`/`gate_conclusion`。
5. **心意三触点**:① 本部门为你挡了/争取了什么;② 留痕已封存(骑缝印护身符);③ 决策不是知识。

## 部门间流向(谁的输出进谁)

- 各部门产出 → **御史**定灯(绿→史馆归档;黄/红→源部门修;黑→**刑部**深查)。
- **丞相**把各部门结论压成一条主线(只调序,**不得改写各部门 item 的 level/原文**)。
- **史馆**归档一切 + 喂自我进化飞轮。**钦天监**在重大/不可逆事前置参谋。

## 落地注意(各 agent 设计时提出的真问题,落地前必看)

- **工部**:`court_doc` 的 `rag_grounded` 对工部语义偏弱(工部靠确定性门非 RAG)→ 落地时 schema 加可选 `deterministic_gated`。
- **兵部/礼部**:异议话术、对外话术也必须过 RAG/red 门,别只对报价/交期设门,否则一线照着说出口的可能是幻觉承诺。
- **锦衣卫**:`detect_change` 的上轮快照本身也要过 vet,否则拿被投毒的旧快照做 diff 会误报异动。
- **丞相**:调序层物理上**不能改写** item 的 level/原文(只能改 order),否则会软化刑部红灯,护身符失效。
- **史馆**:RAG 无源的归档结论标"待考",不得当权威。
