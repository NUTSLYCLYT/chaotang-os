# 兵部 · 天才设计(销售 / 售后 / 客户战情 / 竞品攻防 / 现场推进)

> 定稿 2026-07-01。对齐第一份《刑部设计》与全院文书标准(`schemas/court_doc.json`)。
> 视觉基调延用全院:**卷宗×现代融合** —— 古典骨(令旗/案号/骑缝/楷体)+ 现代肉(灯/卡/渐进展开)。
> 边界:本仓做**机器面(JSON 契约 + 后端链路)**;**人类面(战报卡渲染/CSS/组件)在前端仓 chaotang-web-lyt 实现**。
> 协议定义见 `harness/chaotang_department_protocol/departments.yaml` 的 `bingbu`:销售、售后、客户战情、竞争攻防、现场推进;next 绿→史馆 / 黄→御史 / 红→兵部自回 / 黑→刑部。

## 一、兵部定位

兵部 = 销售人员手里的**底气**,不是催单机器。卖给一线的不是话术,是四个一线最缺的答案:

- **这单现在怎么推进**(下一步具体动作,不是"加强跟进")。
- **客户这条异议怎么拆**(给一句能当场说出口的回应,不是分析)。
- **遇到竞品怎么打**(对方拿什么打你、你的最弱口子在哪、用什么反制)。
- **下一步成交动作是什么**(谁、做什么、卡点是什么、要不要签字)。

兵部不从"我们想卖什么"出发,从**客户真实摩擦**反向工作:把每一次异议、丢单、售后故障,变成下一轮产品优势和下一单的弹药(`genius_design`:从客户真实摩擦反向工作)。

## 二、五个震撼点(接现有资产)

1. **一句话进,一张战报出**:大白话进("客户说太贵了想再看看") → 单屏战报(灯+这单能不能推+Top3 下一步动作/异议拆法+一句话能当场说的回应+自动留痕),SPIN 分析与详细话术藏二级。复用 `flow_haolong`(获客→归档→触达→发布→质检,min_score 3.0)与 `flow_voice_sales`(先提身份/场景/预算/下一问)。
2. **竞品攻防(给这单做红蓝对抗)**:把竞品当"攻击者",模拟"对方销售会拿什么打你"(价格/交期/案例/关系),指出**你这单最弱的口子**和一句反制。复用 `flow_opc` 市场情报专家 + 解决方案架构师 + 冲突仲裁专家(min_score 3.8),产出 `sales_battlecard`。
3. **异议拆解器(chris-voss 上手)**:客户每条异议 → 标注情绪、镜像复述、校准提问("我们怎么才能…"),给一句**可当场说出口**的回应 + 这条异议背后的真实顾虑。不是"你要多沟通",是把话递到嘴边。
4. **售后战情回填闭环(出事不失分,反而长本事)**:`flow_storage_aftercare`(故障分诊→采集→BMS 诊断→失效分析→处置工单,min_score 3.5,`signoff_marker:需人工签字`)的真实结果**强制回填** `customer_outcome`,触发史馆归档 + 钦天监复盘;召回/安全/赔付承诺必须落刑部签字。售后不是成本,是下一单的信任资产。
5. **成交弹药做成产品(commercial_golden_case)**:赢单/拆解成功的异议/打赢竞品的话术,人工 `promote` 成 `commercial_golden_case`,写入 `production_events`,下次同型客户直接复用;只能人工 promote/reject,杜绝把侥幸当套路。

## 三、销售战情团(销售/售后大神,带知识库)

复用大神体系(分席/RAG/eval),建一个**销售售后分支**(profile `sales_aftercare`,见 `config/advisor_protocols.yaml`,四席:aaron-ross / neil-rackham / chris-voss / charity-majors):

- **判官席(定灯 + 定下一步动作)**:
  - **neil-rackham(SPIN)**:用 情境→问题→暗示→需求-效益 判断**这单的真需求成不成立**——需求-效益没到位的单,灯压黄,先补需求确认,不许盲目推进。
  - **chris-voss(谈判)**:判**异议能不能拆、底线在哪**——给镜像/标注/校准提问,给一句可落地回应;无可拆路径或触及红线承诺,灯压红/黑。
- **顾问席(供弹药,不拍板)**:
  - **aaron-ross(可预测营收)**:线索分层、专业化分工、pipeline 是否健康,判断**这单值不值得投入、什么时候该放**,给可预测的推进节奏。
  - **charity-majors(可观测)**:售后战情的**实时健康度**——客户活跃度/故障复发/流失前兆的观测信号,把"客户快不行了"在丢单前点亮。
- **销售铁律(RAG 强制 `gate_conclusion`)**:涉及报价、交期、ROI、安全能力的结论,**一律不许大神自由发挥**——必须回链 `flow_quotation`(户部/兵部,irreversible,无依据数字/单点报价/交期承诺一律 blocked)与礼部话术复核。**幻觉承诺比不承诺更危险:一句没依据的"我们能做到",赔的是真金白银。**
- 每位配 golden 商业案例,过 `persona_eval` 才升判官,同一套飞轮。

## 四、文书:兵部战报(套全院文书标准)

### 4.2 人类面 —— 卷宗×现代渲染(战报 + 底气)

同一 JSON 渲染成有仪式感、可当场用的战报卡(人类面在前端仓实现):

```
┌───────────────────────────────────┐
│ 🚩 兵部战报        〔令旗印〕案号BB-031 │   ← 楷体标题 + 赤橙令旗官印
│ ─────────────────────────────────── │
│ 🟡 可推进·先拆 1 条异议               │   ← 红黄绿灯,结论一行在前

│  1🔴 "太贵了想再看看" 高×¥120万        │
│     →当场说:"是预算,还是怕落地不达预期？"│   ← 递到嘴边的话
│  2🟡 补现场POC,把验收标准写死          │
│  3🟢 竞品X低价无本地售后→打4h响应牌      │
│ ─────────────────────────────────── │
│ 竞品攻防:对方主攻价格,你最弱口子=没算售后值多少钱│  ← 红蓝对抗

│ [用这句回应] [约POC] [核报价] [回填结果] │
```

### 4.4 心意三触点

1. 开头"**兵部为你争取/挡了什么**"——把推进价值说出来(挡了一次盲目降价、争取了一次现场 POC)。
2. 落款"**战报已封存**"骑缝令旗印——每条战情可追溯、可复盘、可变弹药。
3. 结论永远**下一步动作在前、SPIN 分析/详细话术在后**——一线要的是"现在说哪句、做哪步",不是销售理论。
