# 大神评审团 · 架构评审纪要（2026-06-03）

> L5 Persona 层对 jiqun_ai 整体架构的一次评审。5 位大神（芒格 / 塔勒布 / 贝佐斯 / 乔布斯 / Karpathy）
> 各自基于其 `skills/personas/` 人格、独立阅读 `docs/jiqun_architecture.md` + `config/jiqun_registry.yaml` 后给出。
> 免责：persona 为基于公开言论的视角推断，非本人观点。

## 一句话收敛

5 位大神从不同角度撞到同一诊断：**"脚手架建在地基浇好之前"（Karpathy）**——
系统在生产文档而非结果（芒格），在模拟官僚而非解决问题（塔勒布）。

## 最高共识（多位大神撞车 → 最高优先级）

### ① IMA 从"档案柜"翻转成"飞轮入口"（芒格 + 贝佐斯）
现状 IMA 是尾部 `archive_only`，每次蜂群从零开始 → **复利 = 0，系统无记忆**。
**改**：每个核心蜂群**启动前先查 IMA** 注入历史教训；归档可懒，查询必须强制；先在 1 个蜂群（sourcing）试点（双向门，可逆）。

### ② eval 是"自己给自己判卷"的幻觉（Karpathy + 芒格）
LLM 给 LLM 打 `total_score≥4.0`，测的是模型自信心而非现实质量；20 大神评审只是把 1 个回音室扩成 20 个。
**改**：建 golden eval set（人类专家打分 50-100 例）→ 算 LLM 打分 vs 人类的 Spearman ρ，<0.6 即不可信；接真实 KPI（线索转化率 / 方案采纳率）当"真北"。

### ③ 概念过载 / 层数过多 → 先证明值得，否则砍（乔布斯 + 塔勒布 + Karpathy）
三人独立得出"先证明复杂度值得"。Karpathy 第一性原理估算：20+ 步串联 LLM、单步 0.85 成功率 → 端到端 ≈ **1.7%**。
**改**：每个蜂群先做 **single-model baseline**（一个强模型一个 prompt 做同样任务），用数字证明"6 层编排比单模型强多少"；证明不了的层就是塔勒布说的"自己制造的脆弱"。

### ④ 委员会稀释责任（芒格 + 乔布斯）
"20 大神全上 = 没人负责 = 最低公分母。"
**改**：按 `risk_level` 路由——低→1 个最相关 persona；高→最多 3 个且必须给明确 go/no-go；critical→全委员会但要有**主席最终裁决**，禁止"汇总共识"。

## 各自独有的尖锐刀

| 大神 | 独家狠话 |
|---|---|
| **塔勒布** | ① LiteLLM 单网关 = **伪多样性的单点风险**（关键蜂群各持独立备用接入）② Critic **没 skin in the game** → 否决要有牙齿（强制覆盖+署名+追踪后果）③ 反脆弱：**强制归档失败路径** + 定期混沌注入（模拟模型断路） |
| **贝佐斯** | "每个会议室留把空椅子给客户——你这系统里没有空椅子"（定义 3 个客户结果指标）；轻任务该**旁路 Court**（court_bypass 标签，别用单向门节奏处理双向门） |
| **Karpathy** | **prompt 是源代码但 0 版本控制**（建 test case bank + 回归）；"你以为在建可观测系统，其实在建无法 debug 的黑盒"（定义中间诊断指标） |
| **芒格** | 能力圈检查：**从没验证人类实际怎么用**——动架构前先找 3 个真实用户录屏；把衡量标准从"流程完整性"换成"决策采纳率" |

## 如果只做 3 件事

1. **建一个真 eval**（人类锚 + 真实 KPI）——否则所有质量分都是幻觉。
2. **IMA 翻转成入口**——系统唯一的复利引擎。
3. **每个蜂群先有 single-model baseline**——用数据决定哪些层/蜂群该留该砍。
