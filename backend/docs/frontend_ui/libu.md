# 礼部 · 前端 UI 详细策划（策案/话术卡）

> 定稿 2026-07-01。本文是**礼部人类面渲染契约**，给前端仓 `chaotang-web-lyt`。
> 后端只产 **court_doc(机器面 JSON，`schemas/court_doc.json`)**；本文把礼部的 `doc_type=brief` 那份 JSON
> 画成「卷宗×现代」的**策案/话术卡**。设计真相源：`docs/dept_design/frontend_handoff.md`（渲染契约）+ `docs/dept_design/libu.md`（礼部业务）+ `docs/dept_design/README.md`（印章表）。
> 纪律：**统一骨架，各部门换印换色**——礼部不另起一套卷宗组件，只在共享 `<CourtDocCard>` 上挂礼部配置 + 3 个礼部特有插件（多版本话术 tab / 禁忌词高亮 / 一键采用）。

礼部官印=**礼器印**，主色=**青**（建议 token：`--seal-libu: oklch(62% 0.09 195)` 青，可按实测调），doc_type=`brief`，case_id 前缀 `LB-`。

---

## ① UI 定位（这张卡到底替客户决定什么）

礼部不是文案外包，是客户的**对外底气**。这张话术卡要在一屏内回答客户三件事：

1. **说什么打动客户**：从 Top 列表里挑出「最能打动这个客户」的 1-3 条卖点（接兵部 `haolong`/`opc` 真实摩擦倒推，不堆参数）。绿项=有素材撑、可直接用；这是「敢说」。
2. **会不会踩雷**：把绝对化用语、无依据 ROI/交期承诺、贬损竞品、诱导话术，在发出去**之前**红线拦下（御史 red 门产品化）。硬声明（数字/ROI/交期/资质）无素材支撑必标红——这是「不踩雷」。
3. **挑哪个版本发**：同一句对外话术给 2-3 个语域（稳重/亲和/专业），客户挑着用，挑完一键采用、签字后发、自动归档——这是「多版本可选」。

设计铁律（礼部克制是产品级的）：
- **客户看完应该知道下一步，而不是被话术绑架。** 结论一行先给，品牌规范/法条藏二级。
- **幻觉话术比没话术更伤客户信任。** 任何没接地的硬声明绝不渲染成「可直接发」的绿态。

## ③ 组件清单（共享卷宗 + 礼部特有）

### A. 共享组件（全院 11 部门复用，礼部直接吃，不重写）

| 组件 | 吃的字段 | 说明 |
|---|---|---|
| `<CourtDocCard dept="libu">` | 整份 court_doc | 卷宗外壳，注入礼部印/主色配置 |
| `<SealStamp>` | `seal.stamp` `seal.color` | 右上礼器印 + 青；`sealed_archive` 非空时叠骑缝朱（青）印 |
| `<LightBadge>` | `light` | 红黄绿黑灯 + 整卡边框色 |
| `<Headline>` | `headline` | 一级结论楷体大字 |
| `<ShieldedNote>` | `shielded` | 「为你争取了」心意条，高亮小字；为 null 时不渲染 |
| `<ItemList>` | `items[]` | 渐进展开列表，红项置顶，`odds`/`impact` 右对齐，`fix` 折叠二级，`evidence_ref` 出「看证据」链 |
| `<GroundingTag>` | `provenance.grounding` | rag→「素材/法条接地」、deterministic→「重算接地」、none→灰条「未接地·需人工」 |
| `<GatePending>` | `provenance.gate` | =pending 时盖「需人工复核」半透印，禁绿（见④） |
| `<ActionBar>` | `actions[]` `signed` | 底部按钮；不可逆动作 `signed=false` 时置灰 |
| `<ArchiveSeal>` | `seal.sealed_archive` | 骑缝印 + 史馆封存号；为 null 时不显 |

### B. 礼部特有组件（仅 3 个，因为「话术」这件事别部门没有）

| 组件 | 触发字段 | 行为 |
|---|---|---|
| `<ToneVariantTabs>` | `actions[]` 含 `pick_tone_variant` | 语域切换 tab：稳重/亲和/专业。**字段来源说明见下方注**。切 tab 只换正文区文本，不重拉接口；当前选中态记进 URL（`?tone=warm`）便于分享 |
| `<TabooHighlight>` | `items[]` 中 `level=red` 且属禁忌类 + 正文文本 | 在话术正文里把命中的禁忌/夸大词**红底高亮**，悬停弹该词对应 item 的 `fix`（「改成…」）；可跳到 Top 列表对应红项 |
| `<AdoptVariant>` | `actions[]` 含 `apply_fixes`/`pick_tone_variant` | 「一键采用」：把当前语域版本 + 已应用的 fix 合成最终稿，复制到剪贴板 / 回填发布框（接 `xiaohongshu`/`opc`），并标记待签字 |

> **务实提醒（多版本字段来源）**：当前 `schemas/court_doc.json` **没有**专门的多版本话术数组字段，`items[]` 的语义是「卖点/红线条目」，不是「同一句的 N 个语域版本」。前端落地前**必须与后端确认**变体正文的承载方式，二选一：
> 1. 后端在 brief JSON 里加可选字段（建议 `variants: [{tone, text}]`，约定 tone∈{steady,warm,pro}）——**推荐**，前端直接渲染；
> 2. 后端不加，前端先用单一正文（取 `headline`/某 item）渲染，`<ToneVariantTabs>` 降级为「仅 1 个版本」灰显，等后端补字段再开。
> **不要为了画面好看而前端编造三个版本**——那正是礼部要拦的「幻觉话术」，会自打嘴巴。

## ④ 状态（灯 / 闸 / 接地三态联动）

礼部状态由 court_doc 三个字段共同决定，且**门禁优先于灯**（守宪法 C6 禁假 PASS）：

| 来源字段 | 取值 | 卡片表现 |
|---|---|---|
| `light` | `green` | 青绿边框，结论「可直接发」 |
| `light` | `yellow` | 黄边框，结论「可发·须改 N 处」（礼部最常见） |
| `light` | `red` | 红边框，结论「踩红线·禁发，先改」；红项置顶 |
| `light` | `black` | 黑边框，「已落刑部深查」，话术区只读 |
| `provenance.gate` | `pending` | **盖「需人工复核」半透印，整卡禁绿**，即便 light=green 也降级为「待核」黄态显示；`publish_after_sign` 置灰 |
| `provenance.gate` | `blocked` | 红条「御史封驳·禁发」，`actions` 仅留「一键改/存档」 |
| `provenance.gate` | `passed` | 正常按 light 渲染 |
| `provenance.grounding` | `none` | 灰条警示「未接地·需人工确认」，命中的硬声明强制标红，不得显示「可直接用」 |
| `provenance.rag_grounded` | `false` | 同上，话术正文加「素材待补」角标 |
| `signed` | `false` | 「✍ 签字后发」等不可逆动作置灰；卡角「未签字」水印 |
| `source_label` | `DEMO`/`FALLBACK` | 顶部细条标「演示/兜底数据，勿据此对外发布」 |

**联动口诀（实现校验点）**：`gate=pending || grounding=none` ⇒ 永不绿、永不出现「可直接发布」措辞、`publish_after_sign` 必置灰。这是硬约束，写成组件级断言。

## ⑤ 交互（复杂度分档 P0-P3 + 多版本对比 + 复制）

按本仓管线复杂度分档思想，前端交互也分档，避免对琐碎任务上全套：

- **P0 看一眼**：卡片折叠态——只读 light + headline + shielded 一行。无任何写操作，适合列表/通知流里快速扫。
- **P1 展开读**：点 Top 列表展开 `fix`/`evidence_ref`；切换语域 tab 看不同版本；禁忌词悬停看改法。**全是读，无副作用，不弹确认。**
- **P2 改与采用**：
  - 「一键改」=按 item.fix 应用建议改写，正文区 diff 高亮（改前删除线 / 改后高亮），可逐条接受/撤销；
  - 「选版本 + 一键采用」=锁定当前语域版本，复制到剪贴板或回填发布框；
  - 这些是本地态变更，**可撤销**，不弹重确认。
- **P3 不可逆**：「✍ 签字后发」=触发签字流（守 `signed`）；签字前置灰，签字后才可点；点后二次确认弹窗显示「将对外发布 + 自动归档史馆」。发布与归档是不可逆动作，必须人工签字态。

**多版本对比**：`<ToneVariantTabs>` 默认单视图切换；提供「并排对比」开关，把 2-3 个语域版本左右并排，禁忌词高亮在每列各自标注，方便客户挑。对比视图只读，挑定后回单视图再采用。

**复制话术**：每个语域版本正文右上角「复制」按钮（复制纯文本，**剥离高亮标记但保留已采纳的 fix**）；复制时若仍有未处理红线项，toast 提醒「含 N 处未改红线，确定复制？」——不阻断，只提醒（不绑架客户）。

## ⑥ 空 / 加载 / 错误态

| 态 | 触发 | 表现 |
|---|---|---|
| 加载 | 等 `POST /api/libu/brief` 返回 | 卷宗骨架屏（印章位 + 灯位 + 列表位灰条），保留卷宗外形，不要白屏 |
| 空·无条目 | `items=[]` | 显示 headline + shielded，列表区显「本稿无待改项，可直接挑版本发」（仅当 gate=passed 且 grounding≠none 才允许这话） |
| 空·无变体 | 后端未提供 `variants`（见③注） | tab 降级为单版本灰显，提示「暂仅 1 个语域版本」 |
| 错误·接口失败 | 5xx / 超时 | 卡内错误条「策案生成失败，已记录」，提供「重试」；不展示半截话术 |
| 错误·校验失败 | court_doc 缺 required 字段 / 灯-闸矛盾 | **降级为安全态**：按红/待核渲染，禁所有发布动作，错误细节折叠给开发；绝不放行 |
| 部分接地 | 部分 item `evidence_ref=null` | 该项标「素材待补」，不阻断整卡，但禁「可直接发」 |

错误处理原则（接全院编码规范）：宁可显式「需人工」也不静默放行；任何不确定一律降级，不向乐观方向猜。

## ⑦ 响应式

复用全院断点（与 web 规则一致）：320 / 375 / 768 / 1024 / 1440。

- **手机 (≤480)**：单列纵向流。语域 tab 横向可滑；「并排对比」自动改为上下堆叠；ActionBar 吸底固定，主操作（签字后发）占满宽。禁忌高亮正文区可纵向滚。
- **平板 (768-1024)**：卡片居中限宽 ~720px；对比视图最多 2 列并排。
- **桌面 (≥1024)**：卡片限宽 ~760px 居中（话术是阅读密集型，别拉满宽）；对比视图 3 列并排；Top 列表与正文左右分栏可选。
- 触控：tab/高亮词/展开箭头命中区 ≥44px；悬停态（禁忌词改法）在触控端改为点按弹出。
- 动效仅用 transform/opacity（展开、tab 切换淡入）；尊重 `prefers-reduced-motion`。

## ⑧ 对接 chaotang-web-lyt

- **归属**：本卡的 CSS/组件/E2E 全在 `chaotang-web-lyt` 实现，**不在本后端仓**。本文件只是渲染契约。
- **数据**：调后端 `POST /api/libu/brief` → 返回符合 `schemas/court_doc.json` 的 brief JSON（`doc_type=brief`/`dept=libu`）。前端按 schema 校验后渲染，缺字段走⑥降级。
- **组件复用**：必须用全院共享 `<CourtDocCard>` 等组件（见③A），礼部仅注入 `dept="libu"` 配置（礼器印 / 青主色）+ 挂 3 个礼部特有插件（③B）。**不得为礼部 fork 一套卷宗组件**（守 frontend_handoff §三「统一骨架，各部门换印换色」）。
- **印章/主色配置**：在前端的「印章品牌系统」配置表里加一行 `libu → {stamp:'礼器印', color: 青 token}`，与刑部天平印/朱砂红同表驱动。
- **发布链路**：「一键采用 / 签字后发」回填到 `xiaohongshu`/`opc`/客户消息发布框（接发布链路），由前端发布门禁 + 后端 release_gate 双重把关。
- **渲染纪律（照搬 frontend_handoff §四，落地必守）**：
  1. `gate=pending` / `grounding=none` → 绝不渲染成绿/通过，显式「需人工」。
  2. 丞相主线（doc_type=edict）里引用礼部灯**照搬不改**，前端不得美化成更乐观。
  3. `signed=false` 的发布动作置灰，签字态才可点。
  4. 法条/品牌规范默认折叠，一屏先给结论。
- **未决项（给前端的待办）**：多版本话术的字段承载方式需先和后端定（③注，推荐后端加 `variants`）；在此之前 tab 走单版本降级，不前端编造。

## 验证建议（前端仓内）

- 视觉回归：320/768/1440 三断点截图，覆盖 yellow（最常态）/red/gate=pending 三种关键态。
- 断言测试：`gate=pending` 或 `grounding=none` 时，DOM 中不得出现绿灯类名、不得出现「可直接发布」文案、`publish_after_sign` 按钮 disabled。
- 可访问性：语域 tab 键盘可达、禁忌高亮有 aria 标注、reduced-motion 生效。
```
