# 🎯 户部 · 后端第一张任务卡（最小可验证）

> 这不是"实现户部后端"。这是**一个 30 分钟能验证的小目标**——让闭环先转一格。
> 德鲁克：一份 200 行的完美工单，不如一张能立刻开工、立刻验证的小卡。

---

## 目标（一句话）

**让前端户部右栏「✅ 已办 · 价值」显示一条真实数据**——哪怕只有一条真省税记录或一条真对账差错金额。

## 为什么是这张卡（先转一格，再谈全套）

前端右栏「已办·价值」现在是诚实占位：`税务 · 本月省税 ¥— 待接 outcome 账`。
它一旦显示**第一条真数字**，朝堂的核心承诺（裁决→兑现→回灌）就**第一次真转了一格**。
这比前端再开 8 个占位 board、或后端等齐全套数据，值钱十倍。

## 范围

**DO（就做这些）**
- 产出**一条**真实 outcome 记录：`{ office, label, valueYuan, sourceLabel, completedAt, evidenceRef }`。
  例：`{ office:'税务', label:'本月合法节税', valueYuan:12000, sourceLabel:'LIVE', completedAt:'2026-06-27', evidenceRef:'<可追溯依据>' }`
- 暴露一个最小读端点（二选一）：
  - A：扩 `GET /api/court/hubu/overview` 的返回，加可选 `outcomes: HubuOutcome[]`；或
  - B：新增 `GET /api/court/hubu/outcomes` 返回 `HubuOutcome[]`。
- 这条记录的数字**必须真**（来自真实税务/对账计算），带 `sourceLabel` 和可追溯 `evidenceRef`。

**DON'T（先别做）**
- 不做完整 outcome 账系统、不做任务态、不做全部 7 司。
- 不造假数字凑数（宁可这张卡延后，也不给假 LIVE）。

## 契约（前端按这个读）

```ts
interface HubuOutcome {
  office: string;        // '税务' | '出纳' | ...
  label: string;         // '本月合法节税' | '查出对账差错'
  valueYuan: number;     // 真实金额（元）
  sourceLabel: 'LIVE' | 'LIVE_SWARM' | 'MIXED' | 'FALLBACK' | 'DEMO';
  completedAt: string;   // ISO 日期
  evidenceRef?: string;  // 可追溯依据（审计用）
}
```

## 前端配合（几行，确保端到端可验证）

前端 `src/features/hubu/components/hubu-activity-rail.tsx` 的「已办·价值」段，
现在是写死的 `PlaceholderRow`。后端端点就绪后，前端改成读 `outcomes`：
有真数据 → 显示 `office · label ¥valueYuan`（带 sourceLabel 灯）；为空 → 维持"待接"占位。
（前端这步约 15 行，前端团队接。）

## 验收（30 分钟判据）

- [ ] 后端能返回**至少一条** `HubuOutcome`，`valueYuan` 是真实计算值、`sourceLabel:'LIVE'`、带 `evidenceRef`。
- [ ] 打开 `http://localhost:3002/chaotang/departments/finance`，右栏「✅ 已办·价值」显示这条真记录（不再是 ¥—）。
- [ ] 这条记录的 `sourceLabel` 如实（真就 LIVE，兜底就 FALLBACK，禁伪装）。
- [ ] 能从 `evidenceRef` 追溯到这条省税/对账的真实依据。

## 纪律（不可违反）
- **sourceLabel 不撒谎**（铁律13.2）：真 LIVE、兜底 FALLBACK、演示 DEMO，禁伪装。
- **缺证显性**：没有真数据就维持"待接"占位，不编。
- **可追溯**：每条 outcome 带 evidenceRef，审计能查。
