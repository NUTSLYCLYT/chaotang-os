# 成本收敛 · 交主工头(2026-06-29)

> 依据:`docs/部司蜂群-去重架构-SoT.md` §四C + 铁律6。这是 6 部唯一的真重复(成本 pack_rd 三处算)。
> 户部是主工头地盘(铁律13.2.10),架构方不直接改,此为收敛方案。

## 问题(取证)
成本/pack_rd 真算同时在 3 处:
- 户部:`hubu/lib/bom-cost.ts`、`price-library.ts`、`sales-price-library.ts`、`real-decisions.ts`
- 工部:`gongbu/lib/battery-products.ts`(咨询底座,已标"非锁价")、`gongbu-feasibility-envelope.ts`
- 后端:`jiqun pack_rd_sizing.py` / `pack_rd_cost_validator.py`(真产线)

三套成本数 → 谁对?改一处其余腐烂(铁律3 最危险的中间态)。

## 收敛方案(一个领域一个 owner)
1. **真算归后端一处**:pack_rd 成本拆分/sizing 真算 = 后端蜂群(经 `gongbu-pack-bridge` → `live-swarm-adapter`,已建)。
2. **前端两部降为"读者+视角"**:
   - 户部读**财务视角**(NPV/IRR/现金缺口/回收期)——基于后端成本数做财务判断,不自己拆 BOM 成本。
   - 工部读**交付视角**(BOM 物料/sizing/交期)——`battery-products` 保持"选型/查规格"咨询底座,不算 split。
   - **两部读同一份后端 pack_rd 结果**,删除前端各自的成本拆分重算。
3. **判据**:收敛后 grep `成本拆分`/`pack_rd` 只剩后端一处真算 + 前端"调用/展示"。

## 落地步骤(主工头)
1. 后端 pack_rd 暴露成本端点(若未暴露)——`gongbu-backend-bridge` agent 对接。
2. 户部 `bom-cost` 等:把"自己拆成本"改为"调后端 pack_rd 取成本 + 财务视角加工"。保留财务引擎(NPV/IRR),删成本拆分重算。
3. 工部 `feasibility-envelope`:成本部分改读后端,不前端算。
4. 验证:① 双门 tsc+build ② 一条回归断言「成本只有一处真算源」(铁律4) ③ 户/工成本数一致(读同源)。

## 边界
- 铁律9:真算后端,前端只调+视角展示。
- 铁律2:成本数据结构走 contracts,不各立平行。
- 不动户部财务引擎本身(NPV/IRR 是户部财务视角的真价值,保留);只收敛"成本拆分"那段重复。
