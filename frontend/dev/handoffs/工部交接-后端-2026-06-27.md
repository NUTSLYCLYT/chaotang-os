# 工部 · 后端交接文档

> 收件人：jiqun 后端团队（`jiqun_ai_fresh`） ｜ 前端主仓：`chaotang-web-lyt`
> 日期：2026-06-27 ｜ 状态：前端工部 M0-M2 已建成，决策层(定性/分类/产线锁/会审)已真，**真数据全等后端**
> 核心边界：铁律9 —— 工部触真实产线资产(成本/BOM/交期/报价/供应商/毛利)，**前端整字段上锁、转后端**。

---

## 0. 一句话
前端工部能做的定性层（分类、定性裁决、产线锁、对外承诺门、跨部会审、真进度展示）已全做真。
但工部的**真数据几乎全在后端**——建设任务、真实可行性、真进度、真产线核算，全靠 PACK 研发蜂群兑现。

## 1. 前端已有的契约（后端往这里灌真数据）
- 决策队列数据源 = `GET /api/court/backend/tasks`（已读 jiqun 持久化 / primary DB）。前端期望每条：
  `{ id, taskId, title, description, rawCommand, status, progressPct, createdAt, updatedAt }`。
- 工部 CTO/CPO 八司结构 = `src/core/courtos/gongbu/gongbu-types.ts`（已设计：8 司 + 11 交付问题类型 +
  圣裁准奏/补证/复核/驳回 + 缺证 + 生成物含 forbiddenActions/requiresHumanConfirmation/requiresCrossReview + sourceLabel）。
- 可行性引擎 = `gongbu-feasibility-envelope.ts`（已有：LIVE_SWARM vs FALLBACK 判定 + `stripProductionFields` 产线字段剥离）。
- 可行性 BFF = `POST /api/court/dept/gong-bu/feasibility`（已有）。

## 2. 后端工单（按优先级）

### P0 · 让队列有真建设任务 + 真进度
**痛点**：`/api/court/backend/tasks` 当前常空（蜂群未起），前端队列空、态势灯显「兜底」。
**要做**：PACK 研发蜂群把真实建设任务写入持久化，带真 `status` 与 `progressPct`。
**解锁前端**：决策卷轴有真任务、右栏「在办进度」真进度条、「已交付」真完成、产线锁全景真聚合。

### P0 · 真实可行性兑现（LIVE_SWARM）
**痛点**：前端只能给定性「能不能造」，真实可行性需蜂群兑现。
**要做**：`buildFeasibilityEnvelope` 接真 jiqun `/api/swarm/run` 返回可追踪 session + reverify 验真 → `LIVE_SWARM`。
**解锁前端**：架构司「技术可行性」从"待接"变真；可行性会诊真链。

### P0 · 产线资产核算（铁律9 后端侧）
**铁律9 分工**：真实成本/BOM/交期/报价/供应商/毛利 **由后端持有与核算**；前端只拿到「字段名 + 锁」，不拿值。
**要做**：这些产线资产的真实计算在后端；对外承诺/交期/价格的写回**必须过人工确认门**（不可逆，铁律13.2.5）。
**解锁前端**：产线锁全景显示真实"锁了哪些"；承诺门真生效。

### P1 · 方案/PRD/API 契约生成
**要做**：工部生成物（技术方案、PRD、API 契约）由后端蜂群生成，带 sourceLabel + requiresCrossReview。
**解锁前端**：架构司「产出」从占位变真生成物（带跨部会审需求）。

## 3. 三引擎/裁决口径一致
前端 `gongbu-engines.ts`（分类 + 产线锁 + 对外承诺 + 跨部会审 + 定性裁决）**仅用于无副作用展示**；
后端产线版应**镜像同一裁决口径**（准奏/补证/复核/驳回）+ `gongbu-types.ts` 的 8 司分工。两端口径必须一致（SSOT）。

## 4. 必守纪律（前后端契约）
- **铁律9 产线锁**：真实产线资产前端整字段上锁，后端持有/核算；对外承诺写回过人工门。
- **sourceLabel 不撒谎**：LIVE_SWARM/FALLBACK 真标；蜂群未兑现禁伪装 LIVE。
- **接口**：触真实产线/交付 → HTTP 转 jiqun `:8081`（`/api/swarm/run`），经 `@/lib/upstreams` courtosFetch。
- **缺证显性**：可行性未兑现 fail-fast / 明列缺证，禁静默。

## 5. 建议的后端第一步（最小可验证）
让 PACK 研发蜂群把**一条真实建设任务**写进 `/api/court/backend/tasks`（带真 status + progressPct），
打开 `/departments/gongbu` → 中栏卷轴出现这条真任务、右栏「在办进度」显示真进度条。
一条真任务带真进度 > 前端再堆 board。
