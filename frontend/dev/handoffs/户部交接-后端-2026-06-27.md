它们变真**全卡在后端的数据与能力**。本文把这些"待接"翻成后端工单，按优先级排。

## 1. 前端已有的契约（后端往这些结构里灌真数据即可）

前端数据源 = `GET /api/court/hubu/overview`（前端 BFF，现已接 Turso）。返回 `HubuOverview`：
```ts
// src/lib/contracts/hubu.ts（前端 SoT，后端按此供数）
HubuOverview = { summary: HubuSummary; projects: HubuProject[]; llm_advice }
HubuProject  = { id, title, requested_budget, estimated_roi, payback_window,
                 cash_flow_pressure, priority(P0/P1/P2), risk_level(low/med/high/critical),
                 status(pending_review/approved/needs_rework), recommendation, command,

                 cash_reserve, recommendation, source('turso'|'fallback') }
```

## 2. 后端工单（按优先级，每条标"它解锁前端哪块"）

### P0 · 让数字变真（最高杠杆）
**当前痛点**：`overview` 的 `projects` 多是军机处指令种子，`estimated_roi`/`cash_flow_pressure` 常为"—"
（见 `overview/route.ts` 用正则从命令文本抽 budget/roi，抽不到就"—"，cash_flow_pressure 硬编码"—"）。
**要做**：让户部 `projects` 承载**真实财务项目**——真预算金额、预期回报、现金流影响、成本明细。
**解锁前端**：拍板卡 ROI/敞口/评分/裁决从"缺证"变真值；投资/预算四象限点散布到绿黄灰红；优先级排序有意义。

### P1 · 税务（<1000万 老板的杀手功能，但后端缺）
**当前痛点**：`HubuFinanceQuestionType`（hubu-types.ts）为大公司而建，**没有"税务"类**。
**要做**：① 枚举加 `税务申报与筹划`；② 供税负测算数据（各税种应交、报税日历、合法节税机会）。
**解锁前端**：税务司 board 从占位变真；左栏"本月省税 ¥X"高光（自带 ROI 钩子，让小老板愿付费）。

### P1 · outcome 账 + 任务态（让部门"活"起来）
**当前痛点**：右栏「在办进度」「已办·价值」是诚实占位"待接任务态/outcome账"。
**要做**：① 任务态——哪个司正在处理什么 + 进度；② outcome 账——处理产出 + 价值数字（省税 ¥X、查出对账差错 ¥Y）。这正是朝堂主闭环的 **outcome 回灌**（裁决→兑现→史馆→下次引用）。
**解锁前端**：右栏从占位变真实活动流，部门真正"活"起来。

### P2 · 真账 board（会计/成本/内审）
**要做**：损益表/成本 BOM/审计凭证等真账数据。
**解锁前端**：会计/成本/内审司 board（现占位）。

### P2 · 市场 feed（投资③ / 融资利率）
**要做**：实时行情、对标 ROI、利率、汇率源。
**解锁前端**：投资司③市场信息、融资利率走势（现标"待接行情源，不画假 K 线"）。

### P0 · 拍板写回（真实产线动作，铁律9 必后端）
**当前**：前端准奏/削减/驳回是**意向占位**（不写回）。
**要做**：拍板 → 真实记账/付款/承诺，**经后端验签**；HTTP 入口走 jiqun `:8081`（前端 `courtosFetch`，禁前端自建第二套产线 flow）。

## 3. 三引擎：前端咨询版 vs 后端产线版
前端有纯函数咨询版 `hubu-engines.ts`（ROI/风险敞口/优先级评分→四裁决 + 四象限 + 单向门检测），
**仅用于无副作用咨询展示**。后端产线版应**镜像同一套裁决逻辑**但接真账：
- ROI/NPV/IRR/DCF 现值 **需现金流序列**（前端只有回报倍数，标了"待接"）。
- 风险敞口、优先级评分、四裁决规则见前端 `hubu-engines.ts` / 遗产 `docs/legacy-os-reference/HUBU_BUDGET_PLATFORM_DESIGN.md` §4-5，可直接对齐。
- **裁决口径必须两端一致**（SSOT），否则前端展示与后端写回会打架。

## 4. 必守纪律（前后端契约）
- **sourceLabel 不撒谎**：所有产出标 LIVE/LIVE_SWARM/MIXED/FALLBACK/DEMO，经 reality-state 归一；DEMO/FALLBACK 禁伪装 LIVE（铁律13.2）。前端据此显示真假，后端不得给假 LIVE。
- **单向门人工门**：前端已检测预付/独家/大额并提示"需亲裁"；**后端写回时必须强制人工确认门**，禁一键静默采纳（铁律13.2.5）。高危=股权/合同/法律/重大付款/对外报价/供应商锁定/独家/违约金/预付。
- **缺证显性**：后端答复缺数据时 fail-fast 或明列缺证，禁 `?? code` 静默回退（铁律2）。前端会如实展示缺证。
- **接地率**：`/ask` 已有数字接地校验；后端 LLM 答复每个数字须可挂证据，未挂触发 reprompt。
- **特权写入同门**（铁律1）：写台账/付款/承诺的鉴权与写入在同一道门；禁前端 decode-only 放行直写。
- **领域枚举 SSOT**（铁律2）：司码/问题类型跨前后端单一真相源，禁平行 map / 静默回退。

## 5. 接口约定（前端怎么调后端）
- 前端 BFF（`/api/court/hubu/*`）作适配层，**不自建产线**；触真实产线资产即 HTTP 转 jiqun `:8081`（如 `/api/swarm/run`），统一经 `@/lib/upstreams` 的 `courtosFetch`（禁裸上游 URL，`guard:upstreams` 守）。
- WebSocket/SSE 事件名常量见前端 `src/lib/contracts/events.ts`。

## 6. 建议的后端第一步（最小可验证）
按 §0 大神建议：**别等全套**。先接**一条真实的"已办·价值"**——哪怕就一条真省税记录或一条真对账差错金额，
让前端右栏「已办·价值」第一次显示真数字。这一条真 outcome > 前端再开 8 个占位 board。
