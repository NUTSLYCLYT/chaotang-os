# 兵部获客设计 · 交主工头实施(2026-06-28)

> 兵部是主工头地盘,架构方给设计、不实建。复用已建骨架(dept-agent / reference-class / deliverable / evidence),只补兵部本命 + 线索库 + 获客飞轮。
> 刑部已按此骨架做完本命(`clause-risk` + `clause-history`)作参照范例。

## 差距回顾
框架同源已平;差三块:① 真线索库底座 ② 本命引擎(概率博弈,非NPV) ③ 获客飞轮。

## C · 兵部本命引擎(概率+反身性,别照搬户部NPV)
新建 `src/features/bingbu/lib/deal-probability.ts`(纯函数,对照刑部 `clause-risk` 的 shape):
- **ICP 匹配分**:线索属性(行业/规模/痛点)vs 你的好客户画像 → 0-100
- **成交概率**:直接复用 `reference-class`——史馆同类客户成交 base rate("你历史上这类客户成交 N/M"),样本<5 只给类比(同刑部 `clause-history` 范式)
- **竞品胜率 + 反制预判**(Soros 反身性):标"对手在场会怎么抢/你的差异化钩子"
- 输出:`{ icpScore, dealProbability(base rate), winVsCompetitor, suggestion }`,缺数据诚实标缺
- **本命 ≠ 定量**:销售天生概率+博弈,别强行算"成交NPV"=假精确

## D · 真线索库底座(常驻,不靠现传 · 三合法源)
新建 `src/features/bingbu/lib/lead-library.ts`(对照户部 `price-library.ts`):
- 源①:用户上传客户/成交(已有 `customer-import`)
- 源②:公开工商/招标/新闻(合法公开,**非个人隐私**)
- 源③:锦衣卫核实的公开信号(过可信度门)
- 沉淀成库,越用越厚;**喂 reference-class 当成交 base rate 的样本池**

## E · 获客飞轮 ★(合法-by-design,灵魂)
```
锦衣卫公开情报(招标/扩张/痛点信号)
 → 兵部AI备战:ICP评分 + 成交概率(D库+reference-class) + 草拟个性化开场白 + 找钩子
   ★只草拟·不抓个人数据·结构上无auto-send(沿用 prospect-qualify 的"只 humanActions、零auto-execute")
 → 人扳机:人审+点发(L0-L4 人工门,合法渠道:自有客户/inbound/公开商务联系)
 → 成交结果回填史馆 → reference-class 让成交预测越来越准(飞轮)
```
**合法不靠自觉靠结构**:数据来源无 'scraped' 选项、输出无 auto-send 字段(prospect-qualify 已这么设计,延续即可)。
