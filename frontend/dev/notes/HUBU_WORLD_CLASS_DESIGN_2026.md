# 户部 · 世界级 AI 财务部设计（2026）

> 立于 2026-06-27。目标：把户部做成「**比真实公司财务部更可信**的 AI 财务部」——
> 不是更像办公，是更可信、更标准化、可追溯、敢让老板照着拍板。
> 本文是户部设计 SoT，基于现有代码盘点，非空想。建 UI 时走 `chaotang-frontend-design` skill（§0.2）。

---

## 0. 先对齐：户部现在已经有什么（基于代码，别推倒重来）

| 层 | 现状 | 文件 | 成色 |
|---|---|---|---|
| 数据层 | Turso 真实财政总览(待批项目/预算/ROI/现金储备) | `contracts/hubu.ts` · `api/court/hubu/overview` | ✅ 真 |
| 大脑层 | ask 端点：鉴权→拉数据→LLM→**接地率校验(grounding rate)**→reprompt→**跨部冲突黑板(Wilson 浓度场)** | `api/court/hubu/ask` · `lib/swarm/hubu-agent` · `decision-ledger` | ✅ 真且先进 |
| CFO 办公厅 | 7 司结构 + 13 类财务问题 + 圣裁(准奏/补证/复核/驳回)+缺证+假设+风险册+人工门+sourceLabel | `core/courtos/hubu/hubu-cfo-office.ts` · `hubu-types.ts` | 🟡 结构满分，但**关键词分诊**非大神 LLM |
| 前端 | BottomDock 聊天 + 动态快捷问 + SWR 总览(60s) | `features/hubu/components/hubu-bottom-dock.tsx` · `use-hubu-overview.ts` | 🟡 只有"问答"，没有"人员办公"展示 |

**结论**：户部不是要从零建，是要**把已有的好骨架补成世界级**。三个真缺口：
1. CFO 七司从「关键词分诊」升「大神内核 LLM」。
2. 前端从「聊天框」升「**AI 员工办公厅**」（用户要的"部门人员信息展示"）。
3. outcome 回灌闭环（圣裁→兑现→史馆→下次引用）。

## 1. 一句话定位 + 调和户部的「两张脸」

代码里户部有两张脸：`agent.ts` 写的是**投资顾问**(DCF/股票估值/资产配置)，`hubu-cfo-office` 写的是**公司 CFO**(报价/预算/现金流/成本毛利)。

**定位裁决**：户部 = **公司首席财务官办公厅（CFO Office）**。投资顾问那张脸**降为其中一个司（投审司）**，不是平行身份。
理由：用户愿景是"替代公司各部门"，户部对标的是**企业财务部**，不是个人炒股顾问。overview 的真实数据(待批项目/预算/现金储备)也站在 CFO 这边。

## 2. 户部编制：7 司 = 7 个 AI 专业员工（已在 hubu-types 定义）

| 司(sub-office) | 对标真实岗位 | 职责 | 守护大神内核 |
|---|---|---|---|
| **户部尚书** `cfo_chief` | CFO | 总揽、圣裁、对老板负责 | 贝索斯(客户反向/单向门) |
| **度支司** `fpna_budget` | FP&A 预算分析 | 预算编制/审批/ROI 研判 | 马克斯(第二层思维) |
| **金库司** `treasury_cash` | 资金/现金流 | 现金储备/账期/回款/流动性 | 马克斯(风险=永久损失) |
| **计簿司** `controller_books` | 总账/Controller | 记账/对账/财报口径 | 大野耐一(消除浪费/口径一致) |
| **价本司** `cost_pricing` | 成本/定价 | 报价审查/成本毛利/BOM 财务 | 贝索斯(客户价值反推) |
| **投审司** `investment_review` | 投资评审 | 投资/估值/DCF/资产配置(原投资顾问脸) | 马克斯(周期/安全边际) |
| **稽核司** `audit_control` | 内审/合规 | 异常审计/合同财务条款/风控 | 塔勒布(尾部风险/skin in game) |

**这就是"部门人员信息展示"的真实底座**：7 个司官 = 7 个有名有职有专长有大神内核的 AI 员工。

## 3. 前端 · 部门人员信息展示（世界级 2026 形态）

> 抛弃"一个聊天框"。户部首屏 = **一座会呼吸的 CFO 办公厅**，7 个 AI 员工各在其位、各有产出、可点开看其工作。

**首屏三栏（编辑式 bento，非模板卡格）**

- **左·员工编制墙（Org Rail）**：7 司官头像 + 姓名/官职/对标岗位 + **在岗状态灯**(待命/办公中/已出意见/缺证待补)。点头像 → 看该员工的职责书、近期产出、其大神内核镜片。这是"人员信息展示"的核心。
- **中·办公主台（Desk）**：老板提一个财务问题 → 实时看 7 司**并行办公**(SSE 流式)：哪个司被点、各自的 position(准奏/补证/复核/驳回)、keyNumbers、缺证。收敛成**户部尚书的圣裁奏折**。
- **右·财政态势（Ledger）**：现金储备/待批合计/avg ROI/本周已准——真实 overview 数据，带 **sourceLabel 灯**(LIVE/FALLBACK)。

**世界级细节（Jobs/张小龙 镜片）**
- **可信度是第一视觉公民**：每个数字带 `status`(available/missing/assumption/blocked) 的微标——绿=有据、灰=缺证、黄=假设。**缺证不藏，显性化**是护城河。
- **一个问题进，一份能拍板的奏折出**：用户不需要懂 7 司，看到的是一份结构化批复 + "户部建议：准奏，但补这 2 条证据"。用完即走。
- **大神内核可见但不喧宾**：点价本司，能看到"贝索斯镜片：这报价是成本加成还是客户价值反推？"——让专业可解释，不是黑箱。
- 复用冻结视觉系统(帝金 `#F0C66A`/`#ebcb7b`、GlassPanel、SignalPulseDot、EnterStagger)，不新造色不破视觉资产(§2)。

## 4. 功能逻辑 · 端到端一条真 Loop

```
老板问("这三个待批项目先批哪个? 现金够吗?")
  → 鉴权(不可匿名烧 LLM) ✅已有
  → 拉真实 overview 当数据源 ✅已有
  → CFO 分诊: 判问题类型(预算审批) → 点哪几个司(度支司+金库司+稽核司)
  → 各司并行办公: 每司 LLM(大神内核 system) 产出 position+keyNumbers+evidence+缺证+假设+风险
  → 接地率校验(grounding): 每个数字必须挂证据,未挂的标 ungrounded + reprompt ✅已有
  → 跨部冲突黑板: 与刑部/工部近期信号比对,有断层则声明 ✅已有
  → 户部尚书圣裁: 准奏/补证/复核/驳回 + executiveSummary + recommendedNextAction + questionsForEmperor
  → 人工确认门: 单向门(预付/独家/大额)humanConfirmationRequired=true,禁一键静默准奏 ✅结构已有
  → 产出真办公文件: 《预算批复书》docx/pdf(见§7)
  → 史馆归档 + outcome 回灌: 裁决→兑现结果回填→下次引用 🔴待接
```

**现在要做的**：把 `hubu-cfo-office` 的 7 司从关键词分诊**升级为大神内核 LLM**（每司一个 grounded prompt 模块），并把圣裁结构流式渲染到前端办公主台。

## 5. 核心竞争力（为什么比 ChatGPT 和真办公都强）

| 维度 | ChatGPT 写财务 | 真公司财务部 | **朝堂户部** |
|---|---|---|---|
| 接地 | 可能瞎编数字 | 靠人核 | **grounding rate 自动校验，未挂证据即 reprompt** |
| 缺证 | 假装知道 | 口头说"还差" | **缺证显性化进结构,圣裁明列 questionsForEmperor** |
| 多视角 | 单线 | 几个人开会 | **7 司并行 + 大神内核,position 明确** |
| 冲突 | 无 | 部门墙难发现 | **跨部冲突黑板(Wilson 浓度场)自动声明断层** |
| 风险 | 偶尔提 | 看人 | **强制 riskRegister + 尾部风险(稽核司·塔勒布)** |
| 高危 | 直接给答案 | 流程审批 | **单向门强制人工确认门(铁律13.2.5)** |
| 可追溯 | 无 | 邮件散落 | **每条 evidence 带 sourceType+sourceRef,可审计** |
| 一致性 | 每次不同 | 看人 | **typed contract(HubuCFOOpinion)结构恒定,可标准化** |

**一句话护城河**：**Trustworthy by construction**——可信不是靠模型聪明，是靠结构（接地校验+缺证显性+冲突声明+风险册+人工门+可追溯证据）。这是 ChatGPT 给不了、真办公做不到标准化的。

## 6. 前沿技术栈（2026）

- **Grounded generation + 数字接地校验**：每个 keyNumber 必须挂 evidence，接地率 < 阈值自动 reprompt。✅雏形已有，要强化到"未接地数字不进圣裁"。
- **Typed structured output**：`HubuCFOOpinion` 用 Zod schema 强约束 LLM 输出，结构恒定 → 可标准化、可渲染、可 diff。
- **Multi-agent sub-office orchestration**：7 司并行(pipeline/parallel)，CFO 合议——非单 prompt。
- **大神 rubric self-critique**：每司产出后跑守护大神 5 模型自检(eval gate)，抓"专业地生产错误"。
- **Conflict ledger + Wilson 置信浓度场**：跨部断层量化预警。✅已有。
- **SSE 流式办公**：7 司逐个"上岗→出意见"实时可见，体验=看真团队开会。
- **Artifact generation**：圣裁→真 docx/pdf(document skills)，带证据附录+风险册+sourceLabel 水印。
- **Eval-harness**：5-10 真实财务场景做回归，比"接大神内核 vs 不接"的产出质量，数字驱动。

## 7. 真实办公级产出（比真办公更标准化）

每类问题产出一份**正式财务文书**(docx/pdf via `document-skills`)：

- 预算审批 → **《预算批复书》**：批复结论 + ROI 研判 + 现金影响 + 缺证清单 + 风险册 + 人工确认签章位 + sourceLabel 水印。
- 报价审查 → **《报价财务审查报告》**：成本拆解 + 毛利 + 单向门标注 + 客户价值反推校验。
- 投资评审 → **《投资评审意见书》**：DCF/相对估值 + 周期位置 + 安全边际 + 区间(非点估计)。
- 现金流 → **《现金流研判》**：账期/回款/流动性压力测试。

**差异化**：每份文书都带 **①证据附录(可追溯) ②缺证清单(诚实) ③风险册 ④sourceLabel(真假来源水印)**——真公司财务部的文件没有这四样，这就是"更完善专业标准化"。

## 8. 用户体验原则（Jobs + 张小龙）

1. **一个问题进，一份奏折出**：用户不学 7 司，只管问、看建议、拍板。
2. **可信度灯是第一公民**：绿/灰/黄三态贯穿，缺证从不藏。
3. **高危必拦**：单向门弹人工确认门，不让 AI 静默替老板承诺。
4. **用完即走**：给完能拍板的批复就退场，不黏住、不堆 KPI。
5. **专业可解释**：点开能看到大神镜片，黑箱变白箱，但默认收起不喧宾。

## 9. 落地序（先一条真 Loop，别铺 7 司）

- **MVP(第一条真转)**：只做 **预算审批** 一类问题 × **3 司**(户部尚书+度支司+金库司)，用真实 overview 数据，跑通"问→3司大神内核办公→圣裁→《预算批复书》→史馆归档"。配一条 eval。
- **验证**：5 个真实待批项目场景，比"接大神内核 vs 不接"的批复——自检是否真抓出风险，还是只把文档拉长（Karpathy 的 eval）。
- **扩**：eval 数字过线 → 补价本司(报价)、投审司(投资)，再到 7 司全。**永远先有第一条真数据，再扩编。**

## 10. 红线（不可违反）

- **铁律9**：触碰真实产线资产(真实报价/付款/对外承诺/供应商锁定)必须 HTTP 转后端 jiqun；前端 runtime 只做无副作用咨询。CFO 七司的"真办公执行"在后端做，本仓只渲染。
- **铁律13.2**：所有产出带 sourceLabel；DEMO/FALLBACK 禁伪装 LIVE；单向门过人工确认门；改防线靠 eval。
- **铁律2**：7 司枚举/问题类型用单一真相源(hubu-types.ts)，禁平行 map、禁 `?? code` 静默回退。
- **eval 防自检反噬**：大神内核自检必须有 eval 守着，否则只是让错误产出更专业更有说服力（Munger 逆向）。
