## 0. 一句话

**朝堂OS = 储能电池 pack 老板每天"上朝"的 AI 经营内阁。** 内阁把该他拍板的重大经营决策排好队，
一句话结论 + 建议动作，他朱批/下钻/被高风险拦门，拍完归档、下次同类案自动引用。
朝堂不是聊天工具，是**行业无关的 AI 决策操作系统**（电池是当前 dogfood 与第一把尖刀，横向复制是第二幕）。

## 3. 核心 Loop（设计北极星）

```
上朝 → 看排好队的决策(左栏,风险置顶) → 选一件(中栏出决策卡·结论态)
  → 信      → 朱批采纳(2秒)
  → 半信    → 翻面看证据/分析/缺证/风险 → 再朱批
  → 高风险  → 强制翻面落证据页 + 采纳前人工确认门,禁一键静默
  → 拍完    → 写主库 tasks + 归档史馆 → 下次同类案自动引用本次决定+结果
右栏(情报/教学/战略)是"抬头看天"的余光,不抢中栏注意力(注意力状态机压暗两翼)
```

主闭环链路（铁律13）：**上书房问题 → 丞相拟旨 → 缺证检查 → 军机处会审 → 圣旨/奏折 →
用户裁决(采纳/补证/复核/驳回/追问) → 高风险人工确认 → 史馆归档 → 下次引用旧案。**

## 5. 上书房详规（已落地代码，核心）

> 主组件 `src/features/shangshufang/ShangshufangPage.tsx`；路由 `/court-briefing`。

### 5.1 常驻三栏（P1 ✅）
- **左栏 · 奏折收件箱**：聚合真实决策源（丞相 `chancellorItems` + 奏折 `memorials` + 完成蜂群），
  **按 priority 稳定排序、高危/紧急置顶**（P2 ✅ `suggestionPriorityRank`）；每条=由头+风险色+sourceLabel。
- **中栏 · 决策卡**：注意力中心（见 5.2）。
- **右栏 · 情报三段**：上⅓大趋势 / 中⅓引导教学（钦天监真内容）/ 下⅓战略调整意见——
  大趋势与战略意见**诚实标"待接入"**（无真实产出引擎，铁律5 不空转）。
- **Norman 物理光焦**：两翼常驻但默认降一档明度（opacity 0.82），中栏帝金卷轴独占焦点；
  选中左栏奏折瞬间两翼再压暗 220ms 吸回中栏（纯 opacity，合成器友好）。

### 5.2 决策卡（P3/P4 ✅ 核心）
- **默认结论态**：一句话圣裁 + 建议动作 + sourceLabel + 缺证/风险徽 + **朱批五键**。
- **朱批五键 SSOT**（`VerdictActionBar.tsx`）：`采纳 / 补证 / 复核 / 驳回 / 追问`，
  奏折与丞相建议两分支共用同一 `handleVerdictAction` router（收敛旧两套并存按钮，铁律3）。
- **翻面下钻**：EdictStage 两页（案卷主页/原始明细），翻面不跳页可逆，正文+证据+缺证+风险。
- **注意力状态机（张小龙）**：卷轴展开=决策态 → 底部下旨栏**降格成一句提示**，同屏只留一套主动作；
  收卷=提问态复原（`inDecisionState` 精确等于中栏渲染五键的分支）。

### 5.3 高风险拦门（P4 ✅，铁律4/13.5）
- **判据 SSOT** `isHighRiskMemorial`（铁律2）：命中高危词（正式报价/合同/付款/股权/对外承诺…）或来源 FALLBACK/DEMO。
- **强制翻面**：高风险奏折决策卡**默认落在证据明细页**（`openOnEvidence`），逼老板先看缺证。
- **人工确认门**：采纳走 `handleVerdictChoice` → `window.confirm` + 必填人工确认说明 → 才写 `shangshufangTaskDecision` 落库；
  终态（采纳/驳回）后**五键锁定**，防重复/矛盾裁决。禁一键静默。

### 5.4 对话抽屉（P3 部分）
- Dock 抽屉退化为**纯对话**（chat-only），默认收起；问丞相 `/api/chat`、问钦天监 `/api/qintian/chat` 真接后端。
- **待建**：@点名切 persona（锦衣卫/军机处，复用 `/api/chat` 换人格·诚实标）、触发收敛——**设计未定**（不做成第二套五键，避免与注意力状态机冲突）。

### 5.5 史馆取水口（待建）
- 中栏决策卡旁常驻"上次类似案：你怎么判 + 结果如何"——护城河飞轮取水口，缺它=飞轮没入口。

## 8. 工程质量门（16 条铁律摘要 · CLAUDE.md/AGENTS.md）

| 铁律 | 核心 |
|---|---|
| 1 | 特权写入的守门人必须在写入那道门（鉴权与写入同门） |
| 2 | 跨进程领域枚举单一真相源，禁静默回退（fail-fast/warn） |
| 3 | 合并即清理（resolve **再** simplify，删死代码） |
| 4 | 高危改动提交前过双门：独立会审 + 一条回归断言 |
| 5 | 新能力先溶解回主 Loop，溶不进才给版面，且先答"第一条真实数据从哪来" |
| 6 | 部/司是地址簿，蜂群是工厂：一个领域一个 owner，产线一个出口 |
| 7 | 分层启发式≠重复：收敛前先问"它在 live 路径可见吗" |
| 9 | 引擎边界（前端咨询 / 后端产线，判据=是否触碰真实产线资产） |
| 13 | Loop=状态+动作+下一步；6 条不可违反（sourceLabel/高风险人工确认/奏折六要素/裁决持久化…） |
| 15 | 提交纪律：只在用户明确说"提交/推送"时执行 |
| 16 | 清理零事故：取证(knip)→隔离(git mv _attic)→双门验证→到期再删 |
