## 0. 执行摘要

- **是什么**：朝堂OS = 储能电池 pack 老板每天"上朝"的 **AI 经营内阁**。内阁把该老板拍板的重大经营决策排好队，
  一句话结论 + 建议动作，他朱批/下钻/被高风险拦门，拍完写库归档、下次同类案自动引用。
  本质是**行业无关的 AI 决策操作系统**（电池是当前 dogfood 尖刀，横向复制是第二幕）。
- **一个项目 · 两条工程责任线 · 一个内核**：朝堂OS(项目/主线名) = weblyt(前端体验线) + jiqun(后端蜂群线)；CourtOS = 被前后端吸收的内部决策内核/协议名，**永不作为第三条产品线**。
- **现状一句话**：**真东西都有，缺把它们串成老板看得见的一条线。** 前端有真 LLM 咨询发动机、后端有真产线级电池蜂群(654 真 session)、护城河飞轮取水口已通——但三者仍部分游离，且**零真实客户闭环数据**（融资级最高缺口）。

## 1. 战略与商业

### 1.1 战略卡（v-final 冻结）
| # | 维度 | 结论 |
|---|---|---|

### 1.2 融资八格 pitch
Problem(老板独扛决策·养不起战略部) · Why-now(LLM 首次让军师班子可规模化) · Product(决策 inbox→结论→朱批/下钻/拦门→归档复用) · Wedge(储能电池 pack·已真跑) · Business(年费5-20万+浅项目费) · Moat(决策×结果数据飞轮·史馆回填弧) · Vision(横向决策OS=百亿) · **Ask/证据★缺口=真客户+真结果兑现**。

### 1.3 护城河深挖（后端 `AI_MOAT_STRATEGY.md`，大神4轮会审）
- **唯一 all-in 杠杆**：不 all-in AI(会被抹平)，all-in 把独有的"**失败电芯尸体库**"(-40℃鼓包/热失控+低温曲线+现场工单)炼成"低温失效/寿命预测内核"。数据非模型、物理时间不可压缩、反脆弱(寒潮越多护城河越深)。
- **反共识商业化**：不卖 SaaS/预测，**当"低温可用度承保人 underwriter"**——用独家失败数据把行业 15-30% TCO 恐惧溢价抢成收入，预测内核只是定价引擎。护城河=赔付闭环(承保过/赔过/精算收敛)。
- **落代码熔断**：`src/decision_guard.py`(人类签字熔断+数据稀疏弃权+skin-in-the-game) + `scripts/score_swarm.py`(对照人工真值非自评)。
- **火鸡期诚实标**：承保模式**尚未被真实赔付验证**，属战略假设；90天需真金白银赔≥2笔且还活着，否则诚实标"仍在喂火鸡期"。

### 1.4 90 秒北极星 Demo（融资 + 改版验收标尺）
用真跑过的 **314Ah 磷酸铁锂涨价 case**（后端真 session `20260704_173015` 存在）：上朝看排队→提问→后端真蜂群出 `LIVE_SWARM` 决策卡→翻面看成本确定性算法依据→点采纳被高风险拦门(投资人"哇"点)→签字归档→快进3月史馆主动邀功"您那单实际中标毛利高对手6%"。

## 2. 目标用户与核心 Loop

- **主用户/经济买家**：中小储能电池 pack 企业老板(创始人/CEO)，一人扛所有重大决策，养不起战略部。
- **JTBD**：当【客户催正式报价/成本要不要压/供应商锁不锁/市场加不加码/人事动不动】时，我要【一句话给结论、证据一键可达、高风险拦住我别拍脑袋、拍完能复用】的内阁。
- **核心 Loop（北极星）**：
```
上朝 → 看排好队的决策(左栏,风险置顶) → 选一件(中栏出决策卡·结论态)
  信→朱批采纳(2秒) │ 半信→翻面看证据/缺证/风险→再朱批 │ 高风险→强制翻面+人工确认门,禁一键静默
  → 拍完写主库tasks+归档史馆 → 下次同类案自动引用本次决定+结果
右栏(情报/教学/战略)是抬头看天的余光,不抢中栏(注意力状态机压暗两翼)
```
链路：上书房问题→丞相拟旨→缺证检查→军机处会审→圣旨/奏折→用户裁决(采纳/补证/复核/驳回/追问)→高风险人工确认→史馆归档→下次引用旧案。

## 5. 后端蜂群系统详规（jiqun_ai · :8081）

> 自定位"世界首个 LLM-native 多智能体电池 PACK 设计自动化引擎"。声明式：加蜂群=加 `flow_*.yaml`+`prompts_*.py`，不改引擎。

### 5.1 引擎与两套编排
- **FlowEngine** `src/flow_engine.py`：YAML 解释器，6 层(context_budget/step_assertions/run_state/model_tiering/output_linter/guard_rails)。
- **A) 经典业务蜂群** `swarm_orchestrator.py`+`config/swarm_orchestrator.yaml`：注册 **21 蜂群** + **事件驱动流水线**(某蜂群完成发`{id}_completed`→按 bindings 触发下游，带 `min_quality_score` 质量门控)。典型链 `haolong(获客)→opc(方案)→product→quotation(报价)`，fan-out 到 shiguan_archive 归档。
- **B) 上书房决策链路** `swarm_execution_loop.py`(**前端决策真正打到的地方**)：`route_swarms()`按关键词路由到 **7 部门蜂群** + 强制挂**元蜂群**；流水=部门立场→`evidence_audit`→`critic`→`conflict_detector`→`synthesis`→`quality_gate`→装配 court_doc。
  - 7 部门蜂群：hubu_finance/xingbu_legal_risk/gongbu_delivery/libu_communication/bingbu_strategy/libu_org_execution/jinyiwei_intel。
  - **三态执行器**：①规则模板兜底 ②通用LLM角色扮演(`FENGQUN_LIVE_SWARM`) ③真实部门专用引擎(`source_label=LIVE_ENGINE`,最可信)。失败退兜底，绝不崩/绝不假 PASS。
  - 部门间互引：锦衣卫先跑，真实情报注入后续部门上下文。

### 5.2 Agent 设计
- 三种定义：`runtime_prompts/<key>/`(护城河层·90+ agent·各4文件) / `src/prompts_*.py`(PROMPT_MAP) / `flow_*.yaml` step 声明。
- 权威花名册 `harness/chaotang_department_protocol/departments.yaml`(六部+诸司·calls_swarms/output_types/advisor_lenses/绿黄红黑四态 next 路由)。
- **命名撞名坑**：吏部=`libu_personnel`、礼部=`libu`(2026-07-04 改名消歧)。另有 admin 动态部门表(DB)与静态花名册不同。

### 5.3 Provider / 模型 / 数据层
- Provider `config/providers.yaml`(active=**deepseek**主力·火山/Ollama/Claude-LiteLLM:4444/MiniMax，各带 fallback)；多模型(flow/step 级覆盖)；model_tiers(director/worker)；LiteLLM 代理 :4000。成本控制:三层验证分级+min_quality_score+context_budget+real_engine_calls.jsonl 记录。
- **DB** `src/db/models.py`(SQLite主·多租户 tenant_id 逻辑FK)。**⚠️ alembic 仅 3 迁移**(decrees/tasks/memorials/reviews/retrospectives + result_json + dept_admin)；决策/裁决/归档/蜂群链路表靠 `create_all` 兜底建，**无迁移**(PID 风险项)。
- 核心表：治理(decrees/tasks/memorials/reviews/retrospectives) · 上书房 loop(decision_tasks/court_loop_runs/agent_skill_runs/court_reviews/emperor_decisions/shiguan_archives) · 蜂群产线(swarm_runs/swarm_task_runs/swarm_evidence_links/swarm_quality_results，全带 source_label)。

### 5.4 决策落库（前端五源聚合关键·部分已具备）
前端 `shangshufangTaskDecision`→`web/routers/shangshufang.py`(`/api/shangshufang`)。闭环：`draft-edict`(拟旨)→`confirm-edict`(确认·同步跑 `run_swarm_execution_loop` 产线·结果落库)→`tasks/{id}/status`→`tasks/{id}/decision`(approve/reject/request_evidence/archive·archive 写 ShiguanArchive+证据链+`synthetic_flag`)。
