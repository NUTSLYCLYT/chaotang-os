# 御史台设计 ·「进程外·没有手·关不掉·默认闭嘴·连自己死了都被替它喊」（5 大神一致）

> 2026-06-25 由御史会审（Schneier/Charity Majors/Deming/Stuart Russell/Munger 完全收敛）沉淀。
> 御史三铁律:① 只观察+报告+弹劾绝不下场 ② 确定性优先(LLM 只判该不该吵醒老板) ③ 缺席即告警(该活没活=红绝不沉默)。

## 0. 一句话
御史是**站在朝堂进程外、没有手、关不掉、默认闭嘴只在确定性红线响时才开口的常设证人**——它不修朝堂、不裁决、不执行、不改码、不 kill，只持续证明「机器有没有违反它自己定的本分/铁律」，缺席即告警，并持常开急停与对自我提权/源标造假/越权的永久否决。

## 1. 一体三层 + 四条物理事实 + 一只金丝雀
- **一体（本体永远在被监察进程之外）**：御史的全部尊严来自它和朝堂**不共享进程/内存/部署/runtime/DB连接、且丞相关不掉**。进 in-app=监工和小偷关在同一间牢房（朝堂崩它陪葬，dead-man switch 自我失效）。本体 = 已落地的确定性脚本（censor 健康巡查/诚实纠察/jiqun验签姿态/异动雷达 + censor:watchdog + censor:depts）+ cron + Hermes，**不进 in-app**。
- **三层可靠性金字塔（越上层越笨越可信）**：① 御史本体（确定性 grep/curl/ss/只读 sqlite，判朝堂活没活/违没违铁律，写带 HMAC 的心跳）；② 看门狗（异主机/异 cron·极简，只看御史心跳 age 是否过期）；③ 最外圈死人开关（Healthchecks.io 式外部托管 / 后端 jiqun 侧轻量 cron / 老板手机每日"御史在岗"正向心跳，笨到不会静默失败）。**每层只 watch 下一层"还在不在"而非内容**。
- **四条物理事实（不靠纪律靠能力删除）**：独立低权 OS 用户 + DB 只授 SELECT（无 INSERT/UPDATE/DELETE）+ 无写 token/kill/部署凭证 + 二进制不 import executor/harness/dispatch。唯二出口 = 退出码 0/1 + append-only 弹劾账（`chattr +a`，御史自己也只能追加不能改删）。
- **一只金丝雀（Schneier 招牌·替代"假设防线还活着"）**：御史定期主动埋一条**已知必违铁律的诱饵**（伪造高风险股权决策/源标被改成 LIVE 的 DEMO/试图绕人工门的 sign-off），检查人工门拦没拦、源标归一打没打回、审计链记没记。**诱饵被静默放行=那道防线已死=最高级弹劾**。把"红线还红不红"从信仰变成每天用一颗子弹去打它。

## 2. 判断层（LLM）只插一条窄带
确定性检测先分红/黄/绿——红线（自我提权/源标造假/越权/绕人工门）**直接 page 绕过 LLM**；绿默认沉默只留心跳；LLM 仅在黄带判"值不值得 3 点钟吵醒老板"，且**只能降噪不能把硬红线升级为绿或压下去**。

## 3. 脚本 vs 版面（铁律5 判定：溶得进，不给独立版面）
留进程外脚本为**本体**，in-app 只给**「只读墓碑灯板」**嵌进刑部/史馆已有版面：
- 监察本质是"站在所有工位外面看所有工位"——这是唯一不可溶解的能力，所以不强塞上书房/军机处。
- in-app 只在刑部审计页挂一个只读巡查时间线（谁/何时/红黄绿/哪条断言炸/各跳心跳 age），数据源 = censor 脚本写出的 append-only JSON 行，**零写回零判定零引擎零权限**。这块灯板自己也必须显示"报告陈旧/心跳超时"——**版面陈旧本身是一种告警**。
- 新建 `/censorate` 大版面 = 多一个被一起部署进而被一起关掉的攻击面 + 稀释信号，违铁律5。**御史的魂留脚本，in-app 只是它的留声机不是它的器官。**

## 4. 三方边界（御史 vs 锦衣卫 vs 刑部）
- **御史** = 向内·现在时·liveness 与本分：「我们自己的系统此刻健康吗、有没有正在违铁律」。连续实时只观察，确定性断言+死人开关。**防机器自己变质**。
- **锦衣卫** = 向外·情报真伪+变化检测：入史馆前情报可信度把关 + 异动雷达。**防外敌/脏情报**。
- **刑部** = 向后·逐案·法医取证：那件事为什么错、谁担责、怎么改。**断旧案**。
- 硬线：御史只答"活没活/越没越线"，要问"为什么/谁担责"立刻移交刑部；要评"外部情报可不可信"立刻移交锦衣卫。**御史只供线索给刑部立案，自己绝不审判定责。**

## 5. 本轮已落地（grounded，御史本体=脚本，强化它守新治理红线）
- `scripts/chaotang-censor.sh` 加**「治理原语红线哨兵」**：确定性纠察我这一程落地的治理原语红线是否回潮——丞相三必填校验/门下闸禁 score-draft/钦天监 ruin 红线/各自 nodetest 是否还在。红线被删=御史立刻弹劾（缺席即告警）。
- 这正是御史设计的本体形态：**确定性脚本守红线、不下场、缺席即告警**，且第一条真实数据今天就有（退出码/弹劾账）。
- 金丝雀诱饵主动巡检 + 三层死人开关第三跳（外部托管/老板正向心跳）= 需外部 infra，留运维落地（见 §1，本轮不接外部 cron）。

## 6. 顶级风险
1. **御史被静默关掉而朝堂以为它还在岗**（攻击者/图省事的人最理性的一步=先掐掉唯一会喊的喉咙）→ 存活性 > 准确率：「御史不在了」本身=最高级红色告警 + 外部死人开关兜底 + 关闭权从 in-app/丞相完全剥离。
2. **告警疲劳**（每个抖动都 page→老板静音→唯一真火无人看见）→ 每条告警自带"坏了什么+影响半径+下一步那一个动作"，分级（红即刻 page/黄日 digest/绿静默），flap-damping，元监控降噪；**宁可漏报噪声，绝不漏报那一声真红线**。
3. **金丝雀诱饵本身有副作用**（注入伪造决策污染系统）→ 诱饵走隔离/沙盒标记，绝不进真实主库；本轮先用"红线回潮检测"（grep 不变量）这种零副作用形态。
