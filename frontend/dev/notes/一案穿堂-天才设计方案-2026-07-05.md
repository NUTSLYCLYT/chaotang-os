# 「一案穿堂」天才设计方案 — 朝堂 Loop 燃料化

- 版本：v1 · 2026-07-05
- 一句话：让**一个真 taskId** 从「立案」走到「兑现」，把所有等数据的引擎点亮。**全面的路线图，窄切的执行。**
- 背景：全系统体检结论——朝堂是「极完整的引擎 + 没有燃料」。军机处99%空、六部富工作台全孤儿、钦天监 confirmed 永不亮、太医院80%静态，根因同一个：**没有一条真实案子从头流到尾**。

---

## 0. 设计定调（回应"单部独用 vs 军机处汇合"）

两种模式**都要**，不是二选一，共用同一批引擎：

| 模式 | 触发 | sourceLabel | 去向 |
|---|---|---|---|
| **单部独用**（日常工具） | 无 taskId，老板直接进某部用能力 | LOCAL | 到此为止，不进军机处/史馆 |
| **军机处会审**（旗舰·综合决策） | 有 taskId，多部汇合 | LIVE/MIXED | 进穿堂线→裁决→史馆→兑现 |

「孤儿」≠「单部独用」：孤儿是**进不去的死代码**（bug），单部独用是**挂在路由上能直接用的模式**。修孤儿 = 把富工作台挂上 `/departments/[code]`，挂上后天然就是单部独用。

---

## 1. 架构不变量（全程不可违反）

1. **一个引擎两个入口**：部门咨询纯函数**唯一一份**，单部独用 & 会审都 `import` 它，**禁任一入口重算**（铁律3/6）。判据：户部页"算毛利"按钮 与 军机处派给户部的调用，必须走同一个 `hubu-engines.ts` 函数。
2. **taskId 是脊**：有 taskId=会审镜片(进穿堂线/史馆回写)；无 taskId=单部独用(标 LOCAL，不落库)。
3. **穿堂线只在有 activeTaskId 时出现**；军机处是**汇合点不是必经点**。
4. **诚实标全程**：LIVE/LOCAL/DEMO/FALLBACK 不互相冒充（沿用 `reality-state`）。
5. **真实资产转后端**（铁律9）；前端只做咨询决策。
6. **复用优先**：几乎不新建。唯一新组件=穿堂线；唯一新机关=兑现入口。

## 2. 三个关键原语

### 2.1 穿堂线 CaseSpine（唯一要新建的组件）
- 绑 `activeTaskId`，全局常驻（**有案才显**），六站进度：`立案 → 会审 → 预测 → 裁决 → 归档 → 兑现`。
- 每站可点跳；上书房/军机处/六部/钦天监/史馆**每页顶部渲染同一条**。
- 数据源：taskId 的状态（复用 `contracts/task.ts` 状态机 + `db/primary-store`）。
- 本质：把军机处那条页内 stepper **升级成跨页全局脊**。一个组件，照亮全流程。

### 2.2 两入口引擎契约
- 部门引擎统一签名：`engine(input, ctx?)`；`ctx?.taskId` 有无决定 sourceLabel 与是否回写。
- 单部独用：`engine(userInput)` → LOCAL 结果，页面展示，不落库。
- 会审：`engine(caseInput, { taskId })` → 该案镜片，回写 `primary-store`，喂军机处综合决策。
- **不新增引擎**，只给现有部门引擎补一个可选 `ctx` 形参（多数已是纯函数，改动极小）。

### 2.3 兑现闭环 FulfillmentLoop（点亮钦天监 confirmed 的唯一机关）
- 归档时存 `{ prediction, falsifiedBy, dueDate }`（钦天监已有 `forecastPriceTrend` 产出这些字段）。
- 到期入口问老板一句"当初押的成真了吗？" → 一键 `confirmed/refuted`。
- **这是全系统第一条真实结果数据** → 钦天监 `effectiveVerdict` 从 observing 翻 confirmed（现在永远翻不了就缺这一下）→ 次日上书房建议引用它 → 史馆飞轮起转。

## 3. 分期路线（全面路线图 · 窄切执行）

> 纪律（Bezos）：Phase 0-1 期间**禁止铺开**。一个案子、两个部门、一条到底，其余全部忍住不碰。

### Phase 0 · 证明穿堂（1-2 周）— 最高优先
- **先诊断**：立案链路当前断在哪（为什么真 taskId 进不来）——这是第一颗螺丝。
- 立案链路修通 + CaseSpine MVP + 户部/工部两张真卡填满军机处一个真案。
- **验收**：1 个真 taskId 走完 `立案 → 会审` 两站；军机处那张空奏折**第一次被户部+工部真卡填满**；羞耻指标"本周真案数" ≥ 1。

### Phase 1 · 闭合飞轮
- 裁决(五键) → 史馆归档 → 兑现闭环，点亮钦天监 confirmed。
- **验收**：钦天监 confirmed **第一次亮**；史馆第一条带兑现弧的真归档。

### Phase 2 · 两入口对齐（修孤儿）
- 户部/工部富工作台挂上 `/departments/finance|gongbu`；单部独用与会审共用同一引擎。
- **验收**：一条回归断言——同一函数两入口吐同一个数（钉死"两个入口一个大脑"）。

### Phase 3 · 复制模式
- 把 Phase 0-2 的模式套到 刑/兵/礼/吏，每部一个 PR。不重造，只接线。

### Phase 4 · 收尾专项
- 钦天监去硬编码/补回测；太医院红线（不诊断/不开方）；锦衣卫异动雷达（新增/消失/突变 diff）。

## 4. 复用 vs 新建（几乎全复用）

- **复用**：所有部门引擎(`features/*/lib`)、`EdictStage`、`ShangshufangLayoutShell`、`task.ts`、`primary-store`、`reality-state`、军机处三栏、`BattleStream`、各部 `*Workspace`（挂载即用）。
- **新建**：`CaseSpine` 穿堂线 1 个 + 兑现入口 1 个 + 立案链路缺失的螺丝。
- **决断**：`department-offices.ts` 映射表——**要么接上、要么删**，不留孤儿（铁律3）。
