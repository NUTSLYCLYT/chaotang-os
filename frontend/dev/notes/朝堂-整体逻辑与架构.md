# 朝堂 · 整体逻辑与架构（一进来先读这份 · 2026-06-28）

> 给新 agent / 新人的全局地图：5 分钟懂朝堂怎么运转，不用从头扒代码。带文件指针。

## 0. 一句话定位
**朝堂 = AI 决策操作系统。** 给老板配一套 AI 班子（六部+诸司），把"该不该做某件事"的决策做成**快、稳、可信**。
不是聊天工具，是替你拍板还不让你被坑的中枢。

## 1. 主循环（系统的心跳 · 铁律13）
```
①老板提决策(上书房 /study)
   ↓
②丞相拟旨 = 确定性 router 决定召哪几个部门(不让 AI 自由编排;WIP上限≤3)   → src/app/api/court/orchestrate/route.ts
   ↓
③各部门 live agent 给意见(LLM大脑 + 纯函数引擎)                          → src/lib/swarm/dept-agent.ts · src/features/<dept>/lib/*-engines.ts
   每条带:裁决 + 评分 + 缺证 + 风险 + sourceLabel(真/假来源)
   ↓
④军机处 = 确定性 merge(机器不裁决;硬冲突"伏候圣裁")                       → mergeDecisions / src/app/(dashboard)/command-center
   ↓
⑤奏折给老板(圣裁/分奏/证据/缺证/风险/后令)
   ↓
⑥老板裁决(准奏/补证/驳回;高风险=人工亲裁门)                              → orchestrate/sign-off/route.ts
   ↓
⑦史馆归档 →(应)真实结果回填 → 引用旧案让下次更准  ← 飞轮(现断,见 §5)     → src/features/shiguan · src/lib/swarm/decision-ledger.ts
```

## 2. 五层架构
| 层 | 是什么 | 在哪 | 现状 |
|---|---|---|---|
| **编排层** | 确定性路由 + WIP上限 + merge + 全链路 trace | `api/court/orchestrate/*` | ✅ 健康 |
| **部门层** 六部+诸司 | 每部 = 班底(各司) + 引擎(纯函数咨询) + LLM agent | `features/{hubu,gongbu,bingbu,...}` · `contracts/agent.ts`(11码Tier0) | 🟡 户/工/兵/锦真,余薄 |
| **执行层** | 蜂群/庄园:真产线 / agent 执行 | `/manors` · 后端 jiqun `:8081` | 🟡 后端 |
| **记忆层** 史馆 | 归档 + 自学习飞轮 | `features/shiguan` · `swarm/decision-ledger.ts` · `lib/department-learning/` | ⚠️ 能记不能学(§5) |
| **数据层** | Turso(前端) + jiqun后端(真产线) | `lib/db/turso.ts` · `lib/upstreams.ts` | 🟡 真数据薄 |

## 3. 两条贯穿全程的铁律（系统宪法）
1. **铁律9 · 咨询/产线边界**：前端只做**无副作用的咨询决策**；触真实产线资产(付款/报价/BOM/交付/对外承诺)→ **转后端 jiqun**(`courtosFetch`/`lib/upstreams`)。前端动嘴、后端动手。
2. **诚实层 · sourceLabel + 缺证 + guard**：每个产出标 LIVE/FALLBACK/缺证，绝不假装。guard 家族把"系统应该 X"变成 CI：
   - `guard:realdata`(接真度) · `guard:honesty`(诚实债) · `guard:pilot`(能上线门) · `guard:tenant`(租户隔离) · `guard:guardian`(守护大神会审) · `guard:upstreams`(上游单源) · `guard:auth`/`guard:freeze` 等。
   **这是朝堂相对 ChatGPT 的唯一护城河。**

## 4. 治理（哪些点亮、谁守门）
- **pilot 状态**(`features/start/lib/pilot-status.ts` + `guard:pilot`)：板块 live/coming;点亮必须有真数据源证据。**架构大、运行小**——大半休眠,只点亮验证过的。
- **守护大神表**(`AGENTS.md §12.1` + `docs/CHAOTANG_GUARDIAN_INNER_CORE.md`)：每个司配开发态会审大神(改其代码时戴的镜片)。
- **办公厅注册表**(`features/departments/lib/department-offices.ts`)：加部门只往注册表加 1 行,page.tsx 永不改(根治多 agent 争用)。

## 5. 自学习飞轮 · 为什么现在没转（最重要的缺口）
**齿轮全造好了**(outcome列/recordOutcome/回填端点/attribution校准/Wilson冲突场/boss偏好)，但**两头管子没接**：
- 🔴 进料口孤儿：`/api/court/study/outcome` 回填端点存在但零 UI 调它 → outcome 列永远 NULL。
- 🔴 出料口没接：`loadAttributionCalibration` 存在但 orchestrate 没调 → 学了不改决策。
- ⚠️ 在转的偏好半边学"讨好"不学"对错" → 放大老板偏见。
**详见 `dev/notes/自学习飞轮-诊断与天才设计.md`。** 解法:接两根管子(都用已建齿轮)+让结果压过偏好;第一步=一个"上次怎么样[对/错]"的一键回填钩子。

## 6. 实话:逻辑 vs 实现
- **逻辑完整且优秀**：确定性编排 + 缺证显性 + 人工门 + 诚实层 + 飞轮设计,骨架顶级,站在 2026 多 agent 系统活下来的对的一边。
- **实现部分**：真数据薄、飞轮两头没接、110 版面大半休眠。
- **该做的不是改逻辑(逻辑对),是往对的逻辑里灌第一桶真油**:一个真决策、一条真结果回填、一个真用户。

## 7. 对内 vs 对外（产品口径）
- **对内**：守住这套逻辑(确定性 + 诚实)。
- **对外**：把逻辑全藏起来,只露「**给你的生意配一套 AI 班子、帮你拍板不被坑**」。逻辑越复杂,对外越要简单。
