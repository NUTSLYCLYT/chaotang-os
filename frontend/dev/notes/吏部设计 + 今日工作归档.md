### 第一条真闭环（已建，复刻户部成本司范式）
**铨叙司·转正评估**：真转正评价表(评价维度+分值+评分) → 总分/满分 + 转正建议(准转/延长/不予) + 缺证(未评分维度)。
- 实测真表：市场部转正表 12 维度/满分200，**空模板→诚实"评分不全·吏部不替你打分"**（费曼：缺则标缺）。
- 阈值：≥80%准转、60-80%延长、<60%不予；超半数未评→insufficient 不下结论。

### 照户部范式的落地路线
```
①转正评价表上传UI(像户部BOM上传,客户端解析,数据不外传) → 转正建议
②吏部决策卡换真(像户部三轮卡:真转正/招聘决策,缺证/三色标)
③下旨=立项:"招个销售总监"→开创性下旨→吏部人事立项(decree-classifier已支持"招")
④俸禄司定薪引擎(定薪合理性) / 风纪司违纪引擎(照刑部条款扫描范式)
```

### 与已有系统的接法
- 复用 `decree-classifier`（"招/聘/选"=开创→吏部立项）、`project-maturity`（吏部立项成熟度）、`reality-state` sourceLabel、`dept-external-hook`（薪酬可对行业薪资基准——锦衣卫填外部）。
- 触真产线资产（真发 offer/真定薪/真解雇）→ 铁律9 转后端；纯咨询(该不该转正/招谁)→前端。
