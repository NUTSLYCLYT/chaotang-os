# 户部估值工作台 PRD 骨架

日期：2026-06-26
适用范围：`/departments/finance`
状态：待实现

## 1. 目标

把户部从“预算/现金/ROI 工作台”升级为“企业价值裁决中枢”。

这一页不再只回答“这笔钱批不批”，还要回答：

- 公司现在值多少钱。
- 为什么值这个钱。
- 核心竞争力是否真实。
- 商业成长价值是否成立。
- 哪些因素会抬升估值，哪些因素会击穿估值。
- 下一步最值得做的唯一动作是什么。

## 2. 产品定位

户部保持六部中的财务中枢角色，同时新增一层：

- `CFO Office`：预算、现金、成本、报价、融资、核算、审计。
- `Valuation Office`：公司估值、核心竞争力、商业成长价值、估值叙事。

设计原则：

- 不新建“估值部”独立部门。
- 估值能力归于户部，避免形成第二套经营真相。
- 估值结论必须由户部主笔，多部会签，不允许只看单一财务口径。

## 3. 组织结构

户部建议升级为 8 司：

1. 户部尚书
   职责：最终财务立场、总裁决、风险兜底。
2. 度支司
   职责：预算、预测、经营模型、资源重排。
3. 金库司
   职责：现金流、回款、付款、融资、资金安全。
4. 计簿司
   职责：核算、报表、账实一致、收入确认。
5. 价本司
   职责：成本模型、报价边界、毛利结构。
6. 投审司
   职责：ROI、回收期、NPV、IRR、情景分析。
7. 稽核司
   职责：审批、内控、异常、舞弊、红线。
8. 估值司
   职责：企业估值、竞争力评分、商业成长价值评分、估值解释权。

## 4. 会签机制

估值司是主笔，不是单独拍板。

四部协同会签：

- 礼部：品牌势能、客户信任、对外叙事质量。
- 兵部：市场空间、竞争态势、增长质量、赢单效率。
- 工部：产品壁垒、交付能力、研发复利、供应链护城河。
- 锦衣卫：外部情报、竞品验证、行业窗口、证据核验。

会签输出统一进入一份 `户部估值圣旨`：

- 当前估值区间
- 核心竞争力评分
- 商业成长价值评分
- 上调因子
- 下杀因子
- 缺证项
- 下一步唯一动作

## 5. 核心判断模型

### 5.1 三轴模型

企业价值不做单一分数，先做三轴，再合成总裁决：

1. 现金与利润轴
   看现金余量、利润质量、回款质量、预算纪律、抗风险能力。
2. 竞争力与壁垒轴
   看产品差异、交付稳定、客户粘性、供应链控制、组织执行。
3. 成长与市场空间轴
   看收入质量、增长速度、市场空间、复购、渠道效率、竞争位置。

### 5.2 四类结论

- `准奏`：价值主张成立，可进入下一步经营动作。
- `补证`：价值逻辑可能成立，但关键证据不足。
- `复核`：存在重大分歧或红线，需要人工会签。
- `驳回`：估值叙事或成长逻辑明显失真，不应推进。

## 6. 页面骨架

采用“左卷轴 + 中圣旨 + 右业务裁决栏”的结构。

### 6.1 左栏：户部司署卷轴

形态要求：

- 打开收起位置与上书房一致。
- 交互方向与上书房一致。
- 视觉采用户部卷轴，不做普通 sidebar。

左栏第一层只放司署面板与一句话介绍：

- 尚书总览
- 度支司
- 金库司
- 计簿司
- 价本司
- 投审司
- 稽核司
- 估值司
- 六部会签
- 史馆旧案

左栏第二层通过二次链接下钻：

- 点击“估值司”进入估值维度说明。
- 点击“礼部会签”进入品牌与叙事证据。
- 点击“锦衣卫会签”进入外部证据与竞品核验。

首页不堆长文，只给目录、状态、摘要、跳转。

### 6.2 中栏：户部圣旨主舞台

中间永远只突出 1 份主裁决，不同时摆很多卡片。

结构顺序：

1. 圣裁
2. 当前估值区间
3. 三轴总览
4. 核心竞争力
5. 商业成长价值
6. 四部会签摘要
7. 风险红线
8. 后令

中栏重点是“老板一眼能签字”，不是信息堆栈。

### 6.3 右栏：业务清单与方案台

右栏承接“具体问题 -> 判断 -> 方案”。

分四组：

1. 估值问题
   例：为什么估值上不去、为什么融资折价、为什么利润增长不带来价值增长。
2. 竞争力问题
   例：产品壁垒是否真实、交付是否可复制、客户粘性是否足够。
3. 成长问题
   例：收入质量、毛利结构、回款质量、复购、渠道效率。
4. 行动方案
   例：提价、砍低质收入、补证据、修叙事、补交付、重排资源。

每个业务条目结构固定：

- 问题
- 当前证据
- 户部判断
- 协同部门
- 可执行方案
- 风险/代价

## 7. 视觉方向

审美方向：金墨卷轴 + 深色账册 + 冷金属边框。

要求：

- 不做普通 dashboard 卡片墙。
- 左栏是司署卷轴感。
- 中栏是圣旨感，大留白，大标题，强裁决感。
- 右栏是专业案卷感，密度略高但有层级。
- 动效只做卷轴展开、批注浮现、会签盖印。
- 户部主色继续使用现有帝金系，不改设计 token。

## 9. 页面默认态

默认进入“户部尚书总览”。

默认态应展示：

- 今日估值圣裁
- 三轴信号
- 当前估值区间
- 会签进度
- 红线提示
- 右栏问题清单

没有真实数据时：

- 诚实空态
- 明示缺证
- 给出应补材料
- 不显示伪估值

## 10. 交互纪律

- 左栏卷轴开合位置与上书房一致。
- 中栏圣旨固定为主舞台，不被右栏覆盖。
- 右栏滚动独立，不影响中栏卷轴阅读。
- BottomDock 保持底部唯一问责入口。
- 选中某一业务问题后，Dock 自动带入问题上下文。

## 11. 分阶段落地

### Phase 1：结构重构

- 把 `/departments/finance` 从文档介绍页改成工作台壳。
- 落左中右三栏。
- 做卷轴开合与圣旨主舞台。

### Phase 2：估值能力接线

- 新增估值司数据契约。
- 接入三轴评分与会签数据。
- 中栏可展示企业价值裁决。

### Phase 3：协同闭环

- 礼部、兵部、工部、锦衣卫会签接入右栏与中栏。
- 形成“何以上调/何以下杀”自动解释。

### Phase 4：史馆闭环

- 每次估值变化生成一份估值圣旨。
- 可回看历史裁决与驱动因子变化。

## 12. 成功标准

老板打开这一页，应在 30 秒内回答：

- 公司当前价值判断是什么。
- 值这个钱的核心原因是什么。
- 最危险的下杀因子是什么。
- 现在最该做的唯一动作是什么。

如果做不到，这页仍然只是“漂亮的财务展示页”，不是户部工作台。
