# 军机处「像上书房」改版 PRD

- 版本：v1 · 2026-07-05
- 范围：前端主仓 `chaotang-web-lyt`，单页 `/command-center`（军机处唯一入口）
- 性质：**改版收敛**，非新建。军机处已复用上书房三栏壳；本 PRD 目标是把"仪表盘化的劣化版"收回"电影级安静房"。
- 关联：上书房基线 `docs/DESIGN_REFERENCES/05-our-best-shots/真基线-上书房-1440-2026-06-23.webp`；上书房改版 PRD `dev/notes/上书房-战略与改版PRD-2026-07-05.md`

---

## 0. 一句话

军机处不是"要做成上书房式"——它已经用了同一套 `ShangshufangLayoutShell` 三栏壳、同一个 `EdictStage` 卷轴、同样的丞相/钦天监人物翼。问题是**每一栏都被塞满，丢了上书房的仪式感（漂浮卷 + 底部朱批命令轴）与克制空态**。本改版=**做减法 + 让卷轴重新漂起来 + 补底部命令轴**，不换风格、不碰冻结视觉资产。

---

## 1. 背景与问题（证据）

现状截图（1440，prod 3050 实拍）与上书房基线并排对比，六处差距：

| # | 维度 | 上书房基线 | 军机处现状 | 问题 |
|---|---|---|---|---|
| P1 | 顶部 | 直接进沉浸场景 | 多一条 Tab 栏（作战沙盘/会审室/案卷立案）压在最上 | Tab 切断电影感、内容下压 |
| P2 | 卷轴 | 金卷漂浮居中、大留白 | 卷轴顶着 stepper 被压扁成米色面板 | 卷轴失去漂浮、负空间被吃 |
| P3 | 左翼 | 丞相人物卡（一句职责） | 丞相卡 + 钦天监"训诲"三条编号新手教程 | 教程像 help，不像作战室 |
| P4 | 右翼 | 近乎空，钦天监卡 + 一句提示 | 3 数字块 + 六部表态 + 风险封询 + 负责人汇报 | 一整墙小面板、信噪比低 |
| P5 | 空态 | 一张待接案主卷，安静 | 满屏"0 / 待接案 / 暂无 / 尚未接入真案" | 空盒子占据默认视图 |
| P6 | 底部 | 五键朱批命令轴居中 | 只有左右两人物卡，中间无命令条 | 缺最有仪式感的下旨轴 |

根因：复用了对的壳，但用"每栏都想显得有内容"的加法思路填充，丢了上书房"敢空"的克制。

---

## 2. 目标 / 非目标

### 目标（可验收）
- G1 一进军机处即是沉浸三栏场景，顶部无 Tab 遮挡（P1）。
- G2 中央卷轴恢复"漂浮 + 上下留白"，stepper 瘦身为卷内细进度（P2）。
- G3 左翼回归双人物卡（丞相辅政 + 钦天监训诲），无新手教程常驻（P3）。
- G4 右翼空态收敛：仅数字块常驻，会审/风险/汇报三卡空态折叠、真案点亮（P4/P5）。
- G5 新增底部命令轴（军机处语义五键），左右保留问丞相/问钦天监人物卡（P6）。
- G6 空态统一为"一张待接案主卷 + 回上书房立真案"，信号密度对齐安静房（P5）。

### 非目标
- ❌ 不换风格方向（保持上书房电影级三栏；军机处身份差异——靛蓝 `#8AA4FF` / "機密"印 / 会审语义——保留不动）。
- ❌ 不改 `globals.css`、`design-tokens.ts`、keyframe、帝金色值、启动动画时序（冻结）。
- ❌ 不新建视觉组件，不装新依赖。
- ❌ 不改后端 SSE / BattleStream 数据契约；不改 sourceLabel 真链路判据（`resolvePanelMode`）。
- ❌ 不动会审室/案卷立案两视图的**内容**，只调其入口收纳方式。

## 3. 用户与场景

- 主用户：电池老板（决策者），进军机处看"一条真案的会审+作战全貌"。
- 次用户：内部演示/自查（QA、大神会审）。
- 核心场景：
  1. **空态（无 taskId）**：从导航直接进，应看到一张安静的"待接案"主卷 + 回上书房立真案，而非满屏 0。
  2. **接案态（带 taskId）**：从上书房 decreeDispatch 跳入，中央卷轴与 BattleStream 同屏回写；左翼丞相拆解、右翼六部表态/风险/奏折逐个点亮。
  3. **下旨/流转**：通过底部命令轴发圣旨/召六部会审/派蜂群/转史馆。

## 4. 功能需求（PRD）

> 每条给出：现状 → 目标 → 交互/状态。全部落在 `src/app/(dashboard)/command-center/page.tsx` 三栏填充 + 复用现有原语。

### F1 · 顶部去 Tab、场景直入（P1，高冲击）
- 现状：`JunjichuViewTabBar`（command/council/cases）渲染在 `ShangshufangLayoutShell` 之上。
- 目标：默认进入即"作战沙盘"沉浸态，顶部不再有并列 Tab 条。
- 交互：会审室（原 `?view=council`）/ 案卷立案（原 `?view=cases`）两个次级视图入口收进 `ShangshufangLayoutShell` 的 header `actions` 区（次级药丸按钮）或右翼顶部一个小切换；`?view=` 路由参数与 URL 语义**保持不变**（不破坏 54 处引用与深链）。

### F2 · 卷轴漂浮、stepper 瘦身（P2，高冲击）
- 现状：中央 `flex-col` 里 stepper（占整行粗条）→ EdictStage → buildDraft → BattleStream 顺序堆叠，卷轴被压。
- 目标：卷轴恢复漂浮，四周留白；stepper 由"整行粗条"改为**卷轴顶部内嵌细进度线**（或并入卷 kicker 行）。
- 交互：`currentStage`（立项1/会审2/封询3/盖章4）语义与数据不变，仅视觉降权。接案态 BattleStream 仍在卷下同屏，但不得再挤压卷轴主体最小高度。

### F3 · 左翼去教程、回归双人物卡（P3，高冲击）
- 现状：左翼 = 丞相辅政卡 + 钦天监"训诲"三条编号（军机处是什么/怎么开始/四角看什么）。
- 目标：左翼 = 丞相人物卡（辅政一句）+ 钦天监人物卡（训诲一句），对齐上书房 `ShangshufangRailPanel` 人物范式。
- 交互：三条新手教程从常驻移出，收进一个 header 或卡角"?"提示弹层（可选，非常驻）。

### F4 · 右翼做减法、空态折叠（P4/P5）
- 现状：右翼 = 3 数字块(大臣/蜂群/风险) + 六部表态 + 风险封询 + 奏折验收 + 负责人汇报 workflow chip。
- 目标：**数字块常驻**（军机处该有战情计数）；六部表态 / 风险封询 / 奏折验收在**空态折叠为一句提示**，真案（有 minister/risk/memorial 数据）进来才逐条点亮。
- 交互：折叠文案示例"待接案后于此展开六部会审、风险封询与奏折验收"。DepartmentWorkflowChip 是否保留见 Open Q。

### F5 · 底部命令轴（P6，高冲击 · 仪式感核心）
- 现状：底部仅 footer 一行文字 + 全局左右问丞相/问钦天监人物卡；**中间无命令条**。
- 目标：照上书房 `VerdictActionBar` 五键范式，新增军机处居中命令轴，动词换语义：**发圣旨 · 展卷 · 召六部会审 · 派蜂群 · 转史馆**。
- 交互：每键必须对应真实动作或明确标注"待接案不可用"（禁装饰按钮，铁律 13.2）；空态下"召六部/派蜂群/转史馆"应 disabled 并给一句 why。左右人物卡（问丞相/问钦天监）保留。
- 复用：`src/features/shangshufang/components/VerdictActionBar.tsx`（若语义差异过大，参数化其 actions 而非另写一套——铁律 3/6）。

### F6 · 空态统一收敛（P5）
- 目标：无 taskId 时，中央=一张"军机处待接案"主卷（现有 `commandCenterToEdict` 已产出，保留），其余面板空态一律折叠；全屏不再出现多个"0 / 暂无"独立盒子并列。
- 诚实纪律：空态 sourceLabel 必须为 `DEMO`（无真案），禁用 `MIXED` 冒充半真（现有 `buildCommandCenterMinistryBrief` 判据已正确，勿改）。

## 8. 原型屏列表与信息架构（IA）

军机处 = 单路由 `/command-center`，三视图（`?view=`）+ 两数据态。本改版只重排"作战沙盘"视图，另两视图仅调入口收纳。

```
/command-center  (军机处 · 唯一入口)
│
├─ 作战沙盘 (默认 view=command)  ← 本 PRD 主改
│   ├─ Header: eyebrow(JUNJICHU·COMMAND) / title(军机处) / subtitle
│   │         actions: [回上书房] [发圣旨/重新立案] [会审室↗] [案卷立案↗]  ← F1 tab 收纳于此
│   ├─ 左翼 (300px): 丞相人物卡(辅政一句) + 钦天监人物卡(训诲一句)         ← F3
│   ├─ 中央 (flex): 卷轴细进度线(stepper 瘦身) → EdictStage 漂浮卷           ← F2
│   │              接案态: 卷下 BattleStream 同屏 / buildDraft(工部建设案)
│   ├─ 右翼 (330px): 数字块[大臣·蜂群·风险](常驻)
│   │              空态→一句折叠提示 / 接案态→六部表态·风险封询·奏折验收     ← F4
│   └─ 底部: [问丞相卡] — 命令轴[发圣旨·展卷·召六部会审·派蜂群·转史馆] — [问钦天监卡]  ← F5
│
├─ 会审室 (view=council)  ← 入口收纳，内容不改（CouncilView）
└─ 案卷立案 (view=cases)  ← 入口收纳，内容不改（CasesView）

数据态（作战沙盘内）:
  ├─ 空态 (无 taskId, DEMO):   单张待接案卷 + 面板折叠 + 命令轴部分 disabled   ← F6
  └─ 接案态 (有 taskId, MIXED/LIVE): 卷↔SSE 同屏回写 + 面板逐个点亮
```

> 说明：本 PRD 不构建高保真原型（用户未请求 prototype）；如需，交 `frontend-ui-engineering` 按上表落地。
