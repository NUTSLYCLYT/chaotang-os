## 1. 设计① · 军师认怂徽（Confidence Disclosure）

### 1.1 后端契约（接线① swarm trace 结果里**新增**字段）
在决策结果对象上加：
```ts
confidence: number;                 // 0..1，各输入项置信度对结论的加权(后端算)
weakInputs: Array<{                 // 仅列低置信项，全硬则空数组
  item: string;                     // "对手真实底价"
  reason: string;                   // "靠公开中标倒推，无合同"
  sourceLabel: 'INFERRED' | 'MISSING' | 'FALLBACK';  // 复用 source-label 纪律
  impact: 'high' | 'medium' | 'low';
}>;
ifResolved?: { from: string; to: string };  // "±8%" → "±3%"，无则不显
```
> 654 session 那套算法内部已有每项 source_label + 质量分；这是**把已有的诚实暴露到返回契约**，非新建能力。

### 1.2 前端（新组件 + 挂点）
- 新组件 `src/features/shangshufang/components/ConfidenceDisclosureBadge.tsx`
  - props：`{ confidence, weakInputs, ifResolved, onSupplement }`
  - 渲染：琥珀带（非红）「军师坦白 · 这单我 {round(confidence*100)}% 有把握」+ 列 `weakInputs` + `ifResolved` 一句 + 〔派锦衣卫补证〕按钮。
- 挂点：`ShangshufangPage.tsx` 决策卡结论态，圣裁/建议之下、朱批五键之上。
- `onSupplement` 复用已有补证通路：`focusDecree('order', '请锦衣卫补齐：' + weakInputs.map(i=>i.item))`（生成一条真补证 task，认怂不撒手）。

### 1.3 克制规则（张小龙：第二天才是知道何时不出现）
- `weakInputs.length === 0` 或 `confidence >= 0.9` → **不渲染认怂徽**，改渲染绿色小勾「依据充分」。
- 一张卡最多列 3 条 weakInput（`impact` 降序取前 3）。
- 语气规范（Jobs）：老参谋口吻，**禁**"本结论仅供参考"式免责声明——一句免责就毁人设。

### 1.4 验收断言（回归护栏）
- [ ] 全项 `LIVE_ENGINE` 的决策卡（weakInputs 空）**不出现**认怂徽。
- [ ] 含 ≥1 `INFERRED/MISSING` 项 → **必出现**认怂徽且列出该项。
- [ ] 点〔派锦衣卫补证〕→ 真生成一条补证 task（走已有 task 通路，可回读）。
- [ ] `confidence` 文案数字 = 后端返回值，前端不自算。

## 2. 设计② · 可证伪锚点（Falsifiable Anchor）

### 2.1 后端/锦衣卫契约（证据依据项里**新增** anchor）
证据卡的某条依据行可带一个"可核对锚"：
```ts
anchor?: {
  claim: string;          // "对手底价 0.58–0.60 元/Wh"
  evidenceSource: string; // "锦衣卫 · 公开中标"
  evidenceUrl: string;    // 真可访问的公开来源(招投标公告)，禁编造
  credibility: 'high' | 'medium' | 'low';  // 见 §2.3 坑：必须真判，禁硬编码
  derivation?: string;    // "上月 XX 100MWh 中标价倒推单价 0.59"
};
```

### 2.2 前端（证据行支持"锚点"型）
- 新组件 `FalsifiableAnchorRow.tsx`（或证据卡依据行加 `anchor` 分支）：
  - 渲染：`claim` + 「依据：{evidenceSource} · {derivation}」+ **真链接**〔查看原文 ↗〕(`evidenceUrl`) + 可信度徽。
- 挂点：翻面证据卡（建②）里"对手底价/竞品/市场"类依据行。

### 2.3 诚实闸（两道，缺一必崩）
1. **无真 url 不冒充可证伪**：`evidenceUrl` 缺失/非 http → 该行**降级**成普通"推断"标签，不渲染〔查看原文〕。假锚点比没锚点更致命（老板一点发现是编的，全盘崩）。复用 `parse-inbox-feed` 那套边界闸思路，在渲染前 filter。
2. **⚠️ credibility 不许拿硬编码值**（memory 坑取证）：锦衣卫 `rowToSignal` 曾把 `credibility` 硬编码 `medium`，**禁**拿它判可信度徽（否则默认全 medium、失真，会审 CRITICAL 级）。可信度必须来自真判据（来源类型/交叉验证数），拿不到真判据 → 不显可信度徽，只显来源链接。

### 2.4 验收断言
- [ ] 锚点行必须有可访问 `evidenceUrl`（http 开头）；无 url → 降级"推断"标签，无〔查看原文〕。
- [ ] `credibility` 徽**不出现**于 credibility 为硬编码默认值的情况（宁可不显）。
- [ ] 编造/占位 url（示例/待补/#）在边界被拒，不上卡。

## 3. 前端现在能先做的（不等后端，先把壳+闸+测试立好）

铁律9 下前端不算结论，但可**先建可插拔的显示层 + 诚实闸 + 契约类型**，后端字段一到即插即用：
1. `contracts/shangshufang.ts` 加 `DecisionConfidence` / `EvidenceAnchor` 类型 + `schemas.ts` Zod。
2. `ConfidenceDisclosureBadge.tsx` / `FalsifiableAnchorRow.tsx` 两组件 + 克制规则 + 诚实闸。
3. `parse-*` 边界校验：无 url 锚点降级、硬编码 credibility 不显。
4. nodetest：认怂徽克制规则（全硬不显/含缺证显/取前3）、锚点诚实闸（无url降级/占位拒收/硬编码credibility不显）——**照 `parse-inbox-feed.nodetest.ts` 金标+反例范式**，即交后端的 eval fixtures。
5. e2e：mock 一条带 weakInputs + anchor 的决策卡，断言认怂徽出现、锚点真链接可点、假锚点不渲染。

> 这样前端侧"什么算对"先钉死（可测、不依赖后端），后端按 §1.1/§2.1 契约吐字段即接通——延续"前端拥有什么算对、后端拥有怎么产出"(铁律9)。

## 4. 交后端的 delta 契约（在接线① swarm trace 之上加）
```
决策结果  += { confidence, weakInputs[], ifResolved? }
依据项    += { anchor?: {claim, evidenceSource, evidenceUrl(真), credibility(真判), derivation?} }
```
硬要求：weakInputs/anchor **只放真的**，空则空数组/省略，**禁占位冒充**（前端边界闸会拒并 fail-loud）。

## 5. 顺序（张小龙取舍）
接线① 真跑通（关2 底座）→ 建② 证据卡 → **① 认怂徽** →(验证老板买账)→ **② 可证伪锚点**。
两个都上、且都克制得住 = 老板第一次觉得"这不是 AI，是个敢认怂、能验证、值得托付的军师"。**别在关2 没跑通前先做这两层——无处可挂。**

## 6. 文案语气规范（Jobs · 成败在此）
认怂徽/锚点的每个字用「一个敢拦老板、敢认怂、敢立字据的老参谋」口吻：
- ✅ "对手底价我押 0.58–0.60，来自上月那单公开中标，你可以点进去核。"
