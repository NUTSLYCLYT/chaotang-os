# 多 agent 协作 · 防复发方案(2026-07-02)

## 病根
多个 agent 挤在一条分支 `feat/department-flywheel` 上,无地盘、无门 → 脏树、合并冲突反复出现又消失、
UU 冲突标记潜伏一整个 session 挡住 build 没人发现、合码时互相吞 WIP。**所有 git 痛苦都是这个症状。**

## 治根(三选一,推荐 A + C)

### A. 一 agent 一分支 + PR(推荐)
每个 agent 从 master 切自己的分支(`feat/<agent>-<主题>`),各自推、各自开 PR 合 master。
主干只经 PR 进,不再多人同分支直推。**这是最干净的根治。**

### B. 文件地盘表(若坚持同分支,退而求其次)
明文划定谁拥有哪些文件,他人只读不改:

| 区域 | 属主 | 文件 |
|---|---|---|
| 上书房飞轮/史馆 | (本线) | `core/courtos/runtime/live-memorial-*`、`archive/*`、`shangshufang/confirm-edict` |
| 命令中心/统一Loop | 并发线 | `command-center/page.tsx`、`unified/*` |
| 六部/部门页 | 并发线 | `departments/*`、`features/<部>/*` |
| B栈遗留 | 待清 | `api/shangshufang/*`(收敛后进 attic) |
| 共享 SSOT(改前喊 [shared]) | 全员 | `lib/jiqun-api.ts`、`lib/contracts/*`、`lib/reality/*`、`package.json` |

规则:改共享文件前 commit message 首行喊 `[shared] <文件>`;禁 `git add -A` / `git add .`,一律文件级分拣。

### C. CI/pre-commit 挡冲突标记(必上)
`scripts/guard-conflict-markers.sh` 遇 `<<<<<<< / ======= / >>>>>>>` 直接 fail。
- 挂 pre-commit 钩子:提交即拦。
- 挂 CI:红树无处遁形(charity-majors:让树状态可观测)。
- package.json 加 `"guard:conflicts": "bash scripts/guard-conflict-markers.sh"`。

## 合码流程(方案第2-3步)
1. 树干净后跑 `dev/scripts/merge-master-into-flywheel.sh`(master→特性分支,冲突在特性分支解,master不动)。
2. 双门绿(tsc + build)+ 零冲突标记。
3. 开 PR `feat/department-flywheel → master`,人工点合并(单向门,§15)。
