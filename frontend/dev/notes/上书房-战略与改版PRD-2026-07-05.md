- **Product**：私人智囊内阁——决策 inbox → 一句话结论+建议 → 朱批/下钻/拦门 → 归档复用
- **Wedge**：储能电池 pack（已真跑通、有真数据）

## 第二部分 · 上书房改版 PRD v1

### 0. 一句话
上书房 = 老板每天"上朝"的地方：内阁把该他拍板的决策排好队，一句话结论+建议，他朱批/下钻/被拦门，拍完归档复用。三栏服务的是**这一条决策流**，不是一个信息 dashboard。

### 1. 老板的一天（核心 Loop，设计的北极星）
```
上朝 → 看排好队的决策(左栏) → 选一件(中栏出决策卡)
  → 信 → 朱批采纳(2秒)
  → 半信 → 翻面看证据/分析/缺证/风险 → 再朱批
  → 高风险 → 被拦门, 强制展开确认, 不许一键静默盖章
  → 拍完 → 归档史馆 → 下次类似案自动引用本次决定+结果
右栏(情报/教学/战略)是"抬头看天"的余光, 不抢中栏的决策注意力
```

### 2. 三栏信息架构（在用户原案上按战略修正）

| 栏 | 用户原案 | PRD 修正 | 修正理由（挂到战略） |
|---|---|---|---|
| **左** | 奏折队列，紧急重要排前 | 保留。每条=来源徽+一句话由头+风险等级+sourceLabel；排序用**真实风险等级(L0-L4)**，非新造算法 | 步5拦门/铁律5：优先级要有真实数据源 |
| **中** | 圣旨=链接态；回奏=正文2/3+丞相建议1/3+返回/下一步 | **重构为决策卡**：默认=结论态(一句话圣裁+建议动作+朱批区)；正文/证据是"翻面"下钻，不是默认满屏；高风险强制翻面 | 步3结论优先+证据一键可达+拦门。原案缺"老板怎么拍板"=退化成阅读器 |
| **右** | 上⅓大趋势 / 中⅓引导教学 / 下⅓战略调整意见 | 保留三段，但每段**诚实标来源**；下⅓战略建议按铁律4=决策加视觉权重→必须标 sourceLabel、不得伪装定论 | 铁律4/5：数据源与视觉权重是高危 |
| **抽屉** | 丞相&钦天监对话，自动弹出，右侧5亮色按钮(和谁对话未定) | 对话对象=**内阁**(丞相为首，可点名钦天监/锦衣卫等)；**5个按钮=老板的5个决策动作**：采纳/补证/复核/驳回/追问——让"对话"即"下旨" | 统一用户零散想法；朱批动作有归处 |
| **新增** | （无） | **史馆取水口**：中栏决策卡旁常驻"上次类似案：你怎么判的+结果如何" | 步4护城河引擎，缺它=飞轮没取水口 |

### 3. 中栏详规（注意力中心，重点）
**默认：结论态决策卡**
- 圣裁一句话（当前奏折的核心结论）
- 建议动作（内阁建议老板怎么做）
- sourceLabel（LIVE/MIXED/FALLBACK…，不许 DEMO 伪装 LIVE）
- 朱批区：采纳 / 补证 / 复核 / 驳回 / 追问（= 抽屉右侧5键，同一套动作）
- 缺证/风险徽（有则显，红色一针见血）

**下钻：翻面态（非跳页，可逆）**
- 翻到背面=回奏正文（原案 2/3）+ 丞相分析与决策建议（原案 1/3）
- 证据、缺了哪条证、风险点
- 内容过多 → "展开详情阅读"
- 随时翻回正面朱批（Norman：翻面不跳页，信任是翻面）

**高风险拦门**
- 命中高危词（股权/合同/法律/重大付款/对外报价/供应商锁定…）→ 决策卡**强制翻面**、朱批"采纳"前必须过人工确认，禁一键静默（铁律13.5）

### 4. 左栏详规
- 来源：六部 / 军机处 / 丞相 / 钦天监 / 锦衣卫
- 排序键：风险等级(L0-L4) × 紧急度，高危+紧急置顶
- 每条：来源徽、一句话由头、风险色、sourceLabel、未读/已朱批态

### 5. 右栏详规（诚实优先，防空转）
- **上⅓ 大趋势**：国际政治/军事/金融/产业 + 对我们的影响。★数据源待定=最高空转风险区（锦衣卫情报？钦天监预测？占位？）
- **中⅓ 引导教学**：静态文案 or 跟当前奏折联动的上下文教学（待定）
- **下⅓ 战略调整意见**：对创业方向/企业战略的调整建议。**铁律4高危**——标 sourceLabel、标"建议非定论"、产出者需明确（丞相？钦天监会审？）

### 6. 对话抽屉
- 触发：自动弹出的时机需收敛——建议"选中一条奏折且需追问时"弹，而非每条都弹（防挡中栏阅读）
- 对话对象：内阁（丞相为首，可 @点名 钦天监/锦衣卫）
- 右侧5键=采纳/补证/复核/驳回/追问，全亮全可点，点击=对当前决策下旨并落库

### 7. 移动端退化（AGENTS.md §2.1）
- 优先保留中栏决策卡（核心卷轴）
- 左栏队列收成顶部抽屉/下拉；右栏情报三段收到底部顺序展开
- 抽屉对话全屏化

### 8. 待决问题（收敛到真正需老板拍板的）
1. **右栏上⅓大趋势的第一条真实数据从哪来？**（最高空转风险，铁律5——答不出就先别给版面，占位要明示）
2. **右栏中⅓引导教学**：静态 vs 上下文联动？内容源？
3. **右栏下⅓战略建议产出者**：丞相 / 钦天监会审 / 其他？（涉及铁律4视觉权重）
4. **对话抽屉自动弹出时机**：每条奏折弹？还是仅追问时弹？（防遮挡）
5. 下载链接下载什么？（PDF 奏折→走已有官印/公文导出，还是新做？）
6. 左栏风险等级(L0-L4)是否已有真实打分源，还是需接入？

### 9. 验收标准（要点）
- 老板 2 秒能对一条低风险奏折完成"采纳"（结论优先达标）
- 任一决策卡证据"一键可达"、可逆翻回（翻面不跳页）
- 高风险决策无法一键静默采纳（拦门断言，铁律4回归测试）
- 任一面向老板的结论都带 sourceLabel，无 DEMO 伪装 LIVE
- 归档后下次同类案能引用上次决定（护城河取水口通）
- 一眼看出是朝堂OS，非通用 dashboard（AGENTS.md §2.1 截图验收）

### 10. 测试计划（要点，照 e2e/swarm-members.spec.ts 范式）
- 双门鉴权种子（cookie courtos.access_token + localStorage courtos.auth）
- 三态 mock（loading/empty/error）
- 高风险拦门回归断言（构造高危奏折→断言无法一键采纳）
- sourceLabel 归一断言（FALLBACK 不冒充 LIVE）
- 移动端 320/375/768 无横向溢出
