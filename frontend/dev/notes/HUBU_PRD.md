## 1. 背景与问题

中国 95% 企业年收入 < 1000万，**没有财务部、没有 CFO**，老板自己管钱，把记账报税外包给**代账公司**——而代账是个黑箱：只被动记账报税，不主动帮你省税、不管现金流、不预警风险。老板做财务决策（这笔款付不付、这个项目投不投、这笔贷划不划算）时**既慢又容易被盲点坑**。

> **核心痛点**：小老板缺的不是财务软件，是一个**信得过、买得起、主动盯着钱**的 CFO。

## 2. 目标 / 非目标

**目标**
- G1 把老板的钱决策从"看报表 3 天审批"压成"30 秒一张卡拍板"。
- G2 比真办公更可信：每个产出带证据/缺证/风险/来源，老板敢照着拍板。
- G3 主动产生可见价值（省税 ¥X、查出对账差错），自带 ROI 让小老板愿付费。
- G4 一引擎多班底：小公司 6 岗、大公司 +4 岗、用户可增减；成长不换产品。

**非目标**
- N1 不做面向专职财务团队的重型 ERP（那是大公司 v3）。
- N2 不在前端自建真实付款/对外报价产线（铁律9，转后端 jiqun）。
- N3 不画假图表/假数字凑"完整形态"（缺数据就显性缺证）。

## 3. 目标用户与场景

**主用户画像**：年收入 < 1000万、老板即决策者、无专职财务、用代账公司。
**关键场景**：
- S1 早上打开 → "今天 3 件待你拍板，1 件紧急（现金流）" → 扫一眼拍板。
- S2 客户要报价 → 点投资/成本司 → 看财务分析 + 风险四象限 → 准奏/削减。
- S3 月初 → 税务司主动提醒"本月增值税 5 号到期 ¥1.2万，已帮你合法省 ¥X"。
- S4 想借经营贷 → 融资司算还款能力 + 方案对比 → 划不划算一目了然。

## 4. 产品定位与核心价值

**定位**：老板的 **CFO 办公厅**——10 个 AI 财务专员各司其职，把钱决策做成「快·稳·懂」。
**核心价值（护城河）= Trustworthy by construction**：可信不靠模型聪明，靠结构——
接地率校验 + 缺证显性 + 跨部冲突声明 + 风险册 + 单向门人工门 + 可追溯证据 + sourceLabel。
**用户三需求**：**快**（决策提速）·**稳**（盲点兜底）·**懂**（随卡教学，看懂自己的账）。

## 6. 功能需求

### 6.1 顶 · 显示条（Header）
- 户部身份 + **关键数字**（现金储备/待批数/平均 ROI）+ **sourceLabel 灯**（LIVE/FALLBACK 不撒谎）+ 通知。
- 数字来自 `/api/court/hubu/overview`（真 Turso）。

### 6.2 左 · 班底（精简）
- 司列表：每司一行 = 名 + **在岗状态点**（●在岗/◐办公中/○缺证待补）+ 一句话职责（hover/折叠）。**精简，不堆介绍**（张小龙）。
- 点司 → 中栏卷轴切到该司圣旨详情。
- 「+加岗(N)」折叠；「管理班底」进增减（`hubu-roster.ts` 已支持，默认收起）。
- 介绍默认折叠（▸ 展开看户部定位）。

### 6.3 中 · 户部卷轴（展示区 · hero）
两模式：
- **模式 A 全部待拍板**（默认）：决策队列，最急 6 件 + 展开；每张 = 30 秒拍板卡（见 6.5）。
- **模式 B 单司圣旨详情**（点司进入）：该司角色专属板块（见 6.6），顶「← 返回全部」。

### 6.4 右 · 急事 / 在办 / 已办（让部门"活"起来）
- **🔴 急事**：P0/紧急决策（按 priority+风险排序，取 overview）。🟢 真数据。
- **⚙ 在办进度**：哪个司正在处理什么 + 进度。🟡 **需任务态**（v1：追问中=处理中；完整需任务队列）。
- **✅ 已办·价值**：处理完的产出 + **价值数字**（省税 ¥X/查出差错 ¥Y）。🟡 **需 outcome 账**（v1 占位，待接回灌）。
- 诚实：🟡 板块先放占位 + "待接 X"，不造假活动。

### 6.5 拍板卡（模式 A 每张）
- 头：优先级徽 + 清洗后真标题 + 预算/**回报**/回收。
- **三引擎真数字**（`hubu-engines.ts`）：户部裁决（准奏/削减分阶段/缓议补证/驳回）+ 评分 + 风险敞口。**有数据算真值，缺则显性缺证。**
- **随卡讲解 ❔**：每个数字一句人话（grounded 在该卡真数据）。
- **缺证**显性；**最大风险**一句；**单向门** → 强制「需陛下亲裁」。
- 动作：准奏/补证/驳回/追问户部（追问走真 `/ask`，带接地率）。

### 6.6 单司圣旨详情（模式 B · 投资司为样板间）
| 板块 | 内容 | 数据源 |
|---|---|---|
| ① 财务分析 | ROI/NPV/IRR/回收 + 敏感性 + DCF | 🟢 纯函数·真 |
| ② 风险四象限 | ROI×风险，该项落哪象限 + 单向门判定 | 🟢 真 |
| ③ 市场信息 | 行业景气/对标/利率 | 🟡 待接行情源 |
| 产出 | 投资评审意见书 + 四象限定位 | 🟢 |
> 其余 9 司板块设计见 `hubu-design.md`；**先深做投资司🟢板块当样板间**，其余先板块占位+数据源灯。

### 6.7 底 · CommandBar
- 户部快捷问 chips + 羽笔输入 + 追问户部(金)/下旨(蓝)/召户部合议。复用 `ImperialCommandBar`。

## 7. 数据源与真实性分级（设计脊梁）

- 🟢 **现可真**（纯函数/overview）：拍板卡裁决、投资财务分析、四象限、预算执行、税负测算、税务日历、急事。
- 🟡 **需外部 feed**：实时行情、利率、汇率、市场景气、现金时序、在办进度、已办价值。
- 🔴 **需后端真账**（转 jiqun）：损益表、成本 BOM、审计凭证、真实付款/报价。
- 规则：每板块挂数据源灯；🟡🔴 先占位+"待接X"，**禁画假图/假数字**（铁律13.2，DEMO 不伪装 LIVE）。

## 8. 内容质量保障（怎么保证"比真办公更可信"）
1. **接地率校验**：每个数字挂证据，未挂→reprompt（`/ask` 已有）。
2. **缺证显性**：不懂就说缺，进结构进卡，绝不假装。
3. **单向门人工门**：高危（预付/独家/大额）禁一键静默，强制亲裁。
4. **sourceLabel 不撒谎**：LIVE/FALLBACK 真标；演示数据带角标（DESIGN §9）。
5. **三引擎回归断言**：`hubu-engines.nodetest.ts`（5 条）守"数字没算错"，CI 每次复核。
6. **eval-harness**：5-10 真实财务场景，比"接大神内核 vs 不接"，防"专业地生产错误"。
7. **教学也 grounded**：随卡讲解只讲本卡真数字逻辑，禁脱离数据空谈。

## 9. 大神设计原则
- **费曼（真懂自检）**：每个数字旁的 ❔ 必须能用一句人话讲清"怎么来的"——讲不清=我们自己没真懂=不许上。
- **贝索斯（可逆决策/客户痴迷）**：单向门 vs 双向门是投资/大额决策的第一判据；从客户真实价值反推回报，不是成本加成。
- **马斯克（成本拆解/极限）**：报价/成本拆到料工费第一性；问"这步真需要吗"，删到不能再删。
- **张小龙/Rams（克制）**：默认 6 件、左栏精简、定制折叠；less but better，一张数字全真的卡 > 十张漂亮空卡。

## 10. 技术约束与边界
- 视觉冻结：复用 `globals.css`/`design-tokens`/帝金/上书房组件，**禁改冻结资产**（AGENTS.md §2）。
- 依赖纪律：禁装新图表库/radix/shadcn；图表先用 **SVG/CSS**（sparkline/进度条/四象限/饼图）。
- 引擎边界（铁律9）：前端只做无副作用咨询（三引擎纯函数）；触真实付款/报价/BOM → HTTP 转 jiqun。
- 端口：dev 3002 / prod 3050；basePath `/chaotang`。
- 新页面带 E2E spec（§11）。

## 13. 风险与对策
| 风险 | 对策 |
|---|---|
| 富贵病：先搭 10 司×4 板块全占位 | 先一个样板间真转（M2），其余占位+数据源灯 |

| 触碰真实付款被焊在前端 | 铁律9：转 jiqun；前端只读+咨询+意向 |

## 14. 度量指标
- 决策时长：从"打开→拍板"中位数（目标 < 60s）。
- 可信度：拍板卡平均接地率（目标 ≥ 80%）。
- 价值可见：右栏"已办·价值"月度数字（省税/查错金额）。
- 真实度：🟢板块占比逐迭代上升，🟡🔴占位逐步解锁。
