## 业务流程架构分析
- 深入分析了朝堂OS业务流程：三大回路 + 四大版面 + 学习复利
- 核心闭环：runCourtUnifiedDecisionLoop（court_unified_decision_loop_v1）
  - 用户提问 → 起草圣旨 → 规划会审 → 锦衣卫情报包 → 六部会审 → 冲突识别 → 合成奏折 → 质门 → 用户裁决
  - 驳回/补证回流重启；圣裁通过归档史馆
- 三大回路：
  1. 主决策回路（unified-decision-loop）- 上书房
  2. 主动简报回路（proactive-briefing-loop）- 上书房，10秒知道今天该做什么
  3. 庄园蜂群调度（estate-dispatcher）- 军机处，丞相调兵执行
- 四大版面：上书房（主舞台）、军机处（蜂群调度）、史馆（复利引擎）、六部（会审能力域）
- 六部映射：户部=CFO、兵部=CRO、刑部=CLO、礼部=CMO、工部=CTO、吏部=HR、锦衣卫=情报
- 质量机制：四色信号灯（GREEN/YELLOW/RED/GRAY）+ SourceLabel（LIVE/LIVE_SWARM/MIXED/DEMO/FALLBACK）+ qualityGate
- 学习复利：playbook-updater 从归档决策提炼规则，下次同类问题更准
- 关键设计：部门触发关键词命中自动加入会审；冲突识别有预设的部门间张力规则（如兵部推进 vs 刑部红灯）
