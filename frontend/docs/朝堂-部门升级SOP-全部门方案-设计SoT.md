# 朝堂 OS · 部门升级 SOP · 全部门方案 · 设计 SoT

> 立于 2026-07-01。从已成熟的**户部/刑部**提炼一套可复制 SOP，套到其余各部。
> **核心纪律（铁律5/马斯克）**：不是"现在同时建 8 个"——是**一套 SOP + 按真数据成熟度排的路线图，一次真做一个**。
> 每个部的命门只有一句：**它的第一条真实数据从哪来？** 答不出 = 冻结，别建。

---

## 1. 户部/刑部 升级方式 = 6 步 SOP（每个部照填）

| 步 | 做什么 | 户部（已证） | 刑部（已证） |
|---|---|---|---|
| ① 认领真数据源 | 找第一条真数据（H盘文件/Turso表/上游部产出） | H盘带价BOM(63个真) | 合同/法规/出口门 |
| ② 真引擎(纯函数) | 解析+计算，域特定 | parseBomRows→bomCostToDocument | xingbu-lens 合规检查 |
| ③ 盖印呈奏 | 御赐呈奏+本部官印+七段+成色 | 成本呈奏(¥1234·电芯命脉) | 合规呈奏 |
| ④ 御史巡城兵 | 该域"明显错"的确定性守卫 | cost-sanity(命脉非电芯即弹劾) | 缺证出口门 |
| ⑤ 司编制+会审接线 | roster + decision-loop | 户部办公厅(司) | 8司+合规会审(铁律4) |
| ⑥ 双门+回归断言 | tsc+build + 一条咬死的nodetest | cost-sanity 3测试 | 合规会审断言 |

> 复用平台原语：御赐呈奏格式 / DeptSeal(11部官印) / 成色诚实 / 御史巡查 / 省时+闭环 / 复制裂变 / 朝币激励——**全通用，各部只换②真引擎+①真数据+④御史规则。**

## 3. 路线图（按真数据成熟度排 · 一次一个 · 每个都带真数据）

1. **兵部**（🟢 最该先做）：户部真成本 ¥1234 → 兵部按毛利红线测算分档报价 → 盖兵部官印出报价呈奏 → 御史查"报价<成本=亏本"。
   **这一条通了 = 证明 SOP 真能跨部复制(不是又一个 demo)，且第二条真链(继户部后)真转起来。**
2. **钦天监**（🟢 近）：接 H盘同料跨日期价 → 料价真趋势 → 趋势呈奏(标置信)。御史查过度自信。
3. **吏部 / 礼部 / 太医院**（🟡）：各等其第一条真数据(员工档/客户台账/健康档)就位再上。太医院红线最严，先守"不诊断"。
4. 丞相会审收敛、史馆/锦衣卫(已升)持续接御史/激励。

> **判据（铁律5）**：每个部动手前必答"第一条真实数据从哪来"。答不出就**标位置冻结**，绝不建空壳呈奏(否则又是一摞"缺证未核定"的漂亮空奏折)。

---

## 4. 不可破

- **一次一个真链，禁同时铺 8 个**（马斯克：先通一条端到端，再复制）。
- **每个部都过双门 + 一条咬死御史的回归断言**（铁律4）。
- **成色诚实**：缺真数据就标"待接入/缺证"，绝不编(户部那条真链已立标杆)。
- **复用平台原语，禁各部各造一套**（铁律6/2：呈奏格式/官印/御史/激励/成色 全共享）。
