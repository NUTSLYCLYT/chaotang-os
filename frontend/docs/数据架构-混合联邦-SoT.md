# 朝堂数据架构 · 混合联邦 SoT（2026-06-28 · 单向门已定）

> 决策(user):**原文本地 · 洞见上云**。这是两套并行建设(我的 evidence 管线 + 并发的 BOM/dept-external-hook)的**统一真相源**——两边一律按本文对齐,禁再各长一套(铁律2/13.2.10)。

## 〇、铁律:什么存哪
| 数据 | 存哪 | 例 |
|---|---|---|
| **原始敏感文件** | **客户端解析,永不上传** | 财报原文、BOM 明细、合同全文 |
| **分类元数据** | 服务端(史馆) | {证据类型, 司归属, 可信度, 文件名hash, 时间} |
| **脱敏结论** | 服务端(史馆) | "户部判:速动比率健康,应收偏高"(无具体金额) |
| **决策兑现** | 服务端(史馆) | "该建议 3 个月后兑现:对" |

**判据**:能反推出原始敏感数值的,留客户端;只是"结论/标签/对错"的,上云。

## 一、为什么这样:鱼与熊掌兼得
- 钦天监综合的是**各司的结论 + 兑现**(不是原始财报)→ reference-class base rate 照样能算 → **飞轮转**。
- 原始财报/BOM **不离浏览器** → **隐私在**,一次泄露毁不了。
- 前沿名:联邦式(federated)——raw 本地,insight 上云。

## 二、两套建设怎么合一
| 角色 | 谁的 | 在混合架构里的位置 |
|---|---|---|
| 客户端解析(BOM/财报) | 并发 agent `bom-upload-analyze.tsx` | ✅ **正确**,就是"原文本地"那一半 |
| 外部数据口子 | 并发 agent `dept-external-hook.ts` | 合并进 SourceAdapter(见下) |
| 证据分类/可信度门 | 我 `contracts/evidence.ts` + `evidence-classify` | ✅ 分类**脱敏结论**,不存原文 |
| 取证据组上下文 | 我 `source-adapter.ts` | ✅ 读的是脱敏结论,喂司 |
| 司答案→报告 | 我 `deliverable.ts` | ✅ 不变 |
| 史馆 base rate | 我 `reference-class.ts` | ✅ 喂的是结论+兑现 |

**合并动作**:`dept-external-hook`(他)与 `source-adapter`(我)收敛成**一个** SourceAdapter——客户端解析出脱敏结论 → 经 evidence 分类 → 史馆存结论 → SourceAdapter 取用。原文那一步在浏览器,服务端只见结论。

## 三、evidence 契约要符合(调整)
`EvidenceRecord.contentSnippet` 语义改为「**脱敏洞见**」(不是原始内容):客户端解析后**只上传脱敏摘要/结论**,原文留本地。加 `rawStaysClient: true` 不变式,守"原文永不上云"。
