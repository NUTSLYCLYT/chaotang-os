# 朝堂OS · 落地总方案（贯穿版 · SoT）

> 立：2026-06-30 · 把全程讨论贯穿成一条可执行的落地线
> 整合并统领：[[朝堂OS-全量问题清单-对照初心-SoT]]、[[户部财务诊断-资料采集指引]]、设计纲领（行业包部分已搁置）
> 一句话：**把"上传资料 → AI 专业诊断 → 可裁决奏折"这一个引擎，先在户部财务诊断上做成，让 1 个真老板说"这帮我了"，再照范式复制到各部门。**

---

## 一、战略：一条线，不是一堆功能

**北极星（不变）**：让 1 个真实老板，用朝堂真做成 1 件经营决策，并说"这帮我了"（AC5）。当前这个数字 = **0**。整个方案只为把它变成 **1**。

**纪律（贯穿全程，违反即回退）**：
1. **从建造→证明**：不建第七个部门、不铺新版面、不做行业包平台。把已有的用透。
2. **先证明一个**：户部一条路跑通拿到 AC5 之前，其余部门只标位置不投入。
3. **诚实是护城河**：sourceLabel 贯穿、缺证降级、高风险人工门——别人抄得走界面，抄不走它。
4. **成本压到最低**：能确定性算账就不烧 token；LLM 只用在"判断/解读"，不用在算数。

---

## 二、引擎：贯穿一切的核心机制（这是项目的"耦合点"）

整个朝堂只有一个引擎，六部是它的六个专业实例：

```
老板上传资料(A·私有数据)
   ↓ ① 校验 + 诚实标源(sourceLabel)
   ↓ ② 确定性算账(现金跑道/财务比率 · 零 token · 准且省钱)
   ↓ ③ AI 用专业知识库(B)解读判断(grounding · 不瞎编 · 这里才用 LLM)
   ↓ ④ 一份可裁决诊断奏折(圣裁/分奏/证据/风险/缺证/后令/来源)
   ↓ ⑤ 老板裁决(采纳/补证/复核/驳回/追问) · 高风险过人工门
   ↓ ⑥ 史馆归档 + 事后兑现回填
   ↓ ⑦ 下次同类问题更准(飞轮/复利)
```

**两类资料分工（关键，别建错）**：
- **A · 用户上传的经营数据**（财报/流水/合同）→ per-tenant 私有，绝不进公共库。入口 = 各部门《资料采集指引》。
- **B · 专业知识库**（财务比率基准/风险规则/行业标尺/法务条款…）→ 跨用户复用、放知识库、**是真正的资产和护城河**。每条带出处，AI 靠它 grounding，不靠模型记忆瞎说。

**通用的是引擎（①–⑦），垂直的是每个部门的 A 清单 + B 知识库。** 这一句解开"通用 vs 垂直"。

## 三、五个落地阶段（每个都直接服务 AC5，有判据，可逐步做）

### 阶段 0 · 户部一条真诊断闭环 ★最高优先（目标：2 周内拿到 AC5）
**做什么**：让老板上传三年两张表 → 现金跑道 + 基础财务诊断 → 一份可裁决奏折 → 摆到 1 个真老板面前。
- 入口：已写好的《户部财务诊断-资料采集指引》，第一版只要 🔴 必备两张表。
- 算账：**确定性**（现金跑道/比率），复用已验证跑通的 `hubu_travel_budget_memorial` 同款心法（21 测试全过、零 token）。
- 诚实：缺现金流量表就标"利润含金量未验证"，不假装完整。
- 产出：现金跑道（还能活几个月）+ 钱卡在哪 + 下月预报 + 一句圣裁。

**判据（= AC5）**：**1 个真老板看完说"这个有用 / 比我会计专业"。** 不是 build 通过，是真人原话。
**前/后端**：后端出诊断（jiqun，确定性 Python）；前端做上传 + 奏折展示。
**成本**：近乎零 token（确定性算账）。

### 阶段 1 · 专业知识库 B 通电（让诊断从"算账"升到"大师判断"）
**做什么**：把财务比率基准 + 风险信号规则 + 行业标尺做成结构化知识库（YAML/JSON，**每条带出处**）；AI 解读时调 B grounding。
- 这里才引入 LLM——**只在"判断/解读"环节**（把比率翻译成专业判断和人话），算账仍确定性。
- 模型：DeepSeek（便宜）+ router 的 triage/budget；判断环节单次成本极低。
- 基准用**铭硕真实历史 + 同行公开财报**校准电池行业专属基准，不用通用教科书（Deming）。

**判据**：诊断里出现带基准的专业判断——"按电池行业基准，你的应收周转 68 天偏慢，建议…"，且该基准能点出处。
**前/后端**：后端（知识库 + grounding）。

### 阶段 2 · 上线门（能安全给真用户用）
**做什么**：财务数据是最敏感的，租户隔离是底线。
- C1：后端签带 tenantId 的真 JWT，禁 alg:none（部分已在 `26ed731` 合入，需验收）。
- C3：多租户隔离下沉到数据层默认过滤，不靠每端点手加 WHERE。
- honesty:all 改 `;`→`&&` + 建 Gitee `.workflow`（让 CI 真拦）。

**判据**：把链接发给真老板，他的财务数据**跨租户读返回空**（断言）；CI 真拦过一次红 push。
**前/后端**：前后端 + Gitee admin（开分支保护）。

### 阶段 3 · 飞轮（越用越准，护城河）
**做什么**：老板裁决（采纳/补证/驳回）回流史馆 → 下次引用；事后兑现回填（这次说的现金风险 3 个月后兑现没）→ 校准可信度。
- 复用已有但未通电的 `recall-outcome` / `habit-learner`（孤儿能力，通电不重造）。

**判据**：史馆出现第一条"判断→兑现"真实对照；第二次诊断能引用第一次结论。

### 阶段 4 · 复制范式（一个成了再铺第二个）
**做什么**：户部 AC5 达成后，照《资料采集指引》附录范式做刑部/兵部的 A 清单 + B 知识库，复用同一引擎。
**判据**：第二个部门**零改引擎**就能上诊断。

## 四、四条贯穿全程的纪律（落到每一步）

| 纪律 | 怎么落地 |
|---|---|
| **诚实层** | 每条结论挂 sourceLabel（原件/历史/手工确认）；缺数据标"未提供，XX未完成"；验真必备项（现金流量表/纳税表）不给就明说"利润真实性无法验证" |
| **成本** | 确定性算账打底（零 token）→ LLM 只在判断解读 → DeepSeek + triage + per-user budget 封顶；蜂群深挖是老板显式付费动作 |
| **安全/边界** | 诊断只读不操作（不付款/不报税/不改账）；触碰真实付款/产线资产才转后端军机处；租户数据默认隔离 |
| **不脱初心** | 每个阶段判据都连到 AC5 或上线门；不做行业包平台、不建新部门；任何提议先问"这让那个老板更快说'帮我了'吗" |

## 五、第一步：这周就做（最小、可验证）

1. **拿一份真报表**：你用铭硕近三年利润表+资产负债表（脱敏），走一遍现有户部诊断，看现在到底能出什么、缺口在哪。
2. **补上"一句圣裁"**：让诊断输出从一堆数字变成"还能活 X 个月 + 哪笔钱要催 + 一句行动"。
3. **摆给一个真人看**：哪怕就是你自己或一个相熟的小老板，看他会不会说"有用"。

**这一步不需要新架构、不烧 token、不碰上线门——它只需要一份真报表和一个真人的反应。** 那个反应，就是项目成败的唯一信号。

---

## 六、怎么算成功（验收）

- [ ] **0→1**：1 个真老板用真财报跑完诊断，说出"这帮我了/这比我会计专业"（AC5，唯一硬判据）。
- [ ] 诊断带 sourceLabel + 缺证诚实降级，无假精确数字。
- [ ] 成本可算：单次诊断 token 成本 < ¥0.1（确定性打底）。
- [ ] 能安全给真用户：跨租户读返回空。
- [ ] 飞轮起转：第二次诊断引用第一次。
- [ ] 范式可复制：第二个部门零改引擎上线。

> **一句话收尾**：先用一份真财报、一个确定性诊断、一句人话圣裁，让一个真老板说"有用"。这一件事成立的那天，朝堂从"最精致的 demo"迈进"真正的产品"。其余所有阶段，都是这一件事的放大与复制。
