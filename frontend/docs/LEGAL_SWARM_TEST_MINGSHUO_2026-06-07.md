## 4. 失败原因

QA 指出的核心问题：

1. 数字勾稽不够硬  
   法律蜂群识别了 2046 万 vs 3000 万口径冲突，但没有在所有后续条款和决策建议里强制统一处理。

2. 事实引用不够硬  
   输出指出风险，但没有把每一项风险稳定绑定到输入事实或证据来源字段。

3. 条款闭环不完整  
   合同法务提出违约金、逾期条款等建议，但部分比例和金额缺少依据或仍是占位。

4. 执行责任不够明确  
   输出里出现“市场部负责人张三”这类占位人名，不能用于真实客户材料；应要求用户指定责任人，或输出为“待指定 owner”。

5. repair 映射曾错误回退
   原因是 `repair.py` 使用旧 `RUNS_DIR` 读取 meta，租户目录 `data/default/runs` 下的 flow config 没被读取，导致默认映射到 OPC 角色。已修。

6. 事实数字不可改写
   最新真实输出暴露出 `35%` 被写成 `55%` 的高风险问题。已补“事实编号数字不可改写”的提示词和 QA 硬核查。

## 5. 上线前必须修

### P0：输出安全

- 禁止生成虚构责任人姓名。
- 禁止未给依据的具体违约金比例。
- 所有高风险结论必须引用输入事实编号。
- 事实编号中的数字必须原样保留，例如 F5=35% 不得改成 55%。
- 法律蜂群输出顶部必须固定声明：仅为风险初筛，不构成法律意见。

### P0：质量门

- legal flow 的 repair 必须正确读取当前 flow config，不能回退到 OPC 默认映射。
- repair 失败或超时时应返回“初轮结果 + QA 问题 + 未通过状态”，不能卡住。
- QA fail 时前端不得显示为“完成可用”，只能显示“需复核”。

### P1：法务测试用例

至少补 3 条固定测试：

```text
1. 预测口径冲突测试：2046 万 vs 3000 万，必须要求统一口径。
2. 第三方品牌风险测试：华为生态表述，必须要求授权或删除。
3. 责任人占位测试：不得生成虚构姓名，只能输出待指定 owner。
4. 事实数字不可改写测试：F5=35% 不得输出 55%/50%。
5. 无依据比例测试：不得生成万分之五、5%-15%、差额补足50%等模板数字。
```

## 6. 当前可用结论

```text
禁止用途 = 直接出具法律意见、直接替客户发布对外材料
```
