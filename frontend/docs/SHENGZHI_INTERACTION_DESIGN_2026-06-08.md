# 圣旨交互设计 · 大神会审沉淀 · 2026-06-08

> 张小龙(产品克制) · Bezos(客户反向/单向门) · Harrison Chase(agent编排/契约) · Kahneman(决策呈现) · Drucker(管理裁断)
> 用途:直接落成 **丞相 prompt 设计 + 圣旨 UI 信息架构 + 每个蜂群 output 契约**。本档立设计,不写实现。

## 0. 两条定海针(全员一致)

- **用户第一眼只想看一件事** = 丞相替你拍的那**一个决定** + 它替你**默认了什么**(错了点一下改)。其余全折叠。
- **丞相最不该做的那件事** = **汇总**(把各部的话原样转述一遍再"请您定夺")。汇总 = 踢皮球 = 多余的中间层 = Day 2 官僚。丞相唯一不可替代的价值是**替没时间的老板关掉选项、做裁断**。

## 1. 丞相澄清循环(Q1)—— "可纠正的默认",不是"追问"

- **默认不问**。触发追问的唯一判据:缺的参数**会不会推开一道单向门 / 让 router 跑错部门**(不可逆动作 / 客户身份 / 预算量级)——不是"细节不全"。猜错成本 < 打断成本。
- **一次最多问 1 个**(那个致命槽)。其余一律智能默认 + 在圣旨里标注「我默认了 X,错了点一下改」。把交互成本从"回答问题"降到"否决一个猜测"。
- **触发挂在 router 置信度上**(不是关键词):`conf ≥ 0.8` 直接出方案;`0.5–0.8` 出简化方案让确认;`< 0.5` 才追问。(现有 `prime-guidance.ts` 的 VAGUE_WORDS 词表触发是半成品,升级成置信度/槽位触发。)
- **烂提示自动改写 = 结构化槽位抽取,不是模板套壳**。LLM 把口语密旨抽进 `IntentSchema`,抽不出的槽才进 `gaps`。用户确认的是**这张抽取卡片**(一眼否决某一格),不是散文;**永不回显"优化后的提示词"**(那是在教育/纠正用户)。
  ```
  IntentSchema = { objective, target_entity, constraints[], done_criteria,
                   irreversible_flag, assumed_defaults: [{slot, value, source}] }
  ```
  > Harrison Chase 实锤:现有 `prime-guidance.ts:73-89` 的 suggestedPrompt 是把原话塞固定模板=假改写,上生产对真老板就是话术,必须换真抽取。

## 2. 笼统需求 → 简化方案 + 确认(Q2)—— "不反对"即确认,别设门

- **不设"确认门"**(缺时间的老板最恨门;"确认简化方案"= 让他替你的不确定性买单)。**确认 = 被动"不反对"**:简化方案本身就是确认载体,往下读 / 点展开 = 确认,反对就在**首句改一个词**。
- 简化方案必须是**「可裁决的最小版本」**,里面**有一个能被一眼反驳的具体数字或判断**(能被反驳的才不是正确的废话),不是"更短的提问"。
- **砍掉这道门的两个信号**(命中任一即零信息量):(a) 简化方案出现用户**已说过/可从画像默认**的内容 = 复述浪费;(b) "确认后产出" 与 "不确认直接放它跑产出" 差异 **< 一屏** = 纯踢皮球。
  > 反面警钟(Harrison Chase):确认门若被训练成无脑点"确认",它账面一直绿、实际从不拦错 —— 和没有门**无法区分**(飞轮三问"能看见转吗"的反面)。

## 3. 每个蜂群 output 契约(Q3)—— displayTier 决定信息架构

统一卡片契约,**字段自带展开层级**;第一屏只渲染 `headline`(≤1 行),`detail` 折叠"追问才展开":
```
SwarmCard = { dept, claim(一句判断), evidenceNumber(一个数字证据), confidence,
              displayTier: 'headline' | 'detail', deepHref, source? }
```
**判据(Bezos):** 若某部输出无法被压成丞相头版那句话里的一个分句或一条证据,它这次就不该上第一屏。

| 蜂群 | headline 第一眼给什么 | detail / 红线 |
|---|---|---|
| **户部** 财务 | 一个带**区间+单位**的数字 + 一句结论(挂好坏色) | ROI 推导链折叠 |
| **工部** 技术 | 一句**判断**(能不能 / 卡哪道工序),**不给参数** | 参数表折叠 |
| **兵部** 市场 | 一条**"谁赢 / 差距"**判断 | 逐项竞品对比表折叠 |
| **钦天监** 前瞻 | 一条带触发条件的**「如果…就…」+ 概率区间**(非点估计)+ **强制 confidence** | 前瞻无置信度 = 噪声 |
| **锦衣卫** 情报 | **有硬情报才说**,带 **source URL + 时效戳** | 无来源契约层拒收;**禁"暂无异常"**(=噪音 theater) |
| **史馆** 归档 | 当下**完全隐身**,只在复盘时展开 | — |

> 升级:现有 `SwarmOutput`(5 个平铺 `string[]` 共用)→ 上述差异化契约 + `confidence` + `displayTier` + `source`;否则丞相分不清"事实 vs 猜测",优化圣旨质量时是在黑暗里调参。把 `number-verifier` 扩成 `evidence-verifier`,无来源情报拒收。

## 4. 丞相分析(Q4)—— decision object,裁断不汇总

丞相核心产出**不是一段总结,是一个裁断对象**(它生成圣旨头版那句话):
```
ChancellorDecision = {
  theOneThing,        // 现在唯一要做的(本周一件)
  theThingToNotDo,    // 明确点名"绝不做/暂缓"的那件 + 一句理由  ← 最反直觉最值钱
  conflictsResolved,  // 替你裁掉了哪些部门间矛盾(户部说能赚 vs 兵部说对手抢 vs 钦天监说有风险)
  reversibility,      // 'one_way_door' | 'two_way_door'
  signoff             // 由 不可逆 × 现金流占比 触发(非难度,非永远 true)
}
```
缺时间的人最需要的不是更多选项,是**有人负责替他关掉选项**。升级:现有 `PMPreview.aggregationStrategy`(干 string)→ 此结构化裁断对象。

## 5. 工程纪律(Harrison Chase · 贯穿)

- **先抽 Zod 契约 + 30 条真实密旨黄金评估集,再写 prompt**。控制流是代码不是散文,看不见就优化不了。
- 改写 / 确认门 / 折叠 三件事都必须**可量化**(路由命中率 / 返工率 / 拦错率),否则每次改丞相 prompt 都是在消耗运气。
- 验收门见 `scripts/verify-edict-quality.mjs`(6 条样本密旨,reversibility/chancellor_synthesis/qintianjian thresholds/反甩锅/无 weasel)。
