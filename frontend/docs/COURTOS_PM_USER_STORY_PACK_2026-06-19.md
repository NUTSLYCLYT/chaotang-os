# CourtOS 产品经理 User Story Pack

日期：2026-06-19  
方法：`product-manager-ai-workflow` / `/pm-story`  
范围：朝堂 OS 核心闭环：上书房 → 丞相 → 军机处 → 六部/蜂群 → 圣旨/奏折 → 用户裁决 → 史馆归档

---

## 0. 第一屏痛点句

**这个功能让老板少做的痛苦事：**

让老板不用在一堆聊天记录、部门汇报、表格、合同、项目进度和 AI 对话里来回翻找，系统每天自动把最该裁决的经营问题、证据缺口、风险和下一步动作整理成一份可裁决的奏折。

---

## 1. 用户与痛点

| 用户 | 当前痛点 | 成功体验 |
|---|---|---|
| 老板 / CEO | 每天信息太多，不知道今天最该裁什么；AI 给建议但无法判断真假和风险 | 10 秒知道今日一号问题，3 分钟读完一份有证据、有风险、有下一步的奏折 |
| 业务负责人 | 想法和机会很多，但难以变成可执行任务 | 输入一个模糊经营问题，系统自动拆出责任部门、证据缺口、执行路径 |
| 项目负责人 | 任务推进分散在不同人和工具里，状态不清 | 能看到任务从拟旨、会审、执行、裁决到归档的状态 |
| 产品 / 运营团队 | PRD、用户故事、测试用例和原型反复手写 | 脑图/粗需求可转成 PRD、研发需求、验收标准和原型规划 |
| 法务 / 财务 / 营销等专业部门 | 老板的问题常常没有边界，专业风险被忽略 | 各部门按职责输出分奏，风险和证据被结构化保留 |

## 2. Epic

### Epic A：老板每日决策入口

作为老板，我希望进入系统后立刻看到今天最值得处理的经营问题、紧急程度和处理理由，以便不用自己从大量信息中筛选重点。

### Epic B：丞相汇总与减负

作为老板，我希望丞相先处理琐碎事项，只把需要我裁决的少数问题呈现出来，以便我把注意力放在关键判断上。

### Epic C：军机处会审

作为老板，我希望系统能自动组织相关部门和蜂群会审一个问题，以便我看到多视角、有冲突、有证据的判断，而不是单一 AI 答案。

### Epic D：部门电影屏工作台

作为老板或业务负责人，我希望每个部门页都是左右贴边面板 + 中央电影屏，点击四周信息后在中屏看到详细内容，以便我像看一场经营作战电影一样理解重点。

### Epic E：圣旨 / 奏折 / 裁决

作为老板，我希望每份输出都能明确给出结论、证据、风险、缺证、下一步和裁决按钮，以便我能采纳、补证、复核或驳回。

### Epic F：史馆归档与复利

作为老板，我希望每次裁决都进入史馆，未来遇到类似问题能引用旧案，以便系统越来越懂我的判断标准。

## 4. 核心验收标准

### 4.1 北极星验收

| 编号 | 验收标准 | 判定方式 |
|---|---|---|
| NS-1 | 一个真实老板能用系统完成一件经营决策 | 现场操作或录屏 |
| NS-2 | 老板 10 秒内知道今天最该裁什么 | 上书房首屏观察 |
| NS-3 | 老板 3 分钟内读完一份有用奏折 | 计时 + 老板反馈 |
| NS-4 | 老板能明确选择采纳/补证/复核/驳回/追问 | 裁决状态落库 |
| NS-5 | 史馆能找到本次决策，后续可引用 | 归档记录 + 相似问题召回 |

### 4.2 页面体验验收

| 页面 | 验收标准 |
|---|---|
| 上书房 | 中央只显示圣旨/奏折主内容；今日预案 3-5 件；其余进丞相侧栏 |
| 军机处 | 显示议题、参会意见、参与蜂群、丞相主持实况 |
| 部门页 | 两侧面板贴边，中间电影屏显示具体内容；每页信息入口不超过 8 个 |
| 礼部 | 明确是营销、宣传、企业文化、公关、审美门禁，不叫市场页 |
| 锦衣卫 | 信息分类优先，按政策法规/市场竞情/供应交付/核验分流组织 |
| 钦天监 | 展示全球/国家趋势、风险机会、连锁反应、公司影响 |

### 4.3 数据与可信度验收

- 所有用户可见结论必须带 sourceLabel。
- DEMO/FALLBACK 不得伪装 LIVE。
- 高风险事项必须过人工确认门。
- 用户裁决必须持久化。
- 奏折缺关键字段不得进入正式归档。

## 5. Edge Cases

| 场景 | 处理方式 |
|---|---|
| 无真实数据 | 显示“暂无真实建议”或“样板建议”，不得伪装 |
| LLM 失败 | 保留任务，标记失败原因，可重试，不丢状态 |
| 用户输入过于模糊 | 丞相先追问 1-3 个关键问题，再拟旨 |
| 部门意见冲突 | 军机处必须显示冲突点和丞相取舍理由 |
| 高风险但证据不足 | 默认“待补证/复核”，禁止直接准奏 |
| 用户刷新页面 | 当前任务、裁决、归档状态必须恢复 |
| 页面信息过多 | 丞相汇总，只显示不超过 8 个关键入口 |
| 部门职责混淆 | 每个部门先写“本司负责/不负责”，再展示内容 |

## 7. Open Questions

1. 第一批真实老板验收对象是谁？是否仍以铭硕电池业务为 reference implementation？
2. “今日预案 3-5 件”的排序规则以紧急度、金额影响、风险等级还是老板偏好为主？
3. 丞相“已办”事项是否需要老板逐条追认，还是只在每日汇报里摘要？
4. 部门电影屏统一骨架是否先只落礼部、锦衣卫、钦天监，再复制到其他部门？
5. 真实蜂群输出和前端咨询引擎的边界如何在 UI 上明确提示？
6. 产品经理工作流生成的 PRD 是否要进入史馆，成为后续开发复盘材料？
