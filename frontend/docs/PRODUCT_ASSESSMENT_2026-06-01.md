# 朝堂 OS · 顶尖 PM 产品评估（2026-06-01）

> 评估人：窗口 A · Claude Opus 4.8（产品御史视角）
> 立场：不吹、不报喜。PM 的职责是说清"这能不能成、最危险的假设是什么、下一步只做什么"。
> 证据基线：734 个 TS/TSX · 91 页 · 24 feature · 38 路由(8 green/10 yellow) · **77 mock vs 14 真实 API** · 0 商业文档。

---

## 0. TL;DR（一句话裁决）

**朝堂 OS 是一个概念与 UX 都极其出色、规模已经很大的"AI 智能体政府"企业级 SaaS 愿景 —— 但它现在 85% 是漂亮的 mock 演示外壳，最大的风险不是做得不够多，而是"做得太宽、证得太浅"。**

裁决：**有条件 GO**。基础足够强，但必须立刻从"再建更多部门/页面"掉头到"把一条闭环做成真的、拿到一个真实用户"。**砍宽度，证深度。**

## 2. 真正的优势（别丢掉的）

1. **差异化叙事**：把"管理一群 AI agent"包装成"帝王治理朝堂"，这是认知锚点 —— 2026 一堆同质 agent 工具里，这个会被记住。
2. **UX 护城河雏形**：视觉/动效/组件成体系，演示冲击力强，适合融资/招商场景拿下第一印象。
3. **工程治理成熟**：契约即真相、铁律文档、多智能体建设流水线 —— 大多数早期团队没有这套，能支撑后续快速复制部门。
4. **闭环设计是对的**：上书房(决策)→军机处(执行)→史馆(复盘)→次日建议，这个经营闭环抽象是产品的灵魂，方向正确。

---

## 3. 致命红旗（按危险度排序）

**🔴 #1 — "演示外壳"陷阱（生死级）**
77 mock vs 14 真实。产品的核心承诺是"AI 智能体真的替你经营"，但现在几乎全是写死的演示数据。**一个买家问"这是真在干活还是动画？"就会穿帮。** 这是 demo 和 product 的分水岭。

**🔴 #2 — 没有商业模式与用户（生死级）**
0 商业文档、0 真实用户。不知道谁付费、解决谁的什么痛、凭什么收钱。**做得越多、越精美，沉没成本越高，越难掉头。**

**🟠 #3 — 隐喻是双刃剑**
帝制/朝堂极吸睛，但企业买家可能困惑："我要的是看板/自动化，不是当皇帝。" 隐喻可能是护城河，也可能是采购障碍 —— **未验证。**

**🟠 #4 — 广度碾压深度**
38 路由只 8 green。在没有一条做透之前继续铺部门(兵部/礼部/太医院…)，是在稀释有限资源。

**🟡 #5 — 执行碎片化**
25 文件未提交 + gitee 分叉 + 多窗口无锁并发。当前速度在制造未来的合并地狱。

---

## 4. 最危险的未验证假设（PM 的核心关切）

> 一个产品的成败，取决于最危险假设是否成立。按风险排：

| # | 假设 | 现状 | 怎么验证（最小成本） |
|---|---|---|---|
| H1 | 有人愿意为"AI 智能体经营中台"付费 | 0 证据 | 拿现有 demo 找 **3 个真实老板**聊，问"愿不愿付/付多少" |
| H2 | 帝制隐喻是加分而非障碍 | 0 证据 | 同一 demo 给 5 个目标用户，观察是"哇"还是"看不懂" |
| H3 | 智能体能产出**真实有用**的经营产出 | 几乎全 mock | 选 **1 个真实场景**(如厦门AI合作评估)，让 agent 跑真数据出真奏折 |
| H4 | 闭环能在真实使用中持续运转 | 0 次端到端 | 跑通一次 信号→下旨→真执行→真结果→归档→次日建议 |

**H3 + H4 是命门** —— 它们一旦证实，前面 A 档的 UX/叙事才有附着点；证伪，则全是空中楼阁。

## 5. 战略岔路（必须选一条）

```text
路 A：演示驱动（pitch-ware）
  继续铺部门、磨视觉 → 拿融资/招商的"震撼 demo"
  风险：永远停在"很酷但没人用/没人付"

路 B：产品驱动（拿一个真客户）⭐ 推荐
  砍掉 80% 待建，选 1 条闭环 + 1 个真实场景 + 1 个真实用户
  把 H3/H4 做成真的 → 拿到第一个"它真帮我做成了事"的证据
```

顶尖 PM 几乎都会选 **路 B**：**Demo 让人鼓掌，产品让人付钱。现在缺的不是第 9 个部门，是第 1 个用户。**

## 6. PM 裁决 + 唯一最重要的事

**裁决：有条件 GO，立即战略收敛。**

**唯一最重要的事（North Star 重定义）**：
> 不是"建完六部"，而是 **"让 1 个真实老板，用朝堂 OS 真的做成 1 件经营决策，并愿意说'这帮我了'"。**

一切不服务这个的工作，本周都降级。

## 7. 90 天聚焦建议（砍掉什么 / 只做什么）

**砍 / 冻结**：兵部/礼部/太医院新建、22 个 to-build 路由的铺量、任何纯视觉打磨。

**只做（按序）**：
1. **收束执行**（本周）：各窗口提交、gitee 同步、合并地狱拆弹。（Harness §10）
2. **跑通 1 条真闭环**（2 周）：选「经营信号→下旨→军机处→**真 agent 跑真数据**→真奏折→史馆归档→次日建议」，端到端可演示 + 截图存证。把这条链路上的 mock 换成真。
3. **拿 3 个真实对话**（3 周）：用这条真闭环找 3 个真老板，验证 H1/H2，收"愿不愿付"的真话。
4. **据反馈定 v1 商业版图**（30 天）：写第一份**商业文档**(谁/痛点/定价/GTM)——目前这是最大空白。
5. **达标再复制**：闭环+用户验证过关后，才用工部中台复制下一个部门。
