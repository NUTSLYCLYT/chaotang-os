# 11 Demo And Presentation Plan

本文件目的：定义 CourtOS 对外演示和路演脚本，只展示一条可信的老板裁决闭环，不展示散乱页面。
优先级：P1。P0 闭环稳定后进入演示增强。

演示目标：让用户相信 CourtOS 能帮老板做经营决策，而不是只展示炫酷页面。

## 能做什么

- 设计 3 分钟 Demo、7 分钟路演、15 分钟试用三种材料。
- 把上书房、丞相、军机处、奏折、裁决、风险门、史馆串成一条故事线。
- 明示 demo/fallback 数据和真实数据边界。

## 不能做什么

- 不能展示所有页面和所有六部细节。
- 不能把演示样例说成真实客户结果。
- 不能用视觉震撼掩盖 sourceLabel、证据、风险门和归档缺口。

## 演示主线

```text
一个真实经营问题
-> 上书房今日预案
-> 丞相指出证据缺口
-> 军机处多方会审
-> 奏折给出结论、证据、风险
-> 老板裁决
-> 高风险确认
-> 史馆归档
```

## 演示禁止项

- 不展示太多页面。
- 不讲所有六部细节。
- 不把 demo 数据说成真实客户结果。
- 不让用户陷入技术名词。

## 三种材料

| 材料 | 用途 |
|---|---|
| 3 分钟 Demo | 快速说明价值 |
| 7 分钟路演 | 商会/投资人/客户演示 |
| 15 分钟试用 | 让客户带真实问题跑一遍 |

## 验收标准

用户能复述：

1. 这个系统帮我筛重点。
2. 这个系统能给证据和风险。
3. 这个系统能让我做裁决并留档。

## 后续 Codex 可执行任务

```text
你是 CourtOS 演示脚本制作官。
只基于 docs/courtos_launch 和 P0 裁决闭环，输出 3 分钟 Demo 脚本、7 分钟路演大纲和 15 分钟客户试用流程。
不要新增页面，不要修改代码，不要虚构真实客户数据。
```
