# 01 Product Scope

本文件目的：锁定 CourtOS 上线版本的产品边界，防止上线前继续扩成 ERP、OA、CRM 或全量 Agent 平台。
优先级：P0。

## 当前已知事实

- CourtOS 当前已经过概念阶段，进入产品上线收口阶段。
- 第一版核心价值是“老板决策闭环”，不是六部全量自动化。
- 前端和后端都已有不少朝堂相关实现线索，但仍需按 P0 链路筛选。

## 当前缺口

- 上线范围需要继续防止被页面、角色、VAM、AI 盒子和非 P0 后端 flow 拉散。
- 对外产品话术、内测范围和演示范围还需要与 P0 闭环一致。

## 能做什么

- 定义上线 MVP 必须交付的老板裁决闭环。
- 判定新需求是否属于 P0、P1 或 P2。
- 为前端、后端、演示和运营提供统一范围口径。

## 不能做什么

- 不能把所有六部深度能力都塞进首版。
- 不能把 AI 盒子、私有化、本地大模型作为 P0 门槛。
- 不能为了演示新增无法归档、无法验收的伪功能。

## 上线版是什么

一个企业老板可用的 AI 经营决策操作系统 MVP。

它必须做到：

1. 老板看到今日预案。
2. 丞相筛选事项。
3. 军机处会审。
4. 生成奏折。
5. 老板裁决。
6. 高风险操作二次确认。
7. 史馆归档。
8. 下次可引用旧案。

## 上线版不是什么

- 不是完整企业 ERP。
- 不是完整 OA。
- 不是完整 CRM。
- 不是完整 AI Agent 平台。
- 不是所有六部全部成熟。
- 不是所有蜂群全部可用。
- 不是完整本地私有化方案。

## 验收标准

- 老板 10 秒内知道今天最该裁什么。
- 老板 3 分钟内读完一份有证据、有风险、有下一步的奏折。
- 老板能执行：批准、驳回、退回补证、追问、交蜂群执行。
- 高风险事项不能静默通过。
- 正式裁决必须能查回。
