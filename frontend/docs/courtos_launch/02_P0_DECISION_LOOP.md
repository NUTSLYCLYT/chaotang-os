# 02 P0 Decision Loop

本文件目的：定义 CourtOS 上线必须跑通的老板裁决闭环，所有页面、接口、演示和测试都围绕这条链路收口。
优先级：P0。

## 当前已知事实

- 前端存在上书房、军机处/会审、奏折、史馆、蜂群、风险确认相关页面和 API 线索。
- 后端存在 `flow_court`、`flow_shiguan_archive`、`jiqun_registry`、golden case、smoke 和多组朝堂测试线索。
- 当前北极星已明确为“老板裁决闭环”。

## 当前缺口

- 尚未确认用户能从一个事项完整走到史馆归档。
- 尚未确认 `sourceLabel`、`evidence`、`riskGate` 和 `audit trail` 在全链路一致。
- 尚未确认哪些页面是主线，哪些只是旧入口、演示入口或候选入口。

## 能做什么

- 判断某个功能是否服务裁决闭环。
- 给前端跳转、后端 API、数据归档和演示脚本提供主线。
- 作为上线门禁的核心验收依据。

## 不能做什么

- 不能用页面数量代替闭环完成度。
- 不能把缺证据、缺 sourceLabel 的内容直接送到最终裁决。
- 不能把 fallback/demo 数据归档成真实经营决策。

## 主链路

```text
上书房今日预案
  -> 丞相筛选：待裁决 / 待补证 / 已办
  -> 军机处会审：多角色意见 + 分歧 + 风险
  -> 合法奏折：结论、依据、证据、sourceLabel
  -> 老板裁决：批准 / 驳回 / 退回补证 / 交蜂群执行
  -> 高风险确认门：金额、合同、对外发布、删除、调度
  -> 史馆归档：裁决、理由、证据、时间、操作者
  -> 下次引用旧案：复用历史决策上下文
```

## 验收标准

1. 能从一个事项进入上书房。
2. 能被丞相分类。
3. 能进入军机处会审。
4. 能生成奏折。
5. 能被老板裁决。
6. 高风险事项必须二次确认。
7. 裁决结果必须归档。
8. 归档结果能在史馆查到。
9. 下次同类事项能引用旧案。
10. 全流程有 `sourceLabel`、`evidence`、`audit trail`。

## 非法状态

- `sourceLabel=unknown` 不得进入最终裁决。
- 缺证据的奏折只能进入待补证。
- fallback/demo 只能演示，不得归档为真实经营决策。

## 后续 Codex 可执行任务

```text
你是 CourtOS P0 闭环验收官。
只读检查前端路由、页面跳转、后端 contract 和现有测试。
按“上书房 -> 丞相 -> 军机处 -> 奏折 -> 裁决 -> 风险门 -> 史馆 -> 旧案引用”输出断点清单。
不要修改代码，不要启动服务，不要触发真实蜂群。
```
