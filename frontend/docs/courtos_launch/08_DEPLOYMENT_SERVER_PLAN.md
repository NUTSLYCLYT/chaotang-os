# 08 Deployment Server Plan

本文件目的：定义 CourtOS 从内测到正式上线再到企业私有化的服务器部署路线，优先简单稳定、可恢复、可监控。
优先级：P1。P0 是产品闭环和上线门禁；部署进入发布前必须升级为阻塞项。

服务器方案按三阶段推进。厂商价格、套餐和硬件标价变化快，发布前必须联网复核，不在本文档钉死具体价格。

## 能做什么

- 指导 MVP 内测服务器、正式上线服务器、企业私有化部署的阶段选择。
- 规定 HTTPS、备份、监控、日志、回滚等上线底线。
- 阻止第一阶段过早引入 Kubernetes、GPU 和复杂架构。

## 不能做什么

- 不能在产品闭环未跑通前把精力转向复杂基础设施。
- 不能没有备份、监控、回滚就对外上线。
- 不能在未联网复核前写死厂商价格和硬件标价。

## 阶段 A：MVP 内测服务器

目标：便宜、稳定、简单、好维护。

推荐架构：

- 1 台应用服务器。
- 1 个托管 PostgreSQL。
- 1 个对象存储。
- 1 个 CDN。
- 1 套监控。
- 1 套备份。

建议配置：

- CPU：2-4 vCPU。
- 内存：4-8 GB。
- 系统盘：80-160 GB SSD。
- 反代：Nginx / Caddy。
- 进程管理：Docker Compose / PM2。
- 备份：每日数据库备份。

不建议第一阶段上 Kubernetes 或 GPU 服务器。第一版瓶颈是产品闭环、稳定性、可信度，不是算力。

## 阶段 B：正式上线服务器

必须具备：

1. HTTPS。
2. 域名。
3. 数据库备份。
4. 错误监控。
5. 性能监控。
6. 登录权限。
7. 管理员后台。
8. 数据导出。
9. 灾难恢复方案。
10. 发布回滚方案。

## 阶段 C：企业客户 / 私有化

客户明确付费或试点后再考虑：

- 私有云部署。
- 本地 AI 盒子。
- 离线知识库。
- 本地向量库。
- 本地模型推理。
- 企业 SSO。
- 审计日志。
- 权限隔离。

## 验收标准

- 外网、手机、电脑均可访问。
- HTTPS 正常，重启后服务可恢复。
- 数据库有备份，异常有日志，错误可监控。
- 发布失败有明确回滚方案。
