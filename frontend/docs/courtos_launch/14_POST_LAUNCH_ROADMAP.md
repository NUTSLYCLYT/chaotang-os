# 14 Post Launch Roadmap

本文件目的：记录 CourtOS 上线后的版本路线，把好想法留住，但不让它们抢 P0 裁决闭环。
优先级：P2。

上线后再做的事，当前只记录，不抢 P0。

## 能做什么

- 收纳 V1.1、V1.2、V2 的增强方向。
- 防止上线前把后续版本功能混入当前提交。
- 为客户反馈后的产品迭代提供停车场。

## 不能做什么

- 不能把路线图当作当前开发授权。
- 不能抢走 P0 闭环、上线门禁和运营准备资源。
- 不能承诺未验证的 GPU、Kubernetes、全自动执行或全量 ERP/OA/CRM。

## V1.1

- 礼部、锦衣卫、钦天监三页电影屏样板。
- 完整 sourceLabel 可视化。
- 史馆旧案相似度提示。
- 客户试用反馈面板。

## V1.2

- 六部页扩展。
- 后端 17 蜂群与前端角色映射可视化。
- 军机处分歧轴展示。
- 更完整 audit trail。

## V2

- 企业私有化部署。
- AI 盒子。
- 本地知识库。
- 企业 SSO。
- 权限分级。
- 客户独立数据域。

## 暂缓项

- 全量 ERP/OA/CRM。
- 所有部门深度工作台。
- 全自动对外承诺。
- 无人确认的高风险执行。
- 未验证的 GPU / Kubernetes 复杂架构。

## 验收标准

- 路线图条目都有版本归属，不混入当前 P0 任务。
- 暂缓项不会进入上线前提交队列。
- 客户反馈进入路线图前先标注价值、风险、验证方式和优先级。
