# 朝堂世界级 UI 与立体背景执行方案

> 主控部门：礼部。协作部门：工部、史馆、军机处。目标不是多做页面，而是先做出一个能代表朝堂 OS 审美上限的样板间，再复制到六部。

## 1. 一句话方向

把朝堂 OS 做成“电影级 AI 决策操作系统”：真实业务信息在前，宫殿空间、人物、卷轴、金属边、光影和屏幕层叠在后，用户一眼知道这是一个能下决策、能调蜂群、能留证据的顶级软件。

补充产品铁律：八个核心页面不是部门介绍页，而是 **AI 部门作战台**。每个部门都要替代真实部门员工、主管和部门负责人，首屏必须展示具体工作内容、工作进度、可交付成果和负责人裁决。完整定义见 `docs/EIGHT_AI_DEPARTMENTS_PRODUCT_DEFINITION.md`。

## 2. 不先追插件，先建审美系统

Figma、Codex、imagegen、Playwright 都只是工具。真正的核心是礼部审美系统：

- 每个页面必须有一个能被截图传播的首屏记忆点。
- 每个页面必须回答老板的前三个问题：现在是什么、能不能做、下一步谁办。
- 所有 DEMO / FALLBACK / synthetic / blocked 都必须明示，不能被视觉包装成真实结论。
- 背景立体感优先用现有资产 + CSS 伪 3D 实现，真 3D 只用于确有交互价值的场景。
- 先做一个上书房样板间，验收通过后再复制到礼部、军机处、六部。

## 4. 技术路线

### 4.1 立体背景路线

先做伪 3D，不急着上 Three.js：

- 背景层：宫殿图全屏铺底，暗部压低，保留中轴。
- 空间层：用 `radial-gradient`、暗角、纵深遮罩制造远近。
- 前景层：卷轴、屏幕、人物、金属边框放在不同 z 层。
- 透视层：核心大屏/卷轴用 `perspective()`、`rotateX()`、阴影底座。
- 光影层：金色顶光、青色屏幕光、低透明反光条。
- 交互层：只在 hover/focus 和模式切换做 150-300ms 微动效。

### 4.2 字体与排版路线

不新增字体包，不改 `layout.tsx` 字体注入。用现有变量：

- 大标题：`var(--font-serif)`，强识别、少字、电影海报感。
- 业务正文：`var(--font-sans)`，保持老板可读。
- Trace / session / ID：`var(--font-mono)`，压低存在感。
- 首屏字重从“到处都粗”改成“标题重、结论重、证据轻、技术最轻”。

### 4.3 插件与工具分工

| 工具 | 做什么 | 不做什么 |
|---|---|---|
| Codex | 读仓库、改 TSX/CSS、拆组件、跑 build、截图验收 | 不凭空发明已存在组件 |
| Figma | 做首屏构图板、对齐字体层级、留评审意见 | 不替代真实浏览器验收 |
| imagegen | 补缺的 hero 图、背景图、角色宣传图 | 不覆盖现有可用资产 |
| frontend-design | 定审美方向和高质感实现 | 不牺牲业务可读性 |
| ui-ux-pro-max | 检查移动端、触控、对比度、层级 | 不盲目套通用模板 |
| Playwright | 桌面/手机截图、横向溢出、文本遮挡验收 | 不只看构建通过 |

## 5. 第一阶段：上书房世界级样板间

范围只做 `/study`，不扩散。

### 目标

把上书房从“功能很多的朝堂页”提升成“老板愿意截图转发的 AI 决策室”。

### 具体改动

1. **首屏电影构图**
   - 中央卷轴保持，但背景空间更立体。
   - 左右丞相/钦天监像舞台侧翼，而不是普通 sidebar。
   - 底部下旨栏像真实操作台，不像普通输入框。

2. **老板模式**
   - 首屏只强化四行：主张、证据、风险、下一步。
   - 技术回执、Trace、接口状态默认收起。
   - 蜂群结果必须显示 `工部校准` 和 `礼部审稿`。

3. **礼部审稿门禁**
   - `可呈报`：内部可呈报，外发仍需复核。
   - `需改写`：要压缩成老板语言再呈报。
   - `禁外发`：只能复核、补证、重跑，不能准奏。

4. **工部验收门禁**
   - 对 `blocked / failed / synthetic / incomplete` 禁止伪装成成功。
   - 后续把按钮权限接上：禁外发时只允许复核、补证、重跑。

### 验收

- `pnpm exec tsc --noEmit`
- `pnpm build`
- Playwright 桌面 1440x1000 截图
- Playwright 手机 390x844 截图
- 无横向溢出
- 首屏 3 秒内能看出当前决策、风险、下一步
- 截图里不能出现被遮挡或挤压的文字

## 6. 第二阶段：礼部作为审美中台

范围：`/departments/libu` 与 `/visual`。

- 礼部后墙大屏作为全站电影屏参考。
- 礼部素材库变成“审稿、定调、生成、归档”的素材中台。
- 每个素材进入 `礼部审稿单`：用途、渠道、风险、修改建议、发布结论。
- 礼部输出一套可复制到六部的 `审美单`。

## 7. 第三阶段：六部电影屏复制

先做三页样板，再复制：

1. 礼部：品牌、文化、宣传、审美门禁。
2. 锦衣卫：情报、证据、竞品、风险。
3. 钦天监：预测、情景、概率、预警。

统一骨架：

- 背景：部门空间图。
- 中央：电影屏/主判屏。
- 左侧：今日要务。
- 右侧：官员/裁决/证据。
- 底部：行动 dock。

## 8. 第四阶段：Figma 与资产流水线

Figma 只做三件事：

1. 上书房首屏构图基准板。
2. 部门电影屏组件规范。
3. 礼部审美门禁标注。

资产流水线：

1. 从现有 `public` 资产选 A/B/C。
2. 缺图才用 imagegen 补。
3. 新图先进入 `public/assets/libu/` 或对应部门资产目录。
4. 通过浏览器截图后才进入页面。

## 10. 不做清单

- 不新装 UI 框架。
- 不改 `globals.css` 和设计 token。
- 不把 mock/fallback 包装成真实结果。
- 不一次重做十个页面。
- 不为了酷炫牺牲老板决策速度。
- 不做只有人物、背景和诗意文案的部门介绍页；部门页必须展示任务、流水线、成果和负责人裁决。

## 11. 审美系统规格（§2「礼部审美系统」的可验收定义 · 2026-06-20 补）

> 本节把 §2 承诺的"审美系统"落成**可量化验收清单**，供多 agent 并发改界面时共守。
> 礼部研究 Linear/Cursor/Vercel/Igloo + Aceternity/MagicUI 2026 暗金奢侈手法后，按本仓**真实冻结 token** 校正。
> 完整 playbook 见 `.claude/skills/chaotang-frontend-design/references/dark-luxury-playbook.md`。

### 11.A Token 锚点（钉死值，禁记错）
- 舞台底＝深蓝近黑 `#04060E / #02030A`（**不是炭灰**），近黑承担 90%+ 面积。
- 帝金三阶分工：`#F0C66A` 亮金＝最高优先级/hero 数字/圣旨；`#D4A84B` 中金＝次级/hover；`#8A6A2A` 深金＝**仅描边分割，禁做正文**（对比度不足）。
- 正文一律米灰 `#C8CDD8`（`.body-copy`）。蓝 `#4A82F0` + 11 agent 色＝部门/角色语义；红黄绿＝风险/状态。**三套色域各司其职，禁互抢"奢侈强调"角色**。

### 11.B 可量化奢侈纪律（验收硬线）
1. **金光预算 ≤ 8%**：任意一屏帝金（含发光/描边/文字）覆盖面积 ≤ 8%。
2. **一屏 ≤ 1 个 hero**：bento 里只让"当前要裁决那一件"当 hero（跨 6 列×2 行）。
3. **动态金光 ≤ 1 处且必绑真实状态**：纯装饰动效砍成静态。金＝状态信号层，呼应红黄绿/sourceLabel 铁律。
4. **bento 甜区**：12 列，gap 16px，容器 padding 24px。
5. **巨数锚点**：核心判断用帝金巨数（clamp 48–72px），正文压到 11–13px，层级靠尺寸不靠色。
6. **衬线×无衬线分工**：圣旨/奏折标题/部门名用 `.display-serif`；数字/状态药丸/时间戳用 sans（"圣旨衬线、台账无衬线"）。

### 11.C 别外搬，用内置（§10「不新装框架」的正面清单）
研究推荐的暗金动效本仓 globals.css 已做成现成 class，优先复用：Border Beam→`.animate-border-trace`、文字 Shimmer→`.animate-shimmer-h`、实时脉冲→`.animate-live-pulse`（仅 LIVE 来源）、数字绽放→`.animate-stat-bloom`、bento 入场→`.animate-card-in-1..4`。
**唯一值得新增**：全局噪点层 grain（深蓝底叠 2–4% 不透明度噪点去塑料感，本仓未提供）。

### 11.D 性能红线（合成器友好）
动画只许动 `transform / opacity / offset-distance / clip-path`；禁 animate `box-shadow / background-position / width / height / top / left`（发光用静态模糊渐变层切 opacity，shimmer 用平移高光 div）；`filter: blur` 只静态设定；canvas 逐帧方案在多实例驾驶舱慎用。

### 11.E 上书房样板间验收（§5 验收清单的审美补充）
在 §5 原有验收（tsc / build / 1440 / 390 / 无溢出 / 3 秒看懂决策）之外，追加：
- [ ] 金光预算目测 ≤ 8%，未出现"满屏流光"
- [ ] 全屏只有 1 个 hero（当前裁决项），其余降级 metric/accent
- [ ] 帝金巨数做锚点，正文/技术回执字号明显更小
- [ ] 玻璃卡正文用米灰非暗金，对比度 ≥ 4.5:1
- [ ] 动态金光仅绑真实状态（运行/待裁决/告警），非装饰常驻
- [ ] 深蓝底叠了噪点层，无纯色塑料感
