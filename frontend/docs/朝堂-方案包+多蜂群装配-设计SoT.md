# 朝堂 OS · 方案包 + 多蜂群装配 · 设计 SoT

> 立于 2026-07-01。统领概念：**朝堂交付的是「可下载的解决方案包」，不是聊天。**
> 把四件事拧成一条线：工部分层 → 军机处多蜂群装配 → 收敛 → 盖印方案包 → 下载交付。
> 大神镜片：马斯克(端到端先通一条) · 张小龙(克制·先做一个愿意发给客户的交付物) · karpathy(单 owner) · deming(成色闭环)。

---

## 0. 一句话总纲

复杂请求的终点 = 一个**可下载、可盖印、可转发、敢被查**的方案包，
由**多个蜂群并行装配**而成，每个蜂群对应工部一个**产品层**（软/硬/系）。

---

## 1. 方案包（Solution Bundle）= 价值本体

一个复杂请求产出一个 zip / 文件夹，含：

| 文件 | 产出方 | 格式 | 现有地基 |
|---|---|---|---|
| 总览呈奏（盖官印） | 丞相收敛 | **PDF** | 御赐呈奏(sample-hubu-edict) + DeptSeal + `pdf` skill |
| 成本拆解表 | 户部 | **xlsx** | `bomCostToDocument` + `xlsx` skill |
| 技术方案（软/硬/系分册） | 工部 | **PDF/docx** | `packToDocument` + `docx` |
| 报价单 | 户部/礼部 | PDF | 公文模板 |
| 风险与合规 | 刑部 | PDF | `xingbu-lens` |
| 证据附录（citations） | 全体 | PDF | citations 字段 |
| 路演一页纸 | 丞相 | **pptx** | `pptx` skill |

**每个文件强制带**：成色标(sourceLabel) + citations + 生成时间 + 官印。判据：**敢被转发、敢被查**。
入口：一个 `[下载完整方案包]` 按钮，胜过一屏聊天。

---

## 2. 军机处 = 多蜂群装配线

复杂方案 = 一个问题拆 N 个子任务 → 每个派一个蜂群 → 并行 → 收敛成方案包。

```
军机处 · 多蜂群装配
立项 ──┬─▶ [硬件蜂群] PACK sizing/成本 ────┐
       ├─▶ [软件蜂群] BMS/算法可行性 ──────┤──▶ 收敛门(会签) ──▶ [方案包]
       ├─▶ [系统蜂群] 集成/测试/认证 ──────┤   冲突裁决+缺证汇总    盖印·下载
       └─▶ [情报蜂群] 竞品/行情(锦衣卫) ───┘
   每条蜂群行：● 运行中 / ✓ 完成 / ⚠ 缺证 / 🔴 阻塞 · 实时 · 可点开看在干嘛 · 可插话
```

- **单蜂群调用**：一子任务 → 一次 jiqun `/api/swarm/run`（唯一桥 `live-swarm-adapter`）。
- **多蜂群调用**：军机处持一张 **DAG**（依赖关系）→ 并行派发 → 各回 session_id → **收敛门**做会签（冲突裁决 + 缺证汇总）→ 全绿才组装方案包。
- **交互范式**：像 GitHub Actions/CI（每条蜂群一行实时状态）+ Claude Code（每步透明 + 可 steering）。
- **引擎徽**：每条标清 `LIVE_SWARM 真蜂群` vs `callLLM 咨询` vs `降级`（须先在 reality-state 保住 LIVE/LIVE_SWARM 区分，见 §5）。

> 军机处 = 统一决策 loop 的 **多蜂群 mode**；三省审议的「门下省驳议质门」收编成这里的「收敛门」。**一个 owner、一条装配线**（铁律6）。

## 3. 工部 软/硬/系 × 司 矩阵（产品层 × 职能）

**两个垂直轴，组成干净矩阵**（守铁律6：部=领域，司=角色；这里再加一轴 产品层=造什么）：

|  | 软件层(BMS/算法) | **硬件层(已真·PACK/电芯)** | 系统层(集成/认证) |
|---|---|---|---|
| 配置司 | 选型·架构 | 60V32Ah LFP | 拓扑/接口 |
| 成本司 | 授权/算力 | BOM 1086/台·电芯73.7% | 集成工时 |
| 质门司 | 测试覆盖 | 安规/循环 | 整机认证(EMC/路试) |
| 集成司 | 固件烧录 | 结构装配 | 整机联调 |

- **每一产品层 = 一个蜂群** → 直接喂 §2 军机处多蜂群装配（分层天然就是蜂群拆分依据）。
- **每个司横跨三层做同一职能**（成本司在三层都算成本 → 户部统一汇总，**不各算一遍**，铁律6）。
- **⚠️ 版面预算（铁律5）**：只有**硬件层是真的**（PACK 已接后端真算）。软件/系统层先**标位置、不建空舱**，有第一条真数据再长。**禁** 3×N 待接入空矩阵。

## 4. 其他高杠杆交互

1. **方案对比 A/B/C 并排** + 差异高亮（借 Claude Code diff）——老板要"选哪个"，不是一个答案。
2. **实时装配可见**：多蜂群跑时每步亮出来，不转圈（Claude Code 透明）。
3. **随时插话**：装配跑一半可改约束续跑（steering）。
4. **方案包版本化**：每次重跑存一版，可 diff "上版 vs 这版"（史馆归档天然支持）。
5. **下载即交付**：方案包是产物，聊天只是过程。

---

## 5. 前置依赖（做之前必须先有）

- **reality-state 保住引擎区分**：现 `normalizeRealityState` 把 `LIVE` 和 `LIVE_SWARM` 都归一成 `real`，引擎徽拿不到"咨询 vs 蜂群"。须先让 SSOT 保留该区分（决策引擎收编的一部分）。
- **决策引擎收编**：orchestrate(问丞相·横向) + orchestration/run(三省·纵深驳议) → 统一 loop 两 mode（consult/deliberate），军机处 = 多蜂群 mode。一个 owner、一条出口。

---

## 6. 迁移顺序（马斯克：先通一条端到端，别同时铺开）

> **风险**：方案包 + 多蜂群 + 工部三层 + 对比 + 版本化 = 半年工程量，同时铺开 → 全半拉子。

**第一条真链（唯一先做的）**：
`60V32Ah 储能 PACK → 硬件蜂群真算(已有) → 装配成可下载方案包(呈奏PDF + BOM xlsx + 报价单)`

一个**能下载、能转发、有真数字、敢被查**的方案包跑通 → 军机处装配线 / 工部分层 / 下载交付的价值**当场全部被验证**。
跑不通 → 框架搭再大都是 demo。**先做一个"我愿意发给客户"的交付物，再谈系统**（张小龙）。

之后再：② 加软件层蜂群 → ③ 系统层 → ④ 多方案对比 → ⑤ 版本化。每步要有"第一条真实数据从哪来"的答案（铁律5）。
