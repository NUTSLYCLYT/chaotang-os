# 一、/chaotang/study 上书房

## 1. 定位

**上书房是老板的私人 AI 办公室。**

它不是普通首页，也不是仪表盘，而是老板每天早上打开朝堂 OS 后的第一个工作空间。

它回答三个问题：

1. **今天发生了什么？**
2. **我现在最该处理什么？**
3. **哪些事情需要我一句话下旨？**

上书房的核心角色是：

| 角色 | 作用 |
| --- | --- |
| 老板 / 皇帝 | 查看、决策、下旨 |
| 丞相 | 汇总全局、提出建议、拆解任务 |
| 钦天监 | 教学、提醒、即时播报、引导新手 |
| 史官 | 记录老板看过什么、批示什么、决定什么 |

---

## 2. 页面内容

上书房应该包含 7 个核心区块：

### ① 今日朝报

老板一进来先看到当天简报。

内容包括：

| 类型 | 示例 |
| --- | --- |
| 今日经营简讯 | 销售线索、回款、项目进度、客户动态 |
| 今日风险 | 法务风险、员工风险、合同风险、现金流风险 |
| 今日机会 | 新客户、新政策、新项目、新融资机会 |
| 今日任务 | 正在执行、待复核、待裁决任务 |
| 今日建议 | 丞相给老板的 3 条优先建议 |

这个区域要像“早朝前的御前简报”。

---

### ② 重要事件

系统自动把企业里的关键事件提炼出来。

例如：

| 事件类型 | 内容 |
| --- | --- |
| 客户事件 | 某大客户有新需求，需要销售跟进 |
| 项目事件 | 某项目延期、超预算、缺资料 |
| 财务事件 | 本周有大额付款、应收款逾期 |
| 人事事件 | 某岗位空缺、某员工异常 |
| 外部情报 | 政策变化、竞品动作、行业新闻 |

老板不需要自己翻系统，系统主动上报。

---

### ③ 待裁决事项

这是上书房最重要的区域。

凡是 AI 做完分析，但需要老板拍板的事情，都进入这里。

例如：

| 待裁决事项 | 老板动作 |
| --- | --- |
| 是否给客户 A 报价 120 万？ | 批准 / 修改 / 驳回 |
| 是否启动厦门 AI 样板间方案？ | 批准 / 交军机处会审 |
| 是否录用某候选人？ | 批准 / 让吏部复核 |
| 是否投放某营销活动？ | 批准 / 让礼部重写方案 |

这就是“老板一键裁决”的核心体验。

---

### ④ 钦天监教学

钦天监不是普通客服，而是“老板的新手引导 + 即时军情播报员”。

功能包括：

| 功能 | 说明 |
| --- | --- |
| 新手教学 | 教老板怎么下旨、怎么看奏折、怎么召集大臣 |
| 即时提醒 | “陛下，户部刚提交一份预算奏折” |
| 操作解释 | 告诉老板每个按钮做什么 |
| 任务播报 | 实时汇报蜂群执行进度 |
| 建议下一步 | “建议您先处理这 3 件事” |

钦天监解决的是：**小白老板不会用复杂系统的问题。**

---

### ⑤ 快捷下旨

老板可以直接输入一句话：

> “帮我分析一下这个项目值不值得投。”  
> “让财务、人事、法务一起评估这个合作方案。”  
> “给我生成一份给佑总看的汇报材料。”  
> “查一下最近 AI Agent 行业有什么新机会。”

系统会自动判断：

| 判断项 | 结果 |
| --- | --- |
| 这是简单问答？ | 丞相直接回答 |
| 这是复杂任务？ | 进入军机处拆解 |
| 需要哪些大臣？ | 自动召集户部、刑部、礼部等 |
| 是否需要蜂群？ | 自动派出信息蜂群、文档蜂群、执行蜂群 |
| 是否要生成奏折？ | 任务完成后形成奏折 |

---

### ⑥ 最近奏折

展示最近 AI 给老板提交的成果。

例如：

| 奏折类型 | 内容 |
| --- | --- |
| 项目分析奏折 | 某项目可行性分析 |
| 客户方案奏折 | 给客户的销售方案 |
| 财务测算奏折 | 投资回报、现金流、成本预算 |
| 风险审查奏折 | 法务、人事、合规风险 |
| 战略建议奏折 | 企业下一步打法 |

老板可以点进去阅读、批示、转发、归档。

---

### ⑦ 最近任务

展示正在跑的任务。

状态包括：

| 状态 | 含义 |
| --- | --- |
| 待拆解 | 丞相还在理解任务 |
| 军机会审中 | 多位大臣正在讨论 |
| 蜂群执行中 | Agent 正在搜集、生成、分析 |
| 待复核 | 大臣正在审查结果 |
| 待裁决 | 等老板拍板 |
| 已归档 | 已进入史馆 |

---

## 3. 上书房实现的核心功能

上书房负责：

1. **老板每日入口**
2. **今日简报**
3. **重要事件提醒**
4. **待裁决事项**
5. **快速下旨**
6. **教学引导**
7. **最近奏折**
8. **最近任务**
9. **把老板从“找功能”变成“系统主动上报”**

一句话：

> **上书房是老板每天处理企业大事的第一屏。**

# 二、/chaotang/throne 朝廷大殿

## 1. 定位

**大殿是朝堂 OS 的企业 AI 组织全景指挥中心。**

它不是一个普通功能页，而是整个产品最具辨识度的“主场景”。

大殿回答四个问题：

1. **我的 AI 组织有哪些人？**
2. **每位大臣负责什么？**
3. **现在企业哪些部门在运转？**
4. **我要召集谁来处理事情？**

大殿的核心体验是：

> 老板坐在龙椅上，面前是丞相和十位 AI 大臣，每位大臣背后连接不同的蜂群能力。

---

## 2. 大殿中的核心角色

### ① 丞相

丞相是系统的中央大脑。

职责：

| 职责 | 说明 |
| --- | --- |
| 理解老板意图 | 把老板一句话变成可执行任务 |
| 拆解任务 | 拆成多个子任务 |
| 调度大臣 | 判断该找谁处理 |
| 组织会审 | 让多个 Agent 讨论 |
| 汇总结果 | 把复杂结果变成老板看得懂的奏折 |
| 提出建议 | 给出“建议批准 / 建议驳回 / 建议再查” |

丞相是超级助理，也是老板的数字分身。

---

### ② 钦天监

钦天监负责引导和播报。

职责：

| 职责 | 说明 |
| --- | --- |
| 新手引导 | 告诉用户怎么操作 |
| 状态播报 | 告诉老板现在谁在执行 |
| 风险提醒 | 提醒老板某个结果有问题 |
| 气氛营造 | 让产品有“上朝感” |
| 即时反馈 | 老板点什么，钦天监解释什么 |

---

### ③ 十位大臣

大臣不是装饰人物，而是 10 个企业 Agent。

建议设定如下：

| 大臣 | 企业职能 | 主要能力 |
| --- | --- | --- |
| 户部 | 财务 / 预算 / 回款 | 成本测算、报价、利润、现金流 |
| 吏部 | 人事 / 组织 / 招聘 | 岗位、绩效、招聘、员工风险 |
| 刑部 | 法务 / 合规 / 风控 | 合同审查、劳动风险、合规判断 |
| 工部 | 产品 / 技术 / 交付 | 研发、项目、工程、生产交付 |
| 礼部 | 品牌 / 市场 / 销售 | 文案、PPT、客户方案、品牌传播 |
| 兵部 | 执行 / 项目作战 | 任务推进、里程碑、作战计划 |
| 锦衣卫 | 情报 / 监控 / 舆情 | 市场情报、竞品、风险监控 |
| 钦天监 | 预测 / 战略 / 数据 | 趋势预测、行业机会、战略推演 |
| 太医 | 企业健康 / 组织诊断 | 经营体检、现金流健康、团队状态 |
| 史官 | 记录 / 归档 / 复盘 | 记录决策、沉淀知识、形成档案 |

---

## 3. 大殿页面内容

大殿应该包含 6 个核心区域：

### ① 朝堂全景

视觉上展示：

# 三、/chaotang/war-room 军机处

## 1. 定位

**军机处是复杂任务的多 Agent 会审与作战室。**

不是所有事情都要进军机处。

简单问题，丞相直接回答。  
复杂任务，进入军机处。

军机处回答五个问题：

1. **这件事到底要不要做？**
2. **需要哪些部门参与？**
3. **有哪些风险和机会？**
4. **应该怎么拆解执行？**
5. **最后给老板什么决策建议？**

---

## 2. 军机处适合处理什么任务？

例如：

| 任务类型 | 是否适合军机处 |
| --- | --- |
| “今天有什么事？” | 不适合，上书房处理 |
| “帮我写一段文案” | 不一定，丞相或礼部处理 |
| “分析这个项目值不值得投” | 适合 |
| “制定招商方案、报价、合同风险、销售话术” | 非常适合 |
| “评估一个员工离职风险” | 适合 |
| “制定公司 180 天作战计划” | 非常适合 |
| “做一个投资人汇报方案” | 非常适合 |

---

## 3. 军机处页面内容

军机处建议包含 8 个核心模块：

### ① 圣旨原文

显示老板原始输入。

例如：

> “请评估西港 OPC 智能体一站式服务项目的商业模式、股权激励、执行路径和风险。”

这个必须保留，因为后面所有任务都要追溯老板原意。

---

### ② 丞相理解

丞相先把老板的话翻译成结构化任务。

例如：

| 项目 | 内容 |
| --- | --- |
| 任务目标 | 判断项目是否值得推进 |
| 关键问题 | 商业模式、股权结构、执行路径、风险 |
| 需要参与的大臣 | 户部、刑部、礼部、工部、锦衣卫、钦天监 |
| 预期产出 | 一份项目可行性奏折 + 执行路线图 |

---

### ③ 大臣会审

多个大臣分别给出意见。

例如：

| 大臣 | 会审内容 |
| --- | --- |
| 户部 | 算账、利润、成本、估值 |
| 刑部 | 合同风险、股权风险、劳动风险 |
| 礼部 | 品牌表达、招商话术、客户接受度 |
| 工部 | 技术实现、交付周期、系统复杂度 |
| 锦衣卫 | 竞品、政策、市场信息 |
| 钦天监 | 未来趋势、战略机会 |
| 兵部 | 执行路径、项目排期 |
| 史官 | 调用历史资料和过往决策 |

---

### ④ 三省机制

这里是质量控制核心。

建议军机处内置“三省”：

| 三省 | 作用 |
| --- | --- |
| 中书省 | 起草方案 |
| 门下省 | 审查漏洞 |
| 尚书省 | 制定执行计划 |

对应到 AI 产品里就是：

| 产品逻辑 | AI 作用 |
| --- | --- |
| 生成 | 先给方案 |
| 批判 | 找风险、找错、找遗漏 |
| 执行 | 变成任务、流程、文档 |

这样可以避免 AI 只会“胡说一堆”，而是形成可执行方案。

# 四、/chaotang/manor 庄园

朝堂 OS 如果只有“上朝”和“下旨”，会偏管理工具。

# 五、/chaotang/archive 史馆

## 1. 定位

**史馆是企业记忆、决策归档、知识沉淀和复盘进化系统。**

它回答五个问题：

1. **以前做过什么？**
2. **老板当时怎么批示的？**
3. **AI 给过什么建议？**
4. **最后结果怎么样？**
5. **下次遇到类似问题，系统如何变得更聪明？**

史馆非常重要，因为没有史馆，朝堂 OS 就只是一个聊天工具。  
有了史馆，它才是一个会积累、会复盘、会进化的企业系统。

史馆记录所有关键过程。

| 类型 | 内容 |
| --- | --- |

| 任务 | 丞相拆解后的任务 |
| 会审 | 各位大臣的意见 |
| 蜂群记录 | Agent 执行过程 |
| 奏折 | 最终成果 |
| 批示 | 老板批准、修改、驳回 |
| 结果 | 任务最终效果 |
| 复盘 | 做得好不好，下次如何优化 |

## 3. 史馆页面内容

# 六、五个空间之间的完整交互流程

## 流程 1：老板每天打开系统

```
进入朝堂 OS

上书房

```
老板在上书房或大殿输入一句话  
↓  
丞相理解意图  
↓  
判断任务复杂度  
↓  
简单任务：丞相直接回答  
复杂任务：进入军机处  
↓  
军机处召集相关大臣  
↓  
大臣会审  
↓  
蜂群执行  
↓  
生成奏折  
↓  
返回上书房待裁决  
↓  
老板批示  
↓  
史馆归档
```

这个流程解决的是：

> 老板一句话，AI 自动分工、执行、交付成果。

---

## 流程 3：从大殿召集大臣

```
老板进入大殿  
↓  
看到 10 位大臣状态  
↓  
点击户部 / 刑部 / 礼部等大臣  
↓  
进入部门视图或发起任务  
↓  
丞相判断是否需要其他大臣参与  
↓  
需要多人参与 → 进入军机处  
↓  
不需要多人参与 → 单个大臣处理  
↓  
结果形成小奏折  
↓  
史馆归档
```

这个流程解决的是：

> 老板可以像调度团队一样调度 AI 部门。

---

## 流程 4：从庄园发起经营任务

```
老板进入庄园  
↓  
查看客户、项目、供应链、政策、资产

发现一个机会或风险

丞相读取庄园中的项目资料

生成经营建议 / 招商方案 / 风险评估 / 执行计划  
↓  
形成奏折  
↓  
老板裁决  
↓  
更新庄园项目状态  
↓  
史馆归档
```

这个流程解决的是：

> 企业资源不是死数据，而是可以直接变成 AI 行动。

---

## 流程 5：史馆反哺系统进化

↓

老板批示进入决策档案

反哺丞相和各大臣

```

> 朝堂 OS 越用越懂企业，越用越像老板的数字分身。

# 八、最推荐的 MVP 实现顺序

不要一上来全做复杂。最合理的顺序是：

## 第一阶段：先跑通老板核心闭环

必须先做：

1. **欢迎页 / intro**
2. **上书房**
3. **大殿**
4. **军机处简版**
5. **奏折页**
6. **史馆简版**

先跑通：

```
老板下旨 → 丞相拆解 → 大臣会审 → 生成奏折 → 老板裁决 → 史馆归档
```

---

## 第二阶段：再做庄园

庄园属于经营增强层。

等前面的“指挥闭环”跑通后，再把客户、项目、供应链、政策、资产接进来。

---

## 第三阶段：做部门页和蜂群执行页

每个大臣后面再做部门详情页：

| 部门页 | 对应能力 |
| --- | --- |
| 户部页 | 财务测算 |
| 刑部页 | 法务风控 |
| 礼部页 | 品牌营销 |
| 工部页 | 产品交付 |
| 锦衣卫页 | 情报监控 |
| 钦天监页 | 趋势预测 |
| 兵部页 | 执行推进 |
| 史官页 | 归档复盘 |

---

# 九、最终一句话总结

**上书房负责“今天老板该看什么”；  
大殿负责“老板有哪些 AI 大臣可以调度”；  
军机处负责“复杂事情怎么会审、拆解、执行”；  
庄园负责“企业资源、项目、客户、商机怎么经营”；  
史馆负责“所有决策、奏折、经验如何沉淀和进化”。**

真正的朝堂 OS，不是做几个漂亮页面，而是形成一个闭环：

> **老板一句话下旨，丞相理解拆解，群臣会审，蜂群执行，奏折回报，老板裁决，史官归档，系统进化。**
