# 朝堂开发 OS 收口评估 2026-06-07

## 北极星

主产品是「先知和导师」：帮助用户使用 AI agent 解决实际问题。

朝堂不是单独的装饰型页面集，而是这个产品的治理和执行框架。铭硕是第一个客户和最佳实践样板，不是主业本身。

## 今天完成的真实闭环

今天我们把朝堂第一次推进到「可以承接自身开发任务」的 v0 闭环：

1. 工部 `/gongbu/dev-console` 显示第一张真实开发任务卡：`建设朝堂开发工作台 MVP`。
2. 任务卡包含文件边界、验收命令、回滚口径、史馆归档入口。
3. 工部可以把任务写入 build ledger。
4. 军机处 `/command-center` 可以读取同一条 build ledger 并接单。
5. 军机处可以推动状态：`dispatched`、`reviewing`、`returned`、`archived`。
6. 状态迁移由后端 `action: transition` 受控，前端不再直接提交完整 entry 覆盖状态。
7. 迁移会生成 audit trail。
8. 史馆 `/shiguan` 可以读取同一条任务，显示状态和审计记录。
9. E2E 覆盖工部任务卡、写 ledger、军机接单、受控状态迁移、史馆消费。

## 我们现在能用朝堂做什么

可以立刻用朝堂辅助开发朝堂，但要限定在以下工作：

1. 记录真实开发任务：把每个小目标变成工部任务卡。
2. 明确验收边界：每张任务卡必须写清文件范围、命令、回滚口径。
3. 交军机处排队复核：用 build ledger 管理任务状态。
4. 记录关键决策：每次 `reviewing`、`returned`、`archived` 都留下 audit trail。
5. 让史馆沉淀结果：完成后归档成可复盘材料。
6. 用 E2E 固定主流程：防止页面改动把闭环打断。

这意味着：我们可以用朝堂开发朝堂的主线流程、验收流程和归档流程。

## 现在还不能完全交给朝堂的事

以下工作仍必须由 Codex/人工主导：

1. 复杂代码实现和重构。
2. 安全边界判断。
3. 数据库迁移和生产部署。
4. 多人权限和身份审计。
5. 真实 agent 调度和成本控制。
6. 最终上线判断。

原因很简单：朝堂现在能管「任务状态和证据」，还不能独立保证「代码正确、权限正确、生产安全」。

## 明天第一优先级

只做一件事：把 actor 从前端字符串改成服务端会话身份，并把迁移事件写入统一 audit ledger。

验收标准：

1. 前端不再传任意 actor 生效。
2. `/api/court/build-ledger` 从 session 或服务端上下文生成 actor。
3. 非授权用户不能迁移 build ledger 状态。
4. 每次迁移有独立 audit event。
5. E2E 覆盖未授权迁移失败、授权迁移成功。

## 后续完善路线

### P0：可信任务闭环

1. 服务端 session actor。
2. 统一 audit ledger。
3. 合法迁移测试。
4. 史馆展示完整状态时间线。
5. 上书房读取史馆结果，生成次日建议。

### P1：开发驾驶舱

1. 工部任务卡支持新增真实任务。
2. 军机处按状态筛选。
3. 任务详情页显示文件、命令、负责人、验收结果。
4. QA 结果自动写回 ledger。
5. 失败任务可退回工部补证。

### P2：蜂群执行

1. 将固定工具动作接入任务卡。
2. 每个蜂群运行结果结构化入史馆。
3. 加成本、耗时、成功率、失败类型统计。
4. 为法律蜂群、锦衣卫爬虫蜂群建立 golden cases。

### P3：自我改进

1. 史馆复盘生成知识条目。
2. 上书房每日建议引用历史结果。
3. 工部根据失败类型调整任务模板。
4. 军机处根据历史成功率推荐会审部门。

## 大神评估

张小龙视角：不要把朝堂做成复杂系统给用户学习。用户只需要知道「现在该做什么，做完交给谁」。朝堂内部可以复杂，第一屏必须简单。

Andrew Ng 视角：现在最宝贵的是 eval 和数据飞轮，不是更多 agent。每条任务都应该产生可复用样本：输入、决策、执行、结果、失败原因。

Deming 视角：不要奖励英雄救火。把每个失败归因到系统：任务定义不清、验收缺失、权限边界弱、证据不足。改系统，不怪人。

Charity Majors 视角：现在要能 debug 一条任务为什么失败。每次状态迁移必须有 actor、from、to、note、timestamp、source，否则上线后就是黑箱。

## 收口结论

可以开始用朝堂开发朝堂。

但使用方式必须克制：每次只放一个真实小任务进去，走完「工部开工 -> 军机复核 -> 工部验收 -> 史馆归档」再放下一个。

今天的成果是 v0 操作闭环。明天的目标不是扩页面，而是让这个闭环可信、可审计、可复盘、可反哺。
