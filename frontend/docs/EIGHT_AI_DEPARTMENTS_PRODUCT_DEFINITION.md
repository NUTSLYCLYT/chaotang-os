# 八大 AI 部门产品定义

日期：2026-06-21  
主控：丞相台 / 工部 / 礼部  
适用页面：上书房、军机处、礼部、刑部、户部、兵部、吏部、庄园。

## 1. 核心定义

每个部门不是展示页，而是一个 **AI 部门作战台**。目标不是介绍“这个部门是什么”，而是替代真实部门里的员工、主管和部门负责人，持续完成具体工作并交付可验收成果。

页面第一优先级：

1. 今天这个部门在做什么具体工作。
2. 哪些 agent / 工具 / 子流程正在替代员工。
3. 已经产出什么成果。
4. 成果质量如何，能不能交付。
5. 哪些事项需要部门负责人判断。
6. 哪些事项需要老板拍板。
7. 这个 AI 部门节省了多少时间、沟通和人力。

视觉目标仍然是东方电影感，但视觉只服务工作和成果展示。

## 1.1 首屏铁律：进入部门办公室

用户进入任何部门页面，都应该像走进一个正在运转的部门办公室，而不是进入介绍页或空展厅。

首屏必须立刻出现四类高价值信息：

1. **今日有价值内容**：本部门今天正在处理什么、已完成什么、最重要成果是什么。
2. **工作现场**：哪些 AI 员工 / agent / 工具正在干活，卡在哪一步，是否有失败或重跑。
3. **部门分析**：本部门负责人对当前工作给出的判断、风险、机会和建议。
4. **主管汇报**：一句老板能听懂的汇报：现在能不能交付、需不需要老板拍板、下一步谁办。

首屏禁止：

- 只放部门名称、人物头像、口号、诗意文案。
- 只放装饰性宫殿背景，没有具体工作内容。
- 只放统计数字，但看不到成果和下一步。
- 把技术 trace、session、调试信息放在主视觉权重最高处。

首屏推荐结构：

| 层级 | 内容 | 示例 |
|---|---|---|
| 第一眼 | 主管汇报 | “礼部今日已生成 3 份可发布材料，1 份禁外发，需刑部复核。” |
| 第二眼 | 成果墙 | 最新文案、预算表、合同红线、战役计划、会审结论 |
| 第三眼 | 工作现场 | agent 正在处理、等待补证、失败重跑、质量门状态 |
| 第四眼 | 下一步 | 交付、送审、归档、重跑、召集会审、请老板裁决 |

## 2. 统一页面骨架

所有部门页统一为“部门作战台”。

布局铁律：

- **面板在四周**：左侧放任务池/今日要务，右侧放主管分析/质量门，上下放行动 dock、状态、导航和部门员工工位。
- **中间是主卷轴，但默认收起**：中央不做普通卡片堆叠，而是一个可收放的部门卷轴/案卷主舞台；平时必须让办公室、人物、工位和背景空间露出来。
- **卷轴只在处理时展开**：只有用户打开文件/信息面板、点具体任务详情、切到圣旨/主管批示、或输入“下旨/命令”时，卷轴才展开进入案卷处理状态。
- **随时切圣旨**：中央卷轴必须能在“部门文件”和“圣旨/主管批示”之间切换，方便老板从工作内容切到裁决。
- **每个部门有自己的文件类型**：礼部是传播稿/审稿单，户部是账本/预算单，刑部是红线批注，兵部是作战令，吏部是任命/权限册，军机处是会审纪要，庄园是资产地契，上书房是奏折/圣旨。
- **文件可处理**：每份文件都能打开看具体内容，并提供查看、复制、送审、归档、重跑、转圣旨等动作。
- **角落是负责人对话**：上书房左右下角固定为“丞相”和“钦天监”两个 agent 对话框；其他部门把钦天监替换成本部门负责人 agent，例如礼部尚书、户部尚书、刑部尚书。
- **大殿不套部门页**：大殿是全局朝会展示，不是文件作战台；核心体验应是朝会席位、各 agent 出列、语音/字幕汇报、全局状态和老板裁决。

| 区域 | 必须展示 | 目的 |
|---|---|---|
| 今日战报 | 今日完成、进行中、阻塞、需老板裁决 | 3 秒看懂部门状态 |
| 任务池 | 待办 / 进行中 / 阻塞 / 已完成 | 替代员工排班和任务管理 |
| 工作流水线 | 输入、处理步骤、agent、工具、审核门 | 证明不是静态展示，而是真的在干活 |
| 成果墙 | 可查看、复制、导出、送审、归档、重跑的成果 | 页面最重要区域 |
| 部门负责人裁决 | 准、驳、补证、转交、升级老板 | 替代部门领导判断 |
| 员工/Agent 状态 | 谁在跑、谁失败、谁产出、谁需要重试 | 替代部门员工可见化 |
| 底部行动 Dock | 新建任务、交付、归档、召集会审、问部门负责人 | 用户下一步明确 |

## 3. 八部门定义

### 3.1 上书房

替代对象：老板秘书、总助、决策助理、信息整理员。

接收任务：
- 老板问题、临时想法、语音/文字指令、待裁事项。
- 外部材料、历史案例、部门回奏。

工作内容：
- 把老板问题整理成可执行任务。
- 召集丞相 / 军机处 / 六部会审。
- 生成圣旨、奏折、裁决选项和风险提示。
- 追踪任务是否闭环。

成果展示：
- 当前圣旨 / 奏折。
- 已裁决事项。
- 待老板确认事项。
- 已归档决策。

负责人裁决：
- 准奏、补证、复核、驳回、转军机处。

页面首屏必须回答：
- 老板现在最该裁哪一件？
- 风险是什么？
- 下一步谁办？

### 3.2 军机处

替代对象：项目管理办公室、跨部门会议主持、执行总控、风险协调人。

接收任务：
- 上书房下发的圣旨。
- 跨部门冲突事项。
- 高风险 / 高金额 / 高影响任务。

工作内容：
- 召集相关部门并行会审。
- 对齐冲突观点。
- 生成最终合议和执行路线。
- 跟踪行动项、负责人、截止时间。

成果展示：
- 会审结论。
- 冲突点清单。
- 责任分派。
- 执行进度。
- 阻塞原因。

负责人裁决：
- 合议通过、退回补证、升级老板、转具体部门执行。

页面首屏必须回答：
- 这件事卡在哪？
- 哪个部门负责？
- 是否可以推进？

### 3.3 礼部

替代对象：品牌部、市场部、公关、内容团队、设计审稿负责人。

接收任务：
- 品牌表达、营销素材、招商话术、对外公告、产品展示、短视频脚本。

工作内容：
- 生成品牌文案、PPT 大纲、海报 brief、视频脚本、传播计划。
- 审核表达风险、夸大承诺、客户误解。
- 维护视觉圣经和素材库。

成果展示：
- 文案稿。
- PPT / 方案结构。
- 海报 / hero 图 brief。
- 短视频脚本。
- 发布门禁结果：可发布、需改写、禁外发。

负责人裁决：
- 可发布、需改写、禁外发、转刑部复核。

页面首屏必须回答：
- 今天产出了哪些可对外材料？
- 哪些能发？
- 哪些不能发，为什么？

### 3.4 刑部

替代对象：法务、风控、合规负责人、合同审查员。

接收任务：
- 合同、报价、承诺、付款、股权、法律责任、客户协议。

工作内容：
- 识别红线条款。
- 输出风险清单。
- 给出合同修改建议。
- 触发人工确认门。
- 为高风险事项出具不可自动执行提示。

成果展示：
- 合同审查报告。
- 风险等级。
- 红线条款。
- 修改建议。
- 人工确认记录。

负责人裁决：
- 放行、修改后放行、禁止签署、升级老板。

页面首屏必须回答：
- 这事有没有法律/合规红线？
- 能不能签？
- 必须改哪几条？

### 3.5 户部

替代对象：财务、预算、经营分析、投资评估、报价负责人。

接收任务：
- 预算、ROI、报价、现金流、采购、投资、项目盈亏。

工作内容：
- 计算成本、收益、现金流和风险区间。
- 比较方案优先级。
- 给出预算建议和价格底线。
- 对投资/采购给出准、缓、拒建议。

成果展示：
- 预算表。
- ROI / 回收期。
- 现金流影响。
- 报价建议。
- 资金风险。

负责人裁决：
- 批准预算、压缩预算、缓投、拒绝、转刑部/军机处。

页面首屏必须回答：
- 值不值得花钱？
- 钱从哪里来？
- 最坏损失是多少？

### 3.6 兵部

替代对象：执行团队、运营战役负责人、项目推进、资源调度。

接收任务：
- 战役计划、交付排期、运营动作、竞争应对、资源调度。

工作内容：
- 拆任务。
- 排优先级。
- 分派资源。
- 追踪执行。
- 复盘战果。

成果展示：
- 战役地图。
- 行动清单。
- 今日进度。
- 资源占用。
- 战果复盘。

负责人裁决：
- 出兵、暂缓、换路线、增援、撤回。

页面首屏必须回答：
- 今天打哪一仗？
- 谁负责？
- 何时交付？

### 3.7 吏部

替代对象：HR、组织发展、权限管理员、绩效主管、岗位设计负责人。

接收任务：
- 岗位职责、人员评价、权限分配、组织结构、绩效复盘、招聘/替代规划。

工作内容：
- 定义岗位与职责。
- 评价人员/agent 产出质量。
- 给权限和责任边界。
- 提出组织优化建议。
- 识别哪个真实岗位可由 AI 替代。

成果展示：
- 岗位地图。
- 人员/agent 绩效。
- 权限表。
- 责任边界。
- 替代建议。

负责人裁决：
- 任命、调整、降权、转训、替代、升级老板。

页面首屏必须回答：
- 现在谁该负责？
- 谁表现不好？
- 哪个岗位能被 AI 替代？

### 3.8 庄园

替代对象：企业经营驾驶舱、资产管理员、客户经理、项目组合负责人。

接收任务：
- 客户、项目、现金流、合同、风险、资产、团队能力的长期经营视图。

工作内容：
- 把企业业务映射成可视化资产地图。
- 展示客户田、项目田、现金流、风险地块。
- 连接各部门成果和历史决策。
- 给出经营态势和下一步经营动作。

成果展示：
- 企业资产地图。
- 客户/项目/现金流地块。
- 风险热区。
- 部门贡献。
- 历史经营档案。

负责人裁决：
- 扩张、收缩、重点投入、风险清理、召集部门会审。

页面首屏必须回答：
- 企业现在最值钱的资产是什么？
- 哪块地在冒风险？
- 下一步经营动作是什么？

## 4. 实现优先级

### Phase 1：部门生产系统骨架

目标：不要先做八个漂亮页面，先做一个可复用的“AI 部门作战台”。

任务：
- 定义 `DepartmentWorkConsole` 页面骨架。
- 定义通用数据契约：任务、员工/agent、成果、负责人裁决、质量门。
- 做上书房和礼部两个样板。

验收：
- 两页都能展示任务池、工作流水线、成果墙、负责人裁决。
- 桌面/手机截图无溢出。
- `pnpm exec tsc --noEmit` 和 `pnpm build` 通过。

### Phase 2：硬功能部门

目标：先做最能证明替代真实部门的四页。

顺序：
1. 户部：预算/ROI/报价。
2. 刑部：合同/风险/确认门。
3. 军机处：会审/冲突/分派。
4. 兵部：战役/执行/进度。

验收：
- 每页至少 3 个真实成果样例。
- 每个成果有查看、复制、送审/归档、重跑入口。
- 每页有 loading / empty / error / fallback 状态。

### Phase 3：组织和经营页

顺序：
1. 吏部：岗位/权限/绩效/替代建议。
2. 庄园：资产地图/经营态势/部门贡献。

验收：
- 吏部能看出“谁负责、谁产出、谁应被替代”。
- 庄园能看出“企业资产、风险、现金流、下一步”。

## 5. UI 原则

视觉遵守 `docs/DESIGN_REFERENCES/COURTOS_VISUAL_BIBLE.md`，但页面权重改为：

1. 成果展示第一。
2. 任务状态第二。
3. 部门负责人判断第三。
4. 电影感和动画第四。

动画只做四类：
- 工作开始：点火 / 出列 / 任务入池。
- 工作进行：流水线流动 / agent 脉冲。
- 成果完成：落印 / 入库 / 上墙。
- 负责人裁决：朱批 / 放行 / 驳回 / 升级。

## 6. 每页验收模板

每个部门页完成时必须回答：

- [ ] 替代哪个真实部门岗位？
- [ ] 今天做了哪些具体任务？
- [ ] 哪些 agent / 工具在干活？
- [ ] 产出了哪些可交付成果？
- [ ] 成果质量门是什么状态？
- [ ] 部门负责人给了什么裁决？
- [ ] 用户下一步能点什么？
- [ ] 桌面/手机截图是否可展示？
- [ ] 是否明确 LIVE / FALLBACK / DEMO？
- [ ] `pnpm exec tsc --noEmit` 和 `pnpm build` 是否通过？

## 7. 不做清单

- 不做纯介绍页。
- 不做只有头像和诗意文案的部门页。
- 不用 mock 成果冒充真实产出。
- 不让视觉压过成果展示。
- 不一次铺八页再回头补功能。
- 不绕过后端产线边界：涉及真实报价、合同、交付、付款、客户承诺，必须转后端产线引擎或人工确认门。
