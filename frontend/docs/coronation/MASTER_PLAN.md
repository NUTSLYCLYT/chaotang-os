## Phase 0 · 贯穿全程的两条诚实纪律(不是阶段,是每行代码的约束)

### 0.1 表象-状态保真契约(见 coronation-spec §2)
每个大臣可见态必须由真实 agent 状态驱动;失败/慢也诚实演出;保真率<1=戏服,返工。

### 0.2 假数据诚实层(用户新增 · 全局可视标记) ★
**原则**:任何 mock/demo/fallback 数据,UI 上必须可一眼区分,禁止假数据冒充真实(real-loop 铁律的 UI 化,接 sourceMode 已有契约)。
- **数据带 provenance 标签**:`real | demo | fallback | unavailable`(把上书房已落地的 `sourceMode` 泛化成全局原语)。
- **设计系统统一视觉处理**(一处定义,全局消费):
  | provenance | 视觉 | 含义 |
  |---|---|---|
  | `real` | 正常帝金/米色 | 真实 agent/数据 |
  | `demo` | **专留一个"演示色"**(非帝金,如静音青/紫)+ 角标"演示" | 假数据内容(原型/demo) |
  | `fallback` | 角标"兜底" | 可达但回填的引导数据 |
  | `unavailable` | 红条告警(已落地) | 数据源不可达 |
  > 帝金=真实专属,假数据不许用帝金,从颜色层面杜绝"以假乱真"。
- **dev 总开关**:一个"provenance overlay"切换(复用现有 `design-overlay.tsx` 模式),一键高亮全页所有非 real 数据,自检用。
- **登基原型的诚实**:原型是 demo 数据→默认进入"演示态"(clearly labeled),封神不靠骗。标记要**克制**(小角标/色调,不是满屏 FAKE 水印)——既不杀魔法,也不撒谎。
- 验收:任意页面,非 real 数据若用了帝金/与 real 无法区分 = 违约。

## Phase 1 · 双腿并行:封神 + 验经济(1-2 周,都在"选哪朵云"之前)

### 腿 A — 客户面:登基 90s 原型(worktree 隔离)
- 按 coronation-spec:火力压"下旨→满朝回奏"那一秒;塞一位谏官出列;aspiration 靠涌现不喊口号;峰终给"属于他自己的具体结果";加"跳过/30s 速通"对照暗门。
- 假数据内容、**真状态机**(成功/慢/失败/谏言分支),挂 0.2 演示态标记。

### 腿 B — 经济面:看见第一张真实 token 账单(Karpathy/Bezos/Charity 的"第一件")
1. **一页新闻稿**:非技术店主下第一句旨后,怎么向朋友描述。写不出→别碰云选型。
2. **200 行最小端到端链路**:一句旨→首字回奏→深度会审→**真实 token 成本**,跑通看账单。
3. **埋事件 schema + `cost-per-satisfied-旨`** 实时数字(像盯 loss 一样盯它,不是盯请求量)。

### Phase 1 出口闸(用户同意的天才建议)★
**"成本三问"确定性 CI 门**——像后端 fail-secure 门一样焊死:
> 一个付费用户,最坏能让我 ① 花多少钱 ② 跑什么命令 ③ 看到谁的数据?
三个数字没有硬上限 → **CI 红牌,挡上线**。
