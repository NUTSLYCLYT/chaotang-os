# 朝堂 OS · 御史台 · 监察制衡体系 · 设计 SoT

> 立于 2026-07-01。御史 = 朝堂的「监察 + 审计 + 体检」体系，**不是单一 skill 或 agent**。
> 核心心法：御史靠**抽样 + 综合 + 定期上奏**发现系统性问题，不靠全查（全查既烧 token 又狼来了）。
> 大神镜片：芒格(反过来想/不可逆)·Schneier(造假/安全/审计审计者)·塔勒布(异常/尾部)·德明(数据互证)。

---

## 0. 总纲

御史**不该每个项目都出列**（那是巡逻兵）。御史是监察御史：抽查、找系统性漏洞、定期上奏、提精简与纠错升级。
最高价值在**周期性的御史体检奏折**，不在单次弹劾。

---

## 0.1 侦查与审判分离（2026-07-01 · 锦衣卫内查司）

**别让御史既当侦探又当法官（权力集中=不可信）。分两家：**
- **锦衣卫·内查司 = 采证**（找/查/盯）：复用锦衣卫现成两把刀，对内一开就是御史巡城兵——
  异动雷达（盯系统"变了什么"：脏数据/成本突变/证据消失/重复暴增）+ 可信度核查（抽查决策标可信度=幻觉抽查）。
  **产出异动报告 + 可信度评分，不定性。** 守铁律6：内查=内部情报=还是锦衣卫本职（对内对外都它）。
- **御史台 = 断罪**（判/劾/奏）：收锦衣卫证据 → 判是不是真问题 → 弹劾/上奏。**它也审锦衣卫的证据质量（锦衣卫也会幻觉）。**
- 对应下面三层：**①②（巡城+暗访）归锦衣卫内查司，③④（上奏+弹劾）归御史台。**

**分权铁律（Schneier：信息不能被采证方截留）**：锦衣卫异动报告须**全量上报、不预筛**；
御史从全量里独立挑该劾的。侦查方负责"全"、审判方负责"挑"，**绝不同一家做**（否则审判指挥侦查做减法 → 系统性偏）。
锦衣卫的可信度评分也须可复现、可被御史抽查（侦探的证据也经得起法官查）。

## 1. 形态：三层 + 弹劾门（每层用最便宜够用的形态 = token 策略）

| 层 | 形态 | 干什么 | 成本 | 现成零件 |
|---|---|---|---|---|
| ① 巡城·守卫 | **确定性脚本**（非智能体·零 LLM） | 抓规则能抓的：重复、成色造假、缺证、租户漏、成本离谱 | ~0 | `scripts/guard-*.mjs`（已有 guard:task-id 等），扩成御史巡城队 |
| ② 暗访·抽查 | **定时 Agent**（cron · LLM 抽样） | 抓规则抓不了的：**幻觉**、逻辑漏洞 | 低（只查样本） | `callLLM` + cron(CronCreate/create_trigger) + eval harness |
| ③ 上奏·综合 | **周期奏折**（综合报告·入史馆） | 把①②汇成御史体检奏折（五段） | 中（周/月一次） | 御赐呈奏格式 + 史馆归档 |
| ④ 弹劾·出列（罕见） | **人工确认门** | 仅①②命中**高危/不可逆**才跳到用户面前 | — | `src/features/governance/lib/gate.ts` 已有 |

> 一句话：御史 = 一群便宜确定性守卫（身体）+ 一个定时抽查 LLM（眼睛）+ 一份定期奏折（嘴）+ 一道罕见弹劾门（手）。
> 90% 活由零成本守卫干，LLM 只抽查 10%，用户只在真要命时被惊动 —— 又省 token 又全覆盖。

## 2. 幻觉抽查（②层核心）

```
定时(每日/每周) → 从 decisions/tasks 随机抽 N 条 → 御史 LLM 逐条对账(judge)：
  · 数字(¥1234)能追回 BOM 吗？      不能 = 幻觉
  · 结论(电芯是命脉)证据支持吗？    不支持 = 幻觉
  · LIVE 标真是 live 吗？           假 = 成色造假
  · "已兑现"史馆有回填吗？          没有 = 空填
命中率 > 阈值 → 升级：不修一条，查"这一类为什么会幻觉 + 怎么根治"
```
御史产出**不是"这条错了"，是"这一类为什么错 + 怎么根治"**（监察御史，不是校对员）。
御史 judge 戴守护大神镜片：芒格(反过来想)/Schneier(造假)/塔勒布(异常) = 抽查 prompt 的视角。

## 3. 御史体检奏折（③层 · 定期上奏 · 最高价值）

每周/月一份盖印奏折，五段：
1. **幻觉体检**：抽 N 条，X 条幻觉；**根因**（如"某 prompt 允许 LLM 估值"/"某数据源没校验"）+ 解法。
2. **工作流精简**：重复步骤/冗余引擎（三省审议 vs 问丞相会审）/死路径 → 建议合并删。
3. **token & 效率**：哪些操作最烧 token、命中率最低（如"全六部 fan-out 只 2 部有用，白烧 4 份"）、可缓存/可降级处。
4. **漏洞 & 纠错**：安全/数据漏洞（如模具费污染、×50 重复）。
5. **升级建议**：反复抓到的 → **固化成新守卫**（御史每抓一次，巡城队多一条规则，系统越用越严越省）。

## 4. 制衡闭环：谁监察御史（核心 · 没有不被监督的最终权威）

```
御史 ──查──▶ 项目数据/决策（微观·抽查个案）
  └─被查──▶ 丞相 + 钦天监 复核御史
确定性守卫 ──兜底──▶ 所有人（含御史/丞相/钦天监产出）
            用户 ──终裁──▶ 仅不可逆
```

御史会以两种方式出错，丞相 + 钦天监正好一人管一种，且观测尺度互补：

| 复核官 | 看什么尺度 | 纠御史的哪种错 |
|---|---|---|
| **御史** | **微观** · 抽查个案 | （被查方）易**一叶障目**：抽样只见树木 |
| **丞相** | **横向** · 跨部交叉 | **误判**：御史指控其实不成立 → 用全局产出交叉核验，不成立则**驳回 + 记御史误判率**。御史的上诉法庭 |
| **钦天监** | **宏观** · 全局/大趋势/大数据/整体优劣 | **显著性 + 盲区**：御史发现的是孤例还是趋势？补"森林视角"。御史的置信校准官 |

> 御史抓个案、丞相判真假、钦天监判大势 —— 一叶障目与放过系统病，两头都堵住。
> 朝堂三权制衡：御史查项目、丞相+钦天监查御史、守卫查所有人、用户裁不可逆。**没有最终权威，只有互证。**

---

## 5. 互证铁律（让御史可信，否则就是"穿龙袍的幻觉放大器"）

1. **御史每条指控必须可复现、可点回原证据**（像它要求别人那样要求自己；Schneier：能审计审计者，体系才可信）。
2. **御史误判率被记录**（丞相驳回次数 = 御史可信度，吏部可信度加权，御史也有 KPI、也会被降权）。
3. **御史报告自标成色**：每份御史奏折顶上标"本次抽样置信：中（5/200）"——连御史报告都标成色，才是彻底诚实。
4. **超时默认处置（防三权扯皮·德明流程有节拍）**：御史指控后丞相+钦天监 X 小时不复核 = 按风险默认（可逆默认放行、不可逆默认拦到用户）。制衡不卡死。

---

## 6. 现成零件 + 落地顺序

零件：`guard-*.mjs`(巡城已有) · `callLLM`(judge) · cron(周期) · `gate.ts`(弹劾门) · 守护大神内胆(镜片) · eval harness(抽查工具) · 御赐呈奏(奏折) · 史馆(归档)。

**落地顺序（先便宜见效，铁律5）**：
1. **第一名巡城兵 `guard:cost-sanity`**：把真抓到的"模具费污染"固化（电池成本命脉非电芯 → 弹劾），确定性·零 token·以后自动拦。
2. 暗访抽查 cron + 幻觉 judge（先只读、warn-only）。
3. 御史体检奏折（综合①②，盖印入史馆）。
4. 丞相/钦天监复核接线 + 误判率记录。
> 每步先回答"第一条真实数据从哪来"，无真信号不建空舱。
