# 朝堂 OS 前 5 页极致体验设计

版本: 2026-06-07
范围: 上书房、工部、户部、军机处、史馆
设计原则: 每页都是一个操作站，不是展示页。用户每到一页都要知道: 现在最重要的事是什么、为什么可信、该按哪个按钮、下一步去哪、结果在哪里留下证据。

## 总体黄金路径

上书房发现今日最重要决策 -> 工部拆成可建设任务 -> 户部给预算和下行情景 -> 军机处调度执行与复核 -> 史馆归档结果并反哺下一次上书房。

全局按钮语言统一:

- 主按钮: 只保留一个金色按钮，表示本页最应该做的下一步。
- 次按钮: 蓝色或灰色，表示查看证据、补充信息、返回上一站。
- 危险按钮: 红色，只用于驳回、暂停、退回补证。
- 归档按钮: 统一命名为 `入史馆` 或 `送史馆归档`。
- 跨页按钮: 文案必须带目的，例如 `交军机处立项`，不要只写 `去军机处`。

全局状态统一:

- `LIVE`: 真实链路已接通。
- `MIXED`: 部分真实、部分 fallback，必须显示原因。
- `DEMO`: 演示数据，不得伪装真实。
- `LOCKED`: 缺权限、缺证据、缺预算或缺签核。
- `READY`: 可以执行下一步。
- `ARCHIVED`: 已归档，可被未来 brief 召回。

## 1. 上书房

页面价值: 把用户带来的模糊问题，变成今日最该处理的一件事。

目标用户:

- 创始人/老板: 想快速知道今天先决策什么。
- 运营/销售/内容负责人: 想把线索、风险、素材变成可执行任务。
- 极客用户: 想看证据、模型输出、部门分派和链路状态。

首屏排布:

- 顶部: 朝堂导航 + 真/演状态 + 资源阁 + 帮助。
- 左栏: 丞相建议，只放 3 条，按紧急度排序。
- 中央: 今日御案，占最大视觉权重。只显示一个主判断、一句话原因、证据数量、风险等级、下一站。
- 右栏: 史馆可复用依据 + 今日任务脉冲。
- 底部: 正式下旨输入区，固定显示在首屏下缘，让用户知道可以立刻行动。

核心内容:

- 今日御案: 标题、为什么现在、证据、风险、建议下一站、上线状态。
- 丞相汇报: 默认给基础用户看的自然语言解释。
- 玩家视图: 展开证据、风险、下一步、部门建议。
- 极客视图: 展开 run id、source mode、quality gate、confidence、payload 摘要。

按钮体系:

- 主按钮: `按此下旨`，把今日御案写入正式下旨输入框。
- 次按钮: `先问丞相补判断`，进入问策模式。
- 判断按钮: `立即裁决`，只在 memorial 证据足够时可用。
- 证据按钮: `带入下旨`，从史馆召回内容写入输入框。
- 流转按钮: 生成圣旨后显示 `交军机处推进`。

钩子:

- "今天只处理一件最重要的事"，降低用户选择成本。
- "有证据才可下旨"，制造可信边界。
- "史馆召回 3 条历史依据"，让用户感觉系统记得过去。

惊爆点:

- 圣旨生成后默认不是长 AI 文，而是 `丞相汇报`。先讲人话，再允许用户展开专业层。
- 每条建议都带下一站，用户不需要自己想流程。

验收:

- 首屏 5 秒内能回答: 今天最该做什么。
- `按此下旨` 可见且可点击。
- 生成结果默认显示基础用户视图。
- 证据、风险、质门状态在基础视图可见。
- Playwright 覆盖基础/玩家/极客三层展开。

## 2. 工部

页面价值: 把想法变成可施工、可验收、可回滚、可归档的建设任务。

目标用户:

- 产品/工程负责人: 想知道现在该建什么、改哪些文件、怎么验收。
- CEO/运营负责人: 想确认任务是否真的能交付。
- 质量负责人: 想看验收命令、风险、回滚口径。

首屏排布:

- 顶部: `朝堂自举施工台` + 当前服务巡查摘要。
- 中央: 今日开发任务卡。包含业务目标、文件边界、验收命令、验收进度。
- 右侧: 刑部白名单动作。强调只运行固定动作，不开放任意 shell。
- 下方: 回滚口径、史馆归档目标、责任人矩阵。

核心内容:

- 任务卡: 目标、用户价值、文件边界、验收命令、完成标准。
- 施工账本: owner、预算、风险、预计耗时、阻塞项。
- 服务巡查: 3050、8081、数据库、关键 API。
- 执行回执: 每次动作的 run id、耗时、结果、错误摘要。

按钮体系:

- 主按钮: `交军机处立项`，写入 build ledger 并跳转军机处。
- 次按钮: `刷新朝局`，刷新工具和服务状态。
- 归档按钮: `入史馆`。
- 安全动作按钮: `运行白名单检查`、`重跑验收命令`、`查看端口兵符`，必须显示风险等级。

钩子:

- "每个想法必须带验收命令"，把 AI 建议变成工程确定性。
- "只准固定动作"，降低用户对 AI 乱执行的恐惧。

惊爆点:

- 任务卡自动生成对象护照: 输入、owner、证据、验收、归档地址一页齐。
- 验收通过后按钮从 `交军机处立项` 自动升级为 `送军机复核`。

验收:

- 任务卡首屏可见。
- 至少一个验收命令可复制或可见。
- `交军机处立项` 成功后出现 ledger id。
- 页面必须展示回滚口径。
- 工部完成项能在军机处和史馆被召回。

## 3. 户部

页面价值: 把"想做"变成"值不值得做、最多能花多少、亏损边界在哪里"。

目标用户:

- 创始人/CEO: 看项目优先级和资源分配。
- 财务/运营: 看预算、ROI、现金流和风险。
- 工部/军机处: 获取能否开工的预算边界。

首屏排布:

- 左上浮层: 预算总览，显示待批、预算、ROI、现金风险。
- 中央: 户部场景图保留，但热点必须承担真实导航职责。
- 右侧或底部抽屉: 项目预算审批队列。
- 首屏常驻: `预算闸门`，告诉用户哪些任务能进军机处，哪些必须补证。

核心内容:

- 预算闸门: 项目、申请额、预期回报、下行情景、回收期、审批状态。
- 风险三问: 最坏会亏多少、多久见结果、机会成本是什么。
- 工部联动: 建设任务自动带入预算申请。
- 史馆联动: 历史类似项目 ROI 和复盘结论。

按钮体系:

- 主按钮: `批准预算边界`，只在 cost/ROI/risk 齐全时可用。
- 次按钮: `要求补证`，返回上书房或工部补数据。
- 流转按钮: `送军机处排期`。
- 证据按钮: `查看历史 ROI`。

钩子:

- "没预算边界不准开战"，让户部成为约束引擎。
- "下行情景先行"，先看亏损再看收益，建立专业可信感。

惊爆点:

- 给每个任务一个 `资金护城河评分`: 预算确定性、回收速度、风险暴露、战略必要性。
- 用户点击批准后，军机处自动收到"可执行上限"而不是泛泛同意。

验收:

- 每个项目必须展示 cost、return、risk、payback。
- 缺字段时主按钮 disabled，并解释缺什么。
- 批准/退回都进入审计记录。
- 不得出现无来源的市场/金融断言。

## 4. 军机处

页面价值: 把已批准的任务变成执行路径、责任人、状态和复核动作。

目标用户:

- CEO/总指挥: 看现在谁卡住了、今天该推哪一步。
- 项目负责人: 看自己负责什么、下一步是什么。
- 安全/运营: 看执行是否可审计、是否越权。

首屏排布:

- 顶部: 当前最重要命令，显示目标、owner、截止时间、风险。
- 左栏: 接单台，展示来自上书房/工部/户部的待执行对象。
- 中央: 执行路径时间线，决定、派发、执行、复核、归档。
- 右栏: 阻塞和升级，红色只给真正阻塞。
- 底部: 最终奏报/复核记录。

核心内容:

- 任务总览: 待派发、运行中、待复核、已归档。
- 执行路径: 每一步 owner、输入、输出、证据。
- 阻塞台: 缺预算、缺证据、缺权限、缺人。
- 复核台: 通过、退回、归档。

按钮体系:

- 主按钮: `派发执行` 或 `开始复核`，随状态变化。
- 次按钮: `退回补证`、`查看预算边界`、`查看工部验收`。
- 归档按钮: `军机复核完成 · 送史馆`。
- 安全按钮: 高风险动作必须二次确认，并显示执行影响。

钩子:

- "所有任务都要么决定、要么派发、要么解除阻塞"，页面不做静态报告。
- "不用读日志也能知道卡在哪"，降低指挥成本。

惊爆点:

- 军机处中心不是表格，而是一张 `战令卡`: 一句话目标 + 当前阻塞 + 下一动作 + 责任人。
- 每次点击都生成 audit trail，史馆自动归档。

验收:

- 首屏必须有一个主命令。
- 每个任务至少有 owner、status、next action。
- 复核动作后状态变化可见。
- 阻塞项不能只显示红色，必须给解除按钮或下一站。

## 5. 史馆

页面价值: 把完成、失败、退回、复核的结果变成下一次决策会用到的组织记忆。

目标用户:

- CEO/管理层: 查过去为什么这么决定。
- 产品/工程: 复用历史验收和踩坑。
- 运营/财务/法务: 追溯责任、证据、风险和结果。

首屏排布:

- 顶部: 今日归档摘要，新增、已复用、待补证、失败复盘。
- 中央: 可搜索档案流，按任务/部门/风险/日期筛。
- 右侧: 可复用教训，显示下一次会影响哪些页面。
- 下方: 对象护照详情，展示输入、输出、证据、状态、审计。

核心内容:

- 决策记录: command、owner、source、evidence、outcome、createdAt。
- 复盘记录: 预期、实际、偏差、原因、预防动作。
- 召回机制: 哪些历史记录会回到上书房/工部/户部。
- 档案状态: completed、abandoned、superseded、archived。

按钮体系:

- 主按钮: `召回到上书房`，把历史经验带回今日决策。
- 次按钮: `生成复盘`、`查看证据`、`按部门筛选`。
- 修正按钮: `标记为过时`，防止旧经验误导新决策。
- 导出按钮: `导出对象护照`。

钩子:

- "系统不是只会回答，它会记住并变聪明。"
- "失败也入史馆"，降低团队隐藏问题的动机。

惊爆点:

- 每条档案显示 `未来影响`: 会影响哪些 brief、预算、验收或路由。
- 史馆不是终点，而是下一轮上书房的燃料。

验收:

- 每条档案有 source、owner、evidence、outcome。
- 可以按部门、风险、状态筛选。
- 召回内容能进入上书房输入框。
- 失败记录必须包含 prevention step。

## 五页成熟度目标

| 页面 | 当前定位 | 目标成熟度 | 关键缺口 |
| --- | --- | --- | --- |
| 上书房 | 决策入口 | L5 自我改进 | 强化一事一令和史馆召回反哺 |
| 工部 | 建设任务台 | L4 闭环 | 强化任务成本、owner、验收可视化 |
| 户部 | 预算沉浸页 | L3 证据支持 | 从场景图升级为预算闸门 |
| 军机处 | 执行调度 | L4 闭环 | 强化单一主命令和阻塞解除 |
| 史馆 | 档案/记忆 | L5 自我改进 | 显示历史记录如何影响下一次推荐 |

## 第一阶段实现顺序

1. 上书房: 固化首屏一事一令、基础/玩家/极客三层、证据风险状态。
2. 工部: 把任务卡改成对象护照式布局，主按钮明确流转到军机处。
3. 军机处: 首屏增加战令卡，所有按钮围绕派发/复核/退回/归档。
4. 史馆: 档案详情加入未来影响和召回到上书房。
5. 户部: 加预算闸门，不再只做漂亮场景浮层。

## 浏览器验收清单

- Desktop 1440x920: 五页首屏无重叠、主按钮清晰、状态可读。
- Mobile 390x844: 无横向溢出，主动作不被底栏遮挡。
- Release harness: 核心页面 0 console error、0 资源 404。
- E2E: 上书房生成、工部立项、军机复核、史馆召回至少各一条。
- 文案验收: 每个主按钮都能回答"按下后用户得到什么"。
