# 军机处 · 案子流水线设计稿（2026-06-29 · 先审后改·不动代码）

> 用户定义军机处作用：**立项 → 集中会审 → 封询(封驳) → 盖章**。本稿把军机处从"面板堆砌"重设计为"一个项目案子走过 4 道关的流水线"。
> **核心纪律：复用现有原语重新编排，不是重写**（铁律3 不留双份 / 铁律6 一个领域一个 owner）。

## 0. 一句话
军机处不是"展示会审结果的仪表盘",是**一个案子从立项走到盖章的流水线**。4 关就是脊：**立项 → 会审 → 封询 → 盖章**。

## 2. 4 关 · 每关展示什么 + 复用哪个现有原语
| 关 | 展示 | 复用现有(不重写) | 第一条真数据来源(铁律5) |
|---|---|---|---|
| **①立项** | 案号/案由/发起人/立项时间/圣旨原文/缺证 | `createDraftTask`+上书房下旨/工部建设案 | 上书房 dispatch 或工部建设案 |
| **②会审** | 六部灯号(🔴🟡🟢)+理由+缺证+风险,实时跳 | 现有内联**大臣会审**+`BattleStream`SSE+`runMinistryReviewWithRealAgents` | 真 agent 会审(户/刑/工)或规则兜底 |
| **③封询** | 每参询方一行:准/驳/补证;御史台审计 | `门下封驳闸 menxia-gate`(六司套件)+`runYushitaiAudit`御史台 | 御史台审计结果 |
| **④盖章** | 朱批/玉玺仪式·需亲裁·盖下成决议·留撤回窗 | `圣裁卡 edict-decision-snap`朱批 + `stamp-pipeline`原语(户/兵/吏部已用) | 用户圣裁动作 |

**关键:零新造**。会审/奏折/御史/朱批/封驳/盖章原语**全已存在**,军机处只是把它们**按 4 关重新串成一条线 + 加一条 stepper 主脊**。

## 3. 三个天才设计要点（落到机制）
### A. 盖章 = 不可逆封印（贝索斯·单向门 + 铁律13.2.5 人工门）
- 盖章前**强制三显**:会审灯号 + 封驳意见 + 缺证。三者不绿不让盖。
- 高危事项(股权/合同/报价/不可逆承诺)**必须亲裁**,禁一键静默。
- 盖下 = "建议→决议"那一下,留**撤回窗口**(N 秒可撤),过窗即封。视觉最重(朱批放大/玉玺)。

### B. 封询 = 结构化封驳,非自由聊天（张小龙·门下封驳）
- 每参询方一行:**准(绿)/驳(红)/补证(黄)**。
- **任一封驳 → 案子退回 ②会审,禁止进 ④盖章**(异议是硬门不是装饰)。
- 御史台审计(`runYushitaiAudit`)审"会审本身",防自夸。

### C. 诚实标源贯穿每关（Deming + 我刚修的 mergeHonestSource）
- 每关标 LIVE/MIXED/FALLBACK:会审真 agent 还是规则、盖章人还是系统。
- LiteLLM 挂 → 整条流水线诚实显降级,**不让封印仪式掩盖"大脑断电"**。

## 4. 迁移路径（先清后建·铁律3/16）
1. **清僵尸**:军机处 7 个 0 引用面板(`ExecutionPathPanel/CouncilPanel/FinalMemorialPanel/SwarmDispatchPanel/CommandCenterStatusStrip/CommandCenterEmblem/CommandProtocolOverlay`)knip 取证→attic,给主脊腾地。
2. **建 stepper 主脊**:案子头 + 4 关 stepper(状态机,复用 `task.ts` TaskStatus)。
3. **接关**:每关挂现有原语(表 §2),不重写。
4. **盖章门**:复用圣裁卡朱批 + 人工确认门 + mergeHonestSource 标源。
5. **双门双审**(铁律4):tsc + next build + 回归断言(每关状态流转)+ 独立会审。

## 5. 不做什么（防再膨胀·铁律5）
- 不为每关各开一个新版面——**4 关在同一军机处主视图内切换**。
- 不重造会审/盖章/封驳逻辑——全复用。
- 建设台账已归工部,不回流军机处。
