# 吏部:招聘把关,一句话裁断

> 这一程,吏部只做一件事。HR 其余职能 + 整个行政,见 `LIBU_BACKLOG.md`(延后,本程不建卡)。
> 2026-06-22 · 经 4 大神会审(workflow w3wilt5v0 + wr3l23h7h)+ Jobs/张小龙取舍砍到一页。

## 定位(一句话)
**吏部 = 识人理事的守门人。** 老板每个动人/动钱办事的决定进入执行前先过吏部这道门——它不替老板做决定,它把"证据齐不齐、该拉谁、有没有坑"一句话钉死,并禁止不可逆动作被一键静默执行。
**世界级 = 老板抛一句"招个销售负责人",3 秒回一句带把握度的硬裁断;不是 HR 后台。**

## 这一程的脊:招聘把关
唯一现在就能接真链的功能(后端 `flow_libu.yaml` 蜂群已就绪:岗位画像→简历筛选→面试设计STAR→QA门)。高频(天天招人)× 高价值(招错核心岗=3个月灾难)× 唯一真链。**别的 HR 职能/全部行政:无第一条真数据 → 本程不建卡,只在 BACKLOG 占位。**

## 那张卡(吏部核心产出,溶进现有 personnel 工位,不新增版面)
```
┌───────────────────────────────────────┐
│            ◉ 82%                        │ ← 一个徽:数字=把握度,颜色=来源
│                                         │   (帝金=LIVE_SWARM 真 · 灰=DEMO 假)
│   准奏招聘,但先补齐90天目标与试用标准   │ ← verdict 单句,最大字号,主角
│                                         │
└───────────────────────────────────────┘
  ↓ 老板读完这句、自然下看,才出现 ↓
  ⚠ 高风险·需人工确认   [采纳][补证][驳回]   ← 动作下沉到第二眼
  ▼ 证据 / 缺证 / 联动(户部·刑部) / 后令   ← 默认折叠,第三层
```
**纪律(Jobs/张小龙)**:
- 首屏只留 **verdict 一句 + 一个把握度徽**。动作按钮、高风险锁、证据全部下沉/折叠——别把"判断"和"处置"挤在同一眼。
- 把握度与来源**合成一个徽**:数字给把握度、颜色编码来源。老板学读一个信号,不是两个标签。
- verdict 字号 ≥ 证据 3 倍;`confidence` 高但来源 DEMO 时,那个灰色数字让老板一眼看穿"假的"。
- 复用 `contracts/{judgement,chancellor-decision}.ts` 的 verdict 范式,**不新建平行类型**(铁律2)。

## 第一条真数据 & 验证判据
- **第一条真数据**:老板在 personnel 工位输入招聘需求 → HTTP 调 `li_bu` 蜂群 → 真返回画像/筛选/面试 → 渲染成上面这张卡,`sourceLabel=LIVE_SWARM`(蜂群挂时=FALLBACK 明示)。
- **唯一验证判据(过了才扩枝)**:**老板会不会去引用那个"把握度"。** 看他是否因 confidence 低而追问/补证;并加一条——**看完 verdict 那句,需不需要每次点开证据才敢动?每次都点 = 那句不够硬,脊没立住。**

## seed 组织盘点 = 临时试纸(钉死退场条件)
组织盘点现为 `SEED_ORG_HEALTH`(seed),作脊的上下文供给,**必须标 DEMO + confidence≤0.7**。但它是**临时试纸**,不是常驻:**招聘真链一旦跑通,它要么升 turso 变真、要么从首屏撤下——禁永久 DEMO 卡常驻首屏**(否则三个月后它就是那张"老板看久了不信吏部"的假卡)。
