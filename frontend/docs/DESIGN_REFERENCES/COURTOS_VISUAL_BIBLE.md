# 朝堂视觉圣经 · 礼部审美门禁

日期：2026-06-21  
主控：礼部  
适用：上书房、大殿、礼部、军机处、六部电影屏、卷轴/圣旨/人物/操作台等核心 UI。

## 1. 北极星

朝堂 OS 不是普通后台。它要像“电影级 AI 决策操作系统”：

- 用户感觉进入真实朝堂，而不是打开一个模板 dashboard。
- 背景有空间纵深，人物像活的大臣，圣旨/卷轴/印章像可操作器物。
- 所有视觉服务一个目的：让老板 3 秒内看清“现在是什么、能不能做、下一步谁办”。
- DEMO / FALLBACK / synthetic / blocked 必须明示，不能被视觉包装成成功。

## 2. 礼部工作流

每次 UI/美工任务必须按这个顺序：

1. **采样**：从本库和外部案例挑 3-5 个参考，只学手法，不抄品牌。
2. **定调**：一句话写明本轮要学什么，例如“学 Apple 的克制层级、Awwwards 的首屏记忆点、Mobbin 的真实产品密度”。
3. **实现**：优先复用本仓 token、组件、utility class，不改 `globals.css` 和 `design-tokens`。
4. **截图**：Playwright 截桌面 1440 和手机 390；关键状态必须都截，比如展开/收卷。
5. **会审**：用 `design-review` 挑层级、拥挤、遮挡、AI 味、移动端问题。
6. **入史**：满意截图放进 `05-our-best-shots/`，下次优先按自己的好版本进化。

## 3. 常驻工具

| 工具 | 礼部用法 | 红线 |
|---|---|---|
| `frontend-design` | 页面结构、视觉层级、响应式美工、关键器物 UI | 不牺牲业务可读性 |
| `design-review` | 截图后挑毛病并修：层级、间距、遮挡、模板感 | 不只说好看，要给改法 |
| Playwright | 真实浏览器截图、点击、横向溢出、移动端验证 | 构建通过不等于视觉通过 |
| `imagegen` | 缺 hero 图、背景、视觉气氛图时补素材 | 不替代已有真实资产 |
| Figma | 首屏构图、设计系统、评审标注 | 不替代代码和浏览器验收 |
| Mobbin | 学真实产品 UI 密度、导航、移动端模式 | 不照搬具体产品 |
| Awwwards / FWA / Godly | 学首屏记忆点、动效、视觉冲击 | 不让炫技压过决策效率 |
| Apple Design Awards | 学克制、完成度、系统一致性 | 不把消费级动效硬套企业决策 |

## 5. 朝堂十戒

1. **一屏只有一个主角**：圣旨、大殿、人物、数据只能有一个当 hero。
2. **金光预算 ≤ 8%**：帝金是权力和状态，不是背景色。
3. **深色不是一坨黑**：必须有纵深、暗角、局部暖光、低透明纹理。
4. **卷轴像器物，不像卡片**：要有轴、纸、封签、绳结/印章、阴影和可点反馈。
5. **人物像大臣，不像头像**：人物服务身份和职责，不做普通 profile card。
6. **动效解释状态**：展卷、落印、聚光、传旨都要对应真实状态切换。
7. **技术信息降噪**：trace、session、接口状态默认收起或压低。
8. **移动端先保命**：不挡按钮、不横向溢出、不把长标题挤爆。
9. **不为了高级牺牲判断**：用户必须看清风险、证据、下一步。
10. **满意截图入史**：我们自己的最佳版本比外站更重要。

## 6. 每次开工提示词

```text
礼部会审：先读 docs/DESIGN_REFERENCES/COURTOS_VISUAL_BIBLE.md。
本次对标：A 的空间感、B 的动效、C 的产品密度。
目标感受：真实来到朝堂，器物可操作，大臣可交流，背景有景深。
必须验收：桌面/手机截图，关键状态截图，无横向溢出，无按钮遮挡。
不满意继续改，直到能拿出去展示。
```

## 7. 上书房当前审美样板

当前样板方向：

- 中央：圣旨/卷轴是主角，可展卷、可收卷。
- 左侧：丞相栏是首札和短签，不做普通任务列表。
- 右侧：钦天监是观星三问和指导，不做帮助文档。
- 底部：操作台保留 `按此下旨 / 展卷 / 问丞相 / 资料`，不让用户迷路。

下一步最值得做：

1. 收卷/展卷加入真实手卷微动画。
2. 左侧短签点击时投射到中央，触发展卷和落印。
3. 把满意截图存入 `05-our-best-shots/`，作为礼部下次基线。
