# Codex 命令库 · 顶级协作模板

> 目标：把每一次成功的 Codex 协作沉淀成可复用模板，让朝堂史馆能召回、复盘、再派遣。

上位系统设计见：`docs/SELF_EVOLVING_COURT_SYSTEM.md`。

## 1. 黄金命令格式

```text
目标：
  [一句话定义真实业务/工程结果，不写“优化一下”]

上下文：
  - 相关页面/接口/文档：
  - 当前已知事实：
  - 不确定处：

禁区：
  - 不改：
  - 不碰端口：
  - 不新增依赖：
  - 不伪装 mock 为真：

反目标：
  - 本次优化不允许牺牲：
  - 如果出现以下代价，必须停止：

模型策略：
  - mode: auto | cheap | fast | high_reasoning | vision_review | manual
  - riskLevel: low | medium | high | one_way
  - requiredCaps:
  - allowFallback:
  - humanGate:

验收：
  - 类型/构建：
  - E2E/截图：
  - 业务结果：
  - 证据路径：

优先级：
  1. 先修阻塞
  2. 再做最短真闭环
  3. 最后补文档和复盘

输出：
  - 改了哪些文件
  - 验证命令和结果
  - 剩余风险
  - 下一步最小动作
```

## 2. 朝堂项目标准命令

```text
目标：
  跑通“用户真实问题 -> 军机处会审 -> 真奏折 -> 史馆归档”的最短闭环。

上下文：
  - 产品主语是“先知和导师”，朝堂只是治理框架。
  - 优先服务一个真实老板的一个真实经营决策。
  - 相关文档：docs/PRODUCT_POSITIONING_ORACLE_MENTOR.md、docs/NORTHSTAR_REAL_LOOP_V1_PRD.md。

禁区：
  - 不铺新页面。
  - 不碰 3001，不用 dev 占 3050。
  - 不改冻结色板、keyframe、启动时序。
  - 不把 fallback/mock 文案包装成真模型结果。

验收：
  - pnpm exec tsc --noEmit 通过。
  - pnpm build 通过。
  - Playwright 截图核心路由。
  - 输出能标明真模型/真数据/fallback/mock 来源。
  - 老板能采纳、打回或追问。

输出：
  - 文件清单。
  - 截图路径。
  - 验证结果。
  - 史馆可归档的复盘条目。
```

## 3. 史馆归档字段

每次 Codex 协作结束后，归档为一条“协作案”：

```yaml
id: codex-YYYYMMDD-short-name
title: 一句话案名
intent: 原始目标
context:
  files:
    - path
  docs:
    - path
constraints:
  - 禁区 1
  - 禁区 2
antiGoals:
  - 不牺牲真实性
  - 不牺牲安全边界
  - 不牺牲用户可裁决性
modelPolicy:
  mode: auto
  riskLevel: medium
  requiredCaps:
    - reasoning
  allowFallback: false
  humanGate:
    required: false
    reason:
acceptance:
  - 验收 1
  - 验收 2
actions:
  - 改动 1
  - 改动 2
evidence:
  commands:
    - command: pnpm build
      result: passed
  screenshots:
    - /tmp/example.png
outcome:
  status: success | mixed | failed
  user_value: 用户是否说“这帮我了”
lessons:
  - 下次类似任务应该复用什么
  - 下次应该避免什么
contraCheck:
  - antiGoal: 不牺牲真实性
    status: held | violated | unknown
    evidence: 证据路径或检查结果
routingDecision:
  selectedModel: 模型 id 或 provider
  requiredCaps:
    - reasoning
  estimatedCostUsd: 0.00
  fallbackUsed: false
  reason: 为什么这个任务适合此模型档位
playbook:
  可直接复制的下一次命令模板
```

## 4. 模型使用顶级技巧

1. 不问“用哪个最强模型”，先问“这步错了会造成什么损失”。
2. harness 工程、状态机、鉴权、成本、安全、生产发布用高推理模型做方案和复核。
3. 摘要、标签、fixture、低风险文档补料用 cheap / fast。
4. UI/UX 必须有截图或 vision，不能让纯文本模型自夸。
5. 复杂任务拆成：高推理定边界，便宜模型补材料，Codex 改代码，高推理/人工复核。
6. 每次路由都留下理由：requiredCaps、riskLevel、costEstimate、fallbackUsed。
7. 高风险任务 `allowFallback: false`，fallback 只能说“不可用”，不能给假结论。
8. 用户可以手动覆盖模型，但覆盖理由也要进史馆。

## 5. Top 10 训练法

1. 每个任务都写“验收”，不写愿望。
2. 每个任务都写“禁区”，减少误伤。
3. 每次成功都沉淀模板。
4. 每次失败都抽取反面清单。
5. 每周让史馆召回 3 条相似任务，改写下一条命令。
6. 大任务只追最短真闭环。
7. 对单向门决策先会审，再执行。
8. 对 UI 任务必截图。
9. 对后端/成本/鉴权任务必看日志、限流、失败路径。
10. 把“我怎么说”迭代成“系统怎么学”。

## 6. 脑雾恢复协议

当用户说“我脑雾了 / 忘了刚才在干嘛 / 帮我对接上下文 / 先确认主线”时，不继续执行大改动，先恢复上下文。

```text
第 1 步：确认主线
  - 当前目标是什么？
  - 真实用户是谁？
  - 成功指标是什么？
  - 最小可交付是什么？

第 2 步：找证据
  - git status / branch / log
  - 正在跑的端口和服务
  - 最近改动文件
  - 最近用户命令
  - 浏览器当前页面和截图

第 3 步：分三类
  - 已完成：有证据、可复现
  - 未收口：有改动但未验证
  - 未确认：需要用户/客户/安全闸确认

第 4 步：只给下一步
  - 不一次塞 30 条建议。
  - 给 1 个最短动作、1 个备选、1 个风险。
```

恢复输出格式：

```text
我找回的主线：
  ...

现在最可信的事实：
  ...

不要继续做的事：
  ...

下一步最小动作：
  ...
```

## 7. 自动润色器：粗命令 -> 顶级命令

用户可以直接说粗命令，系统负责润色成可执行命令，但必须保留用户原意，不擅自扩大范围。

触发原则：不是每次都润色。用户命令已经具体可执行时，直接执行；只有输入太短、太空、脑雾、全做、上线、高风险、缺少验收时，才轻量引导。

默认输出保持简单：

```text
我基于这些上下文判断：
  - ...

更好的说法：
  ...

重点：
  - 要做什么：...
  - 不做什么：...
  - 怎么算完成：...
  - 下一步先做什么：...
```

输入示例：

```text
帮我把这个上线做好，我脑子乱了，你来搞。
```

默认润色输出：

```text
我基于这些上下文判断：
  - 当前是上线收口场景。
  - 用户明确说脑子乱、希望系统接管，但又不能偏离主线。
  - 已知主线是先知和导师最小真闭环。

更好的说法：
  请先确认先知和导师最小真闭环的上线主线，列出已完成、未收口、未确认事项。只处理 P0 上线必要问题，不新增页面、插件或 skill，不把 mock/fallback 伪装成真能力。每个结论都要有证据：文件、测试、截图或日志。最后给出下一步最小动作。

重点：
  - 要做什么：把最小真闭环收口到可演示状态
  - 不做什么：不新增非 P0 功能，不扩范围，不伪装假能力
  - 怎么算完成：build、浏览器 QA、真实奏折、归档证据齐全
  - 下一步先做什么：先查当前状态和未收口清单
```

深度/上线模式才展开为完整黄金命令：

```text
目标：
  把先知和导师最小真闭环上线到可演示状态。

用户：
  第一个真实老板/客户，不是内部看热闹的人。

成功指标：
  用户能提出真实问题，收到可执行奏折，并明确反馈“这帮我了”。

上下文：
  - 前端：/home/ubuntu/workspace/chaotang-web-lyt
  - 后端：/home/ubuntu/workspace/jiqun_ai
  - 参考：docs/RELEASE_SCOPE_2026-06-06.md

禁区：
  - 不新增页面、插件、skill。
  - 不继续美化非闭环页面。
  - 不伪装 mock/fallback 为真。
  - 不回滚未授权改动。

验收：
  - build pass。
  - production 入口可访问。
  - 浏览器 QA 有截图。
  - 后端主线测试可解释。
  - 生成一份真实奏折并归档。

输出：
  - 改动清单、验证结果、截图路径、剩余风险、下一步。
```

自动润色的硬规则：

1. 具体命令不打扰：能执行就执行，最多补一句风险提醒。
2. 模糊词必须落成可验收结果：优化、完善、搞好、最好，都要翻译成指标和证据。
3. 任何“全做”都必须先冻结范围，再拆 P0/P1/P2。
4. 任何上线命令都必须自动补：安全、QA、回滚、证据。
5. 任何 UI 命令都必须自动补：浏览器截图。
6. 任何后端/agent 命令都必须自动补：测试、日志、失败路径。
7. 任何金融/客户/经营建议都必须自动补：来源、时间、置信度、非个性化建议边界。

## 8. 顶尖用户命令方式

顶尖用户不是话更长，而是更清楚地给边界。最短可用版本：

```text
帮我升级这句话：
[你的原话]
```

系统输出：

```text
更好的说法：
  ...

重点：
  - 要做什么
  - 不做什么
  - 怎么算完成
  - 下一步先做什么
```

深度版本才需要补齐：

```text
目标 = 我要什么真实结果
用户 = 谁用、为什么用
成功 = 什么证据证明有用
禁区 = 什么绝对不要碰
上下文 = 关键文件、页面、事实
验收 = 命令、截图、日志、用户反馈
节奏 = 先做什么、做到哪停
```

一句话版本：

```text
请先确认主线和最小真闭环，只做 P0 上线收口；自动润色我的命令，补齐目标、上下文、禁区、验收和证据；任何偏离上线的建议先拦住。
```

## 9. 朝堂内置方式

朝堂项目中，史馆负责保存命令，丞相负责润色命令，军机处负责执行，御史负责验收。

```text
用户粗命令
  -> 丞相先判定是否需要引导
       - 具体可执行：直接路由执行，不打扰
       - 过短/空泛/脑雾/全做/上线/高风险：给上下文依据 + 更好的说法
  -> 史馆召回相似命令和失败教训
  -> 军机处执行
  -> 御史按验收闸打 PASS / BLOCK
  -> 史馆归档这次命令和结果
```

丞相接口应返回 `promptGuidance`，但不得改变原始 command 的执行语义：

```ts
{
  shouldGuide: boolean;
  trigger: 'none' | 'too_short' | 'vague' | 'brain_fog' | 'all_in' | 'release' | 'high_risk';
  contextBasis: string[];
  gaps: string[];
  suggestedPrompt: string | null;
}
```
