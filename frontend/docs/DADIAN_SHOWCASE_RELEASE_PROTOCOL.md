# 大殿可外部展示放行协议

## 目标

`/dadian` 不是普通后台页面。它只有在用户进入后能立刻感到“真实朝堂、活的大臣、恢弘景深、可交互裁决”时，才允许被称为可展示产品。

## 分工

| 部门 | 职责 | 不合格表现 |
|---|---|---|
| 丞相 | 最终放行，只认门禁 `decision=SHIP` | 凭主观感觉说“可以了” |
| 工部 | 实现交互、响应式、性能、无溢出 | 点不了、卡顿、移动端挤爆 |
| 礼部 | 视觉、文案、仪式感、截图呈现 | 像普通后台、没有进殿感 |
| 锦衣卫 | 错误浮层、坏响应、横向溢出、不可展示缺陷 | 有报错还拿出去演示 |
| 史馆 | 截图与 JSON 报告归档 | 没证据、说不清上次是否通过 |

## 放行门禁

运行：

```bash
pnpm run harness:dadian:showcase
```

默认检查：

- 桌面端 `/chaotang/dadian` 可打开并显示大殿。
- 点击 `工部` 后出现工部奏折。
- 追问工部后出现 `工部回奏`。
- 点击 `下旨` 后进入 `朱砂质门`。
- 最终能点击 `准奏` 并出现回执。
- 移动端可显示奏折并追问。
- 桌面和移动端都无横向溢出。
- 无 React/Next 错误浮层。
- 无未忽略的 console error、坏响应、请求失败。

## 产物

门禁报告：

```text
dev/artifacts/dadian-showcase-gate/latest.json
```

截图目录：

```text
dev/artifacts/dadian-showcase-gate/<run-id>/
```

只有 `latest.json` 里的 `decision` 为 `SHIP`，才允许对外展示。

## 展示纪律

1. 不拿未跑门禁的页面叫产品。
2. 不用静态截图冒充真实交互。
3. 不把 FALLBACK/本地回奏说成真实部门智能。
4. 如果门禁是 `FIX`，先修 blocker，再谈视觉品味。
5. 展示前同时保留桌面和移动端截图证据。
