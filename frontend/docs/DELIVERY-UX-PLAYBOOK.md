# 朝堂交付 · UX/法务/信任 playbook（2026-06-25）

> 配套 docs/BOX-PACKAGING.md。解三个非代码命脉:责任边界、决策可信度、多租户产品化。

## 1. 责任边界（法律护盾 · "能搞垮你"的那条）
**问题**:出决策建议的系统,客户照奏折拍错→亏→找谁担责?
**解 = 三层护盾(缺一不可):**
- **① UX 定性(已建)**:`ResponsibilityNotice` 组件常驻每个出奏折/建议处。
  - `inline`:卡底一行"丞相建议·陛下裁决——本系统提供咨询建议,最终决策与责任在裁决者本人"。
  - `gate`:圣裁动作旁强调版,裁决前提醒"责任在你"。**已挂大殿丞相今日要务;待扩到上书房奏折/圣裁按钮旁**(那块并发同事在改 auth,挂时避开)。
- **② 圣裁审计留痕(史馆已有·并发同事刚加 user_id)**:每次圣裁记 谁/何时/对哪份奏折拍板 → **证明是人决策非 AI**。这是护盾的证据。
- **③ 合同条款(法务·交付必签)**:
  > "本系统(朝堂 AI 决策 OS)提供**咨询性建议**,不构成任何经营、财务、法律决策。最终决策由用户作出,**相应后果与责任由用户承担**。供应商不对用户基于本系统建议所作决策的结果负责。"
  客户签字接受,作交付前置。

## 2. 决策可信度（Deming · 让信任变数字）
**问题**:客户凭什么长期信你的奏折?
**解(已建)**:`DecisionTrustBar` 读 `decision-judgment`(波1 真👍/👎沉淀)→ 显"奏折帮到率 X%·基于你 N 次真评判"。
- **无真样本不显**(诚实,绝不编好看的率)——这是客户自己评出来的信任,不是我们吹的。
- 已挂大殿丞相卡;**交付后这就是客户的月度信任仪表**。波1 那套捕获(`DecisionJudgment` 组件 + 端点)就是数据源。
- 进阶:做成"本月/本季帮到率趋势"图,放客户 IT 的本地仪表盘(不上云)。

## 3. 多租户 = 产品功能（Bezos · 把安全债重构成卖点）
**问题**:一公司多部门用一台盒子,决策互相泄露=泄密;隔离做好=可信。
**实现(并发 session 在改·1aacd09 部分已修)**:court_archives 加 user_id+synthetic 列、recall-guard(default-deny+排除DEMO/FALLBACK)、saveCourtArchive 写归属、跨租户召回 LIKE 加 user_id 过滤。**遗留 HIGH**:shiguan/archive GET 的 tasks/decisions/archives 三表 GET 仍无 user_id 过滤(另案)。
**产品化(把它当卖点,不只是补洞):**
- 卖点话术:"**部门级决策保密**——户部看不到刑部的决策,跨部门旧案不互窜。一台盒子,N 个部门,各自一本账。"
- UX:每个部门界面显"本部门决策"作用域;admin 角色可跨部门(显式授权)。
- 这把渗透 C3 从"安全债"翻成"企业级隔离"产品特性——同一份工作,换个说法就是竞争力。
