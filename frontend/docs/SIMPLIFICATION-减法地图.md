# 朝堂 OS 减法地图(产品复杂度收敛)

> 现状量化(2026-06-02):**25 个 (dashboard) 路由 · 11 个顶导项 · 单页 9~13 个面板**。
> 用户反馈:功能/按钮太多、一页塞太多分区。
> 一句话原则:**一屏一件事 · 主次分层 · 折叠高级 · 减少入口。**

---

## 一、四条减法原则(所有页通用)

1. **一屏一件事**:每页只服务一个核心动作,默认屏只放它。其余收起。
2. **主次三层**:主(默认可见 ≤1 件事)/ 次(折叠在"更多")/ 高级(挪到单独入口)。
3. **面板上限**:默认可见面板 ≤ 4 个;超出的进 tab / 折叠 / 子页。
4. **按钮收敛**:每屏主操作 ≤ 2 个;说明性/跳转性链接降级为次要或删。

---

## 二、三层减法(从宏观到微观)

### 减法 A · 顶导:11 → 6 核心
皇帝高频只需少数入口,其余收进二级"部院"菜单。

| 留在顶导(核心) | 收进二级菜单(部院) |
|---|---|
| 大殿 · 东宫 · 军机处 · 上书房 · 史馆 · 庄园 | 户部/工部/兵部/太医/锦衣卫/吏部/刑部… |

→ 改 `src/features/shangshufang/constants.ts` 的 `TOPNAV_ITEMS` + 加一个"部院"下拉。

### 减法 B · 路由:25 → 收敛重叠
明显重叠/可合并的:

| 现状(分散) | 收敛为 |
|---|---|
| `manor-dept/{finance,gongbu,ops,physician,guard}` + `bingbu` + `libu` + `shiguan` | 统一 `departments/[code]`,一套模板 + tab |
| `manors` + `manor-dept` + `departments` | 一个庄园/部门入口,内部切 |
| `overview` + `throne` | 合并为大殿总局一页 |
| `demo` / `battery-exchange`(垂直 demo) | 移出主导航,归 demo 区 |

→ 收敛后核心路由约 10 个,认知负担减半。

### 减法 C · 单页:面板 9~13 → ≤4 可见
范例见下「东宫 before/after」。规则:核心动作上屏,其余折叠/分 tab。

---

## 三、范例:东宫页 before → after(已落地,作样板)

| | before | after |
|---|---|---|
| 可见面板 | 13(Hero+3卡+待裁+授权账本+反事实3列+边界) | **2**(一行标题总览 + 待裁御批) |
| 按钮/链接 | Hero 2 链接 + 各处 | 御批准/驳 + 1 个"更多"折叠 |
| 默认屏 | 满屏分区,找不到重点 | **只剩"什么等我拍板"** |
| 次要信息 | 全部铺开 | 折叠进"查看运营详情" |
| 容器宽度 | max-w-1600(铺满) | max-w-1100(聚焦) |

**这就是模板**:其他页照此收敛——核心动作留屏,授权/反事实/边界/说明类一律折叠或挪走。

---

## 四、建议执行顺序(逐页,不一次性大改并发仓)

1. ✅ 东宫页(样板已成)。
2. 顶导减法 A(单文件 `TOPNAV_ITEMS` + 二级菜单),收益最大、风险最低。
3. 路由减法 B 逐组合并(departments 统一模板),需和并发方协调。
4. 高密页(governance 11 / grand-council 9)按"≤4 可见"逐页瘦身。

> 不一次性横扫(此仓有并发活动);**先立样板(东宫)+ 原则,再逐页收敛**,每页过 `pnpm build` + E2E + 截图。
