# 朝堂 OS · 交互与反馈标准 SoT

> 立于 2026-06-30，跑真实数据前的交互基线。本文是「用户怎么跟朝堂打交道、朝堂必须回他什么、
> 他必须看到哪些文件、什么才算合格」的唯一尺子。视觉气质另见冻结资产；本文只管**交互+反馈+成色+验收**。
> 大神镜片：karpathy(系统透明) · charity-majors(可观测) · 张小龙(克制) · deming(闭环成色) · schneier(高危授权)。

---

## 0. 一句话总纲

**朝堂不是聊天框，是决策操作系统。** 用户每一步都在一个状态机里：
`问 → 丞相拟旨 → 缺证检查 → 军机处会审 → 奏折 → 用户裁决 → 高风险确认 → 史馆归档 → 下次引用旧案`。
交互标准要做的，是让用户在**每一站都看得懂、控得住、信得过、能闭环**。

## 1. 五条交互铁律（借自顶尖产品，落到朝堂）

| # | 铁律 | 借自谁 | 朝堂落法 |
|---|---|---|---|
| 1 | **透明**：永远显示"正在做什么、凭什么" | Claude Code（每步工具调用都打出来）/ Perplexity（行内引用） | 会审过程显示哪个部在发言；每条结论挂 citations；全程带 sourceLabel |
| 2 | **可控**：随时能打断、改、撤销；高危先问 | Claude Code（plan 模式先提案、危险操作弹窗、可中途 steering） | 拟旨先给"将怎么办"再执行；会审跑一半能补条件；下旨可撤销；高风险下旨弹人工确认门 |
| 3 | **诚实**：不知道就说不知道，假的不装真 | Claude / ChatGPT（"我无法确定"）/ 你自己的真链路纪律 | 三色成色标（真·干净 / 真·脏 / 占位）；缺数据明说"缺什么"，绝不拿 DEMO 冒充 LIVE |
| 4 | **克制**：一屏一件事，键盘优先，不堆砌 | Linear / Superhuman / Things | 上书房只放"今天要定的那一件"；"交给朝堂"即命令面板；其余折叠 |
| 5 | **闭环**：每个动作有回执，落档可回看，结果可追兑现 | deming（outcome）/ Stripe（可执行回执） | 下旨即时回执；裁决落库不丢；史馆归档"事后兑现回填弧" |

## 2. 借鉴映射表：顶尖产品的招牌交互 → 朝堂怎么用

| 顶尖产品 | 它的招牌交互 | 搬进朝堂 = |
|---|---|---|
| **Claude Code** | 执行前先给计划（plan mode），同意才动手 | 丞相拟旨：先出"将如何办+决策类型+期望奏折"，用户点头再会审 |
| **Claude Code** | 执行中实时打出每一步在干嘛 | 军机处 `立项→会审→封询→盖章` stepper 实时点亮 + 哪个部在说话 |
| **Claude Code** | 危险动作（删文件/改主分支）先弹确认 | 高风险下旨（对外报价/付款/合同/股权）弹**人工确认门**，员工无权一键 |
| **Claude Code** | 可随时打断纠偏（steering） | 会审跑一半，用户能"等等，加个约束：预算不超 X"，再续跑 |
| **Claude Code** | 文件引用可点击 / diff 前后对比 | 奏折里证据可点开原文；裁决前后给"台账会变成什么"的 diff 预览 |
| **Perplexity / Claude** | 行内引用 + 来源可溯 | 每条结论挂 `citations`（字段已有）；点开看出处与时间 |
| **Linear / Superhuman** | Cmd+K 命令面板、键盘优先、乐观更新（点了即生效，不转圈） | 下旨/裁决**即时回执 <300ms**，后台再对账；快捷键直达"今日要决" |
| **Notion AI** | AI 建议以"接受 / 拒绝"呈现 | 采纳 / 驳回 / 再议（已有）——建议永远可拒，不强塞 |
| **ChatGPT** | 重新生成 / 编辑重发 / 👍👎 | "再议"=编辑重发；"帮到了/没帮到"反馈（已有）回流改进 |
| **Things / Apple** | 一屏一事、处处可撤销、空态优雅 | 简约上书房；裁决 5 秒内可撤销；"今日无需亲定"做成体面空态 |
| **Stripe** | 错误信息可执行、文档级清晰 | 缺证/失败必须说"缺什么·找谁补·点哪补"，不只报红 |
| **Figma（多人）** | 在场感：谁在场、谁在改、谁有分歧 | 会审显示哪些部在场、谁与谁口径不一（户部 × 兵部） |

## 3. 主交互回路：每一站的「输入 / 反馈 / 产物 / 标准」

| 站 | 用户输入 | 必须给的反馈 | 用户看到的产物 | 合格标准 |
|---|---|---|---|---|
| **① 问** | 自然语一句话（"季度要冲营收，要不要压价清库存？"）+ 可附证据文件 | **回显理解**：把他的话转成"丞相听懂的命令"，让他确认/纠正（借 Claude Code intent echo） | 改写后的待办命令草案 | 回显 ≠ 原话即提示"我理解成…对吗" |
| **② 拟旨** | 确认 / 改命令 | 丞相给"将如何办" | 丞相草案：决策类型 + 拟办法 + 推荐哪几位大臣 + 期望奏折格式 | 先提案后执行；不黑箱直接出结论 |
| **③ 缺证检查** | （自动） | 明示缺什么 | 缺证清单 + "找谁补/点哪补" | 缺证必列且可执行，不静默带病往下走 |
| **④ 会审** | 可中途追加约束 | 实时进度 + 各部发言 + 分歧点 | stepper + 发言流 + 分歧卡（谁 × 谁） | 过程可见；分歧不藏；可打断 |
| **⑤ 奏折** | 读 | 结构化呈奏 | **奏折八要素**：圣裁/分奏/证据/缺证/风险/后令/质门/来源（铁律6） | 缺任一要素即非法奏折 |
| **⑥ 裁决** | 采纳 / 再议 / 补证 / 复核 / 驳回 / 追问 | 即时回执 + 责任徽 + 影响预览 | 裁决卡：你的决定 + blast radius + 改了什么 | 即时回执；落库不丢；可撤销 |
| **⑦ 高危确认** | 亲点确认 | 二次确认 + 后果说明 | 确认门：这一点不可逆，影响 X | 高风险必过门，员工无权（schneier） |
| **⑧ 归档** | （自动）+ 事后回填结果 | 入史回执 | 史馆案卷 + 事后兑现回填弧 | 决策与"后来兑现没"成对存，可复盘 |

> 成色：🟢 已真 agent（户/刑/工） · 🟡 骨架/部分 · ⚪ 占位待接。改其产出须配对应守护大神会审（铁律4）。

| 角色 | 客户的预期（来问什么） | 必须给的核心产物 | 红线 / 质量标准 | 成色 |
|---|---|---|---|---|
| **丞相** prime_minister | 把乱七八糟的问题，收敛成"我现在该定哪一件、几个选项" | 拟旨草案 + 选项 + 分歧收敛 | 不替用户做决定，只把决策整理到"可裁决" | 🟡 |

| **工部** gong_bu | 研发/产线/交期能不能成 | 可行性 + 排期 + 交付风险 | 不承诺做不到的交期；成本读户部不另算（铁律6） | 🟢 |
| **刑部** xing_bu | 合规/法律/风控有没有雷 | 合规结论 + 风险点 + 缺证 + 出口门 | 缺证不放行；验签未过即拦（C1） | 🟢 |
| **钦天监** qin_tian_jian | 时机/趋势/会涨会跌 | 预测区间 + 不确定性 + 触发条件 | **必报不确定性，禁过度自信**；预测≠承诺（taleb） | 🟡 |
| **兵部** bing_bu | 怎么打、竞争对手怎么动 | 作战方案 + 竞争研判 | 情报调锦衣卫不自采（铁律6） | 🟡 |
| **吏部** li_bu | 人事/招辞转正/可信度 | 人事建议 + 可信度加权 | 涉个人不可逆动作（辞退）=高风险过门 | 🟡 |

## 5. 三类用户动作的反馈标准

**A. 下旨（发起一件事）**
- 即时回执 <300ms："已收，正在办"——**绝不让用户盯转圈猜**（Superhuman 乐观更新）。
- 进度可见：stepper 实时走；后台失败也要回滚并明示，不静默吞。
- 落库不丢：刷新页面任务还在（铁律13.2.7）。

**B. 裁决（采纳/再议/补证/复核/驳回/追问）**
- 每个选项都得在：建议**永远可拒**（Notion AI）。
- 采纳前给"影响预览"：这一点，台账会变成什么（Claude Code diff）。
- 高风险：先过人工确认门，再落；落后 5 秒内可撤销（Things undo）。
- 责任留痕：谁裁的、blast radius、时间，入史。

**C. 追问 / 纠偏**
- 会审中途可加约束并续跑（Claude Code steering），不必从头再来。
- "没帮到"要能一键转：补证 / 转军机处会审 / 换个问法（ChatGPT 编辑重发）。

## 6. 反馈分类法（用户在任何时刻该看到的 5 种信号）

1. **受理回执** — 我收到了、在办了（never silent）。
2. **进度** — 走到哪步了（stepper / 流式发言）。
3. **来源与成色** — 这条凭什么、信不信得过（sourceLabel + citations + 三色标）。
4. **结果 + 下一步** — 不只给答案，给"你现在能做的 2-3 个动作"。
5. **失败 / 缺口** — 缺什么、找谁补、点哪补（可执行，借 Stripe）。
> 外加两个闸：**高危确认门**（动作前）+ **可撤销**（动作后）。

## 8. 质量验收标准（Definition of Done · 每个交互上线前必过）

- [ ] 面向用户的每条结论都带 **sourceLabel**（LIVE/LIVE_SWARM/MIXED/FALLBACK/DEMO），且三色成色可分。
- [ ] **DEMO/FALLBACK 绝不冒充 LIVE**；缺数据明示"缺什么"，区分"今天没事"与"读不到"。
- [ ] 高风险动作（报价/付款/合同/股权/不可逆承诺）**必过人工确认门**，员工无权一键。
- [ ] 奏折**八要素齐全**，缺一即拦。
- [ ] 每个用户动作有**即时回执**，且**落库不丢**（刷新不丢），可撤销。
- [ ] 失败信息**可执行**（缺什么·找谁·点哪），不是裸报错码。
- [ ] 列表对脏数据**抗造**：长文截行、重复折叠标 ×N（不静默吞）。
- [ ] 关键流程有一条 **e2e + 一条回归断言**（铁律4），CI 每次替你复核。

## 9. 反模式（禁止）

- ❌ 转圈无回执，让用户盯着猜。
- ❌ 把占位/DEMO 刷成跟真数据一样体面（美术盖脏）。
- ❌ 一键静默采纳高风险（绕过确认门）。
- ❌ 缺数据时编一个像样的答案（编造 > 留白，是大忌）。
- ❌ 一屏堆十张卡，没有主次。
- ❌ 报错只给代码/堆栈，不给"怎么办"。
- ❌ 决策只存"当时怎么定"，不追"后来兑现没"。
