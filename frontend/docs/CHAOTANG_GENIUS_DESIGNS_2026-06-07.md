# 朝堂 OS 天才设计清单 2026-06-07

## 1. 已进入实现的天才设计

### 1.1 对象一致性闸

原则：用户眼前看到的对象、点击动作携带的对象、下个部门接收的对象必须是同一个。

已落地：

- 上书房 `按此下旨` 绑定当前可见御案。
- Playwright 覆盖 `按此下旨 -> 输入框预填 -> 下旨模式`。
- 工部 build ledger 同一对象流向军机处、史馆。

下一步：

- 所有跨部门主动作都要加对象一致性测试。
- 高风险按钮要显示对象摘要，例如 `送史馆复盘 · build-chaotang-dev-workbench-mvp-e2e`。

### 1.2 史馆召回入下旨

原则：上书房不是只看今天，而是在起草前召回历史可复用依据。

已落地：

- 上书房显示 `历史可复用依据`。
- 可把史馆/经营记忆依据带入下旨文本。
- 带入内容包含来源、匹配原因、置信度。

价值：

- 把史馆从“归档页面”变成“决策前的记忆系统”。
- 用户下旨前少走弯路，系统越用越懂业务。

下一步：

- 让召回按当前御案关键词排序，而不是只取最近/默认案卷。
- 把用户是否采用召回依据写回史馆，形成自我改进信号。

### 1.3 跨部门对象护照

原则：每个任务跨部门流转时，都带同一张 `objectId/title/status/source/evidenceCount/nextOwner` 护照。

已落地：

- 工部写入 build ledger 后显示对象护照。
- 军机处接单卡显示同一 `objectId`、证据数和下一责任人。
- 史馆建设台账显示同一 `objectId`，归档后下一责任变为 `上书房召回`。
- Playwright 覆盖 `工部 -> 军机处 -> 史馆` 同一 objectId 流转。

价值：

- 用户不再靠记忆判断“这是不是同一个案子”。
- 页面、按钮、归档、召回共享同一任务身份，降低误派、误归档和重复建设。

下一步：

- 把对象护照扩展到上书房御案、户部预算、翰林 Skill、蜂群 session。
- 高风险动作必须先显示护照，再允许发布、归档、对外输出。

## 2. 下一批最值得做的天才设计

| 优先级 | 天才设计 | 用户价值 | 最小实现 | 验收 |
|---|---|---|---|---|
| P0 | 发布/归档双闸 | 完成不等于可发布，归档不等于学会 | 每次 `完成/归档` 前显示 QA、证据、负责人、下一次复用点 | QA fail 不能出现可发布文案 |
| P1 | 历史依据采用率 | 系统知道哪些历史经验真的有用 | `带入下旨` 记录 `acceptedMemoryId` | 史馆能看到被采用次数 |
| P1 | 一页一主动作 | 降低选择负担 | 每个核心页面只暴露一个主按钮，其它动作降级 | Playwright 检查主按钮唯一 |
| P1 | 部门责任签名 | 用户知道谁负责下一步 | 主动作落地时显示 `ownerDept/actor/status/time` | 军机处、史馆均显示责任签名 |
| P2 | 反事实复盘 | 不只记录做了什么，也记录没做什么 | 归档时保存一个“如果不做/换部门”的短结论 | 史馆卡片显示反事实 |
| P2 | 用户风格镜鉴 | 系统学习用户偏好，但不替用户决策 | 展示“历史 N 次你选择 X”，仅作镜子 | 圣裁页能显示历史选择但仍需人工确认 |

## 3. 大神共识

张小龙：先把主路径做短，不要让用户在“问、下旨、归档、复盘”之间猜。

Deming：每个天才设计都必须有可复验的测试，不然只是口号。

Chaotang Product System：页面不是孤岛，每页都必须改变下一步决策，并给史馆留下证据。

## 4. 当前推荐最小动作

继续做 P0 `发布/归档双闸`。

原因：对象护照已经让任务身份不丢，下一步要防止用户把未验收、未补证、未签名的内容误当成可发布成果。
