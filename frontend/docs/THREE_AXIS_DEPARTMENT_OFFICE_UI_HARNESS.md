# 朝堂 OS · 部门办公室三轴作战台 UI Harness

> 本规范是上书房、六部、诸司、庄园、军机处等“办公室型页面”的视觉门禁。大殿是朝会场景，可单独立规格，但仍应保留顶导、主行动层和下旨入口的秩序感。

## 1. 北极星

用户进入页面时，应立刻感觉自己进入了一个真实衙署办公室：

- 中央有可处理的卷轴 / 圣旨 / 案卷。
- 左侧告诉用户“现在有什么情报、任务、风险”。
- 右侧告诉用户“主管怎么判断、产出了什么、如何验收”。
- 底部可以直接下旨。
- 左下是丞相，右下是本部门负责人。

视觉主角永远是中央卷轴。页面可以有部门差异，但不得破坏三轴布局。

## 2. 三轴结构

桌面端统一三段式：

```text
┌──────────────────── 顶部导航 ────────────────────┐
│ 左侧面板          中央卷轴 / 圣旨 / 案卷          右侧面板 │
│ 情报 / 任务 / 风险       主舞台 / 主行动       裁决 / 成果 / 验收 │
│                                                    │
│ 丞相 Agent             底部下旨栏             部门负责人 Agent │
└────────────────────────────────────────────────────┘
```

硬规则：

- 顶部导航必须可见，不能被卷轴遮挡。
- 中央卷轴必须在页面中线附近，作为最高亮度主行动层。
- 中央卷轴必须支持三态：收卷看背景、半展看摘要、全展处理正文 / 圣旨。
- 左右面板必须同宽、同边距、同标题层级。
- 左下 Agent 与左侧面板左边缘对齐。
- 右下 Agent 与右侧面板右边缘对齐。
- 底部下旨栏固定在底部，不能抢中央卷轴主视觉。

## 3. 尺寸纪律

桌面端推荐网格：

- `lg`: `300px minmax(420px, 1fr) 300px`
- `xl`: `330px minmax(520px, 1fr) 330px`
- `2xl`: `350px minmax(620px, 1fr) 350px`

组件尺寸：

- 面板圆角：`10px`
- 卡片圆角：`8px`
- 主按钮高度：`36px`
- 次级按钮高度：`28px`
- Agent 对话框宽度与侧栏同档。
- 导航项使用统一 slot 宽度；不要靠临时 padding 撑齐。

## 4. 三层美术

每页只保留三层：

1. 背景层：暗宫室 / 办公室背景，低对比。
2. 信息层：左右面板，墨黑玻璃，帝金边线。
3. 主行动层：中央卷轴 / 圣旨 / 案卷，亮度最高。

用户视线顺序必须是：

1. 中央卷轴
2. 左右面板
3. 底部下旨
4. 背景

## 5. 部门差异只放纹理

布局、按钮、面板、卷轴比例不随部门变化。部门差异只允许进入纹理包：

- 户部：账册纹、金算盘、库银暗纹。
- 礼部：绢纸、印章、朱批、礼器纹。
- 工部：图纸、木尺、榫卯、工程蓝图暗纹。
- 兵部：沙盘、军令、阵图线。
- 刑部：朱砂、红线、法帖、封条。
- 吏部：名册、官印、任命文书。
- 军机处：密折、兵符、会审图。
- 庄园：地契、田亩图、经营账本。

部门色只能做 10%-15% 点缀，不得统治页面。

## 6. 动效礼制

动效要像仪式，不像炫技：

- 卷轴展开：300-520ms，中轴铺开；半展态只露摘要，不长期遮住背景。
- 面板出现：上浮 6px，透明度渐入。
- Agent 汇报：头像边缘呼吸光。
- 圣旨切换：朱印轻落一次。
- 任务状态变化：金线扫过。
- 背景：极慢尘光、烛光、月光。

禁止大幅飞入、乱闪、重复弹窗、过多粒子。

## 7. Harness 检查项

`scripts/validate-three-axis-ui.mjs` 会检查：

- `topnav`: 顶部导航存在且贴近顶部。
- `scroll`: 中央卷轴 / 案卷存在，并接近页面中线。
- `visual.scrollBreathingRoom`: 卷轴与顶导之间必须有呼吸感，不得贴顶压导航。
- `visual.scrollNotEdgeToEdge`: 中央主舞台不能横向贴边，必须给背景和两侧信息层留空间。
- `panel-left` / `panel-right`: 左右信息层必须存在，并分列中轴两侧。
- `panel.framesScroll`: 左右信息层必须框住中央卷轴，不得明显压住主舞台。
- `panel.*.contentItems` / `panel.*.contentDensity`: 左右信息层必须有 3 条以上具体工作信息，不能只是空框架。
- `agent-left` / `agent-right`: 双 Agent 存在且位于左右下角。
- `agent-width`: 左右 Agent 宽度接近。
- `decree-input`: 底部下旨栏存在且位于底部。
- `decreeInput.primaryAction`: 底部下旨栏必须提供主管预置主动作，例如准奏、补证、复核、派发或立案会审，不能只留空输入框。
- `decreeInput.actionReceipt`: 点击主管主动作后必须出现动作回执，明确告诉用户“已接旨 / 已入队列 / 已进入会审链路”，防止主按钮只是装饰。
- `decreeInput.actionSeal`: 动作回执必须带朱批落印视觉层，让“下旨被接收”成为有礼制感的可见状态，而不是普通 toast。
- `decreeInput.sourcePlaque`: 动作回执必须带来源铭牌，让“传旨台收到的反馈”与中央案卷使用同一套验真语言。
- `scroll.actionSeal`: 底部主动作必须联动中央卷轴 / 案卷落印，形成“下旨 -> 御案承接”的视觉闭环。
- `visual.dockClearsAgents`: 底部下旨栏不能遮挡左右 Agent。
- `art.ornamentDepth`: 共享页必须渲染礼制器物层，例如漆木屏风、收卷卷轴、Agent 奏报、今日三令令牌；普通部门至少 4 层，上书房至少 2 层。
- `art.scrollManuscript`: 共享部门卷轴展开后必须出现礼制正文排版层，包含案牍 / 圣旨正文、边注和印章栏。
- `art.manuscriptTriad`: 展开态必须同时具备纸面正文、边注 / 侧批、印章三件套，不能退回普通网格或 dashboard 卡片。
- `art.manuscriptTypography`: 展开态必须具备题签、书法题头、朱线和正文韵律层；正文段落、列表和重点字必须像案牍文字，而不是普通网页段落。
- `art.manuscriptVoice`: 展开态必须声明文书字法：圣旨庄重疏朗、奏折密实带批注感、案卷紧凑可扫读。
- `geometry`: 卷轴与页面中线偏差、左右 Agent 对齐偏差在阈值内。
- `scrollRitual.*`: 共享部门卷轴必须默认可收，收卷态必须有主管摘要和至少 3 层器物细节，点击可展，高度显著铺开，再次可收；展开态必须有开卷光扫、开卷朱印、来源铭牌和半展摘要控制。
- `visualReview`: 每页随报告输出礼部截图会审清单，人工看图时必须逐项过。

脚本会输出：

- `dev/artifacts/three-axis-ui/<run-id>/report.json`
- 每个页面截图
- 共享收放卷轴页面的展开态截图：`<route>.expanded.png`
- 礼部视觉会审页：`dev/artifacts/three-axis-ui/<run-id>/visual-review.html`
- 最新会审入口：`dev/artifacts/three-axis-ui/latest-visual-review.html`
- `dev/artifacts/three-axis-ui/latest.json`

礼部人工会审优先打开 `visual-review.html`，逐页对照 collapsed / expanded 截图和自动门禁；JSON 内仍保留 `visualReview` 结构化清单。会审页内置四项评分，浏览器本地保存，可导出 JSON：

- 构图轴线：中轴是否稳、左右是否均衡、卷轴是否是主角。
- 礼制气质：是否像朝堂案卷，而不是普通后台卡片。
- 信息密度：任务、证据、成果、主管判断是否可扫读。
- 主行动清晰：用户是否知道下一步该下什么旨。

单页满分 40，建议发布候选线为 32；低于 32 标记“礼部复审”。会审页顶部会实时生成“礼部复审名单”，把低分页和未评分页列出来，作为下一轮美工优先级。可导入上一次导出的评分 JSON，生成连续低分、退步、改善趋势，并自动导出下一轮美工 TODO；优先级为：连续低分 > 本轮退步 > 当前低分 > 未评分。

礼部人工会审看 `visualReview`：

1. 中央卷轴 / 案卷是否是首屏唯一主角。
2. 两侧面板是否只是框住信息，而不是抢主舞台。
3. 底部下旨栏是否没有遮挡 Agent 或卷轴。
4. 部门差异是否只在纹理、文案和 10%-15% 点缀色里表达。
5. 页面是否保留东方礼制器物感，而不是退化成普通 dashboard 卡片。
6. 展开后的案卷正文是否有圣旨 / 奏折韵味，而不是普通段落堆叠。
7. 来源铭牌是否清楚、克制、像御案验真牌，而不是普通系统标签；LIVE / MIXED / FALLBACK / DEMO 必须一眼可辨。
8. 文字是否有“题签、朱线、正文韵律、重点朱批”的层级，而不是同字号同颜色堆满卷轴。
9. 文书类型是否清楚：圣旨、奏折、案卷不能共用一种普通正文排版。

共享部门页另看 `scrollRitual`：

1. 默认首屏是精美收卷态，不能用大面板永久挡住办公室背景。
2. 点击卷轴后必须进入展开态，展开高度显著增加，像真正案卷被请出来。
3. 展开态必须有“收卷”控制，并能回到收卷态。
4. 展开态必须显示 `scrollRitual.sourcePlaque`，让用户知道案卷来源是真后端、混合、降级还是演示。
5. 展开态必须显示 `scrollRitual.previewControl`，允许用户退到半展摘要，既保留价值信息，也让办公室背景重新透出来。
6. 底部传旨回执必须显示 `decreeInput.sourcePlaque`，不能让回执变成无来源的普通 toast。

## 9. 验收命令

本地 dev：

```bash
pnpm dev
pnpm harness:three-axis-ui

# 本地 dev 进程不稳定，或只审某组页面时，仍用同一门禁分批跑：
THREE_AXIS_STRICT=1 THREE_AXIS_ROUTES=ops,legal,personnel pnpm harness:three-axis-ui
```

生产：

```bash
THREE_AXIS_BASE_URL=http://127.0.0.1:3050 THREE_AXIS_BASE_PATH=/chaotang pnpm harness:three-axis-ui
```

改动 TSX 后仍必须跑：

```bash
pnpm exec tsc --noEmit
pnpm build
```
