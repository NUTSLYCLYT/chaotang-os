# 朝堂 OS 页面存在意义会审

日期: 2026-06-07  
仓库: `/home/ubuntu/workspace/chaotang-web-lyt`  
评审镜头: `chaotang-product-system-panel` + `chaotang-panel-maturity-rubric` + 张小龙产品克制视角 + Tobi Lutke 工具基础设施视角

## 总结

当前不是缺页面，而是页面太多、层级太多、同义页太多。`src/app` 下有 96 个 `page.tsx`，其中 dashboard 66 个，公开/后台/分享/任务页 30 个。真正应该让普通用户反复使用的，不应超过 9 个主工作站。

北极星闭环应固定为:

`上书房 -> 圣旨/大殿 -> 军机处 -> 三省/部门/庄园执行 -> 史馆归档 -> 次日上书房学习`

任何页面只有符合以下至少一项才值得保留为独立入口:

- 它拥有一个明确的用户工作: 输入、判断、执行、验收、归档、复盘。
- 它承担不可替代的对象: 任务、奏折、情报、预算、交易、健康、知识、实验。
- 它能把结果写回系统，让下一次推荐更好。
- 它是内部调试、演示、分享、登录等必要边界页。

## 页面分层建议

| 层级 | 页面类型 | 用户 | 意义 | 处理 |
|---|---|---|---|---|
| L1 主线 | 上书房、圣旨、大殿、军机处、史馆、庄园 | 创始人/老板 | 每天真正使用 | 必须打磨到闭环 |
| L2 部门 | 户部、兵部、锦衣卫、太医院、翰林、礼部、钦天监、三省 | 专项决策/会审 | 主线的专业分支 | 只在有任务上下文时出现 |
| L3 对象详情 | task、report、brief、signal、case、run | 深入追踪 | 查看单个对象的证据链 | 保留，但从列表进入 |
| L4 工具后台 | jiqun、admin、e2e、settings、debug | 开发/运维 | 诊断、配置、验证 | 从普通导航隐藏 |
| L5 市场/演示 | intro、about、guide、demo、present、share | 外部访客/路演 | 获客、解释、分享 | 与产品主线隔离 |
| L6 业务实验 | battery-exchange | 行业垂直场景 | 可做独立产品线 | 不应混进朝堂主导航 |

## 优先整理顺序

1. 修入口: 明确 `/`、`/intro`、`/throne`、`/court-briefing` 的跳转关系。
2. 定 9 个普通用户主入口: 上书房、大殿/圣旨、军机处、户部、兵部、锦衣卫、史馆、庄园、设置/帮助。
3. 把所有 L3 对象详情改为从主入口进入，不在导航里抢注意力。
4. 把 `/jiqun/*` 全部标记为开发者后台，普通模式隐藏。
5. 给每个主入口补一行固定元信息: 输入、输出、下一步、证据、归档位置。
6. 给每个 P0 页面加 Playwright gate: 可打开、无 console error、无坏图、无横向溢出、主要 CTA 可见。

## 大神们的分歧

- 张小龙视角: 页面少一点。用户不是来参观朝堂，而是来处理一件事。每多一个入口，都是一次打断。
- 朝堂系统视角: 部门可以多，但必须是工作站，不是景点。每个部门都要拿输入、给输出、转下一站。
- Tobi 视角: 真正的护城河不是视觉，而是任务、证据、归档、复用这些基础设施。页面要武装用户，不要锁住用户。

## 最小可整理版本

第一版只需要让用户记住 5 件事:

1. 上书房: 今天看什么。
2. 圣旨: 我要下什么命令。
3. 军机处: 现在谁在执行。
4. 史馆: 结果和证据在哪里。
5. 庄园/部门: 具体业务谁承接。

其他页面都可以存在，但先不要争夺首页、顶栏和用户心智。
