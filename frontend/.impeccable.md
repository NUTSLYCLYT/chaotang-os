# CourtOS Impeccable Context

This file is the project-level design context for Impeccable-style reviews.
Use it before changing any CourtOS UI.

## Product Identity

CourtOS is not a costume drama UI and not a generic chat product. It is an AI decision operating system:

```text
real business question
-> chancellor drafts intent
-> grand council reviews
-> departments and swarms produce evidence/risk/conflict
-> user decides
-> archive and learning loop
```

The interface should feel like a restrained command room with ceremonial gravity:

- Palace shell, business core.
- Dark imperial environment, modern operational dashboard.
- Gold is an information accent, not decoration.
- Red/yellow/green/gray states must be immediately readable.
- Ordinary users should not see internal loop names, agent topology, or technical logs.

## Fusion Principle

New capabilities should merge into original screens whenever possible:

- Shangshufang: entry, one-sentence decree, chancellor draft, summary.
- Junjichu: review process, department opinions, evidence, conflicts, quality gates.
- Memorial scroll: final decision report, risks, missing evidence, source label.
- Shiguan: archive, retrospectives, reusable lessons.
- Zhuangyuan: swarm barracks, secret edicts, formations, dispatch authority.

Do not create new pages for every concept. Add panels, rows, or sections to existing screens first.

## Visual Direction

- Emotional positioning: solemn, decisive, premium, operational.
- Volume: normal to keynote for primary decisions; whisper for metadata.
- Temperature: dark neutral with controlled gold, warning red, signal green, source blue.
- Density: compact but legible; dashboards should scan fast.
- Texture: glass and lacquer, not toy-like ancient fantasy.

## Typography

- Chinese titles can use serif-style stacks where already established.
- Operational labels and numbers should stay compact and readable.
- Do not scale font size with viewport width.
- Do not let button/card text overflow on mobile or desktop.

## Layout Rules

- Keep existing CourtOS shell and original screens.
- Do not nest cards inside cards.
- Do not add marketing hero sections to product screens.
- Prefer dense left/center/right operational layouts for command surfaces.
- First viewport must answer: current state, biggest risk, next action.
- Technical loop names such as `court_unified_decision_loop_v1` stay hidden unless in developer/debug contexts.

## Color Rules

- Background: dark blue-black / near black.
- Surface: translucent dark panels.
- Accent: restrained gold.
- Red: blocking, high risk, human confirmation.
- Yellow/gold: missing evidence or warning.
- Green: cleared, live, proceed.
- Blue: mixed/source/process state.

Avoid one-note purple/blue gradients, beige theme drift, and decorative orb backgrounds.

## Quality Bar

Before shipping UI:

1. Is the next action obvious within 10 seconds?
2. Are source labels visible where decisions are made?
3. Are high-risk decisions impossible to silently accept?
4. Are missing evidence and conflicts visible, not averaged away?
5. Does the UI hide internal agent/loop mechanics from ordinary users?
6. Does the new feature live in an original screen unless a new workflow truly needs a page?
