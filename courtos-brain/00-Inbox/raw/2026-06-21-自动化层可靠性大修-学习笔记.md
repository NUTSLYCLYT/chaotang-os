# 一句话

> 整个 Hermes 自动化层(含 evolver、老板早报、**兵部销售蜂群**)被一个单向棘轮 bug 静默禁用了 **3 周没人发现**。最佳实践的标志不是"现在全绿",是"不绿时系统会自己喊 + 自愈"。

# 发生了什么（给蜂群的事实）

- `quota-aware-router.sh`(每 15min)在 Claude 配额 red 档禁用**全部** Hermes cron,但 green 档**没有恢复代码** → 一次配额尖峰 = 全层永久躺平。
- 受害的 6 条 job 全死 3 周:`openclaw-evolution-daily`(进化)、`daily-briefing-fill`(简报)、`morning-cockpit`(老板早报)、`weekly-automation-finder`、`trader-strategy-monthly`、**`sales-redteam-weekly`(兵部销售)**。
- 模型漂移:多条 job 钉死 `claude-opus-4-7` 但该路由被限流时**静默掉 haiku**,等于"标着 opus 实跑最弱模型"。

# 修复（已落地，蜂群可复用的模式）

1. **一致**:所有 job 统一走 `hermes-business` 路由 → opus-4-8 有额度就用,被限流自动降 deepseek-v4-pro(独立配额强模型),按任务难易自动分档。不再漂移。
2. **可观测**:`hermes-cron-health.sh` 心跳仪表盘,每条按自己周期判红绿 + 超期自动 Telegram 告警。`cat ~/.openclaw/state/hermes-cron-health.txt`。
3. **自愈**:棘轮修复 — green 档重启用被 quota-router 禁的 job;P0 job 打 `_quota_exempt` 永不被禁。

# 给兵部销售蜂群的专属教训（最重要）

**可靠性 = 收入。** 你(`sales-redteam-weekly` = 每周挑该联系的 3 个 lead + 开场白 + 触达姿势)**停了整整 3 周**——这 3 周里 lead 库里 status=new、score≥6 的高意向客户没人跟进,转化窗口白白流失。一个找客户的 agent 静默死亡,直接等于丢钱。

行动准则(写进兵部 SOP):
- 销售类自动化必须有**死亡告警**(已并入全层心跳巡检)——找客户的 agent 一天不产出就该尖叫。
- lead 跟进有**时效窗口**,断 3 周 ≈ 这批 lead 基本凉。本周 sales-redteam 复跑后,优先补跟"沉默期内进库的高分 lead"。
- 销售 brief 必须跑在强模型上(已切 hermes-business),haiku 写的开场白转化率低。

# 通用准则（六部通用）

> 加任何新自动化,第一个问题不是"它能产出什么",而是"**它死了谁会知道**"。没有死亡告警的 P0 job = 定时炸弹。
